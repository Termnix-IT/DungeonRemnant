# Phase 9

Godot 4.6系で `project.godot` を開き、F6ではなくF5でプロジェクトを実行します。

## 拠点・永久強化

起動時は拠点画面を表示します。「冒険開始」で1F・Lv1から出発し、冒険終了後はリザルトの「拠点へ戻る」またはRで帰還します。拠点では所持Gold・装備5枠・Inventory使用枠数・永久強化の状態を確認できます。装備変更や倉庫機能はありません。

永久強化は最大HP強化の1種類です。1段階につき最大HP＋1、上限3段階。価格は順に30・60・90 Goldです。Gold不足・上限到達時は購入できません。効果は次の冒険から適用し、装備・冒険中能力のHP増加と加算します。死亡しても購入段階は失わず、次の冒険では能力だけをリセットします。

調整値は `data/upgrades/max_hp.tres` の `Hp Per Level` と `Costs` にあります。初期Goldは0です。たとえば敵を6体倒して60 Gold以上を持って中断・帰還すると、死亡時損失後にも初回購入分の30 Goldが残ります。

Mainが拠点とRunを切り替え、引き継ぎデータを保持します。帰還時にはリザルトで確定済みの残高を使用し、損失を再計算しません。通常起動では自動保存・ロードも有効です。

## セーブ・ロード

保存するのはGold・永久HP強化段階・InventoryのアイテムIDと個数・装備5枠です。冒険中のLv・EXP・能力・HP・地形は保存しません。未実装の倉庫・設定画面・図鑑も保存対象には追加していません。

- 起動時に自動ロードします。
- 永久強化購入時、冒険への出発時、死亡・中断・クリアの結果確定時に自動保存します。
- リザルトから拠点へ戻る前に終了しても、結果確定時の保存が成功していれば損失・報酬が残ります。
- 冒険途中でアプリを終了すると、その冒険は再開せず、最後に保存した拠点状態へ戻ります。途中で拾った物や消費した物は反映しません。
- 保存成否は拠点下部・リザルト下部に表示します。購入時の保存失敗はGoldと購入段階を元に戻します。出発前の保存失敗は拠点に留まります。
- 結果確定時に保存できなかった場合、結果はメモリ上に保持します。拠点へ戻り、保存先の問題を解消して再度出発すると、その状態を保存してから出発します。保存成功までは終了しないでください。

保存先はGodotのユーザーデータ領域 `user://progress.json` です。通常のWindows環境では `%APPDATA%/Godot/app_userdata/RogueLike_play/` 配下になります。バックアップは `progress.json.bak`、書き込み中のファイルは `.tmp` を付けた名前です。

形式バージョン・数値・既知のアイテムID・スタック上限・装備先を検証します。読み込めない本体があればバックアップを試し、復元した場合は画面に通知します。読み込めない元ファイルは、次の保存前に `.unreadable-…` として退避します。本体とバックアップの両方を読めない場合は、上書きを防ぐため保存・出発を停止します。ファイルを削除せず、まず保存フォルダ全体を別の場所へコピーして調査してください。

一時ファイルの書き込み・読み戻し検証後に置き換えます。バックアップは直前の正常な保存内容であり、最新結果と異なる場合があります。ディスク故障や複数プロセスからの同時保存まで保証する方式ではありません。

テストは `res://.godot/` 配下の専用ファイルを使用し、通常の保存データに触れません。従来のルールテストはMainの `Saving Enabled` を無効にしています。Run単体の起動にはセーブ機能は接続しません。

## 操作

- 移動: WASD、矢印キー、テンキー2・4・6・8
- 斜め移動: Q・E・Z・C、テンキー7・9・1・3
- 攻撃: Spaceまたはテンキー5で攻撃モードに入り、移動キーで方向を選択し、もう一度Spaceまたはテンキー5で確定します。
- 攻撃キャンセル: Esc
- 能力選択: 表示されたボタンをクリック、または数字キー1・2・3（キーボード上段）
- Inventory: Iで開閉、Escでも閉じる。所持品を選んで装備先や「使う」をクリック
- Main / Sub武器切り替え: 探索中はTab、Inventory内では切り替えボタン
- 中断確認: 探索中にR（Escで取り消し、ボタンで確定）
- 拠点へ帰還: リザルト画面でR、または「拠点へ戻る」ボタン
- 次の冒険: 拠点の「冒険開始」をクリック

壁や敵に向かって移動すると、向きだけ変わりターンは進みません。空振り攻撃は1ターン消費します。

敵が見えていない探索済み区間では、移動キーを押し続けると約0.25秒後から約0.08秒間隔で同じ方向へ連続移動します。1マスごとに通常の1ターンとして敵も行動します。敵の発見、未探索マス、アイテム・階段の発見または直前、分岐、キー解除、Inventory・攻撃モード・能力選択・リザルトで停止します。停止後に再開するには移動キーを押し直してください。自動探索や経路探索は行いません。

攻撃モード中は移動せず、方向選択・キャンセルでも敵は行動しません。黄色の範囲は攻撃対象マスのうち現在視界内の部分です。壁や角で遮られたマス、最初の敵の背後は範囲に含まれません。

## 武器の検証

初期装備はMainに剣、Subに槍です。探索中はTabで交換できます。拾った武器はInventoryからMainまたはSubへ装備できます。通常起動では拠点の装備を引き継ぎます。Run単体をF6で検証する場合のみ、`game/run/run.tscn`のRunノードのInspectorで `Starting Weapon` に以下のResourceを指定して開始武器を変更できます。

- `data/weapons/sword.tres`: 隣接1マス
- `data/weapons/spear.tres`: 直線2マス、最初の敵に命中
- `data/weapons/hammer.tres`: 隣接1マス、生存した敵を1マス押す

ハンマーは壁・敵・マップ外・斜めの角でノックバックできない場合も、通常ダメージだけ与えます。押された敵もその後の敵ターンで行動するため、接近して元のマスへ戻る場合があります。3武器とも初期ダメージ補正は0です。

初期設定は40×40マス、各階に敵3体です。カメラがプレイヤーに追従します。敵は感知条件を満たすと、各ターンに移動か攻撃を1回行います。死亡すると損失を適用してリザルトを表示します。

## Gold・冒険終了・再挑戦

敵を倒すとGoldを獲得します。初期値は1体10Goldで、敵Resourceの `Gold Reward` で調整できます。EXPと同じタイミングで一度だけ付与され、階層をまたいで維持します。HUDに所持Goldを表示します。

- 死亡・中断時：所持Goldの50%と、Inventory内の総個数の50%を失います。端数は切り捨てです。
- アイテムはスタックも個数単位で均等に抽選します。Inventory内の予備装備も対象ですが、装備中の5枠は必ず保持します。
- リザルトに到達階・今回獲得したGold・失ったGold・残りGold・失ったアイテムを表示します。終了処理を繰り返しても二重に失いません。
- 再挑戦は1F・Lv1・EXP0・能力なし・HP全快で開始します。残ったGold・Inventory・装備を引き継ぎ、装備効果は改めて適用します。
- Rによる中断は確認画面を挟みます。確認・取り消しはターンを消費せず、確定すると死亡時と同じ損失を適用してリザルトへ進みます。能力選択中の中断は無効です。
- 10Fのボスを倒すとクリアです。撃破報酬を付与してから損失なしのリザルトへ移り、そのターンの残りの敵行動・能力選択は行いません。

通常起動では保存された所持品と強化をアプリ終了後も引き継ぎます。Run単体のテスト用起動では、従来どおりリザルトから直接再挑戦できます。

## Inventory・装備・拾得

Inventoryは最大40種類枠です。同じ消耗品は1枠に50個まで入り、50個を超える分を別枠には入れません。武器・防具・アクセサリーはスタックせず、同じ装備でも1個につき1枠を使います。

装備枠はMain Weapon・Sub Weapon・Armor・Accessory 1・Accessory 2の5枠で、装備中アイテムはInventory上限に含みません。初期Inventoryは空です。

Iで画面を開き、左の所持品を選択すると装備先または使用ボタンが表示されます。右側で現在の装備を確認できます。Main武器は攻撃に必要なため単独では外せません。別の武器との交換かMain / Sub切り替えを使用します。他の装備は「外す」でInventoryへ戻せます。

- 画面の確認・所持品の選択・閉じる操作はターンを消費しません。
- 装備変更・取り外し・Main / Sub武器切り替えはターンを消費しません。Inventory内の装備変更後も画面は開いたままです。
- 回復薬使用は成功時に1ターン消費し、画面が閉じて敵が行動します。
- 装備交換は外す装備の収納まで確認してから実行します。満杯でも、選んだ装備が抜けた枠に旧装備を戻せる交換は可能です。
- 収納できない取り外しや、HP満タンでの回復薬使用は失敗し、アイテムとターンを消費しません。
- 最大HPを増やす装備を付けても現在HPは回復しません。外して最大HPが減った場合は、現在HPを新しい上限までに制限します。
- 装備効果は能力による成長と併用でき、外すと装備分だけが戻ります。同じアクセサリーを2枠に装備した場合は両方の効果が加算されます。

| 種類 | アイテム | 初期効果 |
|---|---|---|
| 武器 | 剣・槍・ハンマー | 既存の武器性能 |
| 防具 | 革の防具 | 防御 +1 |
| 防具 | 鎖の防具 | 防御 +2 |
| アクセサリー | 生命のお守り | 最大HP +4 |
| アクセサリー | 遠見のお守り | 視界 +2 |
| アクセサリー | 力のお守り | 全武器のダメージ +1 |
| 消耗品 | 回復薬 | HP +8、最大HPまで |

初期設定では各階に6箇所のアイテムを配置し、そのうち2箇所は回復薬×2です。1個は開始位置の近く、残りは到達可能な床に配置します。階段・開始位置・初期の敵とは重なりません。`DungeonSettings`の `Item Count` で配置数を変更できます。

床アイテムは現在視界内だけ表示し、武器は白い剣型、防具は青い四角、アクセサリーは金色の輪、回復薬はピンク色の瓶です。移動でそのマスへ入ると、敵の行動前に自動取得します。移動以外の追加ターンは不要です。上限で入らない分は床に残り、空きを作って再度そのマスへ移動すると取得できます。

Inventoryと装備は階層移動で維持します。床に残したアイテムは次階・次の冒険へ持ち越しません。

防具・アクセサリー・回復薬の調整値は `data/items/` のResourceにあります。武器アイテムは既存の `WeaponData` を参照します。

## 視界と探索済み地形

- 未探索: 地形も敵も表示しません。
- 探索済み: 地形と発見済みの階段だけを暗く表示し、敵は表示しません。
- 現在視界内: 地形・敵を通常の明るさで表示します。

プレイヤーの初期視界は8マスです。距離は8方向グリッドに合わせ、縦横の差の大きい方（Chebyshev距離）で測ります。視界は全方向を対象とし、白線の向きによって制限しません。

壁と柱は視線・攻撃を遮ります。遮っている壁・柱自体は見えますが、その奥は見えません。斜めの角も、移動や攻撃と同様に片側が塞がれていれば遮断します。敵の身体は視界を遮りません。

探索済みの情報は同じ階では残り、次階・再開始時にリセットします。HUDの敵数は現在視界内で生存している数です。OpenAreaの柱は明るい石の四角として表示され、通行できません。

プレイヤーの視界は `actors/player/player.tscn` の `Vision Range` で調整できます。

## 敵の感知方式

初期3体はVision・Proximity・Turretを1体ずつ配置します。敵数を増やすと同じ順に繰り返します。警戒マークはなく、白線の向きと挙動で状態を表します。

| 方式 | 見た目 | 初期動作 | 調整Resource |
|---|---|---|---|
| Vision | 赤い四角 | 6マス以内かつ視線が通れば接近・隣接攻撃。見失うと最後に見た地点へ進み、到着後に停止 | `data/enemies/basic_enemy.tres` |
| Proximity | 黄土色のひし形 | 壁越しでも4マス以内で感知。通れる経路で接近・隣接攻撃。範囲外では停止 | `data/enemies/proximity_enemy.tres` |
| Turret | 紫の円と四角 | 自分から移動しない。4マス以内で視線が通る縦・横・斜めの直線上を攻撃 | `data/enemies/turret_enemy.tres` |

各Resourceの `Detection`・`Detection Range` を変更できます。`Attack Range`はTurretの射程に使います。VisionとProximityは隣接攻撃です。Turretの射線は壁・柱・別の敵で遮られ、味方にはダメージを与えません。

敵の索敵はプレイヤーから見えているかどうかとは独立して動きます。Fog of Warで非表示になっても、感知条件や最後の目撃地点に基づいて行動します。

## EXP・レベルアップ・能力

敵の撃破でEXPを獲得します。初期値は敵1体につき10EXPで、各敵Resourceの `Exp Reward` から変更できます。同じ敵からEXPや撃破時回復を複数回受け取ることはありません。

Lv1から始まり、初期の必要EXPは `10 + (現在Lv - 1) × 2` です。`data/progression/levels.tres` の `Base Exp`・`Exp Per Level` で調整します。余ったEXPは次Lvへ持ち越し、最大Lv100ではEXP加算を停止します。

レベルアップで能力を3つ提示します。能力は重複なしの単純ランダムで、装備していない武器向けの能力も含みます。選択中は移動・攻撃・敵行動が停止し、能力を取得したあとに同じターンの敵行動を再開します。一度に複数レベル上がった場合は順番に選択します。選択中はRによる中断も停止します。

最大Lvに達した能力は候補から除外します。残りの候補が1～2個ならその個数だけ表示し、候補がなければ選択を省略してターンを進めます。

| 能力 | 1Lvあたりの初期効果 | 最大Lv |
|---|---|---|
| 最大HP強化 | 最大HP・現在HP +3 | 5 |
| 攻撃力強化 | 全武器のダメージ +1 | 5 |
| 防御力強化 | 被ダメージ -1（最低1ダメージ） | 5 |
| 剣威力強化 | 剣のダメージ +1 | 5 |
| 槍威力強化 | 槍のダメージ +1 | 5 |
| ハンマー威力強化 | ハンマーのダメージ +1 | 5 |
| 槍射程強化 | 槍の射程 +1マス | 2 |
| 槍貫通 | 射程内の敵を貫通。壁・柱は貫通しない | 1 |
| 視界強化 | 視界 +1マス | 3 |
| 撃破時回復 | 撃破した敵1体につきHP +1 | 3 |

効果量・最大Lvは `data/abilities/` の各Resourceで調整します。説明文の `{amount}` は効果量に置換されます。撃破時回復は最大HPまでで、選択前の撃破にはその時点で取得済みの能力だけが適用されます。

Lv・EXP・取得能力・現在HPは階層移動で維持されます。Rによる再開始ではLv1・EXP0・能力なしに戻ります。元のプレイヤー・武器Resourceを変更せず、冒険中の状態に効果を反映します。

## ダンジョンと階層移動

- 1Fから順にRoom → Cave → OpenAreaを繰り返し、10Fまで進みます。地形は毎回ランダムです。
- Roomは部屋と通路、Caveは不規則な洞窟、OpenAreaは広場と障害物です。
- 金色の階段へ移動したターンに旧フロアの敵が行動し、生存していれば次階へ進みます。階段上で死亡した場合は移動しません。
- 次階へは現在HP・武器・累計ターン数を引き継ぎます。新しい敵は次のプレイヤー行動まで動きません。
- 10Fには通常敵に加えてボス「深層の守護者」を1体配置します。下り階段はなく、開始地点から到達可能な最も遠いマスがボスの配置先です。

ボスは金色の枠を持つ赤い四角で、現在視界内にいると名前とHPを画面上部に表示します。既存のVision型と同じく視線が通ると接近し、隣接攻撃します。壁・斜めの角・ノックバックのルールも共通です。初期値はHP48・攻撃5・防御1・感知8・EXP30・Gold60で、`data/enemies/boss.tres` から変更できます。通常敵が残っていてもボス撃破でクリアします。

全マップ情報を使うテスト用操作でシード47・81・123の3回を通し、いずれも1Fから10Fへ進みLv14でクリアしました。既存のEXP曲線は想定Lv10～20内に収まるため維持しています。これは実際のプレイヤーの難易度・所要時間の評価ではなく、操作と成長・拾得・戦闘・クリアが接続していることの検証です。

`data/dungeon/default.tres`でマップの幅・高さ（20～60）、敵数（0～20）、開始地点から敵までの最低歩数、部屋数、洞窟の初期壁率、広場の障害物率を調整できます。初期値40×40、上限60×60は仕様の初期検証サイズに対応します。20×20は小規模な生成テスト用です。

生成後に最大の接続領域を残し、開始地点から到達できる遠いマスに階段を配置します。敵は開始地点・階段と重ならない安全距離の候補から選びます。候補が少ない設定では配置できる数まで減らします。生成の再試行は8回までとし、極端な設定で床面積が不足した場合は中央の床領域を補修します。

Runノードの `Generation Seed` は0で毎回ランダム、0以外で地形・配置を再現します。拠点からの出発では毎回Runを新しく作るため、固定シードなら同じ配置で開始します。Run単体の直接再挑戦では乱数列を継続します。`Dungeon Settings`で設定Resourceを差し替えられます。階層移動だけを検証する場合は敵数を0に設定できます。

制限された環境では標準のユーザーディレクトリにログを保存できない場合があるため、ログの出力先を `.godot` 内に指定しています。

生成テストは3サイズ×3方式×20シードの180マップを検証します。1Fから10Fへの実際の経路移動、階段での戦闘・死亡、旧フロアの敵の除去、カメラとタイルの位置一致も確認します。Phase 1・2の戦闘テストは専用の固定配置を使い、ランダム生成から独立させています。

描画確認用の `tests/capture_dungeon.gd` は描画可能な環境で実行すると、`.godot`内に1F・2F・3F・10Fと階段の画像を保存します。ヘッドレスモードでは実行できません。

Phase 4では視線の対称性、壁・柱・斜めの遮蔽、探索記憶、見失った敵の追跡、近接感知、Turretの射程・遮断、視界外の敵と攻撃範囲の非表示を検証します。描画確認スクリプトは探索済み・現在視界内・未探索を並べた `exploration_preview.png` も保存します。

Phase 5ではEXP閾値と持ち越し、Lv100上限、能力の重複・上限・候補不足、10種類の効果、選択中の停止と敵行動の再開、複数撃破、回復上限、階層間の維持と再開始を検証します。`tests/capture_progression.gd` は描画可能な環境で能力選択と数字キーでの再開を確認し、`.godot/progression_choice.png` と `.godot/progression_resumed.png` を保存します。

Phase 6では40枠・50個制限、満杯時の交換・取り外し、効果の重複防止、回復薬と敵行動の順序、部分拾得、床アイテムの配置・非表示、階層間の維持を検証します。`tests/capture_inventory.gd` はInventory画面を保存し、I・マウスによる装備・Tab・Escを実際の入力経路で確認します。

ゲームの入力は `game/main.gd` でInput Mapへ登録します。HP・攻撃力は `data/player_stats.tres` と `data/enemies/basic_enemy.tres` で調整できます。現在HPはResourceとは別に管理します。

Phase 7では損失の端数・個数単位抽選・装備保護・二重適用防止・死亡と中断・クリア・再挑戦を検証します。`tests/capture_lifecycle.gd` は描画可能な環境でHUD・中断確認・リザルト・クリア結果を保存し、R・Esc・マウス確定・再挑戦を実際の入力経路で確認します。

Phase 8ではGold不足・購入価格・上限・冒険中の購入禁止・多重出発防止・拠点往復・強化の保持・HP補正の重複防止を検証します。`tests/capture_hub.gd` は拠点画面を保存し、マウス購入・出発・帰還とRによる帰還を確認します。描画テスト内だけ検証用Goldを付与し、通常ゲームの初期Goldは0のままです。

Phase 9ではボス配置・撃破時の即時クリア・報酬の一度だけの付与、セーブ内容の往復・不正データ・破損復旧・保存失敗・購入取消・再起動後の復元を検証します。`tests/capture_completion.gd` はボス・Space操作によるクリア・保存済みリザルト・復元した拠点・保存失敗を撮影します。撮影用にだけボスHPを減らし、通常のResource値は変更しません。
