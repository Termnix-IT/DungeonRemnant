# 開発メモ

ゲームを作り替えたときの判断と、絵を作る・差し替えるときの決まりです。ゲームの仕様は `docs/ゲーム仕様.md`、作り替えの経緯と計測結果は `docs/履歴/リアルタイム化_再設計計画.md`、テストと撮影のコマンドはリポジトリ直下の `CLAUDE.md` にあります。ターン制だったころの検証手順と各Phaseの記録は、対象のコードを削除したため、このメモから外しました（Gitの履歴に残っています）。

絵ごとのCodexへの依頼文と生成の経緯は、量が多く、同じ種類の絵を作り直す・足すときにしか要らないため、`docs/絵の制作記録/` に分けています。

- `拠点とUIの絵.md`：拠点の背景と立ち絵（目・しぐさの差分を含む）、吹き出し、HPゲージの枠、分岐マップの道と台座、ダンジョンHUDの部品、確認の窓などの枠、石板の質感、章の挿絵、前置きとエンディングの静止画、個別画面の挿絵、試して外したステータス画面の枠。
- `キャラクターと敵の絵.md`：主人公のリグのベース画と層、層の編集のずれをツールがどう扱うか、剣以外の武器、敵とボスの元絵。
- `地形とエフェクトの絵.md`：画風ごとの床・壁・柱・階段・木と、エフェクトの元絵。
- `紋章の絵.md`：強化・スキル・必殺技・イベント・武器などの紋章の盤。

## Codexへの画像の依頼

絵はCodexの組み込み画像生成（gpt-image-2.5）で作ります。これまでの依頼で分かった、どの絵にも共通する決まりです。依頼文を書くときは、まずこの決まりに沿い、次に `docs/絵の制作記録/` から同じ種類の絵の依頼文を探して、その書き方に合わせます。

- 参考画像は、画風の参考（ロビーの立ち絵・主人公のベース画・同じ種類の既存の絵）と、題材や配置の参考を分けて、それぞれ何の参考かを書いて渡す。1回に渡せるのは5枚までで、多いときはCodexに画風の参考を1枚にまとめた補助の絵を作らせて渡す。
- 切り抜いて使う絵は、背景を一様なマゼンタ（#FF00FF）にし、物の中にマゼンタや桃色を使わせない。光るエフェクトや床に光を足す印は純黒の背景に描かせて加算合成で重ね、煙やキャラクターは透過背景で描かせる。透過で光を描かせると縁が濁るため。
- 文字・人物・枠・落ち影・光の勾配・周辺減光など、要らないものは「描かない」と明記する。書かないと描き込まれて返ってくる。
- 実際に表示する大きさを伝え、その大きさに縮めても読める太い形とはっきりした輪郭を求める。
- 9-sliceや横に引き伸ばす枠・帯は、中央の60%を長さ方向に完全に一様にし、辺の中央に飾りを置かないよう指示する。
- 繰り返して敷くタイルは「継ぎ目なく繰り返せる」と指示し、返ってきた絵を半分ずらして継ぎ目がないことを確かめる。つながらないときはツールで重ねて継ぎ目を消す（地形の `SEAM_FIX`、分岐マップの道）。
- 既存の絵の差分（目・しぐさ・表情・層）は、元絵を編集対象として渡し「〜だけを変え、ほかは位置・大きさ・色を変えない」と指示する。それでも変えていない部分の輪郭が揺らいだり数十pxずれたりして返ってくるため、使う範囲の切り出しと位置合わせはツールで行う。
- 生成結果の大きさや縦横比は指定どおりにならないことが多い（1024×1024の指定に1254×1254、1024×512の指定に1774×887など）。また、マゼンタの地も一様にはならない。そのため、ツールは等分で切らず、地の色と透明な切れ目を自動で判定して切り出す。
- 画風はヨーロッパのゴシックのダークファンタジーにそろえる。第3章の挿絵の最初の版がアジアの寺院のように見えて浮いたため、背景や建物にはアジアの建築を描かないよう明記する。
- 迷う絵は2案以上を作らせ、実際の画面で並べて選ぶ。採用する前に、ファイル名ではなく画像の中身を確かめる（主人公が描かれた絵は、ベレー帽の白い花・白い長い髪・赤白の縁取りの黒い服が立ち絵と一致しているか）。
- 元絵は `source/` 系のディレクトリに置き、`tools/` のスクリプトで加工する。生成したまま使わない。

## 素材を差し替えるときに一緒に直すもの

元絵を差し替えたら、次のスクリプトで作り直し、右の列の値を合わせます。合わせないと、絵と表示位置や枠の余白がずれます。リグ・地形・エフェクト・紋章・枠の金具の作り直し方は、この下のそれぞれの節にあります。

| 素材 | 作り直すコマンド | 合わせて直すもの |
| --- | --- | --- |
| 拠点の背景 `art/hub/lobby_hall.png` | （加工なし） | 背景内の物の位置を参照する `ui/hub_ambience.gd` の `LIGHTS` と `FOCUS` |
| 拠点の立ち絵と差分 | `python tools/build_lobby_hero.py` | ツールの `PATCHES` の矩形を変えたら、`ui/lobby_hero.gd` の `POSES` と `SMILE_RECT`（余白40pxの分だけずれた座標） |
| 吹き出しの地 | `python tools/build_speech_bubble.py` | なし |
| ボスのHPゲージの枠 | `python tools/build_gauges.py boss`（`--measure` で溝の位置と飾りの幅を表示） | `ui/boss_gauge.gd` の定数 |
| 主人公のHPゲージの枠 | `python tools/build_gauges.py hero`（同上） | `ui/action_hud/action_hud.gd` の `HP_CAP_LEFT` などの定数 |
| 分岐マップの道 | `python tools/build_route_roads.py` | なし |
| 分岐マップの台座と物 | `python tools/build_route_stages.py`（`--measure` で台座の上面の中心の高さと半幅を表示） | `RouteNode` の `PLATE_TOP`・`TOP_HALF_HEIGHT`・`TOP_HALF_WIDTH` |
| ダンジョンHUDの部品 | `python tools/build_hud_art.py`（描く大きさを表示） | `ui/theme/dungeon_theme.tres` の9-sliceの余白（`HudSurface`・`HudMapFrame`・`HudLogBand`・`KeyCap`・`BannerBand`・`BannerBandWarning`・`AbilityCardNew` ほか） |
| 拠点の個別画面の石板の質感 | `python tools/build_slab_texture.py a` | 暗い石板の上では濃淡が潰れるためコントラストは大きめに作り、暗さはテーマの `grain_tint` で決める |
| 個別画面の挿絵 | `python tools/cut_card_art.py --scenes` | なし |
| レベルアップの光の柱 `art/effects/painted/source/level_up.png` | `python tools/build_painted_effects.py` | 絵の高さの約72%にある輪を、`Run.LEVEL_UP_LIGHT_OFFSET` で主人公の靴底に合わせている |
| 剣以外の武器 | `python tools/build_weapon_art.py` | `Moveset.art_grip`（切り詰めた絵で測った握りの中央の、頭からの高さの割合。槍0.69・大槌0.8）を測り直す |

## ダンジョンの主人公のイラストリグ（PoC）

ダンジョンの主人公をドット絵から、部位に分けたイラストをボーンで動かす表現へ移す検証です。Phase 1で正面を、Phase 2で8方向を作り、Phase 3でダンジョンの主人公（`actors/player/player.gd`）に組み込みました。ゲーム中の見え方の仕様は`docs/ゲーム仕様.md`の主人公の絵の段落にあります。8方向は`art/characters/mio_rig/mio_rig.tscn`（`DirectionalRig`）にまとまり、`facing`に合わせて向きのリグを切り替えます。確認は `tests/rig_poc_viewer.tscn`（矢印・WASDとQEZCで歩く、Rでその場で向きを変える、Spaceで向いた方へ本物の`BattlePresentation`による剣の攻撃、1/2/3で高さ56/64/72、Pでピクセルスナップ、Tで31体の負荷。下段に8方向の待機を実寸で並べる）で行います。

素材を差し替えたら、次の順に作り直します。

1. `python tools/build_rig_parts.py [キャラクター] [向き ...]`（キャラクターは`mio`が既定、敵は`sentinel`）：元絵と層を位置合わせして部位に切り、向きごとに`<向き>_parts.png`（アトラス、ミップマップ付きで取り込む）と`<向き>_parts.json`を書く。元絵と出力の場所、切り方はツールの`CHARACTERS`と`FACINGS`にある。組み直した絵とベース画の差分を`.godot/rig_<向き>_parts_check.png`に出す。層がまだない向きは、ベース画1枚（`Whole`）と剣だけの仮の部位にする。
2. `godot --headless --path . --script res://tools/build_character_rig.gd -- res://art/characters/mio_rig/<向き>_rig.json`：`<向き>_rig.json`（ボーン・部位の描画順・アニメーション）から`mio_rig_<向き>.tscn`を組み、`mio_rig.tscn`にその向きとして登録する。切り出し結果にない部位（仮の向きの腕など、層ができたあとの`Whole`）は飛ばすので、同じ記述のまま仮から本番へ移れる。組み直すたびにノードの`unique_id`が変わるため、中身を変えていない向きの`.tscn`の差分はcommitしない。
3. `godot --headless --path . --script res://tests/test_character_rig.gd` と、描画できる環境で `godot --path . --script res://tests/capture_character_rig.gd`（`.godot/rig_*.png`）。

判断と制約：

- 体型は約2.2頭身。ロビーの立ち絵と同じ塗り・衣装で、約2.7頭身の案は画面上96pxで顔の幅が約14pxしかなく、当時のドット絵より細く小さく見えたため、頭を大きくした。
- 高さは`CharacterRig.world_height`（ワールドのpx）で決め、64で1600×900の画面上96px。部位の絵は帽子から靴底まで320pxで持ち、`LINEAR_WITH_MIPMAPS`で縮める。
- `front_rig.json`の関節とアニメーションの移動量は元絵（1024×1536）のpxで書く。左右の名前（`ArmL`など）は画面の左右。画面上1pxは元絵の約14pxに当たるため、待機の呼吸のような動きは元絵で数px動かしても実寸では見えない。見せたい動きは実寸で1〜2px（元絵で15〜30px）を目安にする。
- 部位はすべて`Polygon2D`で、描画順は兄弟の順。`z_index`を使わないのは、アクターのy-sortに漏れて敵や床の物の上下関係を崩すため。髪とスカートは鎖の向きに沿った重み（`"weights": "along"`）で曲げ、ボーンのばね（`CharacterRig`）が遅れと揺れを付ける。
- プロジェクト設定のピクセルスナップがONのままだと、待機中の絵は半分のフレームで止まり、動くときにまとめて跳ぶ（実測、144フレーム中69フレームしか変わらず、変わるときは最大2249画素）。プロジェクト全体のスナップを外すと当時の地形のドット絵がずれて見えたため（ドット絵の地形をなくしたあと、全体のスナップは外した）、Phase 3ではスナップを外した主人公専用の`SubViewport`にリグを画面の拡大率のまま描き、その絵をスナップされた1枚の絵として置く方式にした。実際の冒険では待機中の144フレームすべてで絵が少しずつ変わる。`SubViewport`の大きさは毎フレーム画面の拡大率から決め直す（1600×900で180×192、1920×1080で216×231）。敵に使うときは体数分の`SubViewport`になるため、Phase 4で負荷と合わせて見直す。のちにドット絵の地形をなくして全体のスナップを外したので、`SubViewport`はやめ、リグはワールドへ直接描くようにした（`RigView`はリグを載せ、隠れている間は止めるだけ）。主人公が持つ武器は、手のボーンの子にすると部位より先に描かれるため、リグの後ろの兄弟に置き、手のボーンに付けた`RemoteTransform2D`で手に合わせる。負荷は1600×900・RTX 3060の実際の冒険（敵30体を視界に置く、各4回の中央値）で、番兵30体が1フレーム約5.9msから約5.6ms、ネズミ30体が約4.5msから約4.1ms、敵なしが約1.3msから約1.1msになった。差は小さく、負荷の大半は`SubViewport`ではなく、リグのアニメーションとボーンによる変形そのものにある。計測のたびに±1ms程度ばらつき、まれに大きく外れる回がある。
- 負荷は1600×900・RTX 3060で、1体のとき1フレーム約1.0ms、31体で約5.0ms（1体あたり約0.13ms、うちScriptのアニメーションとばねは約0.03ms）。
- 描くのは正面・背面・左・左前・左後の5方向で、右・右前・右後は左向きを左右反転して見せる（`DirectionalRig.MIRRORED`）。花とリボンは彼女の左側の頭にあり、左向きでは手前に見え、右向きでは奥に回るので、左向きの3方向では花とリボンを`Ornament`という別の部位に切り（`mirror_hide`）、反転したときだけ隠す。体の層はそのため花とリボンを除き、その下を描き足したものにする。
- 剣は向きの先か手前の手に持たせる（正面・左前・背面は右手、左・左後は手前の左手）。反転した向きでは持つ手が左右入れ替わる。当時のドット絵も横向きでは手前の手に描いており、それに合わせた。
- 向きを変えると、新しい向きのリグが同じ動きの同じ位置から続け、髪のばねの揺れも同じ名前のボーンへ引き継ぐ（`CharacterRig.pose_state()`・`resume()`）。表示していない向きのリグは処理を止める。動きの速度と向きはリグ自身の座標で読むので、反転した親の下でも髪や重心が正しい向きに揺れる。

元絵の依頼文と、層の編集のずれをツールがどう扱うかは `docs/絵の制作記録/キャラクターと敵の絵.md` にあります。

### 敵のイラストリグ

最初の敵として、さまよう番兵（`EnemySprites`の`basic`）をリグにしました。`art/enemies/rig/basic_rig.tscn`があると、その種類の敵はリグで描かれます。ファイル名は`EnemySprites.visual_id()`の`<id>_rig.tscn`なので、ほかの敵も同じ名前で置けば1種類ずつ移せます。元絵は`art/enemies/rig/source/sentinel_*.png`、部位は`python tools/build_rig_parts.py sentinel`、リグは`art/enemies/rig/sentinel_rig.json`から組みます。

- 番兵は横向き（右向き）の1枚だけを描き、左を向くと左右反転する。以前のドット絵の帯も右向きの1列を反転していたため、見え方の決まりは変わらない。
- 高さはワールドの60px（主人公は64px）。仕様の「人型の番兵は主人公と同程度」に合わせた。
- 戦闘演出の合図をリグの動きに置き換える。溜めと打撃のコマの代わりに`play_attack()`で振りを始め、被弾のコマで`hurt`（のけぞり）、とどめのあと`down`（後ろへ倒れて止まる）を再生する。歩くと`play_walk()`で歩行を再生する。倒れる動きを持つので、図形用の潰れる演出は行わない（`has_sprite()`が真）。
- 影と向きの矢印・HPの棒は敵のノードが描き、リグはその後ろに描く（`show_behind_parent`）。
- リグは`RigView`に載せ、主人公もこれを使う。敵が視界の外で非表示になってもリグの処理は続くため、`RigView`が表示の切り替えに合わせてリグを止める。演出の伸び縮みは`RigView`に掛ける。
- 剣は手の位置から前方へやや上向きに持たせた。真下に垂らすと脚の前に重なり、以前の帯の絵（前方斜め上に構える）とも違って見えたため。
- 層の編集は、腕と脚の層に別の部位が残り、マントの層は約60pxずれて返ってきた。主人公と同じく、脚はスカート（腰当て）の下をベース画から取り、手前と奥の足先が重なるため斜めの線で分ける（`left_of_line`・`right_of_line`）。
- 負荷は1600×900・RTX 3060の実際の冒険で、番兵30体をリグで描いて1フレーム約6.5ms、帯の絵で約4.3ms（敵なしで約1.9ms）。60fpsの16.7msに十分収まる。

### ほかの敵とボスのリグ

番兵以外の通常の敵5種類（スライム・ネズミ・突進獣・巣・砲台）と名前付きのボス10体も、リグにしました。こちらは部位の層を作らず、1枚の絵（`art/enemies/rig/source/<id>_base.png`）を網目にしてボーンで曲げます。腕や脚を分けなくても、体の曲げ伸ばしと踏み込みで動きが付くうえ、層の編集のずれを直す手間が要らず、Codexへの依頼も1体1枚で済むためです。

- 体の型（`tools/build_rig_parts.py`の`ENEMY_MESHES`）ごとに、ボーンの並べ方と動きを決める。「塊」（スライム・巣）は足元から伸び縮みし、倒れると床へつぶれる。「獣」（ネズミ・突進獣・疾風の狼王・群れの主）は体の長さに沿って後ろ・前・頭の3本で曲げ、倒れると崩れ落ちる。「立ち姿」（砲台とほかのボス）は足元から上へ3本で曲げ、倒れると足を軸に後ろへ倒れる。
- `python tools/write_enemy_rigs.py`が、絵の輪郭からボーンの位置を求めて`<id>_rig.json`を書く。動きの量は輪郭の大きさに対する割合なので、ネズミもボスも同じ書き方で体に見合った大きさになる。続いて`python tools/build_rig_parts.py enemies`で部位を切り、`tools/build_character_rig.gd`で各リグを組む。
- 大きさは以前のドット絵の帯の体の高さを引き継ぎ、リグのメタ`world_height`に持つ（`Enemy.rig_height()`）。値は`write_enemy_rigs.py`の`HEIGHTS`で、番兵はリグの記述の`height`（60px）。帯を消す前に帯から求めた値を固定した。
- 予告のターン（砲台の照準・突進獣の構え・巣の孵化前）は、以前の帯では溜めのコマを出し続けていた。リグでは`brace`（構えたまま小さく震える）を保ち続ける。
- 負荷は、ネズミ30体をリグで描いて1フレーム約6.0ms、帯で約4.6ms（敵なしで約2.1ms）。

## イラストの地形

4つの画風（青灰の遺跡・苔むした洞窟・灼熱の深層・黒曜の聖域）の床・壁・柱・階段と深緑の森林の木を、キャラクターと同じ塗りのイラストにしました。森林の床は苔むした洞窟のものを使います。画風ごとに`art/tiles/painted/source/<画風>_floor.png`・`_wall.png`・`_pillar.png`・`_stairs.png`を作り、`python tools/build_painted_terrain.py <画風>`で`art/tiles/painted/<画風>_terrain.png`を組んで、`world/dungeon/dungeon.gd`の`PAINTED_ATLASES`に画風の番号で登録すると、その画風がイラストになります。森林の木は`python tools/build_painted_terrain.py trees`が`source/forest_tree_a.png`～`_d.png`から1本128pxのコマの帯にし、ワールドの64pxで描きます。

- 床と壁の元絵は、継ぎ目なく繰り返せる真上から見た1024×1024の絵にする。床はツールが4×4マスに、壁は2×2マスに広げて切り分け、マスの位置で選ぶ。1マスごとに同じ絵を繰り返すとマス目が見え、壁の絵を1マスに縮めると石が細かく潰れて平らな暗い塊になったため。
- 壁の明暗の決まり（床より暗く平らにする、開いた辺の明るい縁と暗い縁、床との境の暗いすき間）は、以前のドット絵のアトラスと同じにした。
- タイルは1マス96pxで持ち、TileMapLayerを0.5倍にして48pxのマスに合わせる。アクターや攻撃の印はワールドの48pxのまま置くため、地形の位置の計算だけが縮小を考える。
- 壁際の影（`WallShade`）は地形のすぐ上、明かりの下に描く。
- 灼熱の深層と黒曜の聖域の床と壁は、端の石が途切れていて完全には繰り返せなかった。ツールがこの2画風（`SEAM_FIX`）だけ、絵を半分ずらした自分自身と端の18%で重ねて継ぎ目を消す。遺跡と洞窟は生成のままでつながるため、かけていない。
- 第2章の樹海（`grove`）・第3章の霊廟（`crypt`）・第4章の深淵（`abyss`）は床と壁だけを描いた画風で、階段と柱はほかの画風のものを借りる（ツールの `BORROWS`）。

## イラストのエフェクト

攻撃・被弾・撃破・治癒のエフェクト8種類（斬撃・突き・衝撃・被弾・魔弾・炎・治癒・煙）をイラストにしました。元絵は`art/effects/painted/source/<種類>.png`、`python tools/build_painted_effects.py`が256pxに縮めます。

- 連番のコマを生成でそろえるのは難しいため、各エフェクトの最も強い瞬間の1枚だけを描かせ、`StrikeEffect`が拡大・回転・明滅・フェードで動かす。大きさ・長さ・拡大の幅・回すかどうか・加算するかどうか・前へ滑る量・回転の量は`StrikeEffect.PAINTED`にある。
- 光るエフェクトは真っ黒な背景に描かせ、加算合成で重ねる（黒は何も足さない）。透過で光を描かせると縁が濁るため。生成した黒地の細かなノイズが周りをかすかに明るくするので、ツールが暗い部分を黒へ押し下げる。煙は暗い色なので加算では見えず、透過で描かせて普通に重ねる。

ゲーム中のキャラクター・地形・アイテム・エフェクトにドット絵はもうない。ドット絵の素材とドット絵へ戻す切り替えは削除した（素材はリポジトリ外で保管している）。

## UIのイラスト化（紋章・枠の金具）

UIに残っていたドット絵（能力と永久強化の紋章12種類、HUDの顔4表情、パネルの枠の角金具とボタンの端飾り）も、キャラクターと同じ塗りのイラストにしました。これに合わせて、プロジェクト全体の画素スナップ（`rendering/2d/snap/*`）を外しています。

- 紋章：`art/emblems/painted/source/emblems_a.png`・`emblems_b.png`（2×3の盤、マゼンタの地）を`python tools/process_emblems.py`が切り出し、192pxの`art/emblems/<キー>.png`にする。並び順はツールの`BOARDS`。描く側（レベルアップのカード・強化ツリー）はミップマップ付きの線形補間で縮める。
- 枠の金具：`art/ui/source/painted/ornaments.png`（2×2）から`python tools/build_ui_frames.py`が角金具と端飾りを滑らかに縮めて、枠とボタンの画像を作る。
- 生成した盤のマゼンタは一様な#FF00FFにならなかった（隅で(230,15,240)前後）。切り出しは平らな地の色を自動で判定するため問題はなく、輪郭に残るマゼンタはツールが縁を5px内側へ削って除く。

## 主人公の動きの足し方

主人公の動きは各向きのリグの記述（`art/characters/mio_rig/<向き>_rig.json`）の `animations` に骨のキーフレームとして書き、`godot --headless --path . --script res://tools/build_character_rig.gd -- res://art/characters/mio_rig/<向き>_rig.json` で5つの向きのSceneを作り直します。

- Phase 6で足した `attack_back`・`attack_heavy`・`attack_slam`・`brace`・`dash`・`hurt` は、各向きの `attack_sword` のキーを元に作った。剣を持つ腕（回転の幅が最も大きい腕）と、振り上げの符号を向きごとに読み取り、逆薙ぎは振り上げと振り下ろしを入れ替え、大振りは角度を1.25〜1.4倍・時間を長く、叩きつけは腕を頭上へ上げてから振り下ろす。腕の回転は±172度までにして、拡大した振りが一周しないようにしている。
- 攻撃の当たる瞬間（`impact`）は、その攻撃の `AttackData` の予備動作の終わりに近い時刻にそろえる。`tests/test_character_rig.gd` が、各向きにすべての動きがあり、当たる瞬間が動きの中にあることを確かめる。
- 右向きの3方向は左向きのリグを左右反転して使うため、記述を足すのは正面・背面・左・左前・左後の5つだけでよい。
- 槍の突き `attack_thrust` は、各向きの `attack_sword` から、回転の幅が最も大きい腕を武器の腕として選び、0.04秒に振り上げの0.2倍だけ引き、0.07秒（当たる瞬間）に振り下ろしの1.3倍まで前へ伸ばす形で作った。手首はほぼまっすぐ（振り下ろしの0.2倍）にして、武器が腕の延長に並ぶようにしている。胸・頭・もう一方の腕は振りの値を0.5〜0.8倍に弱めて使う。
