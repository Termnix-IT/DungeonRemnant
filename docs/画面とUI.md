# Dungeon Remnant 画面とUI

この文書は、Dungeon Remnantの拠点の画面と、UI全体（共通Theme・動き・個別画面のUI文法・ラン中の画面・言語）の現在の仕様です。ゲームのルール・データ・進め方は [ゲーム仕様.md](ゲーム仕様.md) にあり、この文書はUIを作る・直すときに読む部分を分けたものです。

---

## 1. 拠点

拠点（`Hub`）はロビーと5つの個別画面からなり、右上に残響の所持数を常に示します。

- ロビー（`HubLobby`）は左にメニュー（出撃・強化・ステータス・図鑑・設定）、中央下に選んだ項目の情報パネル、右に主人公の立ち絵を置きます。ロビーでEsc（B）を押すと、設定の「ゲームの終了」と同じ確認の窓（「ゲームを終了しますか？」。最初のFocusは「戻る」）を出し、操作の案内にも「Esc 終了」を並べます（`Hub.ask_quit`）。ロビーの操作の案内は、上の行に「↑ / ↓ 選ぶ」、下の行に「Enter 決定」「Esc 終了」の2行で置きます（`Hub.lobby_guide`）。3つを1行に並べると、メニューの右の縦の飾り線を越えて広間の絵にはみ出すためで、2行とも飾り線の内側に収めます。ロビーはメインメニューを兼ねるので、そこから1操作で終了に届くようにするためで、メニューの項目と絵は増やしません。立ち絵をクリックすると、主人公が吹き出しで台詞を1つ話します。台詞は進み具合ごとの組（第1章の踏破前、第1章・第2章・第3章の踏破後、エンディング後。`HubLobby.SPEECHES`）から順に出し、次に向かう章やボスに触れます。エンディング後は「もう、あの声は聞こえない。」のような、解放を受けた台詞になります。出撃の情報パネルは、次に出撃する章の名前・説明・挿絵、道のり（「3層とボス」）、その章の記録（「なし」「第2層まで」「ボスまで」「踏破 2回」、難易度の段階で踏破していれば「踏破 2回・段階3」、`Chapters.record`）と、「出撃先を選ぶ」のボタンを示します。章を選ぶのは出撃の画面（次の項目）だけで、ロビーでは切り替えません。ほかの項目のパネルは、強化できる数、装備中のスキルの数と最大HP、出会った敵の数、音量などをそれぞれ示します。
- 出撃（`HubSortie`）は、ステージ選択で定番の「行き先を扉の絵で横に並べる」形です（Halls of TormentやSlay the Spireの出発の画面に近い）。ロビーの出撃の項目かそのボタンを決定すると開きます。広間に、章ごとの扉（`ChapterDoor`、`Chapters.ALL` の順）を隙間なく横に4枚並べます。踏破した章の数は扉の進み具合で分かるため、別には書きません。扉は、章の挿絵を上が半円のアーチ形に切り抜いたもの（挿絵のうち、その章の階段や門が描かれた辺りを見せる）と、足元の暗い板に書いた章の番号・名前・進み具合（「未踏」「第2層まで」「ボスまで」「踏破 2回」「封印中」）です。選んでいる扉は大きく明るくなって隣の扉の上に出て、金の枠（内側に細い金線、外側に淡い光）で囲みます。ほかの扉は小さく暗くして奥に下げ、どれを選んでいるかがひと目で分かるようにします。まだ開いていない章の扉は、挿絵を暗くして章の封印の紋章を重ねます。扉は背景の広間の上に直接立てます。この画面だけは出発の場面として広間を見せるためで、文字は扉の板と下の帯の面の上にだけ置きます。
  - 扉の下には、横長の帯（`SortieBand`）を1枚置きます。出撃の画面はロビーの「出撃」の続きなので、帯はロビーの情報パネルと同じ装い（暗い面、右側に選んだ章の挿絵を淡く敷いて文字の側へ溶かす、角の金具と上下の菱形の装飾枠、`HubUI.ornate_frame()`）にします。帯の左の列には、選んだ章の説明と、ロビーと同じ数値の帯（明朝の数値、菱形の区切り、`HubUI.fact_strip()`）に道のり・記録・ボス（出会うまでは「？？？」）を並べ、その下に「現れる敵」と「装備」を1行に並べます。章の名前は扉に書いてあるので、帯では繰り返しません。縦の細線を挟んだ右の列には、段階の行（段階が開いた後）と、「第1章へ出撃する」のボタンを置きます。出撃のボタンは、ほかの画面の札ではなく、このゲームが章の封印・強化の節・ロビーのメニューで使っている紋章の形にします（紋章の札、`CrestButton`、Themeの `CrestAction`）。左端の丸い紋章にロビーの「出撃」と同じ交差した剣を描き、紋章から右へ青銅の札を伸ばして、明朝の文字を載せます。ボタンを選ぶ（Focusを置く、またはマウスを合わせる）と紋章が灯り、札が明るくなって縁が金に変わり、紋章のまわりに光が広がって、金の輪が紋章を一周して閉じます。押すと札が暗く沈み、すぐに出撃します。輪が閉じるのを待ってから出撃する作りにはしません。演出の完了をゲームの処理から待たないためで、扉の上でEnterを押したときもボタンを経ずにすぐ出撃します。封印中の章では、紋章も札も縁も暗いままにします。「現れる敵」は、章のエリアの出現表・精鋭・ウェーブとボス、それらが呼ぶ敵を図鑑の順に並べ（`Chapters.foes`）、出会った敵は絵、まだ出会っていない敵は影で示して、名前はTooltipで出します。「装備」は武器・付けたスキル・必殺技の紋章で、空いている枠は出しません。封印中の章も選んで読めますが、説明を「封印されている。第1章を踏破すると開く。」に替え、ボタンを「第2章は封印中」として押せなくし、Tooltipで開く条件を示します。
  - 左右キー（十字キー・左スティック）で扉を選び、扉でEnter（A）を押すとそのまま出撃します（強化ツリーの節でEnterを押すと購入になるのと同じ作法。封印中の章では拒否の音だけ鳴らす）。下キーで出撃のボタンへ、ボタンから上キーで選んでいる扉へ戻ります。ロビーで押したままのEnterの繰り返しでは出撃しません。マウスは扉に少し合わせるかクリックで選び、出撃はボタンで行います。Tab（View）でステータス画面へ移り、そこで戻るとこの画面へ戻ります。戻る（Esc・B）でロビーへ戻ります。
  - 開いたときは、最後に選んだ開いている章を選びます。起動直後は、開いている章のうち踏破していない最初の章（なければ最後の章、`Chapters.frontier`）を選び、ランから戻ったときに新しい章が開いていれば、その章を選びます。開いている章を選ぶと、ロビーの出撃の情報パネルもその章を示します。ロビーからこの画面へ進む操作が確認の役を果たすため、出撃の前に確認の窓は挟みません。この画面の見せ場は、出撃したときの章の挿絵の幕（`SceneTransition`）です。
  - 難易度の段階（[ゲーム仕様.md](ゲーム仕様.md) の8.6）が開いた後は、帯の右の列の出撃ボタンの上に「段階 ◀ 3 ▶」の行を出します（Slay the Spireのアセンションの選び方に近い形）。その下の行に、選んだ段階で増える制約の1文と、持ち帰る残響の増え方（「残響 +30%」）を書き、その文を指すと、効いている制約の一覧をTooltipで示します。段階はQ／E（LB／RB）か◀▶で切り替え、開いている最高の段階より上は選べず、▶のTooltipで「段階1で第2章を踏破すると開く」のように開く条件を示します。出撃ボタンは「第1章へ出撃する（段階3）」となり、選んだ段階はそのプレイ中は覚えておきます。段階が開く前は、この行と操作ガイドの「Q / E 段階」を出しません。
- 強化（`MetaUpgradePage`）は、スキルツリーで定番の形です。左の石板の中に、透けない暗い面（`TreeWell`）を窓として置き、そこに窓より広い盤を載せて、中央の節から枝を伸ばします。盤の地は、彫りの入った丸い石の祭壇です（Diablo IVがツリーを彫刻のアーチの中に置く形に近い）。中央の節「残響の灯」を祭壇の中心として、石は灯に近いほど明るく、灯のまわりに淡い光を敷き、同心円の溝と放射状の細い溝を浅く彫り、外周に縁と菱形の鋲を置きます。溝は暗く浅く描き、線と紋章の読みやすさを黒い地のときと変えません。放射状の溝は、枝が中央から出る向きの間に置き、線の下に溝が重ならないようにします。節の紋章は60px、中央の節だけ84pxで、節の間隔は横108px・縦92pxです。名前や効果は選ぶと右の列に出るため、盤の紋章は小さく保ちます。節は紋章だけで描き、段階が複数ある節は下に目盛りを付けます。名前は盤に書かず、右の列に出します。各節は元の節と線でつなぎ、線は前提を満たすと少し明るく、習得すると最も明るくします。前提を満たさない節は紋章を暗くし、未開放の枝の封印は点線でつなぎます。線は動きで状態を見せます。習得した線の上を、中央の灯から外へ向かって小さな光の粒が流れ（毎秒70px、150pxおき）、粒は線から線へ1本の流れとしてつながり、節に近づくと消えます。今の残響で買える節へ向かう線は、淡い金で1.8秒ごとに明滅します。選んでいる節は金の輪で示します。今の残響で次の段階を買える節には、節の上に小さな金の菱形の印を付けます（Rogue Legacy 2の金貨の印と同じ役目）。盤には文字を書きません。枝ごとの方針は紋章の並びで伝わり、枝の名前は盤の上ではノイズになるためで、枝の名前は右の列に出します。節が窓から完全に外れた枝は、窓の端に矢印だけで示します。
  - 盤はドラッグ（ゲームパッドは右スティック）で動かし、マウスホイール（ゲームパッドはLT／RT）で0.7〜1.8倍に拡大・縮小できます。ホイールはポインターの下の点を、LT／RTは窓の中央を動かさずに拡大・縮小します。盤は、節の全体に窓の半分の余白を足した範囲までしか動きません。Focusした節が窓の端から90pxの内側に入っていないときは、盤が220msでその節を追います。マウスで選んだときは盤を動かしません。
  - 矢印キー（十字キー・左スティック）は、押した向きの±60°にある節のうち、線でつながった節、近い節、上の節の順に選んで移ります。C（Y）で中央の節へ戻り、拡大率も1倍に戻します。マウスは節に少し合わせるかクリックで選び、押したまま8px以上動かすとドラッグになって、何も選びません。開いたときは、そのプレイ中に最後に選んだ節（初めは中央）を選びます。
  - 右の判断の列は、ロビーと同じ装飾枠（`HubUI.ornate_frame()`）で囲み、選んだ節の紋章、名前、段階の目盛り（段階は目盛りだけで示し、「段階 x / y」や枝の名前は書かない。1段階の節も目盛りを1つ出す）、今と次の数値と次の段階で増える量（「最大HP 115 → 130（+15）」、未習得なら「習得すると　最大HP 115（+15）」、0から始まる数値は増える量を省く）、効果（数値の行と同じ数字しか書いていない説明は出さない）、前提を満たさないときの案内（「『鍛えた体』を習得すると解放」）を並べます。列の下には、ロビーと同じ数値の帯（`HubUI.fact_strip()`）に「必要」（次の段階の価格）と「所持」（今の残響）を並べ、足りないときはその下に「残響があと360足りない」と書きます。最後に、価格を書いたボタンを出撃と同じ紋章の札（`CrestButton`、紋章の中はロビーの「強化」の印）で置きます。上限に達した節では数値の帯を出しません。Enter（A）を節で押しても、このボタンと同じ操作になります。上限に達したものは「習得済み」、前提を満たさないものと残響が足りないものはボタンを押せない状態にし、Tooltipで理由を示します。封印を選ぶと、枝の名前と「この枝はまだ開放されていない」だけを出し、ボタンは出しません。
  - 購入は保存まで成功してから演出し（節の脈打ちと、新しく買えるようになった節の明るさの戻り）、保存に失敗した場合は購入を取り消します。
  - Tab（ゲームパッドはView）でステータス画面へ移ります。
- ステータス（`HubStatus`）は、見開きの1冊の本です（2026-11-14に作り替え。武具庫・魔導書・祭壇の3つの試作を同じデータで比べ、読んで比べて決める行動にいちばん合い、状態を言葉と印で区別でき、スキルが増えても形を変えずに済む魔導書を選んだ）。この画面に限り、黒い石板と金の枠、左に枠・右に詳細という拠点のほかの画面の決まりは使わず、羊皮紙に墨の明るい画面にしています。本の章が4つの枠（第一章 攻撃：左クリック・X／第二章 スキル1：Q・Y／第三章 スキル2：E・B／第四章 必殺技：R・LB）と、第五章の能力です。本の右端の見出し（タブ）が章で、開いている章は赤く伸びます。
  - 左ページは章です。上に章の番号・枠の名前・「Q で放つ技」のような1行、その下に「いまの装備」（付けているものの挿絵と名前、右に枠のキーを押した赤い封蝋。空いている枠は点線の輪と「空欄」、必殺技を1つも覚えていない間は「封印」）、その下に目録を置きます。目録は、その枠に付けられるものの一覧で、上に習得した数（「習得 3 / 6」）を書きます。行は、小さな挿絵、名前、点線、短い数値（スキルは「再使用 6秒」、武器は連撃の段数、必殺技は必要なゲージ量）と、右端の今の状態です。この枠に付いているものには赤い封蝋と「装備中」、別の枠に付けたスキルには青い墨で「E に装備中」、まだ持っていないものは挿絵の影と「？？？」「未所持」です。スキルと必殺技の章の先頭は枠を空ける「外す」で、攻撃の章にはありません。状態は色だけでなく、印と文字でも分かるようにしています。封印中の必殺技の章でも、必殺技を影の行として並べます。カーソルのある行は、淡い墨の面と左端の赤い線で示します。目録は9行まで見せ、それより多いときはカーソルに合わせて送ります。
  - 右ページは、カーソルのある項目を1つの頁として読ませます。左上に大きな挿絵（紋章の絵を、青銅の縁を外して墨の二重の輪で囲む。周りに短い放射の線）、その右に種類・名前（46px）・今ある場所（「この章に記されている」「「スキル2」の章に記されている」「まだ記されていない」）、飾り罫の下に説明、その下に「記録」として数値を1行ずつ書きます。数値は、スキルが再使用・威力（「攻撃力の200%」）・範囲、武器が連撃の段数・最も強い段の威力・溜め攻撃の威力と範囲、必殺技が必要なゲージ量・奥義の研鑽を含めた威力・範囲です。範囲・射程・吸い寄せる範囲のような距離は、画面ではpxで書かず、床の1マス（48px、`AreaGround.CELL`）を単位に0.1マス刻みで示します（「半径2.9マス」）。pxは世界の中の言葉ではないためで、強化の画面の数値も同じ書き方にします。カーソルの項目が今の装備と違うときは、記録が2列になり、「候補」の値の右に「いまの「叩きつけ」」の値を薄く並べます。付け替える前に、数値を見比べて決められるようにするためです。
  - 右ページの足元には、Enter（A）で起きることを書きます。付けられるときは、封蝋の印と「Enter で封を押す」、その下に結果の1文（「Q に付ける」「「叩きつけ」と替える」「E から移す」「「叩きつけ」と場所を入れ替える」「「雷閃」を外す」）です。すでに付いているものは「すでに封が押されている」、持っていないものは「まだ封を押せない」と書き、Enterを押すと拒否の音が鳴って足元に赤い線が走るだけで、何も変わりません。
  - 操作は次のとおりです。上下キー（十字キー・左スティック）で目録のカーソルを動かし、Q／E（LB／RB）か左右キーで章をめくります。Enter（A）で封を押し（付ける・入れ替える・持ち替える・外す）、X（X）で開いている枠を空けます。R（Y）で第五章の能力へ飛び、もう一度R（Y）か戻る（Esc・B）で元の章へ戻ります。章の上で戻るとロビーへ、Tab（View）で強化画面へ移ります。マウスは、見出しのクリックで章を開き、行のクリックでカーソルを置き、同じ行をもう一度クリックするか右ページの足元をクリックすると封を押します。ホイールでカーソルを動かせます。章をめくると、頁の中身が少し横から入り、紙の影が見開きを横切ります（約0.24秒。操作は待たせない）。
  - 付け替えはその場で保存し、保存できたら、中身が変わった枠の封蝋が上から押され、赤い輪が広がって消えます。右ページの挿絵の放射の線も、一瞬だけ赤く伸びます（この画面の見せ場、約0.6秒）。保存に失敗した場合は付け替えを取り消します。
  - 第五章の能力は、見開きの左に「戦う力」（最大HP・ダメージの軽減（一撃から引く量）・攻撃力・移動速度（初めの速さを100%とした割合。px/秒の値は世界の中の言葉ではないため書かない）・ダッシュ・被弾後の無敵・不屈）、右に「探索と成長」（宝石を吸い寄せる範囲・回復の報酬・報酬の残響・得る経験値・レベルアップのカード・引き直し・レベルアップの瞬間の効果）を1行ずつ並べます。値の横に永続強化で増えた分を赤で（「115 (+15)」）、行の下に内訳を青い墨で（「基礎 100　＋ 鍛えた体 +15」）書きます。内訳をTooltipではなく行に書くのは、ゲームパッドでも読めるようにするためです。ステータス画面を開き直したときは、枠の章から始まります。
  - 作りは、Focusを持つ1つのControlが `_draw()` で全体を描く形です。本の表紙と紙はシェーダー（`ui/grimoire/grimoire_book.gdshader`）で描き、質感は生成した羊皮紙と革の絵の濃淡（`art/ui/grimoire/`）で付け、設計上の大きさ（1520×686）を画面の領域に合わせて拡大・縮小します。色・書体・文字サイズは、共通Themeの `Grimoire` 型から取ります（墨・セピア・薄墨・封蝋の赤・書き込みの青・紙・表紙。トークンは `ink`・`page`・`wax`・`leather`・`note` の系統）。`tests/test_ui_theme.gd` が、紙のいちばん暗い所に対して墨・セピア・赤・青が4.5:1以上、薄墨（持っていないもの）が3:1以上の明るさの比を持つことを検査します。英語では、見出しの文字を90度回して縦に流し、説明は単語の切れ目で折り返します。
- 図鑑（`HubCodex`）は、博物誌の図譜です。敵1体に図版を1枚ずつ当てます（2026-11-14に作り替え。調査台帳・魔物図譜・追憶の祭壇の3つの試作を同じデータで比べ、探す・調べる・眺めるの3つをどれも満たし、ステータス画面の本と同じ紙と墨で揃う図譜を選んだ）。ステータス画面と同じく、この画面は黒い石板と金の枠、左に一覧・右に詳細という拠点のほかの画面の決まりを使いません。
  - 図版の左には、敵の立ち絵（`art/enemies/codex/<見た目のID>.png`、`EnemySprites.codex_portrait()`）を大きく立たせます。上に「図版　第06」と「群れの類」、その下に名前（明朝体、46px）、ボスには二つ名を赤で添えます。立ち絵は、足元を軸にゆっくり呼吸するように伸び縮みし（3.2秒で1回）、足元には版画の陰影のような斜めの細線を引きます。強敵版は同じ立ち絵を敵の色（`FoeData.tint`）で染めます。
  - 図版の右には、分かっていることを博物学者の書き込みとして書きます。立ち絵の上に a・b・c の丸い印を置き、それぞれから線を引いて、余白の注釈（a. HP、b. ぶつかる力、c. 速さ）につなぎます。注釈は、項目名、目盛りの付いた定規、数値です。定規は、出会った敵の中でいちばん大きい値を右端として、その敵の値までを赤く塗ります（値の平方根で伸ばすので、小さい値も読める）。印の位置は立ち絵の決まった割合の所で、体の部位を指しているわけではありません。その下に「観察記」（どう動くか）と「棲息」（どこに現れるか。説明の2行目）を書きます。
  - 図版の下の盆（標本の盆）には、開いている分類の敵すべてを、丸い顔のアイコン（`FoeIcon`）で番号と一緒に並べます。開いている図版の標本は、赤い縁でピンの上に持ち上がります。盆に収まらない数（18体を超える分）は、開いている図版に合わせて送ります。盆の左に、分類の名前、観察した数（「14 / 33 を観察」）、並び（「並び：番号順」）を書きます。
  - 図版の上端から下がるリボンが分類（すべて・群れ・精鋭・ボス）で、それぞれ出会った数を書きます。開いている分類のリボンは長く下がります。
  - 操作は次のとおりです。左右キー（十字キー・左スティック）で前後の図版をめくり、Q／E（LB／RB）か上下キーで分類を替えます。R（Y）で盆の並びを、番号順・HPの高い順・ぶつかる力の高い順・速さの高い順の順に替えます。並びを替えても、開いている図版は開いたままです。マウスは、盆の標本かリボンのクリックで直接開き、図版の左右の三角で前後へめくり、盆の「並び」のクリックで並びを替えます。ホイールでも前後へめくれます。図版をめくると、立ち絵と書き込みが、めくった側から少し横へずれた所から淡く入ります（約0.24秒。操作は待たせない）。同じ図版をもう一度選んでも動かしません。
  - 出会っていない敵は、まだ描かれていない図版です。立ち絵は形だけを1色で塗った影にし（`ui/grimoire/flat_shape.gdshader`）、名前を「？？？」、その下に「いまだ観察されず」と書き、分類だけを示します。数値・二つ名・観察記は出さず、「覚え書き」として「まだ出会っていない敵。探索で戦場に現れると記録される。」だけを書きます。影を、絵に色を掛けて作らないのは、目や模様が透けて見えて、決まりより多くのことが伝わるためです。並びを数値の順にしたときは、出会っていない敵を必ず出会った敵の後ろに置きます。順番から強さが伝わらないようにするためです。難易度の段階の強敵版（[ゲーム仕様.md](ゲーム仕様.md) の8.6）も載ります。
  - 顔のアイコン（`FoeIcon`）は、図鑑の立ち絵から顔や頭（頭のない敵は目や口など見分けやすい所）を正方形に切り出して丸く抜いたもので（立ち絵のない敵はリグの絵から）、切り出す位置は見た目のIDごとに `FoeIcon.CROPS` に書きます（書いていない敵は絵の上部）。戦闘用に縮めた連番画像からは作りません。小さく、拡大するとぼやけるためです。アイコンは一度作ったら使い回します。出会っていない敵のアイコンは暗い影です。
  - 作りは、Focusを持つ1つのControlが `_draw()` で全体を描く形で、設計上の大きさ（1520×686）を画面の領域に合わせて拡大・縮小します。紙はシェーダー（`ui/grimoire/grimoire_plate.gdshader`。質感はステータス画面の本と同じ羊皮紙の絵）で、立ち絵は紙の上・書き込みの下に置いた `Sprite2D` です。色・書体・文字サイズは、共通Themeの `Bestiary` 型から取ります。`Bestiary` は `Grimoire`（ステータス画面の本）を継ぐ型で、リボンの4色と盆の色だけを足しています。`tests/test_ui_theme.gd` が、リボンと盆の上の文字が4.5:1以上の明るさの比を持つことを検査します。英語では、説明を単語の切れ目で折り返します。
- 設定（`HubSettings`）は10項目（全体の音量・音楽・効果音・環境音・画面の揺れ・画面モード・言語・操作の案内・ヘルプ・ゲームの終了）で、「サウンド」（音量4つ）「グラフィック」（画面の揺れ・画面モード）「その他」（言語・操作の案内・ヘルプ・ゲームの終了）の3つのタブで切り替えます。タブはQ／E（ゲームパッドはLB／RB）かクリックで替わり、替えるとそのタブの先頭の項目にFocusが移ります。上下キーのFocusはタブの中だけを巡ります。画面は、アクションローグライトの設定画面で定番の、画面中央の1枚のパネル（幅1000px）で、上にタブ、中に項目の行、その下に金の細線を引いて選んでいる項目の説明を出します。項目が少ないため、説明だけの右の列を置くと大半が空くからです。パネルの高さは項目が最も多いタブに合わせ、タブを替えても変わりません。変更はすぐに反映され、`GameSettings` が保存します。「操作の案内」は戦闘中の画面下の操作説明の表示を切り替えます。ヘルプは、設定画面を暗くした上に重ねる枠付きのウィンドウで開きます。アクションゲームのTipsで定番の形で、窓の上に「ヘルプ」の見出し、その下の左に話題の一覧、右に説明用の枠（`HelpPage`。窓より一段暗い面と淡い金の縁）を置き、その中に選んだ話題の見出しと金の細線と要点を出します。説明を枠に入れるのは、話題の一覧と本文の境目を見て分かるようにするためです。窓の大きさ（1280×780px）は話題を替えても変わらず、最も長い「操作」に合わせています。要点は1つずつ行を分け、頭に金の小さな菱形を付けます（図鑑の数値と同じ印）。長い段落で書くと読み流しにくかったためです。「操作」の話題だけは、要点の上に、行動・キーボード・ゲームパッドの3列の表を置き、キーをキーの札（`HelpKeyCap`）で示します（`HubSettings.HELP_KEYS`）。閉じるには、Esc（ゲームパッドはB）のほか、窓の下の「閉じる」の案内か、窓の外の暗い部分をクリックします。ロビーのメニューと同じく、マウスを話題に少し合わせるとその話題が選ばれます。設定の項目も同じで、項目名か操作部品にマウスを少し合わせるとその項目が選ばれます。設定の行は、選んでも帯や枠や下線を付けません。項目が少なく、行の帯がパネルの中で目立ちすぎたためです。代わりに、Focusのある操作部品そのものが示します（音量のつまみが淡く光り、切り替えの「〈 〉」が明るくなり、「開く」「終了する」の文字が明るくなる）。切り替えの値（「標準」「全画面」「ON」など）には下線も面も付けません。「開く」「終了する」には「›」を付けません。ヘルプの話題は、行に帯や枠を付けず、選んだ話題の文字を金色にして淡い光（Themeの `HelpTopic` の `glow`）で包んで示します。選んでいない話題は少し暗い文字にします。ゲームの終了の確認は、戻るボタンを「戻る」とします。「やめる」では、終了をやめるのか、ゲームをやめるのかが分かりにくかったためです。ヘルプの文は、ゲームのほかのメッセージと同じく「です・ます」で書きます。「環境音」は戦場の風の音の大きさです。ヘルプは探索の流れ・残響と強化・操作・図鑑・強化と状態異常・イベントと呪いの6つの話題を持ちます（`HubSettings.HELP`）。感電と燃焼の効果、強化の前提、呪いの中身のように、カードや窓に書ききれない決まりごとはここに置きます。キーを変えたときは、表（`HELP_KEYS`）も合わせて直します。同じ設定画面を戦闘中のメニューからも開けます。ただし「言語」は拠点の設定だけに出し、戦闘中のメニューには出しません。言語を替えると拠点の画面を作り直すため（2.5）、探索の途中の画面では切り替えられないからです。

出撃すると `SceneTransition` が章の挿絵と名前を出し、分岐マップへつなぎます。初めての出撃のときだけ、その前に前置きの静止画を見せます（[ゲーム仕様.md](ゲーム仕様.md) の8.7）。旅立ちの加護を持っている場合は、分岐マップで最初のエリアを選んだあと、そのエリアに入る前に強化を3択で1つ選びます。

## 2. UI

### 2.1 共通Theme

UIは `res://ui/theme/dungeon_theme.tres` をプロジェクト共通Themeとして使用する。暗色の面・明るい本文・控えめな金色を基調とし、通常面は低彩度の細い輪郭、選択と主要操作は金色の輪郭を使い、面の明度・余白・控えめな影で階層を示す。金色は、どこにでも使うと特別に見えなくなるため、次の2つの意味に限る。1つは「今選んでいるもの・押すべき操作」（選択枠・Focus・主要ボタン）、もう1つは「通貨と手に入れた価値」（残響の残高、獲得済みの段階の目盛り、勝利の見出し）である。能力値やエリアの情報は明るい本文色（`BodyLabel`・`ValueLabel`・`ItemNameLabel`）で示し、上昇は緑（`StatUp`・`PositiveLabel`）、下降と損失は赤（`StatDown`・`LossValueLabel`）で示す。規則の常設案内は控えめな色（`MutedLabel`）とする。参考アートは方向性の基準であり、実行時素材として使用しない。HUDのHPなど意味を持つ専用表示は別途維持する。

- 操作は `PrimaryButton`（主要操作）、`SecondaryButton`（戻る・補助操作）、`DangerButton`（取り消せない操作）、`ItemButton`（選択）、`GoldButton`（購入・成長）を使い分ける。
- 文字は画面名 `TitleLabel`（30px）、見出し `HeadingLabel`（24px）、項目名 `ItemNameLabel`（20px）、主要値 `ValueLabel`（26px）、本文 `BodyLabel`（18px）、説明 `DescriptionLabel`（18px）、補足 `MutedLabel`（16px）、価格 `GoldLabel`（21px）を使用する。ボタンは原則18px、補助操作は16px。画面ごとのフォントサイズ・色overrideは追加しない。
- 拠点のヘッダー・ページ・フッター、各画面の列はContainerで配置する。ただしロビー（`HubLobby`）は、背景の一枚絵と一体に見せるため、1600×900の画面全体へ直接配置する。`HubUI` はパネルとMargin・VBox/HBoxの構造だけを共通化する。基準内容幅1440px・高さ810px（1600×900の画面で左右に80pxずつ背景を残す）、画面端は最低20px相当を確保して縮小する。通常のパネル内余白24px、列間20px、縦間隔12px、密な詳細は8px。
- 外観の調整はTheme内の名前付きStyleBox（`MainSurface`、`SurfaceHover`、`FocusOutline`など）を編集する。同一のStyleBoxを共有するControlへ一括反映されるため、画面側で複製しない。
- Themeの色と文字サイズは、すべてトークン（`ui/theme/theme_tokens.tres`）から書き出す。GodotのThemeには値を参照する仕組みがなく、同じ金色が何十か所にも直接書かれていて全体の調子を一度に変えられなかったためである。色は系統（`gold`・`parchment`・`umber`・`neutral`・`ember`・`moss`・`frost` と、ステータス画面の本が使う `ink`・`page`・`wax`・`leather`・`note`）ごとに暗い順の番号で名前を付け（`gold.1` が最も暗い金）、透明度は使う場所ごとに持つ。文字サイズは小さい順に `size.1` からの段にする。Themeのどの場所がどのトークンを使うかは `ui/theme/theme_bindings.tres` に `tools/build_theme.gd` が記録する。トークンを変えたとき、またはThemeに色や文字サイズを手で足したときは `tools/build_theme.gd` を実行する。トークンと同じ値は自動でそのトークンに結び付き、どのトークンとも違う値はエラーとして示されるので、トークンを足すか既存のトークンに合わせる。系統全体の色味は、トークンの `families` に色相の回転・彩度と明度の倍率を書くと、その系統のすべての色に反映される。`tests/test_ui_theme.gd` が、Themeの値がトークンどおりであることを検査する。
- `tests/test_ui_theme.gd` が守るのは、どの見た目にしても崩さない品質に限る。Themeがトークンどおりであること、画面ごとのoverrideがないこと、Focus・選択・Disabledが区別できること、状態によって余白が変わらないこと、拠点の小さい文字が16px以上であること、本文系の文字が面に対してWCAG 2.2 AAの4.5:1以上の明るさの比を持つこと（Disabledは3:1以上）、戦闘の上に浮かぶ文字が不透明な板に載っていることである。枠や面の形（補助操作は普段は枠を持たずFocusで左の金の棒になる、くぼんだ欄は浮いたカードより暗い、スクロールバーは青銅の細い溝、押したボタンと選んだタブは平らな面、戦闘中の窓は暖かい石の板）は見た目の選択であり、この文書に書いて撮影画像（`tools/compare_captures.py`）で判断する。見た目の選択まで検査に入れると、見た目を試しに変えるたびに壊したのと同じ扱いで検査が落ちたためである。
- 光のにじみ・輪・細線は、`ui/ornaments/` のシェーダーで描く装飾のノード `Ornament` で描く。種類は、柔らかい光の円（`GLOW`。`breath` を与えると息づくように強弱が付く）、輪（`RING`。`sweep` で上から時計回りに一周の途中まで描け、外側に淡い光の円 `halo` を付けられる）、両端が消える細線（`RAIL`）の3つである。種類ごとにシェーダーの設定（ShaderMaterial）を1つだけ共有し、色・大きさ・進み具合はノードごとの値（instance uniform）で渡すので、同じ装飾をいくつ並べても重くならない。部品の中では、自分の `_draw()` で描く面の上、後から足す子（絵や文字）の下に置く。色は必ず `Ornament.set_value()` で渡す。標準の描画方式（Forward+）では、Color型のまま渡した色が暗く濁るため、`set_value()` がVector4に変えて渡している。ステータス画面と図鑑を自分で描く画面に作り替えたため、今この形を使っている画面はない。ほかの画面の装飾は、画面ごとの見直しのときに移す。
- 拠点の画面は、それぞれ自分の表情（`ui/theme/moods/<画面の名前>.tres` の `ThemeMood`）を持てる。表情は共通Themeのトークンの一部を差し替えたもので、系統ごとの色味の回転（`families`）と、個々のトークンの色（`colors`）だけを変えられる。文字の大きさ・余白・書体・枠の形は変えられない。拠点（`Hub._page()`）は、画面を作るときに、トークンを差し替えた共通Themeの写しをその画面のいちばん上のNodeに付ける。そのため表情はその画面の中だけに効き、ヘッダーやフッターは共通Themeのままになる。写しは初めて使うときにその場で作るので、共通Themeやトークンを変えても作り直すファイルはない。`tests/test_ui_theme.gd` が、表情が実在するトークンだけを差し替えていることと、表情の中でも文字が面に対して読める明るさの比を保っていることを検査する。今は表情を持つ画面はない（ステータス画面で「武具庫」の表情を試したが、画面そのものを本に作り替えたため外した）。表情を足すときは、その画面のファイルを置けばよく、やめるときは消せば共通Themeに戻る。

色の役割は背景 `#020305`、主面 `#252525`、浮いた面 `#2B2B2B`、一覧の内側 `#1C1C1C`、Hover `#363636`、選択面 `#26241A`、通常境界 `#525252`、選択境界 `#B89759`、金 `#D6B77B`、本文 `#EEE9DF`、説明 `#C9C9BF`、補足 `#B2B3AA`、減少 `#DB857A`、増加 `#91C2A3` とする。拠点背景の画像は暖かい光を残し、上に重ねる中立色の暗幕を薄くして石造りの奥行きを見せる。主パネルは青みを含まない不透明な石墨色で背景と分離する。

画面上の用語は日本語に統一する。1回の出撃は「探索」（このファイルとコードでは「ラン」・`run` のまま）、通貨は「残響」と書く。周回限定強化と永続強化は、どちらも画面上では「強化」と書き、1つの文で両方に触れるときだけ「レベルアップの強化」「拠点の強化」のように場所を添えて分ける。「ラン」はローグライトを遊ばない人に伝わりにくく、永続強化は拠点の画面の名前が「強化」になったためである。通貨の量は数字だけ（例：残響 160）で示し、Lvは「Lv 3」、層は「第2層」と書く。ロゴは「Dungeon Remnant」と単語の間を空ける。

書体は、日本語のゲームで定番の「題名は明朝、本文と数字はゴシック」の組み合わせとする。表示書体はSIL Open Font Licenseのしっぽり明朝（Bold・Medium、`ui/fonts/`）とし、`TitleLabel`・`HeadingLabel`・結果の見出し・ロゴ・中央の知らせの帯（`HudBanner`）・通貨（`PurseValue`）・ロビーの数値（`LobbyFactValue`）に当てる。本文・ボタン・数値は、同梱したSIL Open Font LicenseのBIZ UDPゴシック（Regular・Bold、`art/third_party/biz_udp_gothic/`）とする。ThemeのDefault Fontを Regular にし、数値の役割（`ValueLabel`・`HudValue`・`StatValue`・`SettingsValue`・`PriceLabel`・`OptionCycler` など）と項目名（`ItemNameLabel`）・主要ボタン（`PrimaryButton`・`PrimaryAction`）は Bold にする。端末に入っている書体に頼らないため、どのPCでも同じ見た目になる。本文と説明は行間を6px空ける。Themeの `FontVariation` でOpenTypeの `palt` を有効にし、小書きカナの字間が開かないようにする。2行に収まる日本語の説明は `TextWrap` で中央付近の助詞・句読点の後に改行を入れ、最終行に1〜2文字だけが残らないようにする。大きなパネルの地は `art/ui/` の9-slice装飾枠を使う `StyleBoxTexture` とする。

### 2.2 動き

操作の時間変化は `ui/ui_motion.gd` の `UIMotion` で管理する。色・枠線はThemeに残し、scaleとalpha、選択カードの内側金枠の強さ、HPの残像ゲージの表示値を動かす。Controlごと・プロパティごとに前のTweenを停止し、非表示・解放時に基準値へ戻す。Containerの位置や最小サイズはアニメーションせず、位置の動きが必要な場合は表示層を動かす。表示層とは、Containerが配置するControlの内側に置いた、Containerの管理を受けない見た目用のControl（`mouse_filter` はIgnore）であり、その `position`・`scale`・`modulate` だけをTweenする。

各画面に「プレイヤーの選択が結果に変わる瞬間」を1つだけ定め、その瞬間の演出を最も手厚くする。これを見せ場と呼ぶ（強化カードを取る瞬間、永続強化を買う瞬間、ランの結果が出る瞬間）。見せ場以外の操作は控えめな反応にとどめる。演出の時間は3段階に分け、Hover・Focus・押下などの反応は80〜120ms、画面・パネル・選択詳細の入れ替わりなどの遷移は180〜260ms、見せ場は400〜900msとする。入場は `TRANS_CUBIC` の `EASE_OUT` を基本とし、見せ場の強調だけ `TRANS_BACK` の `EASE_OUT` で最大1.05倍までのオーバーシュートを許す。退場は120msの `EASE_IN` とし、退場中も次の画面が入力を受け付ける。

残響や撃破数など結果の数値は、状態と保存上の値を即時に確定させたうえで、表示だけを前の値から新しい値へ数えて見せる。購入の成功演出は保存まで成功してから始め、UIのTween完了をゲーム処理から待たない。開いた直後の誤選択は、キーリピート（`echo`）を受け付けないことで防ぐ。

拠点の画面切り替えでは、ページ全体を表示層として扱い、16px横から180msで入場させる。奥の画面へ進むときは右から、ロビーへ戻るときは左から入る。

### 2.3 個別画面のUI文法

拠点の個別画面（出撃・強化・ステータス・図鑑・設定）は、次の共通ルールに従う。画面ごとに作法が違うと、同じ操作でも毎回探し直すことになり、ロビーで整えた雰囲気も画面を開くたびに途切れるためである。ロビーはこの対象に含めない。新しい個別画面を足すときも、この節に合わせる。

**画面の骨格。** すべての個別画面を上段・本体・下段の3段で組む。上段は左に画面名（`TitleLabel`）だけを置き、右に残響の表示を置く。本体は主要パネル1〜2枚とする。下段は左端に操作ガイドを置く。上段と下段はページ本体（1440×810）の内側ではなく、画面の端を基準に置く（左右40px、上22px、下16px、`Hub.EDGE_X` など）。

**メインコンテンツパネルは1枚の静かな面。** 拠点の個別画面の本体は、ポップアップの窓と同じ静かな面（`QuietWindowStyle`）の1枚のパネルとし、画面の左右端から40pxずつ空けて置く。左の選ぶ場所（`SlabSolid`）と右の判断の列（`SlabSolidEnd`）は同じパネルの2列で、間を1本の細い縦線で区切る。ただし強化の画面は右の列を装飾枠（`HubUI.ornate_frame()`）で囲むため、枠と線が二重にならないよう縦線を引かない（左の列を `SlabSolidOpen` にする）。パネルにもポップアップの窓にも、上端の金の細線は引かない。上端だけ色の違う面はWebのカードのように見え、館の雰囲気を損なうためである。石の質感と青銅のレールは使わない。パネルの中の区切りは金の細線（`HubUI.rule()`）と余白で付ける。ただし出撃の画面は、ロビーの「出撃」の続きとして、ロビーの情報パネルと同じ装いの帯を使う（1章の出撃の項）。

**画面の型は定番に合わせる。** 画面の配置は独自に考えず、多くのゲームで使われている形式に合わせる。プレイヤーがほかのゲームで覚えた読み方と操作がそのまま通じるようにするためである。今の対応は、戦闘HUDがアクションローグライトとサバイバー系の配置、出撃がステージ選択の扉の並びと詳細の帯、分岐マップがノードマップ、結果画面がランのまとめ、永続強化がスキルツリーと詳細の列、ステータスが章で枠を分けた本の見開き（左ページに目録、右ページに詳細）、図鑑が敵1体に1枚の図版と下の標本の盆（この2つは定番の型から離れ、試作を比べて選んだ）、設定が中央1枚のパネルのタブと行と説明、戦闘中のメニューが一時停止画面とビルドの一覧である。他のゲームの絵・枠・アイコンはまねず、色と書体と枠の素材はこのThemeのものを使う。

**選ぶ場所と判断の列。** 選んで決める画面（強化。ステータスは本の見開きで、左ページが選ぶ場所、右ページが判断の列に当たる。図鑑は下の盆が選ぶ場所、上の図版が判断の面に当たる）は「選ぶ場所（左）＋判断の列（右）」で組み、右の列は画面の右端まで延びる石板（`SlabSolidEnd`）に、上から絵や名前、数値、説明の順で並べる。強化の選ぶ場所は強化ツリーの盤とし、主要操作（購入）は右の列の下に1つだけ置く。左の石板は不透明な `SlabSolid` とし、背景の絵の上に文字を直接載せない。

**金色の用途。** 個別画面の金色は、①選択中とFocus、②主要操作、③通貨の3つに限る。③の通貨は、残響の残高と、今の判断に関わる値だけを金とする。

**等間隔の格子と埋め込みパネルを避ける。** 同じ大きさの箱を同じ隙間で縦横に並べると、表計算やフォームのように見える。まとまりの中は詰め、まとまりの間は大きく空け、大事なものだけを大きくして、間隔に強弱を付ける。箱の中に箱を重ねない。ただし強化ツリーの盤だけは、パネルの中の透けない黒い面（`TreeWell`）に置く。動かせる盤が石板の質感に重なると、節と線が背景に紛れるためである。

**主要操作は1つ。** 1画面（強化では1行）に主要操作は1つとし、`PrimaryAction`（`HubUI.primary_action()`）か `PrimaryButton` で作る。見た目は静かな札（金を薄く敷いた面と1pxの金の縁、指すと少し濃く、押せないときは縁も面も消えかける）とし、装飾の金具は使わない。ロビーの決定ボタンだけは、ロビーの絵と一体の装飾の札（`LobbyAction`）とし、出撃の画面の出撃ボタン、強化の画面の購入ボタン、ステータスの画面の装備のボタンだけは、その画面の見せ場として紋章の札（`CrestButton`、`CrestAction`、1章の出撃・強化・ステータスの画面）とする。そのほかの操作は `SecondaryButton` とする。押せないときは理由をTooltipで示す。

**戻るは全画面で左下、操作ガイドとして示す。** 下段の左端に、キーの記号と動作を並べる操作ガイド（例：`Esc 戻る`　`Enter 決定`）を置く。ボタンの枠には入れず、記号の部分を押しても同じ操作になる。キーボードとマウスの間はキーの名前を文字だけで書き、ゲームパッドの操作中だけ記号を札（`B`・`A`）にして示す。部品は `KeyGuide`（`add_hint()` でキーの記号・ゲームパッドの記号・動作を渡す）。

**文字の階層を固定する。** 1つのまとまりの中は、見出し（`HeadingLabel` 24px）→ 主要数値（`ValueLabel` 26px）→ 補足（`MutedLabel` 16px）の順に並べ、1つのパネルの中で使う文字の段階は、見出し・主要数値・本文・補足の4段階までとする。

**通貨の強弱。** 残響の表示は全画面で同じ位置（ロビーと同じ右上）に置く。通貨を使う画面（強化）では今の強さで示し、それ以外の画面では大きさと明るさを落として控えめにする（`GoldPurse.quiet`）。位置を変えたり隠したりしないのは、残高を確かめたいときに探さずに済むようにするためである。

**説明の置き場所。** 画面には、その場で選ぶ・決めるために要る情報（名前・数値・条件・価格・結果）だけを置き、ゲームの決まりごとや操作の説明を文章で常に並べない。
- 詳しい説明は、設定画面の「ヘルプ」に話題ごとにまとめる（`HubSettings.HELP`）。ここに書く内容は、ゲームの実際の規則と一致させ、規則を変えたら一緒に直す。
- その場で知らないと困る決まりごとは、見出しの横の小さな「?」（`HintMark`）にする。マウスを合わせると1行のTooltipで規則を示し、押すとヘルプのその話題を開く。
- 部品の補足は、その部品のTooltipに短く置く。操作ガイドに出ている操作は、画面の文章で繰り返さない。
- 配置・枠・絵で分かることは、見出しや補足の文で言い直さない。画面名と同じ見出し、選んだ枠（金の枠）が示す対象の名前、ボタンや状態の表示と同じ文、スライダーの両端の「小・大」、絵と大きさで分かるボスの名札は置かない。ラベルは、値だけでは何の数字か分からないとき（持ち帰った残響、結果の統計など）に限る。

**背景とキャラクターは全部を見せようとしない。** 背景の絵と主人公の立ち絵はロビーで全体を見せているため、個別画面では背景を雰囲気の役とし、パネルの外の上段と下段にだけ見せる。ただし出撃の画面は出発の場面なので、章の扉を広間の上に立て、扉の間から背景を見せる（パネルは扉の下の帯）。

**情報は「常時表示／開いた時だけ／別画面」に分ける。** その場で判断に要る情報だけを常に出し、詳しい情報は選んだとき・指したとき・「詳しく見る」で開いたときにだけ出し、決まりごとの説明はヘルプ（別画面）に置く。表示から外した情報も、この3つのどれかの導線で必ず読めるようにし、機能は消さない。キー・マウス・ゲームパッドのどれでも同じ情報に届くようにする。

**枠線は必要な箇所だけに絞る。** 枠を付けるのは、主要操作（`PrimaryButton`・`PrimaryAction`）、選択中とFocus中の項目、確認の答えのボタン（`BandButton`・取り消せない操作は赤い `BandDangerButton`）だけとする。通常の操作（`SecondaryButton`）は文字だけとし、指したときは淡い帯、Focus中は左端の金の縦線と淡い帯で示す。窓の中に箱を重ねず、区切りは細線（`HubUI.rule()`）と余白で付け、まとまりを示したいときだけ枠のない淡い面（`QuietSection`）を使う。

**項目カードは共通の1つの形。** 一覧の1件（レベルアップの強化カード、結果の統計のタイル）は、同じカードの面とする。普段は枠のない淡い面（`CardSurface`・`CardButton` の通常）、指すと少し明るく、Focus中は明るい本文色の細い縁（`CardSurfaceActive`・`CardButton` のFocus）、選んだものは金の枠とする。カードに常に出すのは絵・名前・主な数値と主要操作だけとし、説明や条件は選んだときに右の判断の列か、カードの中の「開いた時だけ」の欄に出す。強化カードには色の帯を付けず、新規か段階上げかは紋章の上の「新規」「Lv 1 → 2」の文字で示す。片側だけに別の色の線を引くと、Webページのカードのように見えてゲームの面になじまなかったためである。

**ポップアップの窓は静かな面にする。** ヘルプ・戦闘中のメニュー・分岐マップの札・イベント・結果の窓は `QuietWindow`（`QuietWindowStyle`：暗い半透明の面、細い縁、下へ落ちる淡い影。上端の金の細線は引かない）で作り、装飾の金具は使わない。レベルアップの強化カードだけは窓を置かずに戦場の上に浮かべ、共通のカードの面を使う。確認は窓ではなく、画面を横切る帯で尋ねる（次の節の `ChoicePrompt`）。

**状態表現の共通化。** ボタン・カードなどの部品ごとに、通常・Hover・Focus・選択中・押下・無効の6つの状態を全画面で同じものにする。選択中は金の枠、Focusは明るい本文色の細い縁と軽い拡大で示し、ゲームパッドで「今どこにいるか」と「何を選んだか」を見分けられるようにする。Focusの縁は全部品で共通の1つ（`FocusOutline`。面を塗らず、下の状態を隠さない）とする。行を選ぶ一覧（戦闘中メニューの強化）は、尖った帯や枠を使わず、行全体の淡い暖色の帯と左端の金の縦線で選択を示す。設定の項目は行に帯を付けず、操作部品が自分でFocusを示し、ヘルプの話題は文字の光で示す（設定の節）。

**普段の動き。** 画面を開いたとき、部品を一度に出さず順に入れる（`play_entrance()`。拠点が画面を開くときに呼ぶ）。メインコンテンツパネルの右の判断の列（設定の項目の説明、ヘルプの本文）は、示す内容が替わるたびに、右から40pxの位置から淡く入って0.2秒で定位置に収まる（`UIMotion.slide_in()`）。示す内容が同じとき（同じ項目をもう一度選んだとき、クリックがFocusと押下の2回として届いたとき）は動かさない。列は内容を自分の枠の中で切り取るので、左の列の上へははみ出さない。選択の光の帯と、文字タブの金の下線は、前に選んでいた場所から新しい場所へ0.12秒で滑って移る（`UIMotion.follow_mark()`、`TabUnderline`）。見せ場より目立たせず、入力は動きの途中でも受け付ける。

**数値の表記。** 3桁ごとに区切り（1,280）、通貨の表記は `UIFormat.amount()` で作る。変化は「現在 → 変更後」で示す。

### 2.4 ラン中の画面

- 戦闘のHUD（`ActionHud`）は、アクションローグライトとサバイバー系で定番の配置にし、中央の主人公の周りを空ける。上端に経験値の帯と、その右端にレベル。上中央にエリア名、目標の文（`HudObjective`）、目標の進み具合の帯（アリーナでは、終わったウェーブに今のウェーブで倒した割合を足して進める。ボスが現れたら、同じ位置にボスのHPゲージが代わりに出る）。エリアに入ったときの中央の帯にはエリア名だけを出し、目標は上中央にだけ書く。左上に取得した強化を紋章（40px）と段階の数字で並べる。右上にこの探索の残響（金色で大きく）と、その下に探索を通した撃破数（「総撃破」。上中央の目標の「撃破 0/150」はそのエリアの数なので、言葉を分ける。目標が「敵を倒す」のエリアでは出さない）。左下にHPの数値と帯（減った分は明るい残像が少し残ってから追いつく。`UIMotion.update_vital`）。帯は、赤いハートの宝石をはめた青銅の紋章を左端に持つ描いた枠の溝に収め、上中央のボスのHPゲージ（王冠の骸骨の紋章を持つ鉄と青銅の枠）と同じ作りで対にする。どちらも `FramedGauge` が、両端の飾りを保ったまま溝だけを引き伸ばして描く。右下に攻撃・回避・スキル1・スキル2・必殺技の丸い枠（`ActionSlot`）を並べ（攻撃の枠は持っている武器の紋章、スキルと必殺技の枠は付けたものの紋章で、何も付けていない枠は出さない）、それぞれの紋章、キー（ゲームパッドで遊んでいる間はボタン名）、再使用を待つ間の暗い扇、ダッシュの残り回数の点、溜めている間の輪を示す。キーの名前は枠の下に常に出し、待っているものは紋章の上に重ねて書く（スキルは残りの秒数、必殺技は「62%」のような溜まり具合）。どのキーの枠かを、待っている間も見失わないようにするためである。必殺技の枠は、ゲージを暗い扇と外側の金の弧でも示し、満ちると割合の文字が消えて音が鳴り、ゆっくり脈打つ。画面下中央に枠にない操作の案内を、ほかの画面と同じキーの案内（`KeyGuide`。キーボードではキーの名前、ゲームパッドでは描いたボタンの札）で並べ（スキル2つと必殺技を付けて行動の枠が5つになると枠が中央の下まで届くため、案内を枠から24px空く所まで左へ寄せる。HPの帯には重ねない）、中央の上寄りにエリア名・制圧・敗北・ボスの激昂を知らせる帯（`BannerBand`・`HudBanner`）を置く。sandboxでは、右上の下に敵の数・FPS・出現の状態を、操作の案内の上に試験用のキーを出す。画面の上端と下端には淡い暗がり（Themeの `HudEdge` の `shade`）を敷き、HUDの文字には暗い縁取りを付ける。HUDの補足の文字（エリア名、「残響」「総撃破」の見出し、キーの名前、段階の数字。Themeの `HudCaption`）は16pxとする。14pxでは、1280×720に縮めたときに約11pxになり、床の模様の上で読みにくかった。明るく模様の多い床でも、暗い床と同じように読めるようにするためである。
- 画面の外にいるボス・精鋭と、アリーナでウェーブの残りが5体以下になったときの敵には、その向きを指す小さな矢印を出す（`ActionHud.pointer_targets`・`pointer_spot`）。矢印は、HUDの上段と下段を避けた枠の上に置き、ボスと精鋭は赤、そのほかは本文の色にする。アリーナとボスの間は画面より広く、残った砲塔や巣を探して歩き回ることや、見えないボスの弾を避ける理由が分からないことをなくすためである。フィールドの群れには出さない（向こうから寄ってくるため）。
- HPが最大値の30%以下になると、画面周辺を赤く脈打たせる。残りが少ないほど濃く、速く脈打ち、回復すれば消える。色は共通Themeの `HpCaption` から取り、入力は妨げない。
- レベルアップの強化カードは横並びの3枚（永続強化で4枚）とし、取った瞬間を見せ場にする。報酬の強化と旅立ちの加護も同じカードで選ぶ。強化と永続強化の紋章は、それぞれ専用の絵（`art/emblems/<強化のID>.png`）を使う。
- 分岐マップは画面いっぱいの横にスクロールする地図にし、ランの状態は戦闘のHUDと同じ四隅に置く（[ゲーム仕様.md](ゲーム仕様.md) の8.1）。結果画面は、章の挿絵を暗くした上の画面中央に置く。
- 戦闘中のメニューは戦闘を止めた上に重ねる。
- 確認（`ChoicePrompt`）は、大作のアクションRPGで定番の、画面を横切る薄い帯の形とする（2026-11-13にユーザーのデザイン案から決定）。画面全体を暗くして軽くぼかし（暗幕のShaderが後ろの画面をぼかす）、後ろの操作を止める。画面の中央に、横幅いっぱいで高さを抑えた帯（`PromptBand`）を置き、その中に、あれば小さな見出し（分岐マップの「フィールド　★☆☆」など）、質問、結果の説明（1〜2行）、左に戻る・右に進むの2つの答えを中央に並べる。キーの案内は帯のすぐ下に置く。帯は、中央が暗い半透明で左右の端へ消えていく面と、上下の金の細線（中央が明るく、端で消える）だけで作り、上の線の中央に四つ角の星と短い光の筋、下の線の中央に小さな菱形を置く。枠で囲んだ窓にしないのは、尋ねている場面（戦場・地図・拠点）を上下に見せたまま、何を決めるのかに目を集めるためである。色はThemeの `PromptBand` が持つ。答え（`BandButton`）は細い縁の板で、選んでいる1つだけが、縁が金に、面が下から暖かく灯り、周りが淡く光る。選びを移すと、前の答えが消え、新しい答えが灯る変化が0.2秒で滑らかにつながる（`UIMotion.stand()`）。マウスを答えの上で動かすとその答えが選ばれ、キーとマウスで2つが同時に光らないようにする。帯が開いたときにカーソルがたまたま答えの上にあっても、動かすまでは選びを変えない。取り消せない操作（ゲームの終了、探索の中断）を確かめるときは、進む答えを赤い縁と赤い文字（`BandDangerButton`）にし、灯ったときも赤く光らせ、最初の選びを戻る答えに置く。開くときは、暗幕とぼかしが0.18〜0.26秒で深まり、帯の金線が中央から両端へ伸び、文字が少し遅れて浮かぶ。答えはその間も受け付ける。答えると、確認そのものはすぐ閉じて続く処理（メニューを開き直す、ゲームを再開するなど）に進み、見えていた帯と暗幕だけが0.16秒で薄れて消える（`ChoicePrompt._view`）。薄れている間の答えはFocusもクリックも受けず、続けて押したEnterやクリックは次の画面に届く。Enter・Aで決定、Esc・Bで戻る。探索の中断は、質問「探索を中断しますか？」、説明「この探索で得た残響は持ち帰れます。」「この探索中のレベルと強化は失われます。」、答え「探索を続ける」「探索を中断する」で、戦闘中と地図の上で同じ文（`DungeonMenu.ABANDON_*`）を使う。ゲームの終了は、質問「ゲームを終了しますか？」、答え「戻る」「ゲームを終了する」で、説明は保存の状態（拠点では保存済みであること、探索の途中では探索で得たものが残らないこと。`HubSettings.QUIT_BODY`・`QUIT_BODY_IN_RUN`）だけを書く。拠点・戦闘・分岐マップの確認はすべてこの部品を使う。

### 2.5 言語

画面の文字は日本語と英語で出します（`docs/公開準備.md` の5章）。文は日本語のまま、使う場所（Scriptの文字列と、`data/` の `.tres` の名前・説明などの項目）に書き、表示するときに `tr()` を通します。英訳は `rogue-like-play/locale/text.csv` の1つの表にまとめ、日本語の文そのものを鍵にします。代替の言語を日本語にしているので、日本語を選んでいるときや英訳のない行は、書いたままの日本語が出ます。鍵を記号（`HUB_QUIT` など）にしなかったのは、約800件の文をScriptと `.tres` から書き換えずに済み、日本語の文を直す人が表を見なくてよいからです。代わりに、日本語を直すと英訳が外れるため、表を作り直す手順（`tools/text_catalog.gd`）とテスト（`tests/test_translation.gd`）で、表にない文や、表に残った使われていない文を見つけます。テストは、英訳の空いた行と、英訳の数の差し込み（`%s`・`%d` など）が日本語と数や順番の違う行も失敗にします。GDScriptの `%` は値を並んだ順に差し込むため、英訳でも同じ順に書く必要があるからです。

- 言語は設定の「その他」タブの先頭で替えます（`GameSettings.language`、`settings.cfg` に保存）。選ぶまでは、パソコンの言語が日本語なら日本語、それ以外なら英語にします。言語の名前（「日本語」「English」）は、どの言語でもそれぞれの言葉のまま出します。
- 言語を替えると、`Main` が拠点（`Hub`）を作り直し、設定の言語の行を開いた状態で戻ります。拠点の画面は文字を作るときに一度だけ書くため、作り直すのがいちばん確実だからです。ウィンドウの題名は、日本語では「残響の迷宮」、英語では「Dungeon Remnant」にします（`project.godot` の `config/name_localized`）。
- 文はすべて `tr()` を通して書き、部品が自分で訳し直す自動翻訳（`auto_translate_mode`）は止めています（`Main._enter_tree`）。数を差し込む文は、訳してから数を差し込みます（`tr("踏破 %d回") % clears`）。キーの案内（`KeyGuide`）・タブ（`CategoryTabs`）・切り替えの値（`OptionCycler`）は、日本語を受け取って部品の中で訳します。
- 強化の系統（「連撃」など）のように、規則が日本語の文字列どうしを比べているものは、比べる値は日本語のまま残し、画面に出すときだけ訳します（`BoonData.families_text`）。アイコンの種類（`NavigationIcon.kind`）は英字のIDにしています。
- 1つの日本語が英語で別々の語になる場合は、文脈を付けて別の行にします。たとえば「強化」は、拠点の強化（Upgrade）とエリアの報酬の強化（Boon）で英語が違うため、報酬の側を `tr("強化", "reward")` と書きます。定数に書いた文は、その行の末尾に `# context: lobby` のように書いて文脈を付け、使う所で同じ文脈を渡します（`HubLobby.ACTIONS`）。
- 文として出さない日本語（`TextWrap` の改行の規則の文字、言語の名前）は、行の末尾に `# not translated` と書いて表から外します。
- 日本語の改行を整える `TextWrap` は、助詞や句読点の後で行を分けます。日本語を含まない文（英語）は、単語の途中で切らないよう、空白の位置でだけ行を分けます。
- 英文は日本語より長くなりやすいため、撮影用Scriptに `--language en` を付けて英語でも撮り、文字切れを確かめます。狭い所には短い訳を当て（章の説明はロビーの札に1行で収まる長さ、難易度の段階の説明は「残響 +30%」と1行に並ぶ長さ）、ロビーのキー案内の「決定」は、飾りの線の内側に収まるよう文脈 `lobby` で「OK」と訳します。設定の項目名の幅は、いちばん長い名前にそろえ、どの言語でも操作の列が1本の線から始まるようにします。

英訳は、次の訳語と書き方にそろえます（2026-11-11に決めた用語集）。名前（章・エリア・敵・強化など）の訳語は表の英語の欄そのものが正で、別の一覧は持ちません。

| 日本語 | 英語 | 日本語 | 英語 |
|---|---|---|---|
| 残響 | Echoes | 探索 | Run |
| 強化（レベルアップ、周回限定） | Boon | 強化（拠点、永続） | Upgrade（強化ツリーはUpgrade Tree、習得はLearn） |
| 難易度の段階 | Tier | 層 | Floor |
| 必殺技 | Special | 拠点 | Base |
| 出撃 | Set Out | 踏破 | Clear |
| 制圧 | Secure（制圧完了はArea Secured） | 中断 | Abandon |
| 図鑑 | Bestiary | 締めの一撃 | Finisher |
| 赤い印 | red warning | 床の帯 | lane |
| マス | tile | ミオ | Mio |

- 名前・ボタン・タブ・見出しは単語の頭を大文字にし（Title Case）、説明文は文の頭だけを大文字にします。ピリオドは日本語に「。」がある行にだけ付けます。
- 名前を囲む「」は英語では外します。項目と値の間の全角の空白は「:」か2つの空白に、項目を並べる「・」は「, 」に、キーの並び（X・RT）は「X / RT」にします。
- Godotの翻訳の表は、数によって単語の形（1 card・2 cards）を変えられません。数を差し込む文は「Clears: 3」のように、数で形が変わらない書き方にします。単位は、秒を「s」、マスを「tiles」と書きます。
- HP・Lv・FPS、キーとボタンの名前、スタッフロールの人名・団体名・作品名は訳しません。ミオの台詞は短く砕けた口調に、プロローグとエンディングは過去形の地の文にします。
