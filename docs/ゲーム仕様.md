# Dungeon Remnant ゲーム仕様

この文書は、Dungeon Remnantの現在のゲーム仕様です。ゲームは2026年10月に、ターン制のローグライクから、リアルタイムの見下ろしアクションに大量の敵との戦闘と周回ごとの育成を組み合わせたローグライトへ作り替えました。作り替えの経緯・計測結果・各Phaseの判断は [履歴/リアルタイム化_再設計計画.md](履歴/リアルタイム化_再設計計画.md) に、MVPの完成条件と判定は [履歴/MVP受け入れ確認.md](履歴/MVP受け入れ確認.md) に残しています。MVPと内容の区切り（M1〜M3）は終わり、今はストア公開に向けた品質向上の段階です。その進め方と課題は [公開準備.md](公開準備.md) にあります。拠点の画面とUI（共通Theme・個別画面のUI文法・言語など）の仕様は、UIを作る・直すときにだけ読む量が多いため、[画面とUI.md](画面とUI.md) に分けています。

---

## 1. ゲームの概要

プレイヤーは主人公ミオを操作し、拠点から章へ出撃します。章は分岐する層の連なりで、層ごとに2〜3個のエリアから1つを選んで戦い、最後の層でボスに挑みます。戦闘はリアルタイムで、移動・ダッシュ・コンボ攻撃・溜め攻撃・スキルを使い、時間とともに増える敵の群れを倒します。

ラン（1回の出撃）の中では、倒した敵の宝石で経験値を集めてレベルを上げ、レベルアップとエリアの報酬で「周回限定強化」を取って攻撃の挙動を変えていきます。強化はランが終わると消えます。ランで得た「残響」は勝っても負けても拠点へ持ち帰り、拠点で「永続強化」に使うと次のラン以降ずっと効きます。

1ランは約10分（フィールド約3分、アリーナ約2分を2回、ボス約2〜3分と、分岐と報酬の選択）を目安にしています。

## 2. 開発方針

**デザインの柱。** 仕組みやコンテンツを足す・変えるときは、次の3本のどれかに効くか、どれも損なわないかで採否を決める。柱は戦闘（秒）・ラン（約10分）・長期（時間単位）の3つのループに1本ずつ置いており、柱どうしがぶつかるときは番号の小さい柱を優先する（2026年10月に決定）。

1. **一振りの手応え**（戦闘）：入力するとすぐ攻撃が出て、当たったことが分かり、避けられたときはその理由が分かる。敵の数や派手さより、入力から攻撃が出るまでの速さ、命中の感触、回避の分かりやすさを優先する。
2. **強化で戦い方が変わる**（ラン）：ランの中で選んだ強化で攻撃の挙動が変わり、ランごとに違う戦い方になる。数値が上がるだけの強化や装備はこの柱に効かないため、足すなら戦い方が変わる形にする。
3. **残響は無駄にならない**（長期）：負けたランも必ず何かを持ち帰り、次のランは少し深くまで届く。初回エンディングまでのラン数（16章の「ゲームの終わりの目標」）は、持ち帰る量と永続強化の伸び方で調整する。

- 柱1を守るため、調整値はすべて `data/` の `.tres` に出し、操作確認で決める。
- ルールは `step(delta)` で進む `RefCounted` に置き、Headlessのテストで固定の `delta` と固定のシードで検証する。Nodeは物理移動と描画だけを受け持つ。
- Autoloadは使わない。共有処理は `class_name` を持つstaticなScriptで提供する。
- 当たり判定とダメージは攻撃データの時間（予備動作・攻撃判定・硬直）だけで決まり、アニメーションはそれに合わせて再生するだけにする。描画方式を替えても戦闘の結果は変わらない。
- ゲームに必要のない仕組み（汎用のスクリプト言語、ノードグラフ）は作らず、外部Addonは入れない。Steamの実績などはAddonが要るため、発売時は入れない（[公開準備.md](公開準備.md) の5章）。

## 3. 技術構成

| 項目 | 内容 |
|---|---|
| エンジン | Godot 4.7.2 stable、GDScript |
| レンダラー | Forward+（Windowsはd3d12）。撮影用Scriptは `gl_compatibility` でも動く |
| 画面 | 基準解像度1600×900（16:9）、Stretchは `canvas_items` |
| 物理 | 標準のGodot Physics 2D。主人公と敵は `CharacterBody2D`、攻撃の当たり判定は物理を使わず計算する（`HitQuery`） |
| 描画の補間 | 主人公・敵・飛ぶ弾の体は物理の刻み（毎秒60回）で動くが、絵は毎フレーム、直前の刻みの位置と今の位置の間に補間して描く（`TickSmoothing`）。カメラはこの絵の位置を追う。60Hzより速いモニター（240Hzでは4フレームに1回しか体が動かない）で、動きがカクついてぼやけて見えないようにするため。当たり判定は体の位置で測る |
| 入力 | `project.godot` の `[input]` にInputMapとして定義し、エディターのInputMap画面から変更できる |
| ワールドの単位 | 1マス48px。戦場の床と柱は48pxの格子に置くが、主人公と敵は格子に縛られず自由に動く |

## 4. 操作

| アクション | キーボードとマウス | ゲームパッド |
|---|---|---|
| 移動（`move_*`） | WASD・矢印キー | 左スティック・十字キー |
| 照準（`aim_*`） | マウスの位置 | 右スティック（倒していなければ移動方向） |
| 通常攻撃（`strike`） | 左クリック | X・RT |
| 溜め攻撃 | 左クリックの長押し | X・RTの長押し |
| 回避（`dash`） | Space | A・RB |
| スキル1（`skill_1`） | Q | Y |
| スキル2（`skill_2`） | E | B |
| 必殺技（`special`） | R | LB |
| メニュー（`pause`） | Esc | Start |

ゲームパッドの攻撃をRTにも割り当てているのは、Xだけだと照準の右スティックと同じ親指になり、狙いながら攻撃できないためです（右スティックを倒したまま、人差し指のRTで振れる）。今の照準の向きは、主人公の足元の小さな矢じりで示します（`Hero.aim`、`HeroView`）。マウスのカーソルは群れやエフェクトの中で見失いやすく、ゲームパッドにはカーソルがないためです。

スキル1とスキル2は、拠点のステータス画面で付けたスキルを出します。何も付けていない枠のキーは何もしません。必殺技は、付けた必殺技のゲージが満ちているときだけ出ます。拠点とメニューは `ui_accept`・`ui_cancel`・方向の標準アクションで操作し、ゲームパッドでは十字キーでFocusを移し、Aで決定、Bで戻ります。

入力には先行入力（攻撃の硬直中に押した次の攻撃やダッシュを0.18秒覚えておく仕組み）があります。溜め攻撃は、押した瞬間に1段目の攻撃が出て、押し続けると押した時点から数えて溜めが進み、溜め終わってから離すと溜め攻撃が出ます。押した瞬間の反応を遅らせないためです。

## 5. 主人公のアクション

主人公の調整値は `data/hero/mio.tres`（`HeroTuning`）、攻撃の組み合わせは `data/movesets/sword.tres`、各攻撃は `data/attacks/` にあります。`HeroMotor` が入力から移動・ダッシュ・攻撃の状態遷移を計算し、`Hero` が物理移動と攻撃の発生を行い、`HeroView` がリグの向きとアニメーションを合わせます。

- 移動は加速・減速付きのアナログ移動で、最高速度は250px/秒です。溜めている間は速度が0.35倍になります。
- ダッシュは0.17秒で150px進み、0.22秒の無敵があり、0.45秒で再び使えます。回数は1回で、永続強化の「二段ダッシュ」で2回、「三段ダッシュ」で3回になります。
- 武器は `data/movesets/` の `Moveset`（通常攻撃のコンボ・溜め攻撃・溜め時間・名前・説明・紋章・手に持つ絵）で、ステータス画面の攻撃の枠で持ち替えます。剣は初めから持ち、槍と大槌は強化ツリーの武器の枝で習得します。各段にキャンセルできる時刻があり、次の段やダッシュへつなげられます。周回限定強化は、どの武器の攻撃にも同じように効きます（「追い打ち」はどの武器でも2段目に効く。「衝撃波」「円月」「連撃の極み」は連撃の最後の段＝締めの一撃に効き、剣と槍では3段目、大槌では2段目になる）。

  | 武器 | 通常攻撃 | 溜め攻撃（溜め時間） |
  |---|---|---|
  | 剣（`sword`） | 前方120度・届く距離92pxの斬撃の3段（`sword_combo_1`〜`3`） | 周り半径124pxを攻撃力の2.6倍で斬る（0.75秒） |
  | 槍（`spear`） | 長さ150〜160pxの帯の突き2段と、前方160度・140pxの薙ぎ払い | 前へ170px踏み込み、長さ300pxの帯を攻撃力の2.6倍で貫く（0.7秒） |
  | 大槌（`hammer`） | 前方200度・118pxの振り下ろし（攻撃力の1.8倍）と、周り半径132pxの叩きつけ（2.4倍）の2段。振りが遅く（連撃1周が0.72秒。剣は0.54秒）、大きく吹き飛ばす。時間あたりの威力は剣より1割ほど低く、広さ・吹き飛ばし・硬い敵への通りで補う | 周り半径210pxを攻撃力の4.2倍で打つ（0.95秒） |
- スキルは `data/skills/` の `SkillData`（名前・説明・紋章・攻撃・再使用時間）で、ステータス画面で2つの枠に付けます。スキルは6つです。「叩きつけ」（`slam`、攻撃は `skill_ring`）は主人公の周り半径140pxを打つ範囲攻撃で、使うと6秒休みます（初めから持っている）。「雷閃」は前へ280px踏み込みながら長さ200pxの帯を斬り、感電させます（7秒）。「飛燕」は振り抜いた斬撃を、敵を貫く波にして480px飛ばします（5秒）。「烈火輪」は周り半径170pxを薙ぎ払い、燃やします（8秒）。「霊火の礫」（第3章で追加）は霊火の弾を前へ520px放ち、当たった敵を燃やします（6秒）。「雷陣」（第4章で追加）は周り半径180pxに雷を落とし、感電させます（7秒）。叩きつけ以外の5つは、強化ツリーのスキルの枝で習得します（`MetaProgress.owns_skill`）。2つの枠は、それぞれ別々に再使用を待ちます。新しく遊ぶ人は、スキル1に叩きつけを付けた状態で始まります。
- 必殺技は `data/specials/` の `SpecialData`（名前・説明・紋章・攻撃・必要なゲージ量）で、強化ツリーの必殺技の枝で覚え、ステータス画面の必殺技の枠に1つ付けます。ゲージは、自分の攻撃が当たるたびに0.4、敵を倒すたびに1.0、被弾で失ったHP1につき0.8溜まり（`HeroTuning.special_per_hit`・`special_per_kill`・`special_per_hurt`）、ランの中ではエリアをまたいで持ち越します（`RunState.special_charge`）。満ちたゲージでR（LB）を押すと、ダッシュ中を除くどの状態からでも割り込んで出ます（ダッシュ中に押した分はダッシュの終わりに出ます）。出している間は無敵で、ゲージは0に戻り、必殺技自身の攻撃ではゲージは溜まりません。必殺技は、攻撃の形や威力を変える周回限定強化（`AttackBoon`）の影響を受けません。攻撃力そのものを上げる「剛力」だけは、ほかの攻撃と同じく乗ります。
  - 「残響解放」（`echo_burst`、ゲージ200）は、主人公の周り半径280pxの敵すべてに攻撃力の14倍を与え、大きく吹き飛ばします。
  - 「天裂き」（`sky_rend`、ゲージ240）は、前方へ長さ560px・幅150pxの帯を攻撃力の18倍で断ち切り、感電させます。
  - 「紅蓮」（`crimson_lotus`、ゲージ200、第4章で追加）は、主人公の周り半径300pxを炎の渦で薙いで攻撃力の12倍を与え、燃やします。
  - ゲージと威力は、必殺技を「1エリアに1〜2回の決め技」にする値です。ゲージ100・威力6倍のころは、群れの中で約30秒ごとに溜まり、1回の威力は剣の連撃1周の2倍に満たず、世界を止める演出の重さと釣り合っていませんでした。
  - 出した瞬間、世界がほぼ止まり（`HitStop.hold` で0.04倍、0.8秒）、カットイン（`SpecialCutIn`）が入ります。同じエリアで2回目から後は、カットインを約0.34秒に縮めて流します（`SpecialCutIn.QUICK`）。画面の中央に黒い帯が開いて光の筋が流れ、左から主人公の顔（ロビーの立ち絵の上半分を切り出したもの）が、右から金の「必殺技」と技の名前が滑り込み、帯が閉じると技が出ます。当たった瞬間は、画面が大きく揺れて白く光り、重い音が鳴ります。
- 被弾すると0.8秒の無敵になります（永続強化の「立て直し」で1.0秒）。無敵の間は絵が明るく点滅します。大きく透かすと、群れに囲まれて逃げる向きを決める瞬間に主人公を見失うため、透けはわずかにとどめています（`HeroView.MERCY_ALPHA`・`MERCY_GLOW`）。最大HPは100で、永続強化の「鍛えた体」で増えます。

主人公の見た目は、カットアウトリグ（部位に分けたイラストを骨で動かす方式）で描きます。剣以外の武器を持つと、各向きのリグの剣の部品を隠し、同じ手の骨に武器の絵の四角形を付けます（`WeaponMount`）。四角形は、その向きの剣の絵の長い軸（不透明な画素の主軸）に沿って置き、手に近い端を握りとして、武器の絵の握り（`Moveset.art_grip`）をそこへ合わせ、長さは剣の `art_length` 倍にします。剣を振るどの動きでも、武器が同じように振られます。武器の絵は `art/characters/mio_rig/weapon_<ID>.png` です。動きは各向きのリグの記述（`art/characters/mio_rig/<向き>_rig.json`）に骨のキーフレームとして持ち、`tools/build_character_rig.gd` でSceneにします。

| 動き | 使う場面 |
| --- | --- |
| `attack_sword` | コンボの1段目 |
| `attack_back` | コンボの2段目（逆向きの薙ぎ） |
| `attack_heavy` | コンボの3段目と溜め攻撃（大きく振りかぶる） |
| `attack_slam` | スキル（武器を頭上から地面へ叩きつける） |
| `attack_thrust` | 槍の突き（腕を少し引いてから前へまっすぐ伸ばす）。各向きの `attack_sword` の振り上げと振り下ろしの値から作った |
| `brace` | 溜めている間の構え（繰り返す） |
| `dash` | ダッシュ（低く踏み込む） |
| `hurt` | 被弾（のけぞる） |

どの攻撃がどの動きを使うかは `AttackData.motion` で決め、リグにない動きは `attack_sword` で代用します。ダッシュ中は、その瞬間の姿勢を青く透けた残像として床に残し、0.26秒で消します。溜めている間は歩く動きを止めて構えたまま進みます。

## 6. 戦闘

`AttackData` が1回の攻撃を定義します（当たり形状は扇形・円・直線の帯、範囲、予備動作・攻撃判定・硬直の時間、キャンセルできる時刻、威力倍率、ノックバック、ヒットストップ、移動速度倍率）。`HitQuery` が攻撃の形と敵の位置から命中した敵を計算で求め、1回の攻撃で同じ敵に二度当たらないようにします。`Combatant` がHP・防御・無敵時間を持ち、`DamageInfo` を受けてダメージを確定します。防御はその点数を一撃から引きますが、引く量はその一撃の3割までです（`Combatant.GUARD_SHARE`）。点数をそのまま引くと、防御4の敵は軽い一撃を半分にして重い一撃をほとんど減らさず、連鎖や爆発や燃焼のような小さい攻撃を重ねるビルドだけが、硬い精鋭とボスに通らなくなるためです（柱2）。呪いで防御が0より小さくなったときは、その点数がすべての一撃に上限なしで足されます。ダメージは最低でも1です。主人公も敵も同じ仕組みで攻撃します。

命中の手応えとして、次の演出を出します。

- ヒットストップは `Engine.time_scale` を短く下げて戻します。同じフレームに命中が重なっても延長は1回に限り、大量戦闘中に動きが止まり続けないようにします。
- 敵の白い明滅、のけぞり（`hitstun`）、ノックバック、ダメージ数字、`StrikeEffect`（斬撃・衝撃・撃破の1枚絵を拡大・回転・明滅させる演出）を出します。
- ダメージ数字（`DamagePopups`）は、まだ出ているほかの数字と、上がっていく道筋も含めて重ならない場所に出します。同じ敵に続けて当たった「9」と「8」が「98」のような別の数に読めないようにするためです。まず当たった体の真上、ふさがっていればその左右、それもふさがっていれば一段上の順に試し（`DamagePopups.LANES`）、群れをまとめて打ってすべてふさがったときは、重なりの最も少ない場所に出します。精鋭の数字は、頭上のHPの帯より上から出します（`CombatArea.number_spot`）。
- 主人公のHPが強化の効果で戻ったときは、戻った量を緑の数字（「+3」）で頭上に出します。
- 画面の揺れは設定の「画面の揺れ」で強さを変えられます。
- 円形の攻撃（溜め攻撃・スキル）は、届く範囲まで床に光の輪が広がります（`GroundRing`）。ダッシュの踏み出しには土煙、レベルアップで強化を取った直後には主人公の周りに光の柱が立ちます。
- 撃破と命中のエフェクトは種類ごとに同時表示数の上限を設け、効果音も短い間隔の重複を1つにまとめます。

敵の攻撃は、予備動作の間に攻撃の形が床に赤く描かれ、内側から埋まっていきます（`Telegraph`）。見てから避けるための予兆です。形の縁は、赤い線の中央に淡い色の細線を通して描きます。赤茶の床（灰の荒野）では赤だけの縁が床に沈んだため、色ではなく明るさで輪郭が読めるようにしています。

状態異常は感電（4秒間、歩く速さが30%落ちる）と燃焼（3秒間、0.5秒ごとに、燃やした一撃のダメージの30%。より強い一撃で燃やし直すと、その一撃の分に上がる）の2つで、周回限定強化から付きます。

音楽は `GameMusic` が鳴らします。拠点・分岐マップでは拠点の曲、フィールドとアリーナでは戦闘の曲、守護者の間ではボスの曲を流し、場面が替わると1.2秒かけて曲を重ねて切り替えます（結果画面では曲を止め、勝敗のジングルだけを鳴らします）。レベルアップのカードと戦闘中のメニューが開いている間は、音楽バス（`Music`）のローパスフィルターで高い音を削り、5dB下げて、こもった音にします。曲はすべてCC0の録音で、`tools/build_music.py` が前後の無音を詰め、ラウドネスを-20 LUFSにそろえています。拠点の操作には、Focusが移る音（同じ瞬間の連続は1つにまとめる）、画面を開く音、戻る音、押せない操作の音があります（Kenney Interface Sounds）。

効果音は `GameAudio` が鳴らします。攻撃は効果の種類ごと（斬撃・衝撃・魔法）、命中・撃破・宝石の取得（短い間隔の重複は1つにまとめる）、ダッシュ、溜め完了、連鎖する雷、炎や旋風の爆発、レベルアップ、エリアの開始、ボスの登場、ボスの第2フェーズ、エリアの制圧、敗北に音があります。同時発音は12音までです。録音素材のない音はコードで合成した音で鳴らします。戦場では、生成した低い風の音（`BattleAmbience`）を環境音として繰り返し、設定の「環境音」の音量に従います。

## 8. ランの構成

### 8.1 章と分岐マップ

章は `ChapterData` で、`Chapters.ALL` の順に「第1章　灰の回廊」（`data/chapters/ash_corridor.tres`、3層とボス）、「第2章　風哭きの樹海」（`gale_woods.tres`、4層とボス）、「第3章　紫晶の霊廟」（`amethyst_mausoleum.tres`、4層とボス）、「第4章　残響の深淵」（`abyss_of_echoes.tres`、4層とボス。最終章）があります。後の章は、1つ前の章を1度踏破すると開きます（`ChapterData.unlocked_by`、`MetaProgress.chapter_open`）。`RouteMap` がランの開始時に分岐マップ全体を作ります。最初の層はフィールドだけの3個（`ChapterData.first_choices`）で、すべて選べます。以降の層には2〜3個の候補を並べます。同じ層に「同じエリアで同じ報酬」の候補は並びません。第2層からは、各層が60%（`ChapterData.event_chance`）の確率で、章のイベント（`ChapterData.events`、8.4）を1つ候補に加えます（層の候補がすでに3つなら最後の候補と入れ替えます）。各節点からは、次の層のうち隣り合う1〜2個へ道が延びます（`AreaData.branches`）。★3のアリーナ（聖堂の試練・番人の祠・封印の礼拝堂・門衛の試練）だけは、次の層を3個にしたうえで3個すべてへ道が延びます。ボスの手前の最後の層では、どの道もボスへ行くので開く道がありません。そこでは代わりに、制圧したときにそのエリアの残響の5割を上乗せします（`RunState.trial_echo`。札の「残響 +」の数に含まれる）。エリアを選ぶたびに先の道が絞られ、試練を越えたときだけ道が広がるため、どの候補を選ぶかで先の選択肢が変わります。道は上下の並びをそろえてつなぐため、交わりにくくなっています。次の層のどの節点にも少なくとも1本の道が届き、最後の層の節点はすべてボスへつながります。

分岐マップ（`RouteMapView`）は、ローグライトで定番のノードマップを、画面いっぱいの横に長い地図にしたものです。1枚の板に全部を収めず、横へスクロールさせて道のりを旅として見せます。地面は章の戦場の床（`AreaGround` のアトラス。第1章は青灰の遺跡、第2章は樹海、第3章は霊廟、第4章は深淵）を暗くして敷き、層を左から右へ600px間隔の列に並べ、最後の列にボスを置きます。地図の幅は層の数で伸びるため、章の層を増やしても地図のほうは直さなくてよい作りです。各エリア（`RouteNode`）は、章の地面でできた楕円の台座（`art/ui/route/plate_<章のID>.png`、幅190px。ボスは1.15倍）を少し上から見た形で示し、台座の上にそのエリアの敵を、主人公のいる左を向いて構えた姿（戦闘と同じリグの構えの動き）で立たせます。フィールドはいちばん多く出る敵を前に、2番目に多い敵を右奥に小さく立たせ、アリーナは最終ウェーブの先頭（精鋭）を、ボスの間はボスだけを立たせます。章の戦闘エリアはどれも同じ精鋭を含むため、フィールドにも精鋭を立てるとどの台座も同じに見えてしまうからです。イベントの台座には、敵の代わりにイベントの物（血の祭壇、呪いの石碑、行商人の荷車、記憶の書架、浄めの泉。`prop_<イベント>.png`）を置き、クリアした台座は空にします。台座の手前には、クリアで得る報酬の小さな札（強化は光る籠手、回復はハート、残響は金貨。ボスとイベントには付けない）を、その下に難易度（★3段階）を出します。エリア名・形式・目安時間・報酬・クリア条件・出現する敵の絵と傾向は、節点にマウスを合わせるか、キーやゲームパッドでFocusを当てたときに出る札（`QuietWindow`）に書きます。札は節点の左（通り過ぎた側）に出し、同じ層のほかの候補とこの先の道を隠さないようにします。左に入りきらないときは右に出します。先の層の節点も札を読めますが、進めず、札の下に「この先にある」「この道からは行けない」「通り過ぎた」のどれかを添えます。

道はすべて、章ごとの道の絵（`art/ui/route/road_<章のID>.png`。灰の敷石、根の張る土の道、紫水晶に縁取られた石畳、金の筋が光る黒い石。`tools/build_route_roads.py`）を `Line2D` で道筋に沿って繰り返して描きます。通ってきた道と今選べる道は太く、今選べる道には両側へぼける金の光を重ねます。その先の道は同じ絵を細く透かして描き、まだたどり着ける道は36%、選んだ道からもう届かない道と、通り過ぎた層で選ばなかった道は13%の濃さにして、交わる所でも今の道筋が読めるようにします（薄い道ほど下に描く）。道は濃さごとの層に分け、層の中ではまず全部の道を縁ごと描き、その上に全部の道の真ん中の帯（道の絵の中央64%を切り出し、切り口をぼかしたもの）を重ねます。こうすると、道が分かれる所や交わる所では路面が1枚につながり、縁は道の外側にだけ残ります。透かす層は `CanvasGroup` で1枚の絵にしてから透かすため、薄い道どうしが交わっても重なった所だけ濃くはなりません。金の光は、透かさない道の層の下にまとめて敷きます。道は始まりと終わりが水平になるゆるいS字です。

主人公は、戦闘と同じリグ（`mio_rig.tscn`、持っている武器も）を小さくして、最後に通った台座の上（最初は第1層の左の、道標（`prop_sign.png`）を立てた小さな出発の台座）に立たせ、選んでいる間は右前を向いて待機の動きをさせます。マップを開くと、今選べる道が主人公から0.45秒かけて伸びていきます。章の始まりだけは、先に右端のボスを0.6秒見せてから、1.3秒かけて主人公の所まで戻ります（キーやボタンを押すと飛ばせます）。それ以外は主人公を画面の左から28%の所に置き、マウスホイールかゲームパッドの右スティックで地図を左右に見渡せます。キーやゲームパッドで画面の外の節点にFocusを移すと、その節点と札が入る所まで地図が動きます。

エリアを選ぶと、まず確認の窓（`ChoicePrompt`）で「『苔むす平原』に進みますか？」と尋ね、形式と難易度、報酬とクリア条件を添えます。「進む」を選ぶと、主人公が道に沿って1秒歩いて選んだ節点へ向かい（進む向きを向いて歩きの動きをし、地図も付いていく）、着くと節点が脈打ってからエリアに入ります。「やめる」（Esc・B）でマップに戻ります。確認の窓が開いている間と主人公が歩いている間は、ほかの選択を受け付けません。ボスの台座は、1.8秒周期でゆっくり赤く光ります。ボスは、その層に着くまで台座ごと暗くした影として立たせ、札も名前を「？？？」、説明を「この章の最奥で、何かが待ち構えている」とだけ出し、報酬と敵の絵を伏せます。ボスの層を開いたときに一度だけ、地図がボスまで0.7秒で動き、ボスが0.9秒かけて影から姿を現し、同時に画面が赤く明滅して地図が揺れ、低い鐘の音とともにボスの二つ名と名前が浮かびます。1秒見せた後、名前が消えて地図が主人公の所へ戻ります（キーやボタンを押すと飛ばせます）。最後に通った台座から道が延びている台座（最初は第1層のすべて）だけが明るく選べます。この先たどり着ける台座はやや暗く、通り過ぎた台座と、選んだ道からはもう届かない台座はさらに暗くし、その上の敵は動きを止めます（通った台座は金の縁）。操作は、選べる節点のクリック、矢印キー（十字キー）で選んでEnter（A）、または1〜3キーです。ランの状態は戦闘のHUDと同じく四隅に置きます。左上に章の名前（難易度の段階で出撃したときは「段階3」のように段階も）と取得した強化の紋章、上中央に直前のエリアやイベントで得たもの、右上にLvと残響（呪いを受けていれば、その下に赤い文字で「呪い：脆さ・渇き」のように）、左下に戦闘と同じ枠のHP、下中央に操作の案内です。

### 8.3 報酬

エリアを制圧すると、報酬の種類にかかわらず、そのエリアの残響（8.2の表）の3割を必ず得ます（`RunState.CLEAR_ECHO_SHARE`、`RunState.clear_echo`）。報酬が強化と回復の節点だけを通って倒れても、持ち帰りが0にならないようにするためです（柱3）。そのうえで、節点ごとの報酬を受け取ります。報酬は「強化（3択から1つ）」「回復（最大HPの35%）」「残響（そのエリアの残響の残りの7割。制圧の分と合わせて、表の全額になる）」の3つで、エリアごとの重み（`AreaData.reward_weights`）で抽選し、分岐マップの札に先に示します（「報酬：強化　残響 +18」「報酬：残響 60」）。精鋭を倒すと、その場で少量の残響を得ます（`FoeData.echo_reward`。突進獣2、風の番人3、石門の番人4、深層の守護者5、結晶の大砲台4）。戦闘中にHUDの残響が動き、精鋭に向かっていく理由になります。フィールドは残響、アリーナは強化が出やすく、ボスの報酬は必ず残響です。取れる強化が残っていない場合、強化の報酬は残響に替わります。

### 8.4 イベント

イベントは戦闘のない立ち寄り先で、`data/areas/event_*.tres`（`AreaData` の形式「イベント」、`event` に中身の種類、`emblem` にイベントの窓の紋章）です。分岐マップのイベントの節点の札は「イベント　戦闘なし」と何ができるかを出し、選ぶと確認の窓が「『行商人』に立ち寄りますか？」と尋ねます。立ち寄ると、主人公はその節点に止まったままマップを暗くし、その上にイベントの窓（`EventView`）を開きます。窓には紋章と名前、どんな場所かの一文、所持する残響とHP（と受けている呪い）、選択肢の行を並べ、最後の行が「立ち去る」（Esc・B）です。選べない選択肢も行として出して無効にし、理由（「残響が30足りない」「購入済み」など）をその行の右端に赤い文字で書きます（マウスのTooltipでは、キーボードとゲームパッドで読めないため）。行の下には、ほかの窓と同じ操作の案内（選ぶ・決定・立ち去る）を置きます。どんな場所かの一文は控えめな色、できることと所持は本文の色で書き、払えるものがすぐ読めるようにします。強化を選ぶ選択肢は、いつもの強化カード（3択）を、代価を払う前に開きます。カードの見出しに払うものを書き（「行商人　残響 70 で強化を1つ選ぶ」）、Esc（B）の「やめる」で何も払わずにイベントの窓へ戻れます。代価（残響・HP・呪い・手放す強化）は、カードを取ったときに払います。同じ選択肢を開き直しても、出るカードは同じです（やめて開き直すことを引き直しにしないため）。払ってからカードを見せていたころは、望まない3枚でも払った分が戻らず、選びにくかったためです。立ち去るか、終わりのある選択肢を選び終えると、次の層へ進み、マップの上中央にイベントで起きたことを出します。進行は `RunDirector` が受け持ち、値は `RunDirector` と `RunState` の定数です。

| イベント | 選択肢 | 終わり方 |
|---|---|---|
| 行商人 | 「強化を1つ選ぶ」残響70、「傷の手当て（最大HPの50%回復）」残響40。どちらも1回まで | 立ち去るまでとどまる |
| 血の祭壇 | 最大HPの30%（切り上げ）を捧げて強化を1つ選ぶ。残りのHPがそれより多いときだけ選べる | 強化を選ぶと終わる |
| 呪いの石碑 | 石碑が示す呪い1つ（まだ受けていないものから抽選）を受けて強化を1つ選ぶ | 強化を選ぶと終わる |
| 記憶の書架（第3章から） | 持っている強化のうち4つまで（立ち寄ったときに抽選）を「『剣速 2』を手放して、強化を2つ選ぶ」の行で並べる。選ぶと、その強化を段階ごと手放して、手放した段階の数だけ代わりの強化を選ぶ（1つ目のカードは手放す前に見られる。段階の高い強化を出しても損にならないようにするため）。手放した強化はそのカードに出ない。強化を持っていなければ選べない | 強化を選び終えると終わる |
| 浄めの泉（第4章から） | 受けている呪いごとに「呪い「脆さ」を解く　残響 50」の行を並べ、選ぶと残響50を払ってその呪いを解く（呪いの害と、その呪いの分の残響の上乗せがなくなる）。もう1つの行は「泉の水を飲む（最大HPの35%回復）」で、HPが満ちていると選べない。呪いを受けていなければ「解く呪いがない」の行を無効で出す | どれかを選ぶと終わる |

呪いはランの終わりまで残り、1つ受けるごとに、以後のエリアの残響の報酬が元の量の50%ずつ増えます。呪いは「脆さ」（受けるダメージが2増える）、「鈍足」（移動速度が12%落ちる）、「渇き」（あらゆる回復が半分になる。回復の報酬、行商人の手当て、浄めの泉、強化や永続強化による戦闘中の回復のすべて。回復の報酬だけを半分にしていたころは、回復の節点を選ばなければ害がなかった）の3つで、同じ呪いは重ねて受けません。

### 8.5 ランの終わり

ボスを倒すと踏破、HPが0になると1.6秒後に敗北、戦闘中のメニューから「ランを中断する」を確認して選ぶと中断で、ランが終わります。結果画面（`RunEndView`）は、ランの戦績をまとめて見せる定番の形（Risk of Rain 2やVampire Survivorsの、記録と取ったものを1画面に並べる型）です。タブで隠さず、すべてを1枚の窓に並べます。上から、見出し（踏破・敗北・中断）と終わった場所の一文（難易度の段階で出撃したときは「第1章　灰の回廊（段階3）」のように段階も）、ランの旅路の帯、その下の2列、一番下の「拠点へ戻る」です。
  - 旅路の帯（`RunJourney`）は、分岐マップと同じ台座と章の道の絵を小さくして、出発点（道標の台座）から章のボスの層まで横1列に並べたものです。たどり着いた台座までの道は濃く、そこから先の道と台座は薄く描き、通り過ぎた台座は空にします。ランが終わった台座には、踏破なら主人公がボスの台座に、中断なら主人公が引き返した台座に立ち、敗北ならとどめを刺した敵が構えて立ちます（主人公に最後に届いた攻撃の主。遠距離の弾は撃った敵。攻撃の主が分からないときは、分岐マップでその台座に立つ敵）。その台座の下に「風の番人に倒された」「風狼王を倒した」「苔石の古道で引き返した」のように一文を添えます。
  - 左の列は、持ち帰った残響（大きな金の数字）と所持する残響の合計、その下に到達・戦った時間・撃破・レベルの4つのタイル（2×2）です。右の列は、このランで取った強化を、戦闘中のメニューと同じ丸い枠の紋章の格子（10列。全種類を取っても4段）で並べ、段階は紋章の右下の数字で示します。指した（Focusした）強化の名前・段階・効果を格子の下に出します（最初は先頭の強化。なければ「この探索で取得した強化はない」）。Focusは「拠点へ戻る」から始まり、上で格子へ、格子の最後の段から下でボタンへ戻ります。
  - 開くと、勝敗の印章（踏破は月桂樹と王冠、敗北は折れた剣、中断は石のアーチ）が、窓の右上の角に、大きく傾いた状態から0.22秒で落ちて押され、重い音とともに窓が小さく揺れます。それまでより深い層に着いたランは「最深到達を更新」、初めて踏破したランは「初めての踏破」を、見出しの下に金の文字で出します。最終章を初めて踏破したランは「難易度の段階が開いた」を、開いている最高の段階で最終章を踏破したランは「段階2が開いた」のように、同じ金の文字に続けて出します（8.6）。
  - 印章が押されると、持ち帰った残響を0から数え上げます（残響が多いほど長く、0.6〜1.6秒）。数える間は、上がるにつれて音程の上がる音を鳴らし、所持する残響の合計も一緒に数えます。数え終わると、数字が脈打って光り、金の粒が周りへ飛び散って、高い和音が鳴ります（この画面の見せ場）。残響と記録は、数え上げの前に確定し、保存しています。残響は踏破・敗北・中断のどれでも全額を持ち帰ります。結果は拠点へ戻る操作の前に保存し、保存できなかった場合は結果画面にその旨を出します。

戦闘中のメニュー（`DungeonMenu`）は、サバイバー系の一時停止画面で定番の形にし、1枚の窓の左に「この探索の強化」、右にメニュー（「戦いに戻る」「操作」「設定」「探索を中断する」）と、その下に探索の状態（章と層、難易度の段階、受けている呪いとその効果）を置きます。「操作」は、ヘルプの操作の話題をそのまま開きます（設定のその他のタブまで降りなくてよい）。同じメニューを分岐マップでもEsc（Start）で開けます（最初のボタンは「地図に戻る」になる）。エリアとエリアの間は、休む・設定を直す・強化や呪いの中身を確かめる・探索をやめるのにいちばん向く場面だからです。メニューが開いている間は、下のマップで何も選べません。開いているメニューは、Esc（B・Start）で1段ずつ戻ります。右の列は、見出し・ボタン・キーの案内をすべて列の中央にそろえ、揃えの基準線を1本にします。4つのボタンの文字は、いちばん長い「探索を中断する」の幅まで字間を広げて同じ幅に見せます（均等割り付け、`JustifiedButton`）。ただし字の間は1字ぶんまでしか広げず、2文字の「設定」のように短い言葉は、字が離れて1語に読めなくなるのを避けて、少し狭いまま中央に置きます。英語のように日本語を含まない言葉は、字間を広げると単語がばらけて読めないため広げず、そのまま中央に置きます。左の列も見出しと格子を列の中央にそろえ、強化の説明の文だけは長い文なので左にそろえます（強化がまだないときの1行の案内は中央）。開いている間は戦闘が止まります。ゲームのウィンドウがほかのウィンドウの後ろに回ったときと、遊んでいるゲームパッドが抜けたときは、このメニューが自動で開きます（カードの選択中と演出の最中は、すでに止まっているので何もしません）。取得した強化は、図鑑と同じ丸い枠（`EquipSocket`）に入れた紋章の6列の格子で並べ、段階はHUDと同じく紋章の右下の数字で示します。行の一覧では強化を10個ほど取ると画面からはみ出したため格子にしており、全32種類を取っても6段で窓に収まります。格子の下に、指した（Focusした）強化の名前・段階・効果を出し、メニューにFocusがある間も、説明を出している強化の枠に控えめな金の輪を残します。強化がまだないときは「レベルアップで選んだ強化が、ここに並ぶ」と出します。メニューから左キーで格子へ移り、格子の右端から右キーでメニューへ戻ります。

### 8.6 難易度の段階

最終章（`Chapters.ALL` の最後の章。今は第4章）を初めて踏破するとエンディング（初回クリア）となり、難易度の段階が開きます。段階は、Slay the SpireのアセンションやRisk of Rain 2のEclipseと同じ積み重ね式の8段階（`DifficultySteps`、各段階は `data/steps/` の `DifficultyStep`）で、選んだ段階までの制約がすべて効きます。段階0は段階のないゲームのままです。制約を自由に組み合わせる型（Hadesの罰の契約）にしなかったのは、選ぶための専用画面が要り、「最高の段階」という天井を定義しにくいためです。柱1（2章）を守るため、攻撃の予備動作を短くしたり、画面や情報を隠したりする制約は使いません。

| 段階 | 足す制約 | 中身 |
|---|---|---|
| 1 | 群れが2割増える | フィールドの敵の数の目標と出る速さ、アリーナの各ウェーブの敵の数が1.2倍（増える分はそのウェーブの敵から選ぶ） |
| 2 | 回復の報酬が25%減る | 回復の報酬で戻るHPが0.75倍（行商人の手当ては変わらない） |
| 3 | 精鋭が早く、多く出る | フィールドの精鋭が最初に出るまでと次に出るまでの時間が0.7倍、同時に出る上限が1体増える |
| 4 | 強化の候補が1枚減る | レベルアップ・報酬・旅立ちの加護・イベントの強化カードが1枚減る（永続強化で4枚なら3枚） |
| 5 | 敵のHPが25%増える（ボスも） | すべての敵のHPが1.25倍 |
| 6 | 呪いを1つ持って出撃する | 出撃するときに、呪い（8.4）からランダムに1つを受ける。呪いの分の残響の上乗せも付く |
| 7 | 群れに強敵版が混ざる | フィールドの群れの2割が、その章の強敵版（`ChapterData.kin`）になる |
| 8 | ボスが早く怒り狂い、手下を多く呼ぶ | ボスが怒り狂うHPの割合が0.2上がり（遺跡王と風狼王は50%から70%）、そのとき呼ぶ手下が1.5倍 |

- 強敵版は、群れの敵の色違い（`FoeData.tint` を赤みにしたもの）で、HPとぶつかる力か飛びかかりの威力が高い。第1章は「血錆の番兵」「血眼の疾走ネズミ」、第2章は「血錆の苔番兵」「血眼の疾風ネズミ」、第3章は「血錆の骨の兵」「紅の霊火」、第4章は「血錆の亡者」「血錆の鐘」で、図鑑にも載る。
- 解放：最終章を初めて踏破すると段階1が開く。その後は、開いている最高の段階で最終章を踏破すると、次の段階が開く（`MetaProgress.steps_open`）。選んだ段階は、どの章に出撃しても効く。やり込みの天井は、段階8で最終章を踏破すること。章を足して最終章が替わると、解放の条件も新しい最終章へ移る。
- ごほうび：持ち帰る残響が段階ごとに+10%増える（段階3なら+30%）。呪いの上乗せとは足し合わせる。
- 記録：章ごとに、踏破した最高の段階を残す（`MetaProgress.chapter_steps`）。開いている段階の数とエンディングを見たかどうかは、最終章の踏破数とこの記録から求め、別には保存しない。
- エンディング（`EndingView`）：最終章を初めて踏破したランだけ、結果画面で「拠点へ戻る」を押すと、拠点に着く前に流れる（`Main.ending_due`）。物語の結びは「解放」で、残響の主が倒れ、ダンジョンに縛られていた者たちの残響が眠りにつく。
  1. 静止画3枚（`art/hub/ending/ending_1.png`〜`ending_3.png`）を、下を暗くした絵の上に1〜2行の文を添えて見せる。絵が0.9秒で浮かび、文が0.6秒遅れて続き、両方が出てからEnter（A）かクリックで次へ進む。文は順に「残響の主が崩れると、深淵に溜まっていた声が、ひとつずつほどけていった。」（崩れる玉座と昇る金の光の粒）、「ダンジョンに縛られていた者たちの残響は、ようやく行き場を見つけて、静かに眠りについた。」（霊廟と樹海を抜けて昇っていく金の光）、「ミオは地上へ戻り、朝の光の中で、一度だけ振り返った。」（夜明けの遺跡の入口に立つミオの後ろ姿）。
  2. 3枚目の次はスタッフロールで、題名と制作、使っている第三者素材（音楽・効果音・書体）とGodot Engine（ロゴを含む）の作者とライセンスを、秒速70pxで下から上へ流し、最後に「遊んでくれて、ありがとう。」を3.5秒出す。ライセンスの全文は `THIRD_PARTY_NOTICES.md` にあると添える。
  3. 拠点のロビーへ戻り、幕に「難易度の段階が開いた。出撃の画面で選べる。」と出す。ロビーの主人公の台詞は、エンディング後の組（[画面とUI.md](画面とUI.md) の1章）になる。
  - Esc（B）を押し続けると右下の輪が1秒で満ち、満ちるとその場で飛ばして拠点へ戻る。離すと輪は空に戻る。誤って押しても飛ばないようにするための、多くのゲームで定番の形である。
  - 見たかどうかは別に保存せず、最終章の踏破数から求める（`MetaProgress.ending_seen`）。そのため、2回目からの踏破では流れない。

### 8.7 導入（前置きと最初の探索の案内）

初めて遊ぶ人には、物語の前置きと操作の案内を、最初の探索のときにだけ見せます（2026年11月に決定。経緯は [公開準備.md](公開準備.md) の5章）。アクションローグライトで定番の「前置きは短く、操作は最初の探索の中で覚えさせる」形です。起動するとすぐロビーに着くことは変えません。

- **前置き**：挑んだ探索がまだ1つもない人（`MetaProgress.runs` が0）が出撃すると、分岐マップへ入る前に、静止画3枚と文を見せます（`Main.prologue_due`）。エンディングと同じ演出（`EndingView`。絵が浮かび、文が続き、Enter（A）かクリックで次へ、Esc（B）の長押しで飛ばす）を、スタッフロールなしで使います（`EndingView.PROLOGUE`、`rolls` を切る）。3枚目の次で、そのまま出撃します。見たかどうかは保存せず、探索の記録から求めます。最初の探索を終える前にゲームを閉じると、次の出撃でもう一度流れます。
  1. 「このダンジョンで果てた者は、声だけを残す。残響と呼ばれるその声は、いまも深みへ流れ続けている。」（灰の回廊の階段に残された剣と盾から、金の光の粒が深みへ流れていく）
  2. 「ミオには、その声が聞こえた。呼ばれるままに、灰に沈んだ回廊の入口に立つ。」（夕暮れの遺跡の入口に立つミオの後ろ姿。エンディングの3枚目と同じ入口で、あちらは夜明け）
  3. 「倒れても、拾った残響は手に残る。それを灯に変えて、もう一度、もう少し深くへ。」（拠点の広間の祭壇に置かれた、残響の灯）
  - 3行で、残響が何か、なぜ潜るのか、倒れても次につながること（柱3）を伝えます。絵は `art/hub/prologue/prologue_1.png`〜`prologue_3.png` です。
- **操作の案内**：その最初の探索の最初のエリアでだけ、操作を1つずつ教えます（`RunState.guided`、`FirstLessons`）。画面下の操作の案内のすぐ上に、キー（金色）と動作を1行で出し、その操作をすると0.6秒おいて次へ進みます。順番は、移動（0.8秒歩く）→ 攻撃（3回振る）→ ダッシュ → 溜め攻撃 → スキル（スキル1の枠が空なら飛ばす）です。1行は、すぐ済ませても1.2秒は出します。エリアを制圧すると、途中でも終わりです。2つ目のエリアからと、2回目の探索からは出ません。操作は、戦闘中のメニューの「操作」でいつでも見返せます。
  - ルールは `FirstLessons`（`step(delta)` で進む `RefCounted`）に置き、`BattleArea` が主人公の行動を伝え、`ActionHud.show_lesson` が表示します。表示は、ほかの画面と同じキーの案内（`KeyGuide`）を一段大きくしたもの（Themeの `LessonHint`）で、キーボードとゲームパッドで表記が切り替わります。

## 9. 周回限定強化

### 9.1 経験値とレベル

経験値は敵の宝石から得ます。必要経験値は `data/progression/action_levels.tres`（Lv2まで8、以後6ずつ増える）です。宝石は1つのノードでまとめて描き、300個を超えると近くの宝石に合算します。

レベルが上がると、まず0.32秒（実時間）だけ世界が0.15倍の速さに落ち、主人公の足元から金の光の輪が広がって画面が少し揺れます（`BattleArea` の導入。`HitStop.hold` で減速し、この間に命中したヒットストップは減速を深めも縮めもしません）。そのあと戦闘が止まり、強化のカードを3枚（永続強化の「四枚目の札」で4枚）出します（`AbilityChoice`・`AbilityCard`）。カードには強化の紋章、名前、新しく得る強化では「新規」（指すかFocusすると系統）と効果の説明、ランクを上げる強化では「Lv a → b」と、上げると増える数値（「威力 80% → 110%」「3体 → 4体」「飛距離 7.1 → 9.2マス」。2行まで。`BoonData.gain_text`）を出します。段階を上げるカードが1段階目と同じ文のままだと、何が増えるのか分からなかったためです。数値は強化の定義から作るので、定義を変えれば文も変わります。カードは窓に入れず、暗くした戦場の上に、見出し・カード・操作ガイドと、その下に主人公のHPと取得した強化の紋章（段階つき）を浮かべます。HPと強化は、回復を取るか攻撃を伸ばすかを決める材料ですが、戦闘のHUDは暗幕の下で読めなくなるため、カードの側に出します。カードゲームの報酬の画面で定番の形で、窓の枠をなくすと、配る動きとカードそのものに目が向くためです。窓がない分、カードは1枚ずつ、窓と同じ暗い石の板（細い縁と淡い影。Themeの `AbilityCard` の `plate`）の上に共通のカードの面を重ねて描きます。カードの高さ（300px）は、紋章・名前・段階・2行の説明が収まる分にしています。カードは、カードゲームで手札を配るように出します。画面が暗くなり（0.16秒）、カードが1枚ずつ0.09秒おきに下から定位置へ上がってきます（1枚0.24秒）。最後のカードが着くまでは暗いままで、クリック・数字キー・決定のどれでもカードを取れません。着くとカードが明るく光り、カードの下の操作ガイドが現れ、最初のカードにFocusが付きます（カードが取れる状態になる）。このときマウスの左ボタンを押したままなら、一度離すまでマウスでは選べません。攻撃の連打でレベルが上がったときに、見る前のカードを取ってしまわないようにするためです。攻撃・ダッシュ・スキル・必殺技のキーとボタンは、カードの決定（Space・A）と引き直し（R・Y）を兼ねるため、これらをすべて離して0.3秒経つまでは、決定にも引き直しにもなりません（`AbilityChoice` の `REST`。配っている間に手を止めていれば、取れる状態になった瞬間から効きます）。数字キー・Enter・方向の操作は、取れる状態になればすぐ効きます。配る時間はカードのアニメーションと同じ時計で数えるので、処理が重くてアニメーションが遅れた場合も、カードが見える前に取れる状態になることはありません。エリアの報酬と旅立ちの加護のカードも同じように配り、引き直しで出た新しいカードも同じように配り直します。永続強化の「引き直し」を持っていると、カードの下の操作ガイドに「R 引き直す（残りn）」（ゲームパッドはY）が出て、1ランに決まった回数まで、出ているカードを引き直せます。エリアの報酬と旅立ちの加護のカードは3枚のままで、引き直せません。

### 9.2 強化の一覧

強化は `data/boons/` の `BoonData` で、効果は次の3種類の組み合わせです。

1. `StatBoon` は、攻撃速度（`attack_speed`）・溜め時間（`charge_time`）・攻撃力（`damage`）・移動速度（`move_speed`）・スキルの再使用時間（`skill_cooldown`）の数値に段階ごとの加算をする。
2. `AttackBoon` は、条件（コンボの何段目か（`combo_step` が−1なら、持っている武器の連撃の最後の段）、ダッシュ直後か、溜め攻撃か、スキルか）に合う攻撃の写しを、攻撃の開始時に変える（状態異常・範囲・開き・威力（段階ごとの上乗せあり）・飛ぶ波）。元の攻撃データは変わらない。
3. `TriggerBoon` は、`CombatEvents` のイベント（命中・撃破・回避の始めと終わり・スキル使用・スキルの命中（スキルを使ってから1秒以内に最初に当たった一撃。使うたびに1度）・被弾）に、範囲爆発・連鎖する雷・HPの回復で応える。連鎖が止まらなくならないよう、1物理フレームに発動できる回数を24回までにしている。

## 10. 永続育成

### 10.1 残響と永続強化

残響はランで得る通貨で、拠点の「強化」で永続強化に使います。永続強化は `data/meta/` の `MetaUpgrade` で、中央の「残響の灯」（`MetaProgress.ROOT`）から枝分かれする強化ツリーの節です。各節は、それが伸びている元の節（`parent`）が段階1以上になると買えます。元の節を最後の段階まで上げる必要はありません。主人公の数値に効く節は、ランの開始時に主人公の数値の写しへ当てます（`MetaProgress.tuning`、元のデータは変えません）。ランの決まりごとに効く節は、`MetaProgress.lasting()` の値を `RunState.lasting` に写し、ランの中で読みます。

左の「身体」の枝はステータスを、右の「成長」の枝はレベルアップを強くします。上の「スキル」の枝ではスキルを覚え（`skill_unlock` の節は `grants` のスキルを習得させる）、スキルの再使用時間を縮めます。下の「必殺技」の枝では必殺技を覚え（`special_unlock` の節は `grants` の必殺技を習得させる。最初に覚えた必殺技は、空いている必殺技の枠にそのまま付く）、ゲージの溜まりと威力を上げます。右上の「武器」の枝では武器を覚えます（`weapon_unlock` の節は `grants` の武器を習得させる）。価格の単位は残響です。

### 10.2 記録

`MetaProgress` は、残響、永続強化の段階、スキルの枠に付けたスキル（`loadout`）、必殺技の枠に付けた必殺技（`special`）、攻撃の枠の武器（`weapon`）、挑んだラン数、踏破数、最深到達の層、章ごとに踏破した最高の難易度の段階、出会った敵を持ちます。ランの開始時に、付けたスキルを `RunState.skills` に、付けた必殺技を `RunState.special` に、武器を `RunState.moveset` に写し、戦場で主人公の枠に付けます。ランの結果は `MetaProgress.record_run` で受け取ります。敵は、ランでその敵が戦場に現れた時点で「出会った」と記録され、図鑑に載ります。

## 12. セーブ

保存先は `user://progress.json`（`MetaStore`、形式は `MetaCodec` のversion 5）で、残響・永続強化の段階・スキルの枠・必殺技の枠・攻撃の枠の武器・挑んだラン数・踏破数・最深到達の層・章ごとの踏破数と最深到達の層と踏破した最高の難易度の段階（`chapters`）・出会った敵を保存します。章ごとの記録がなかったころのセーブは、踏破数と最深到達の層を第1章のものとして読みます。知らない章の記録があるセーブは、壊れたものとして扱います。難易度の段階がなかったころのセーブは、どの章も段階なしで踏破したものとして読みます。踏破していない章に段階があるセーブと、最後の段階より上の段階があるセーブは、壊れたものとして扱います。スキルの枠がなかったころのセーブは、新しく遊ぶ人と同じ枠（スキル1に叩きつけ）として、必殺技の枠がなかったころのセーブは必殺技の枠が空いているものとして、攻撃の枠がなかったころのセーブは剣を持つものとして読みます。覚えていない必殺技や武器が枠にあるセーブは、壊れたものとして扱います。強化ツリーの中央の節がなかったころのversion 5のセーブで何かを習得していれば、読み込むときに中央の節を習得済みにして、持っている節を前提ごと活かします。端末ごとの設定（音量・画面モード・揺れ・操作の案内）は `GameSettings` が別のファイル（`user://settings.cfg`）に保存します。

`user://` は、Windowsでは `%APPDATA%\DungeonRemnant` です（`project.godot` の専用の保存先の設定）。開発中の版はGodotの既定の場所 `%APPDATA%\Godot\app_userdata\RogueLike_play` に保存していたため、起動時に新しい保存先にセーブ（`progress.json` か `.bak`）がなく、旧い保存先にあるときだけ、`SaveFolderMove` がセーブ・その控え・`progress.json.v4`・設定を一度だけコピーします。セーブを先にコピーし、各ファイルは一時的な名前で書いてから名前を付け替えるので、途中で止まっても、書きかけのファイルがセーブとして読まれることはありません。旧いファイルは消しません。

保存するのは拠点での購入、出撃の直前、ランの終了時だけで、ランの途中の状態は保存しません。保存は一時ファイルへ書いて読み戻して検証し、前の内容をバックアップしてから置き換えます。読めないデータは退避して保存を止め、拠点にその旨を示します。

旧形式（version 1〜4、ターン制のゲーム）のデータを読んだ場合は、最初の保存の前に旧ファイルを `progress.json.v4` として残し、所持Goldと旧永続強化に使ったGoldの合計を、4 Goldあたり残響1の割合で換算して引き継ぎます。出会った魔物は、同じ絵の敵がいるもの（番兵・疾走ネズミ・突進獣・遺跡王）だけ引き継ぎます。アイテム・装備・到達階・途中開始の解放は、新しいゲームに対応する概念がないため引き継ぎません。

## 16. コンテンツの量と制作の順番

MVPの仕様は実装済みで、受け入れ可能と判定している（[履歴/MVP受け入れ確認.md](履歴/MVP受け入れ確認.md)）。これ以降の追加はMVP後の追加として扱い、MVPの完成判定を変えない。MVPの後に足した仕組みとコンテンツの仕様も、上の各節にある。

これからの追加は、次の「ゲームの終わりの目標」と「コンテンツの表」に沿って進める。表にないものを足したくなったときは、先に2章のデザインの柱に照らして表を見直す。難しさを上げるときは、既存の敵の色違い（`FoeData.tint`）の強敵版を出す。

### ゲームの終わりの目標

追加が際限なく続かないように、ゲームの終わりを2段に分けて先に決めた（2026年10月）。時間とラン数は、初めて遊ぶ人を想定した目標値で、遊んで測りながら調整する。

- 1段目（初回エンディング）：章は全4章とし、第4章のボスを初めて倒したランの後にエンディングを見せる。初めて遊ぶ人が約5時間、1ラン約10分で約30ランで届く長さを目標にする。1章あたり平均7〜8ラン（序盤の章は少なく、終盤の章は多く）を目安に、難しさと永続強化の伸び方を調整する。
- 2段目（やり込みの天井）：エンディングの後に難易度の段階を解放し、段階ごとに敵の強化や制約を1つずつ足す。天井は「最高の段階で第4章を踏破する」とし、エンディングの後さらに約5時間（合計約10時間）で届く段階数にする。
- 決めた理由：1ランが約10分なので、目標の時間をラン数に換算して章の数を逆算した。章を1つ足すには地面の絵・敵・ボスのリグが要り、増える遊びは足し算にとどまる。そのため章は4つで止め、長く遊ぶ部分は今ある章を使い回せる難易度の段階に任せる。初回エンディングまでのラン数は章の数だけでなく難しさと永続強化の伸び方でも変わるので、セーブの `runs` と章ごとの踏破数で測り、目標とずれたときは章を足すのではなく、難しさと永続強化の配分を直す。

### 制作の順番

| 区切り | 中身 | 終わったと言える条件 |
