# Godot 2Dローグライク MVP開発仕様 Ver.0.1

## 1. プロジェクト概要

Godotを使用して、2D見下ろし型・ターン制のローグライク／ローグライトゲームを制作する。

「不思議のダンジョン」系の探索・レベルリセット・ランダム生成をベースにしつつ、

- 武器ごとに異なる攻撃範囲
- 8方向を利用した位置取り
- 障害物・地形を利用した戦闘
- Fog of War
- 敵ごとに異なる索敵特性
- レベルアップ時の3択能力
- 拠点による微小な永久成長

を特徴とする。

MVPでは「1回の冒険を開始し、ダンジョンを探索・戦闘・成長し、死亡またはクリアして拠点へ戻る」というゲームループの完成を最優先とする。

---

# 2. 開発方針

## 最重要方針

MVPでは必要最小限の機能のみ実装する。

将来の拡張を妨げない構造にはするが、将来機能を先回りして実装しない。

以下は禁止する。

- 要求されていない機能の追加
- 過剰な抽象化
- 不必要なデザインパターン導入
- MVPで使わないシステムの実装
- Hardモードの先行実装
- オンライン機能
- マルチプレイ
- 実績システム
- 課金システム
- 複雑なクラフトシステム
- 高度すぎる敵AI
- 大規模なストーリーシステム

実装前には必ずPlanを提示し、変更対象・新規ファイル・実装内容を説明すること。

ユーザーの承認なしに仕様を拡張しないこと。

# 4. ターンシステム

基本ルール：

1. プレイヤーが行動
2. プレイヤーの行動が確定
3. 1ターン経過
4. 敵が行動
5. プレイヤー操作へ戻る

ターンを消費する行動：

- 移動
- 攻撃
- アイテム使用
- その他、ゲーム世界へ直接作用する行動

ターンを消費しない操作：

- インベントリ確認
- ステータス確認
- マップ確認
- 攻撃方向選択
- 攻撃範囲確認
- 攻撃キャンセル
- Main / Sub武器切り替え
- 武器・防具・アクセサリーの装備変更

安全な探索済み区間では、移動キーを押し続けると通常入力の後に連続移動する。連続移動の各1マスは通常の移動と同じく1ターンを消費し、敵も1マスごとに行動する。敵を視界内に発見、未探索マスの直前、アイテムまたは階段の発見、分岐への到達、既知のアイテムまたは階段の直前、移動入力の解除、UI表示、攻撃モードへの移行のいずれかで停止する。停止後は新しい移動入力が必要となる。

連続移動は同じ方向への入力反復だけを行い、自動探索・経路探索・分岐選択は行わない。

「攻撃ボタン + 8方向指定」方式とする。

1. 攻撃ボタン
2. 攻撃モードへ移行
3. 8方向から攻撃方向を指定

# 7. 武器システム

武器ごとに攻撃範囲そのものが異なることを本ゲームの主要な特徴とする。

## 想定武器

### 剣

- 射程：1
- 指定方向と左右隣の計3方向を同時攻撃
- 隣接した複数敵への対応

### 槍

- 射程：2
- 直線攻撃
- 間合い管理に優れる

### 斧

- 短射程
- 高威力
- 前方複数マスへの攻撃候補

### 大剣

- 前方横方向への広範囲攻撃
- 複数敵への対応

### 短剣

- 射程：1
- 低威力
- 将来的に連続攻撃・背面攻撃などを追加可能

### ハンマー

- 射程：1
- 生存した敵を最大2マスノックバック
- 途中に壁・敵・マップ外・斜めの角があれば、移動可能な距離まで押す

### 斧

前方2マスの固定範囲を攻撃し、剣より高火力にする。槍のレベル上昇による射程拡張は適用しない。

### 弓

- 遠距離直線攻撃
- 射程4～6程度を想定
- 将来的に弾薬システム対応可能

### 杖

杖ごとに1枚の魔導スクロールを装着し、MPを消費して魔法を使う。未装着時は剣型の低威力近接攻撃。初期魔法は直線攻撃・範囲攻撃・回復の3種類。

スクロールは購入・敵のレアドロップで入手する。装着中は装備の一部として保護し、未装着なら通常の所持品としてロスト対象にする。操作と数値は[開発メモ](../rogue-like-play/開発メモ.md)の「杖と魔法」を参照。

# 9. 防具・アクセサリー

装備枠：

- Armor ×1
- Accessory ×2

装備中アイテムは死亡時ロスト対象外とする。

## 防具の役割

基本的には、

- 防御力
- 属性耐性
- 軽度の特殊効果

を担当する。

## アクセサリーの役割

コンテンツ追加では、購入・敵ドロップで得る消費型アクセサリー（護符）を追加する。通常の床配置には含めない。既存の装備型は互換性のため保持する。

同じ効果の再使用は不可。ターン継続バフは異なる5種類まで、フロア継続効果は枠外。使用不可時は消費せず、帰還時は全効果を終了する。ダンジョンでは、発動中の効果を階層・Goldパネルの下の「効果中」パネル（`HudEffects`）に1件1行で示し、記号・名前・残りターン（フロア継続は「この階」）を並べる。残り5ターン以下は赤で示し、効果がない時はパネルを隠す。冒険終了時は、止めの一撃を見せ終えるまで最後の一覧を残す。具体的な種類・数値と追加敵の挙動は[開発メモ](../rogue-like-play/開発メモ.md)の「追加の敵と消費型アクセサリー」を参照。

# 17. ダンジョン

ランダム生成されたフロアを探索する。

現在のコンテンツ構成：古代遺跡と深緑の森林を各50階とする。10・20・30・40Fに中ボス、50Fに最終ボスを配置する。ボス撃破まで階段は使用できない。遺跡の最終ボス撃破で森林を開放し、その先は「？？？」として表示する。

## 地形の表示仕様

テストプレイ時の視認性と雰囲気を整えるため、フロア地形は暗い青灰色の石造ドット絵で表示する。

- 1 Tileは32×32pxとし、16×16px相当のドット絵をNearestで2倍表示する
- 床には少数の模様差分を用意し、座標に基づいて固定選択する
- 壁は上下左右の接続状態を16通りのタイルへ対応させ、連続した輪郭として表示する
- 階段は暖色の金色、Pillarは床と区別できる石柱として表示する
- Fog of Warの現在視界・探索済み表示は既存の明暗差を維持する
- 1～3Fは青灰の遺跡、4～6Fは苔むした洞窟、7～9Fは灼熱の深層、10F以降は黒曜の聖域として配色を切り替える
- 各テーマは同じタイル形状を共有し、地形ルールや当たり判定を変更しない

森林では苔色の床と木々の装飾を使用する。当たり判定と視界のルールは遺跡と共通。

# 19. 特殊フロアと将来的なマップタイプ

モンスターハウスは通常フロアで暫定5%の確率で生成する。7×7の部屋に敵8体・アイテム8枠を追加し、床の色と発見ログで危険を伝える。床はマスごとの枠線で囲まず、暖色の薄い染み、一部のマスの爪痕、部屋の外周だけに引いた燻った色の線で「荒らされた部屋」として見せる。ボス階では生成しない。ショップ・ドロップ限定品は床配置に含めない。

入室や通路を封鎖しないため、配置次第では回避・撤退できる。開始地点がモンスターハウス内になるケースも意図した不意打ちとして許容する。

以下は将来の追加候補。

- Maze
- Island
- Bridge
- Trap Floor
- Treasure Floor
- 特殊環境フロア

# 25. MVP Enemy Detection

MVPでは複雑にしない。

最低限：

- Vision型
- Proximity型
- Fixed/Turret型

程度から開始する。

HearingやShared AlertはMVP対象外。

通常敵は遺跡で各階3体、森林で4体を基本とし、Vision・Proximity・Turret・高速型・召喚型を巡回配置する。10階ごとに別途ボス1体を追加する。深度ごとに通常敵を強化し、森林は遺跡より補正を1段階高くする。

Turretは1敵ターン予告した後、同じ位置・方向から射線が通る場合に射撃する。予告中は長い白線を表示する。射線から外れる、射程外へ出る、遮蔽物が入ると予告を解除する。射撃後およびノックバック後は再予告が必要。装備・UIなどの無料操作では予告は進まない。

# 31. Permanent Upgrade

拠点のスキルツリーで、基礎HPから生命力・攻撃力・防御力・魔力量の永久強化へ分岐する。段階と前提条件・価格はResourceで調整する。

ステータス強化とは別に「ダンジョン途中解放」の枠を設ける。各ダンジョンの10・20・30・40F中ボス撃破後、コインで対応する11・21・31・41F開始を解放する。価格は暫定150・350・600・900 Gold。条件と解放はダンジョン別に保持する。

途中開始はLv1で、永久強化と持ち込み装備を適用する。深層は永久強化を前提とする一方、1Fから時間をかけて育成する攻略も可能とする。

# 34. Item Loss

Inventory内のロスト対象の所持枠から、半数（奇数は切り上げ）をランダムに選択して消失させる。選択された枠はスタック全体を失う。

例：回復薬×10、爆弾×6、毒消し×2の3枠なら、ランダムな2枠を全個数失う。

装備中アイテムは抽選対象外。死亡・中断・滞在上限による強制帰還に共通して適用する。Goldは半額を失い、損失の端数は切り捨てる。

# 36. Safe Return

最終階以外の10Fごとの中ボス撃破後、フロア入口に脱出口を出す。脱出口に乗り確認で「帰還する」を選ぶと、Gold・Inventory・Equipmentを保持して帰還する。消費アイテムは不要。

各フロアの滞在上限は暫定5000ターンで、次階への移動でリセットする。ボス階にも適用し、中ボス撃破では一度だけ150ターン延長する。残り30%・20%・10%・100ターンでイベントログに警告を出す。上限で強制帰還し、通常の損失を適用する。

階段では確認後に次階へ移動する。確認は共通Themeの `ChoicePrompt` で画面下寄りに出し、主人公と周囲を隠さない。「降りる」「とどまる（Esc）」を選び、Escとゲームパッドのキャンセルでも留まる。確認・キャンセルやメニュー閲覧でターンは進まない。同一マス上で確認を繰り返さず、再進入時に表示する。上限と重なる場合の優先順は階段移動、ボス撃破、脱出、強制帰還。死亡時は移動・脱出できない。

# 40. 設計上の注意

Godotの責務を適切に分離する。

候補：

TurnManager
RunManager
DungeonManager
Player
Enemy

AbilitySystem
FogOfWar

ただしMVP段階で必要のないManagerを大量に作らない。

巨大なGameManager一つにすべてを詰め込むことも避ける。

UIは `res://ui/theme/dungeon_theme.tres` をプロジェクト共通Themeとして使用する。暗色の面・明るい本文・控えめな金色を基調とし、通常面は低彩度の細い輪郭、選択と主要操作は金色の輪郭を使い、面の明度・余白・控えめな影で階層を示す。金色は、どこにでも使うと特別に見えなくなるため、次の2つの意味に限る。1つは「今選んでいるもの・押すべき操作」（選択枠・Focus・主要ボタン・有効な装備枠）、もう1つは「お金と手に入れた価値」（Gold残高・価格・収支、獲得済みの段階の目盛り、勝利の見出し）である。アイテムの効果、能力値、ステージの階数と難易度、移動の方向、キャラクターの台詞は情報として明るい本文色（`BodyLabel`・`ValueLabel`・`ItemNameLabel`）で示し、上昇は緑（`StatUp`・`PositiveLabel`）、下降と損失は赤（`StatDown`・`LossValueLabel`）で示す。冒険結果の数値のうち、今回獲得と残高だけが金（`MoneyValueLabel`、`GoldLabel` から色を受け継ぐ）となる。規則の常設案内は控えめな色（`MutedLabel`）とし、操作の結果だけを本文色で示す。参考アートは方向性の基準であり、実行時素材として使用しない。拠点・ショップ・装備・倉庫・永久強化・出撃準備はこのThemeの役割を使用し、HUDのHP・MPなど意味を持つ専用表示は別途維持する。

- 操作は `PrimaryButton`（主要操作）、`SecondaryButton`（戻る・補助操作）、`ItemButton`（選択）、`GoldButton`（購入・成長）を使い分ける。
- 文字は画面名 `TitleLabel`（30px）、見出し `HeadingLabel`（24px）、項目名 `ItemNameLabel`（20px）、主要値 `ValueLabel`（26px）、本文 `BodyLabel`（18px）、説明 `DescriptionLabel`（18px）、補足 `MutedLabel`（16px）、価格 `GoldLabel`（21px）を使用する。ボタンは原則18px、補助操作は16px。画面ごとのフォントサイズ・色overrideは追加しない。
- 拠点のヘッダー・ページ・フッター、各画面の列はContainerで配置する。ただし拠点ホームのロビー（`HubLobby`）は、背景の一枚絵と一体に見せるため、縮小されるページ内容とは別に1600×900の画面全体へ直接配置する。`HubUI` は `MainPanel` / `ItemPanel` とMargin・VBox/HBoxの構造だけを共通化する。基準内容幅1440px・高さ810px（1600×900の画面で左右に80pxずつ背景を残す）、画面端は最低20px相当を確保して縮小する。通常のパネル内余白24px、列間20px、縦間隔12px、密な詳細は8px。倉庫は独立した1440×650pxのContainer構成を同様に縮小する。
- 外観の調整はTheme内の名前付きStyleBox（`MainSurface`、`SurfaceHover`、`FocusOutline`など）を編集する。同一のStyleBoxを共有するControlへ一括反映されるため、画面側で複製しない。文字色・文字サイズは該当するTheme Typeを編集する。Theme内の色項目とStyleBoxの色はGodot上では別プロパティであり、自動連動するパレットではない。
- `CharacterButton` と `SpeechPanel` は拠点キャラクターの透明なクリック領域と吹き出し専用とする。新規画像を要する装飾は、後述「UI体験の改善」の素材差し替え口を通してのみ追加し、素材がない状態でも現行の表示で成立させる。

色の役割は背景 `#020305`、主面 `#252525`、浮いた面 `#2B2B2B`、一覧の内側 `#1C1C1C`、Hover `#363636`、選択面 `#26241A`、通常境界 `#525252`、選択境界 `#B89759`、Gold `#D6B77B`、本文 `#EEE9DF`、説明 `#C9C9BF`、補足 `#B2B3AA`、減少 `#DB857A`、増加 `#91C2A3` とする。拠点背景の画像は暖かい光を残し、上に重ねる中立色の暗幕を薄くして石造りの奥行きを見せる。主パネルは青みを含まない不透明な石墨色で背景と分離する。透過率と影はTheme内のStyleBoxに集約する。一覧／詳細比率はショップ約53:47、出撃約52:48、倉庫は所持品／中央／倉庫が約37:26:37。拠点ホームの配置は後述のB3に従う。

ショップの商品詳細と装備比較、倉庫の選択説明は `ItemDetails`（RichTextLabel）を使用する。商品名・価格・補足は既存LabelのTheme役割から色と文字サイズを取得し、能力差分は変更前→変更後と符号付き数値を併記する。増加は `PositiveLabel` の控えめな緑、減少はThemeの `ItemDetails/decrease_color` を使用する。長文は枠内でスクロールし、Tabで詳細へFocusを移した後は方向キー・Home/Endで閲覧できる。アイテム名・説明はBBCodeとして解釈せず、選択変更時は先頭へ戻す。

ショップ・装備・倉庫の一覧は `ItemTooltipList` で標準Tooltipを共通化する。幅はThemeの `ItemList/tooltip_width`、背景は既存TooltipPanelを使い、長文を折り返す。表示待ち・消去・画面端の位置調整はGodotに任せる。Tooltipは補助表示とし、選択内容の説明は画面内にも表示する。

画面上の用語は日本語に統一する。装備枠は `Equipment.SLOT_NAMES` の「主武器・副武器・防具・装飾 1・装飾 2」、能力値は「HP・MP・攻撃力・防御力・射程」、1回の挑戦は「冒険」と表記し、ATK・DEF・Main・Sub・Runなどの英語表記は使わない。金額は数値の後に「G」を付け（例：20 G）、見出しや項目名としてだけ「Gold」を使う。Lvは「Lv 3」、階数は「全50階」のように書く。ダメージ補正が0の武器は、カードの主効果に「+0」を出さない。ロゴは「Dungeon Remnant」と単語の間を空ける。

表示書体（しっぽり明朝）はThemeの `FontVariation` でOpenTypeの `palt` を有効にし、「ショップ」「モンスターハウス」のような小書きカナの字間が開かないようにする。2行に収まる日本語の説明は `TextWrap` で中央付近の助詞・句読点の後に改行を入れ、最終行に1〜2文字だけが残らないようにする。

ショップ・倉庫・装備・出撃確認の所持品は `ItemCardList` を使用し、48pxの種類アイコン・名前・主効果を約80pxの行に配置する。一覧がFocusを持つ間は、一覧全体を細い半透明の金線（`ListFocus`、1px）で囲む。ボタンと同じ2pxの金枠（`FocusOutline`）にすると、行の選択枠と二重になり、所持品が少ないときは空の大きな金枠が目立つためである。選択中の行は従来どおり金枠で示す。ショップは右端に価格と所持数、倉庫と装備では個数と所在を表示する。レアリティは現行ItemDataに存在しないため表示しない。アイテムはアイテムごとの絵で示す。`ItemIcons` が `ItemData.id` から `art/items/<id>.png`（武器は `weapon_<種類>`）を引き、アイテムのデータには手を加えない。絵は48pxのピクセルアイコンを2倍で保存したもので、48pxのカードではちょうど半分、`ItemVisual` では48の整数倍で描き、画素をぼかさない。画像のないアイテムは、`ItemGlyph` が武器種・防具・装飾品・護符・巻物・HP／MP回復薬をGodotの図形で描く共通記号で表示する。どちらも `ItemGlyph.paint()` を通るので、一覧・詳細・HUD・移動演出・永久強化で同じ絵になる。Themeの色は、明るい役割ではそのまま、灰色の役割では絵を暗くする形で反映する。床に落ちたアイテムも同じ絵を敵と同じ0.8倍で描き、影を付ける。絵は `art/items/source/` の生成画像の格子（行・列・並び順は `tools/process_item_icons.py` の `BOARDS`）から切り出す。`ItemShowcase` は絵・商品名・分類・主効果を並べ、商品名は行数を制限せずに折り返して全文を示すため、その下の詳細は名前も主効果も繰り返さない。ショップの詳細は装備の比較と同じ `InsetPanel` の枠に収める。ショップ購入・売却・装備の詳細で共用する。

カードの入力・選択・検索・Tooltip・スクロールは標準ItemListに任せ、描画だけを拡張する。ネイティブの項目文字列は名前検索とアクセシビリティのために保持し、Themeの `ItemCardList/font_*_color` を透明にして二重描画を防ぐ。表示色・文字サイズは既存Labelの役割を参照し、行高・アイコンサイズ・価格領域・余白は `ItemCardList` のTheme定数で調整する。長い名前はTextLineで省略し、全文は選択品の表示（`ItemShowcase` の商品名）とTooltipに残す。

永久強化は、強化名・現在Lv・その強化による補正の現在値→次回値・前提の必要Lvと現在Lvを、購入ボタンと分けて表示する。前提条件はSkillNodeの定義から取得し、条件未達・Gold不足（不足額）・強化上限を区別する。条件未達の価格は金色にせず、購入できない状態と分かる色で示す。段階が10を超える能力は、細かい目盛りを並べず、5段階ごとに刻みを入れた1本のゲージで進捗を示す。各強化は能力と同じ紋章（後述A1）を48pxで示し、選択中の強化は詳細の見出しにも96pxで示す。基礎HPは最大HP、攻撃力・防御力は同名の能力の紋章を共用し、生命力（芽の出たハート）と魔力量（青い結晶）は専用の紋章を持つ。紋章がない場合は図形の記号で描き、基礎HPと生命力は生命力の記号に小さな「+」を添えて区別する。補正の現在値から次回値への変化は、文字の矢印ではなく描画した山形で示す。強化のツリーは詳細と同じ装飾枠の `MainPanel` に収め、背景の上に直接置かない。枠の最上行には見出しと永久補正の合計を1行で並べ、合計が収まらない幅では末尾を省略して全文をTooltipに残す。途中開始の解放は選択ステージごとに、中ボス撃破→開始地点の関係、ステージ未解放・中ボス未撃破・Gold不足・解放済みを表示する。購入可否の判定と保存は既存のRunCarryover／Mainが担う。

永久強化は能力選択カードと選択詳細に分け、現在Lv・上限・進捗と次回効果を表示する。能力強化と途中開始の解放はカテゴリタブで切り替える。条件未達の能力も選択して説明を読める。購入操作は詳細領域のPrimary Actionで行い、可否は既存の状態判定に従う。

拠点の各画面の題の下には、機能の説明（「品を選び、価格と取引後の所持数を確認。」など）ではなく、世界観に沿った短い一言を置く（ショップ「薬も武具も、金次第。」、装備「身につけるもの、背負っていくもの。」、永久強化「冒険の記憶は、この身に残る。」、ステージ選択「次は、どこへ潜ろうか。」、出撃確認「持ち物を確かめたら、出発だ。」）。操作や規則の説明は、売却できない品のように知らないと困る箇所にだけ置く。数個の選択肢から1つを選ぶ操作（ショップの購入先・売却元の「倉庫／持ち込み」、出撃確認の開始階「1F／11F…」）はドロップダウンに隠さず、`SegmentedChoice` の切り替えボタンで全部を並べて見せる。開始階では各ボタンを階数だけにし、全ての開始に共通する「Lv1・永久強化を適用」は行の端に一度だけ書く。ショップの右パネルは、商品の絵を主役（アイコンの3倍、144px）にした陳列と、その下の勘定台で構成する。勘定台は1枚の浮いた面に、数量（−／＋と上限）、取引額を大きな1つの数字（購入は「20 G」、売却は「+5 G」、表示書体の `PriceLabel`）、その下に所持数と所持金の現在→取引後を控えめな1行で示す。「購入価格 20 G × 1 = 20 G」のような計算式や、項目名と値の羅列は使わない。取引ボタンは「3個を購入する」のように数量だけを示し、金額は勘定台に任せる。売却では「1個を売却する」と「全部売却」を1行に並べ、詳細欄の高さを確保する。詳細欄は中身の行数に合わせた高さ（最低64px）とし、空いた高さは勘定台の上に置いて、勘定台を取引ボタンのそばに保つ。列に空きがなくなったら、詳細欄は伸びるのをやめてスクロールし、勘定台と取引ボタンを列の外へ押し出さない（`ItemDetails.fit_lines`、装備画面の比較欄も同じ）。売却後の選択解除と、保存成功後だけに出す符号付きGoldフィードバックを維持する。倉庫は所持品・選択品と移動操作・倉庫の3領域とし、中央に移動方向を示す。中央の列は装備画面と同じ見せ方にそろえ、選んだ品の絵を3倍（144px、176pxの枠）で列の中央に置き、その下に名前・効果・選択数を中央揃えで並べる。分類は一覧の行が示すため繰り返さず、「選択した1スタックをまとめて移動」という規則は移動ボタンのTooltipに置いて、列の高さを品の表示に使う。「倉庫の品は冒険へ持ち込まず、死亡・中断でも失いません。」という規則は、移動結果の表示欄に常時示し、結果の通知があるときだけ置き換える。ショップの詳細には、倉庫・持ち込み・装備中の個数を「手元に」の1行で表示する。移動は既存の1スタック単位であり、全種類を一括転送する機能は持たない。

装備は候補／比較／キャラクターと装備枠を隣接させ、既存の主武器・副武器・防具・装飾 1・装飾 2の5枠を維持する。3列は同じ重さに並べず、キャラクターと装備枠の列を最も広く取って画面の主役にする。中央は選んだ候補の絵を3倍（144px）で上に置き、名前・分類・主効果をその下に中央揃えで並べる（`ItemShowcase.stack()`）。比較は枠付きの領域にまとめて中身の行数に合わせた高さ（最低96px）とし、空いた高さは操作ボタンの上に置く。変更で外れる装備の名前と主効果も示す。`CharacterPreview` は既存の待機アニメーションを使用し、ピクセル絵の画素が揃うよう整数倍（装備画面では2倍）で描く。枠に収まらない場合だけ縮小する。出撃は `StageCardList` でステージの既存画像・階数・難易度・説明を示し、右側に選択先の詳細と準備操作を置く。未解放・今後追加予定のステージは画像を暗くして錠前を重ね、名前と状態を控えめな色で示す。未解放の場合は「古代遺跡を踏破で解放」のように解放条件を添える。ステージ詳細の末尾には、各守護者を階ごとに並べ、撃破済みは名前、未撃破は「？？？」で示す。Enterまたはダブルクリックで、挑戦できるステージの出撃確認へ進む。説明文の欄はTabのフォーカス対象にしない。存在しない推奨Lv・報酬は表示しない。最終出撃確認は引き続き別段階とし、左に `CharacterPreview`・`HudEquipment` の5枠・出発時のHP／ATK／DEF／射程、右に行き先の既存画像と持ち込み一覧を置く。持ち込みが空の時は無効な行ではなく「装備のみで出撃します」という案内を表示する。

操作の時間変化は `ui/ui_motion.gd` の `UIMotion` で管理する。主要ボタンのHoverとFocusは100ms、押下は70ms、選択詳細は140ms、Gold増減は220ms、装備枠は160ms、画面表示は180msを基準とする。色・枠線はThemeに残し、scaleとalpha、選択カードの内側金枠の強さ、HUDのHP・MP残像ゲージの表示値を動かす。選択枠は140msで強まり、ショップの詳細・大型アイコン・所持数、装備の比較・大型アイコン、倉庫の詳細・大型アイコン・移動方向は、選択内容と操作可否を即時更新した後に同じ140msでFade更新する。装備枠の切り替えで自動選択される候補にも選択枠の演出を適用する。通常の一覧再描画では選択演出を再生せず、古い選択のTweenと透明度をリセットする。倉庫では選択元を切り替えた際に反対側の選択演出も解除する。Controlごと・プロパティごとに前のTweenを停止し、非表示・解放時に基準値へ戻す。Containerの位置や最小サイズはアニメーションせず、位置の動きが必要な場合は後述「UI体験の改善」の表示層を動かす。

HUDのHP・MPは数値と実ゲージを即時更新し、減少時は明るい残像を120ms保持してから280msで現在値へ追従させる。増減時は数値を220msで一度だけ1.06倍に拡大して戻す。同値の再描画は演出を再開せず、連続減少は残像の現在位置から追従し直し、回復は残像を即時更新する。初回表示・最大値変更・冒険開始時は演出せず同期し、非表示時はTweenを停止して残像と拡大率をリセットする。実数値・ゲーム処理・入力は演出を待たない。残像の色と実ゲージのStyleBoxは共通Themeで管理する。

HPが最大値の30%以下になると、ダンジョンとHUDパネルの間の層（`DangerVignette`）で画面周辺を赤く脈打たせる。残りが少ないほど赤を濃く、脈を速くし、回復すれば消える。色は共通Themeの `HpCaption` から取り、入力は妨げない。

取引・装備・倉庫移動・永久強化の成功演出は、保存まで成功した `Main.preparation_completed` 通知で開始する。UIのTween完了をゲーム処理から待たず、残高・一覧・装備は即時更新する。購入は負、売却は正のGold増減を既存のフィードバック欄に表示する。永久強化は、確定したランク増加がある能力カードを220msで1.025倍に拡大して戻し、選択中の能力が上がった場合は詳細の現在値も同時に1.04倍で強調する。初回表示・選択だけでは成功演出を出さず、選択変更時は詳細の拡大をリセットする。画面を閉じる操作は即時とし、退場演出による入力待ちを設けない。

戦闘の結果は先に確定し、`BattlePresentation` が記録済みのイベントから予備動作・攻撃・被弾・死亡を再生する。剣は斬撃、槍は突き、ハンマーは衝撃波、魔法は発光輪で表現し、攻撃範囲の演出は視界内に限定する。敵は種類ごとの描画と待機・移動・被弾の姿勢を持つ。同一敵の連続移動、追従、交差する斜め移動は順序を維持し、経路が重ならない敵の移動だけを同時再生する。演出は論理座標を変更せず、既存の戦闘演出中の入力制御を維持する。中断・階層移動時は姿勢、位置補正、残存エフェクトを解除する。

攻撃方向の選択中は、射程の各マスを薄い下地と金色の角ブラケットで示し、ゆっくり明滅させる。敵がいるマスには赤みのある照準を重ね、ベタ塗りの四角は使わない。ダメージ数値は、与えたダメージを淡い金、止めの一撃を濃い金でひと回り大きく、受けたダメージを赤で大きく強い弾みで表示し、いずれも同系色の暗い縁取りと影を付ける。敵のHPバーは減った時だけ表示し、暗い枠付きの太いバーで残量に応じて金・橙・赤に変える。

冒険結果は、タイトルの下に結末を1文で示す（例：「3Fで突進獣に倒された。」「最深部の主を討ち果たした。」）。数値は到達階・今回獲得・失ったGold・残高に加え、到達Lv・倒した敵・経過ターンを表示する。死亡時は、止めの一撃の演出後に主人公が崩れ落ちて暗くなり、画面が0.7秒かけて沈んでからパネルを出す。この間は確定・再挑戦の入力を受け付けない。結果の確定と保存は演出を待たず先に終える。

カメラは探索中の追従を平滑化し、新しい階の開始位置へは即座に合わせる。カメラは主人公より1マス弱（40px）下を中心に映し、主人公を画面中央より少し上、下側のHUDにかからない位置に置く。倍率1.25倍は、0.8倍で描くキャラクターの絵がちょうど等倍になり画素が揃う値で、視界（半径8マス）も縦方向ではすでに画面より広いため、これ以上寄せない。階層開始とモンスターハウス発見は短い非操作型バナーで知らせ、ボスはその階で初めて視界に入った瞬間に一度だけ `BossCutIn` で知らせる。画面上部を横切る暗い帯に、ボスの待機コマ（1.5倍）を左から、階とボスの名前を右から入場させ、約1.35秒保ってから0.3秒で消す。帯は入力を受け取らず、ターンは演出を待たない。専用の絵がないボスは名前だけを中央に示す。表示中の階層バナーはカットインに置き換え、成長選択・冒険結果・階の移動では即座に消す。画面の揺れは被弾時だけのため、登場では揺らさず専用の効果音（`boss`）を鳴らす。成長選択・持ち物・冒険結果には共通ThemeとUIMotionを適用する。環境の微粒子と階段・脱出口の淡い光は視界内に限定し、未探索の情報を表示しない。

音源素材が揃うまで、`audio/game_audio.gd` の `GameAudio` が生成する仮のPCM効果音を使用する。武器、被弾、撃破、取得、足音、保存成功後の拠点操作、成長、階層開始、警告、帰還・敗北を鳴り分ける。同時発音は最大8音で、音の生成はゲーム進行の乱数を消費しない。実素材への差し替えには `GameAudio.set_override(cue, AudioStream)` を使い、nullを渡すと仮音へ戻る。環境音は `audio/dungeon_ambience.gd` の低音量ループで代用し、`stream_override` へ実素材を設定できる。これらは完成音源ではなく、音量とタイミングを確認するための仮実装とする。

拠点UIはキーボードの既存操作に加え、ゲームパッドの十字キーでFocus移動、Aで決定、Bで戻る操作を受け付ける。`ui_accept`・`ui_cancel`・方向の標準アクションへ登録し、マウスと同じButton signalで演出する。既存のキーボード割り当ては保持する。

ダンジョンでは、ゲームパッドの十字キーを上下左右の移動、左スティックを8方向の移動（`StickDirections` がスティックの向きを移動アクションの押下と解放に変換し、押し続けによる連続移動もキーボードと同じ仕組みで行う）、Aを攻撃、Bをキャンセル、Xを所持品、Yを武器切替、Startを中断と結果画面からの再挑戦・帰還に割り当てる。所持品画面は開くと一覧にFocusを置き、Space・Enter・Aで選択中の消耗品を使うか、装備品を比較中の枠へ装備し、Yで武器を切り替える。能力選択は1〜3キーとマウスを開いた直後から受け付け、Focusは攻撃の連打で誤選択しないよう0.3秒後に最初のカードへ置く。中断の確認はEnter・Aで確定し、Esc・Bで取り消す。所持品の取り外しと魔法の装着先の選択は、現状マウス操作だけとする。

変更時は `tests/test_ui_theme.gd`、`tests/test_ui_layout.gd`、`tests/test_ui_motion.gd`、`tests/test_upgrade_ui.gd` に加え、該当する取引・装備・セーブのテストを実行する。描画可能な環境では `tests/capture_art_direction.gd`（7画面を1600×900・1280×720・1920×1080で確認）、`tests/capture_shop.gd`、`tests/capture_preparation.gd`、`tests/capture_ui_motion.gd`、`tests/capture_item_details.gd`、`tests/capture_upgrade_ui.gd`、`tests/capture_item_cards.gd` で通常サイズ・縮小表示・各入力・ボタン端のクリックを確認する。演出用キャプチャは60 FPS上限でアイドル時と演出中のフレーム時間も比較する。生成画像は `.godot/` に出力する。

## UI体験の改善（優先度順）

現行UIは、情報を正しく・崩れずに表示するという条件は満たしているが、プレイヤーに何かを感じさせる場面としては設計されていない。拠点の背景は描き込まれているのに、その上のパネルは平らな石墨色の矩形とゴシック体の文字だけで構成されているため、背景とUIが別々の作品のように見える。全画面が「ヘッダー＋暗いパネル＋戻る」の同じ構造なので、画面を移っても場面が変わった感覚がない。演出は0.07〜0.28秒の縮小・拡大と透明度の復帰だけで、動きに方向や溜めがなく、購入・装備・能力獲得のような報酬の瞬間も、ボタンを押した時と同じ手触りで終わる。さらに、プレイ時間の大半を占めるダンジョン側の能力選択・所持品・冒険結果は、拠点側で整えた `ItemCardList`・`ItemGlyph`・`ItemShowcase` を使っておらず、文字だけのボタンとリストで構成されている。この節は、これらを製品として遊べる水準へ引き上げるための方針と、画面ごとの改善内容を優先度順に定める。本節と上記の記述が矛盾する場合は本節を優先する。ゲームロジック・セーブ仕様・Item / Stage / Ability Dataは変更せず、現行データにない値を表示のために作らない。

### 共通方針

各画面に「プレイヤーの選択が結果に変わる瞬間」を1つだけ定め、その瞬間の演出を最も手厚くする。以下ではこれを見せ場と呼ぶ。見せ場以外の操作は、現行の控えめな反応のままでよい。演出を全画面に均等に足すと、どれも見せ場にならないためである。

演出の時間は3段階に分ける。Hover・Focus・押下などの反応は80〜120ms、画面・パネル・選択詳細の入れ替わりなどの遷移は180〜260ms、能力獲得・購入・装備・冒険結果などの見せ場は400〜900msとする。入場は `TRANS_CUBIC` の `EASE_OUT` を基本とし、見せ場の強調だけ `TRANS_BACK` の `EASE_OUT` で最大1.05倍までのオーバーシュートを許す。退場は120msの `EASE_IN` とし、退場中も次の画面が入力を受け付ける。見せ場の演出は、決定・キャンセル入力で即座に最終状態へ飛ばせるようにする。いずれの演出もゲーム処理・保存・入力の可否を待たせないという既存の原則は維持する。

位置を動かす演出は、Containerの子そのものではなく表示層で行う。表示層とは、Containerが配置するControlの内側に置いた、Containerの管理を受けない見た目用のControl（`mouse_filter` はIgnore）であり、その `position`・`scale`・`modulate` だけをTweenする。Focus・入力・レイアウト計算は元のControlが持ち続ける。一覧から詳細へアイコンが飛ぶような、Controlの境界をまたぐ演出は、画面最上位の `CanvasLayer` に置いたオーバーレイへ一時的な複製を描いて行い、終了後に破棄する。

Gold・EXP・到達階など結果の数値は、状態と保存上の値を即時に確定させたうえで、表示だけを前の値から新しい値へ数えて見せる。数える時間は差の大きさに応じて最大600msとし、差が小さいときは短くする。開いた直後の誤選択は、キーリピート（`echo`）を受け付けないことで防ぎ、時間による入力の無視は設けない。入場演出の途中でも、キー入力で即座に選択できる状態を保つ。

書体は、画面名・見出し・ロゴ用の表示書体（明朝体またはセリフ体）と、本文用のゴシック体の2系統にし、数値には等幅数字を使う。書体の指定はThemeの `TitleLabel`・`HeadingLabel`・`ValueLabel`・`GoldLabel` などで行い、画面ごとのoverrideはしない。採用する書体は商用利用と同梱が許されるライセンスのものに限る。

パネルの質感は、Themeの `MainSurface`・`ItemSurface` などを、装飾枠つきの `StyleBoxTexture`（9-slice）へ差し替えられる構成にする。枠素材がない間は現行の `StyleBoxFlat` のまま表示する。これを素材差し替え口と呼び、カードの挿絵や背景の差し替えも同じ考え方で、素材がない場合は現行表示で成立させる。

ダンジョン中のHUD・能力選択・所持品・冒険結果も、拠点と同じTheme・書体・`ItemGlyph` を使う。拠点とダンジョンで作品の質感が途切れないようにするためである。効果音は、反応段階にカーソル移動音と決定音を、見せ場ごとに専用の音を割り当てる。素材が揃うまでは `GameAudio` の仮音cueを追加して代用する。

### 優先度A：ダンジョンの見せ場

**A1. レベルアップの能力選択。** 現行は縦に並んだ3つの文字ボタンで、能力名・Lv・効果が1行に詰め込まれている。これを横並びの3枚のカードにし、各カードに能力の記号、能力名、Lvの進捗（上限までの目盛り）、次のLvで得る効果を大きく表示する。記号は、ブロンズの縁と鋲を持つ暗い円盤に浮き彫りの図柄を載せた生成画像の紋章とし、96pxで描く。紋章は `EmblemIcons` が `Effect` の名前の小文字（`max_hp`・`sword_damage` など）から `art/emblems/<キー>.png` を引くため、AbilityDataには手を加えない。絵はアイテムと同じく48pxのピクセル絵を2倍で保存したもので、`art/emblems/source/` の2×3の生成画像2枚（並び順は `tools/process_emblems.py` の `BOARDS`）から切り出す。武器別の威力は橙の火花、槍の射程は先へ伸びる青い山形、貫通は穂先が通り抜ける青い輪で区別し、全武器に効く攻撃力は火花をまとう籠手で表す。紋章がない能力は、`Effect` から `ItemGlyph` の図形の記号へ対応づけて描く。見せ場は能力を選んだ瞬間とする。カードは開いた時に60ms間隔で下から順に入場し、Hoverしたカードは少し持ち上がる。選択と同時にダイアログは閉じてターンが再開し、選んだ瞬間の演出は、入力を受け取らない別の `CanvasLayer` に複製したカードで再生する。選んだカードは拡大して金色に光り、Lvの目盛りが1つ埋まり、他の2枚は沈んで消える。次の選択が続く場合は、前の演出を即座に破棄して新しいカードを入場させる。1・2・3キーとマウスでの選択と、残り回数の表示は維持する。今後、HUDの該当する数値（最大HPなど）を一度だけ強調する演出と、ゲームパッドでの選択を加える。

**A2. ダンジョンHUDと戦闘の手応え。** HUDのパネル・書体・色を拠点のThemeへ揃える。装備欄は「Main 槍」のような文字だけの表示をやめ、5枠をそれぞれ小さな枠に入れたアイテムの絵（32px、元の絵の3分の1で画素をぼかさない）で示す。ダンジョンのHUDでは床を覆う面積を抑えるため、5枠を1列（武器2枠と、少し離して防具・装飾2枠）に並べ、その下に主武器と副武器の名前だけを書く（`HudEquipment.strip`）。すべての名前は所持品画面（I）で確認できる。出撃確認では枠名と名前を添えた5行のままとする。主武器の枠は金色にし、空いた枠には受け付ける種類の記号（`ItemGlyph.slot_symbol()`、拠点の装備画面と共通）を薄く描く。ミニマップは既知の範囲をパネルいっぱいに拡大し、壁はどの床よりも暗く描いて部屋の形を縁取り、プレイヤーと既知の階段を記号で示す。未探索の情報は表示しない。メッセージログは古い行から薄くして、最新の2行だけをはっきり見せる。階層開始のバナーは、画面中央の箱から、上下に余白を持つ帯状の見出しへ変え、階数を表示書体で大きく見せる。戦闘では、プレイヤーの被弾と敵の撃破の瞬間に40〜60msのヒットストップを入れ、プレイヤーの被弾時だけ3〜6pxの画面揺れを加える。ヒットストップは `BattlePresentation` が再生中のTweenを一時停止して実現し、`Engine.time_scale` は変更しない。揺れは固定のパターンで行い、ゲーム進行の乱数を消費しない。揺れの強さは1か所の定数で管理し、将来の設定画面で弱められるようにする。HUDのパネルは共通Themeの `HudPanel` とHUD用の文字役割（`HudCaption`・`HudValue`・`HudSmall` など）を使い、Scene側のTheme overrideを持たない。パネル内部の配置は、テストと演出が参照するノードの構成を保つため当面は固定配置とし、Containerへの移行は表示書体の導入（B4）と合わせて行う。ダメージ数値は大きさと縁取りで他のポップアップより目立たせ、EXP・Goldの取得表示とは位置と色で区別する。ルールは入力時に確定させるが、HUDのHPは被弾の演出が当たった瞬間に減らし、その行動のログ行は演出の再生後に1行として追加する。ログは攻撃した相手・攻撃してきた敵の名前を示し、通常の移動は記録しない。同じ行動で続く取得・撃破・召喚の記述は同じ行へまとめる。主人公の顔（`HudPortrait`、`art/ui/hud_portrait.png` の96pxの4コマ）はHP・MPと同じ1枚のプレートの左上にブロンズの細枠（`HudPortraitFrame`）で収め、その右にHP・MPのバー、下にLv・EXPと経過ターン・所持数を並べる。ふだんは落ち着いた顔で約3.6秒ごとに短く瞬きし、HPが減った瞬間は約0.6秒だけ痛がる顔にして枠を弾ませる。HPが危険表示と同じ3割以下では疲れ切った顔を保つ。回復と最初の表示は被弾として扱わない。HP・MP・EXPのバーは、ブロンズの縁と鋲を持つ9-sliceの枠（`art/ui/vital_frame*.png`）に収め、中身は上端が明るく下端が陰る縦のグラデーションとし、HPとMPには4分の1ごとに刻みを入れてゲージとして読めるようにする。枠はThemeのexpand marginでバーの外側に描き、バーの位置と大きさは変えない。これらの画像は `tools/generate_vital_bars.py` が作る。

**A3. 冒険結果。** 現行は到達階・獲得Gold・失ったものを文字で並べただけで、クリアと敗北の見た目がほとんど変わらない。見せ場は結果が確定する瞬間とする。タイトルを表示書体で大きく出したあと、到達階・獲得Gold・残高を1行ずつ順に表示し、Goldは数えて見せる。失ったアイテムは `ItemCardList` と同じ記号付きの形式で並べ、失われたことが一目でわかる表示にする。持ち帰れた装備5枠も記号で並べる。クリアは暖色の金、敗北は彩度を落とした赤を基調とし、効果音も分ける。値は表示前にすべて確定させ、行の順次表示と数値の数え上げは約1秒以内に終える。演出中も拠点へ戻る・再挑戦の操作は即座に受け付け、画面を閉じた時点で数値と表示を最終状態に戻す。失ったアイテムと持ち帰る装備は、基準解像度と縮小表示のどちらでもスクロールせずに見える高さを確保する。保存状態の表示は維持する。結果は結末を描いた一枚絵（`art/results/clear.png`・`defeat.png`）の上に出す。クリアと無事な帰還は出口へ差す朝の光と主人公の後ろ姿、それ以外は火の消えた広間に落ちた帽子と剣とし、絵は画面を覆うように縦横比を保って広げ、上の暗幕を薄くしてパネルの左右に場面を見せる。敗北時は暗幕と同じ0.7秒で絵も沈んで現れる。中断の確認は結末ではないため、絵を出さず従来の暗幕だけにする。

### 優先度B：流れと第一印象

**B1. ダンジョン内の所持品。** 現行は文字だけの所持品リストと「Main：剣」形式の装備一覧である。拠点の装備画面と同じく、所持品を `ItemCardList`、選択品を `ItemShowcase` と `ItemDetails`、装備5枠を記号付きの枠で表示する。選択品の主効果は `ItemShowcase` に1回だけ表示し、説明欄には射程やノックバックなど追加の情報だけを載せる。装備品を選んだ場合は、装備後の最大HP・攻撃・防御・射程・視界のうち変化するものだけを、現在値→装備後の値で示す。比較先は空いている対応枠、なければ最初の対応枠（武器ならMain）とし、装備操作にポインタを重ねるとその枠との比較に切り替える。比較値はプレイヤーの `stats_with()` で求め、レベルアップの能力と一時効果を含めて実際の装備後の値と一致させる。空の装備枠には取り外し操作を出さず、Main枠は外せないことを無効化した操作で示す。装備・取り外し・使用・武器切替の操作と、ターン消費の説明は維持する。

**B2. 画面遷移と出撃の流れ。** 拠点の画面切り替えでは、Containerに配置されていないページ全体を表示層として扱い、16px横から180msで入場させる。奥の画面へ進むときは右から、ホームへ戻るときは左から入る。一覧の項目を順に表示する演出は、`ItemCardList` が行ごとに透明度を扱えるようになってから加える。出撃確認からダンジョンへ移る時は、最前面の `SceneTransition` がステージの既存画像と名前を見出しとして出し、そのまま1Fのバナーへつなげる。冒険終了から拠点へ戻る時も同じ暗転を挟む。階段を降りる時は、直前の画面を約0.2秒で暗くしてから次の階を明かし、階層バナーは明ける途中から入場させる。次の階はルール上すでに読み込み済みで、暗転は入力を受け止めるだけとする。暗転している間はキー入力とポインタ入力を受け止めて破棄し、見えない画面への操作を防ぐ。シーンの切り替えと状態の確定は暗転の開始より先に同期的に終え、暗転は約0.8秒で自動的に明けて入力を解放する。見出しは暗幕より先に消し、明けていく途中の画面と重ならないようにする。

**B3. 拠点ホーム（ロビー）。** ホームはWebページのようなカードの並びにせず、ゲームのロビー画面として構成する。左に装飾付きのメニュー（画面幅の約2割、300px）、中央下に選択中の項目の情報パネル、右に主人公の立ち絵を置き、拠点の一枚絵（`art/hub/lobby_hall.png`）を画面全体に敷いて、3つの領域を1つの場面としてつなぐ。情報量を増やすより、ゲーム画面としての雰囲気と視線誘導を優先する。メニューは出撃・装備・倉庫・ショップ・強化・設定の6項目で、項目ごとに箱で囲まず、暗い石板の帯と細いブロンズの縁・菱形の鋲で装飾したパネルの上に、記号と表示書体の名前を並べる（`LobbyMenuButton`）。選択中の項目だけを、右端が尖った暖かい光の帯と金の文字（`LobbyMenuButtonSelected`）で強調する。選択と決定は分ける。キーボードとゲームパッドではFocusの移動が項目を選び、決定で入る。マウスでは1回目のクリックで選び、選択中の項目をもう一度押すか、情報パネルの決定ボタンで入る。他の画面からホームへ戻ったときは、最後に選んだ項目を選択したままにする。情報パネル（`LobbyInfoPanel`）は床の上に浮く程度の大きさとし、項目名（出撃では次の行き先のステージ名）、世界観の一言、その項目の情報1行（出撃は全階数と難易度、装備はMain武器の記号と名前、倉庫は持ち込みと倉庫の使用枠、ショップは所持金、強化は習得した強化の段階数）、決定ボタンだけを置く。現行データにない推奨Lvや到達階は表示しない。パネルの右側には、開く先の挿絵（出撃はステージの絵、それ以外は `art/hub/cards/` の挿絵）を暗幕越しに薄く見せる。挿絵は `art/hub/source/home_cards.png` から `tools/cut_card_art.py` が切り出したものである。設定は他の項目と同じく独立した画面（`HubSettings`）として横からスライドして開き、ロビーのパネルには現在の音量と画面モード、「設定を開く」ボタンだけを置く。設定画面では、音量を「← 小 ◈━━●━━◇ 大 →」のバー（`GameSlider`、0〜100%を5%刻み、ドラッグ・左右キー・十字キーで操作）で、画面モードを「〈 ウィンドウ 〉」のセレクター（`OptionCycler`、左右キーか矢印のクリックで切り替え、端で折り返す）で選び、変更はその場で適用する。設定は冒険の進行とは別に `GameSettings` が `user://settings.cfg` へ保存するため、進行セーブの読込失敗や復元の影響を受けず、設定ファイルが壊れていても既定値（音量最大・ウィンドウ）で起動する。選択中の項目に応じて、背景の関連する物（出撃は奥の門、装備は武器棚、倉庫は右下の宝箱、ショップは商人の台、強化は祭壇の水晶、設定はランタン）を `HubAmbience` が加算合成の光でゆっくり明滅させ、メニューと背景を連動させる。光の位置は背景画像内の相対座標（`HubAmbience.FOCUS`）で持つため、背景を差し替えるときは合わせて直す。立ち絵（`art/characters/mio_lobby.png`）は画面高さの約78%で右側の床に立たせ、足元には全体の淡い影と、両足の靴底それぞれの接地影を描く。立ち絵は `LobbyHero` のシェーダーで動かす。絵は体（`mio_lobby.png`）と長い後ろ髪（`mio_lobby_hair.png`）の2層に分け、後ろ髪を体の後ろに重ねる。後ろ髪は体の後ろにあるため、揺れて離れた場所に描き足しは要らない。各画素を読む位置をずらす方式なので、絵が裂けない。常時は約5秒周期の呼吸と、足元を支点にしたゆっくりした体の傾きを続ける。後ろ髪は首の後ろを支点に根元から先端へしなり、約1Hzのばね（減衰比0.3）で体の傾き・顔の向き・跳ねる動きに遅れて追従し、少し行き過ぎてから落ち着く。根元は動かさず、しなりと上下の遅れは先端ほど大きくする。揺れは上限に近づくほど緩やかに頭打ちにし、上限で急に止めない。元の絵では後ろ髪のうちコートや袖に隠れた部分が描かれていないため、後ろ髪の層には隠れた範囲へ髪の色を約48px延ばしておき、外へ揺れても体との間に隙間が開かないようにする。肩の前の髪の束とコートの裾は同じ動きの一部を受けて揺れ、揺れる範囲は `mio_lobby_motion.png`（赤が髪の束、緑が裾。根元から先端へ大きくなる）で決める。目は `mio_lobby_eyes.png` の差分（半目・閉じ目・左目線・右目線）を目の周りだけ差し替えて表す。3〜7秒ごとに半目→閉じ目→半目の3段階で瞬きする。6〜12秒ごとに、目線だけ・顔だけ・両方のいずれかで少し横を見る。顔は1〜2°傾けて少し保ち、目線を先に戻してから顔を戻す。立ち絵を押すと、足元から小さく跳ねて顔を傾け、瞬きし、顔の横の吹き出しで次の台詞を言う。吹き出しは約4秒で消える。跳ねている間と、その後0.3秒の間に押した場合は、跳ね直しや顔の向きの反転はせず、台詞だけを進める。連続で押しても動きが途切れたり暴れたりしないようにするためである。動きの間隔はゲーム進行とは別の乱数で決める。これらの画像は `tools/build_lobby_hero.py` が `art/characters/source/` の元絵と目の差分から作る。後ろ髪は暗い布・手・袖口などを体の領域としてまとめ、その外側の髪を切り出す。目の差分は、目の周りの顔が元絵と最もよく重なる位置を探して位置ずれを補正する。12〜25秒ごとに、両手で剣の柄を持つ・ベレー帽に手を添えるのどちらかのしぐさ（Random Idle）をする。しぐさは約0.18秒で重ねて1〜1.8秒保ち、約0.22秒で元に戻す。立ち絵を押したときは笑顔を約1.6秒見せる。しぐさと笑顔は、元絵を編集した差分のうち変わった範囲の矩形だけを、縁をぼかして体の層に重ねる。しぐさの差分は後ろ髪を描かれたまま含むため、しぐさの間は後ろ髪の揺れを止め、差分と後ろ髪がずれないようにする。しぐさはクリックの反応の最中には始めない。上部には所持Goldだけを置き（設定は左メニューから開く）、ロゴと画面名はホーム以外の画面でだけ表示する。所持Goldは四角い枠に入れず、硬貨の印・「Gold」・金額を背景の上に直接置き、下に細い金の装飾線を引く（`GoldPurse`）。レベルは冒険ごとに1へ戻るため、拠点では表示せず、ダンジョン内のHUDだけで示す。保存の状態は、保存失敗・保存停止・バックアップからの復元のように注意が必要なときだけ画面下に表示し、「保存済み」のような通常の結果は常時表示しない（`SaveStore.alert`）。背景と立ち絵はCodexの画像生成（gpt-image-2.5）で作り、生成時の指示は `rogue-like-play/開発メモ.md` に残す。

**B4. 書体と枠素材の導入。** 表示書体はSIL Open Font Licenseのしっぽり明朝（Bold・Medium）とし、`ui/fonts/` に同梱して、`TitleLabel`・`HeadingLabel`・`ValueLabel`・結果の見出し・HUDの数値・ロゴに当てる。ライセンス文は書き出しに含め、配布物にも同梱する（`THIRD_PARTY_NOTICES.md` と `docs/Windows配布手順.md`）。大きなパネルの地（`Panel`・`PanelContainer`・`MainPanel`・`DetailPanel`）と拠点ホームのカードは、`art/ui/` の9-slice装飾枠を使う `StyleBoxTexture` とし、内容の余白は従来の値を保つ。枠は192pxの画像の四隅に、生成したブロンズ（選択中は金）の角金具を42pxの余白で置き、細いレールでつなぐ。枠の地は単色の平塗りにせず、108pxごとに繰り返す淡い石墨の粒状の質感を敷き、レールの内側には影を落とす。Themeは地を引き伸ばさずに並べる（`axis_stretch` はTILE_FIT）ため、パネルの大きさによらず質感の細かさは一定になる。パネルの中身は明暗で3段階に分ける。カードとボタン（`ItemSurface`・`Surface`）は上端を明るく、下へ向かって暗くして浮き上がって見せ、Hover（`SurfaceHover`）はそれより明るく、選択（`ItemSelected`）は暖かい金にする。詳細の枠・アイテムの絵の枠（`InsetSurface`）、一覧の地（`ListBackground`）、入力欄（`FieldSurface`）は上端に影を落として一段へこませる。押下中と選択中のタブ（`ButtonPressed`）は平らなままにして、浮いた面と区別する。これらの面の画像（`art/ui/surface_*.png`）も同じスクリプトが作る。主な操作（`GoldButton`・`PrimaryButton`）は、両端に宝石付きの端飾りを持つ金のプレート（高さ44px、余白は左右19px・上下21px）とし、44pxより高いボタンでは宝石の中央2行だけが伸びて縦長の宝石になる。タブの選択中は操作と区別するため平らな `TabActive` とする。これらの画像は `art/ui/source/ornaments.png`（角金具と端飾りの2×2の生成画像）から `tools/build_ui_frames.py` が作り、余白を変えるときはThemeの `texture_margin` も合わせる。

### 優先度C：拠点の各画面

**C1. ショップ。** 右パネルで効果が上下に2回表示されている重複をなくし（名前の全文は選択品の表示の商品名が行数を制限せずに示し、詳細欄には主効果以外の説明だけを載せる）、空いた領域は、装備品なら次の冒険で装備した場合の能力値の変化（空いている対応枠、なければ最初の対応枠との比較）に使う。購入数はGodot標準のSpinBoxをやめ、−／＋ボタンと直接入力できる数値欄の組（`QuantityStepper`）にし、見出しに上限を示す。見せ場は取引の瞬間とし、商品の記号を購入なら所持数の表示へ、売却なら画面右上のGold欄へ飛ばし、着地した表示を強調する。Goldの表示は常に確定した値を示し、数え上げはしない。購入後は同じ品を選んだ状態に戻して続けて買えるようにし、売却後と通常の再描画では選択を解除する。

**C2. 装備。** 比較欄には変化のある能力値だけを、能力名・変更前・変更後・差分の列を揃えた表で示し、差分は増加と減少の色で塗る。変化がなければその旨を1行で示す。主効果以外の説明は比較の後に載せる。装備枠は、上段に装備中の品の48pxの絵と枠名、下段に装備名を枠の幅いっぱいに表示し、空の枠にはその枠が受け付ける種類の共通記号を淡く描く。次の冒険の能力値はHP・攻撃力・防御力・主武器の射程の4つを表示書体の数値で並べ、候補を選んでいる間は変わる値だけを「変更前 → 変更後」にして増加・減少の色（Themeの `StatUp`・`StatDown`）で示し、見出しに「変更後」と添える。見せ場は装備を変更した瞬間とし、候補の記号を大きな表示から変更した枠へ飛ばし、着地で枠を弾ませ、`CharacterPreview` を短く明るくし、次の冒険の能力値の表示を強調する。能力値の表示は常に確定値を示し、数え上げはしない。Main・Subの入れ替えや取り外しのように運ぶ品がない変更は、変わった枠を弾ませるだけにする。

**C3. 永久強化。** 各能力のLvを上限までの目盛りで示す。前提条件の深さに応じてカードを字下げし、前提元から子へ折れ線で結ぶ。前提を満たした線は金、満たしていない線は薄くする。見せ場は強化の瞬間とし、新しく得た目盛りが薄い状態から埋まる動き、カードの短い発光と拡大、上部の永久補正の合計の強調を同時に見せる。

**C4. 倉庫。** 見せ場は移動の瞬間とし、選択品の記号を中央の選択品の表示から移動先の一覧の該当行へオーバーレイで飛ばし、着地で移動先の一覧を強調する。該当行が見えていない場合は一覧の中央へ着地させる。飛ばす記号は親の描画順（倉庫パネルは前面に上げている）を引き継がないため、明示的に最前面へ描く。

**C5. 拠点の環境演出。** `HubAmbience` が、背景画像の光源（吊りランタン・燭台・商人の台のランタン）の位置に暖色の光を加算合成で重ねて個別にわずかに明滅させ（強さの揺れは約3割以内）、画面全体に暖色の埃の粒子をゆっくり漂わせる。光源の位置は背景画像内の相対座標で持ち、背景と同じく縦横比を保って画面を覆う配置に換算する。拠点の立ち絵は呼吸・瞬き・髪の揺れなどの待機動作を続け、ホームでは選択中の項目に対応する背景の物を光らせる（B3）。操作していない間も画面が生きて見えるようにするためである。これらはUIの読みやすさを妨げない強さに抑え、Focus表示と本文の視認性を優先する。

**C6. ダンジョンの環境演出と絵の差し替え口。** 拠点の描き込みに対してダンジョンが平板に見えないよう、画像がなくても成立する環境演出を先に置く。`DungeonLights` は、見えている床を見下ろす壁面に座標のハッシュで松明を掛け（1画面最大10本、森林では掛けない）、炎を2つの波で明滅させ、光を加算合成で床へ落とす。見えている階段には、広い光と階段のマスに絞った強い光の2層の金色を重ねてゆっくり脈打たせ、暗い石段の絵でもログの言う「金色の階段」として見つけられるようにする。光の色は地形テーマごとに変える。`AmbientDetails` の粒子は地形テーマに合わせ、蒼灰は埃、苔と森林は立ちのぼる胞子、燠火は上昇して消える火の粉、黒曜は瞬く光とする。どちらもゲーム進行の乱数を消費せず、見えているマスだけに出す。`DungeonVignette` は画面の縁を暗くし、照らされた部屋を画面の中心として見せる。地形の下には 霧の層（`world/dungeon/unexplored_mist.gd`）を敷き、まだ知らない範囲を真っ黒の画面ではなく、地形テーマ（森林は専用の緑）の色でゆっくり流れる薄い霧として見せる。霧の模様は位置だけから作るノイズで、間取りとは無関係なので未探索の部屋を示さない。既知のマスの地形が上を覆うため、霧は未知の範囲にだけ見える。層は危険表示とHUDより下とする。

敵の絵は `art/enemies/<id>.png` に置いた右向きの横一列の帯（通常96px・ボス176pxの正方形コマ。待機4コマ、溜め、攻撃、被弾、倒れの順）で差し替える。体の高さは主人公の56pxを基準に敵ごとに決め（人型の番兵は主人公と同程度、ネズミやスライムは小さく、ボスは約2倍）、コマの余白は突進などの動作に使う。待機のコマで決めた倍率を動作にも使い、それでも枠からはみ出す動作のコマだけを個別に縮める。`EnemySprites` が敵の種類（ボスは表示名）から `id` を決め、画像がない敵は従来の図形で描く。名前付きのボスに専用の画像がなければ共通の `boss` を使う。溜め・攻撃・被弾のコマは `BattlePresentation` が演出の間だけ保持する。砲台の射線予告と突進獣の突進予告の間は溜めのコマを出し続け、矢印だけでなく体の姿勢でも次の行動を示す。突進の巣は攻撃しないため、孵化の1ターン前に溜め、孵化したターンに攻撃のコマを出す。とどめを受けた敵は、のけぞりの直後に倒れのコマへ切り替え、不透明なまま約0.2秒見せてから消える。倒れのコマがある敵は、図形用の潰れる演出を行わない。キャラクターの層は行でY方向に並べ替え、下の行ほど手前に描く。同じ行では主人公を最後に描き、大きな敵が隣に立っても主人公を隠さない。コマの大きさは主人公と同じく画素の0.8倍とし、主人公と同じ密度で見せる。生成画像は `art/enemies/source/` と `art/tiles/source/` に置き（`.gdignore` によりGodotへ取り込まない）、`tools/process_enemy_sheet.py` が背景の除去・コマの分割・縮小・減色・縁取りを、`tools/build_terrain_atlas.py` が3×2の地形の絵から48pxのアトラス（床3種・柱・階段、壁は接続16通りを合成）を作る。壁の開いた辺は、平らな線を描かずに石の模様そのものを明るく、または暗くして縁を表す。壁の石は床より暗く（0.6倍）、模様の濃淡も半分に抑え、通れない場所より床と敵・アイテムに目が行くようにする。森林の木も同じ理由で、見えている木を少し暗く描く。敵の減色は、目の光や宝石のような少数の差し色が残るoctree方式とする。主人公のダンジョン用の絵は承認済みの64pxのコマ（`art/characters/mio_dungeon_chibi_64/`）を元とし、`tools/refine_mio_sprites.py` が `art/characters/mio_dungeon_refined/` に敵と同じ1pxの暗い縁取りを付けた版を作る。デザインを変えないため作り直しの生成はせず、待機は同じ絵の頭と肩を1px下げたコマとの2コマで呼吸させ、正面の瞬きもコマに焼き込む。松明にも `torch` の帯を置くと、図形の炎を置き換える。深緑の森林の壁は木として描き、`art/tiles/forest_trees.png`（生成した4種類の木を64pxに変換したもの、`tools/process_tree_sprites.py`）から座標のハッシュで1本を選び、マスの下端に根元を置いてマスより大きく描く。上の行から順に描いて手前の木が奥の木に重なるようにし、覚えているだけで見えていない木は暗くする。

### 必要な素材

以下の素材は外部で用意する。どれも差し替え口を通して使い、未着手の状態でも各項目の実装は進められる。表示書体と本文書体のフォントファイル（ライセンス確認済みのもの）。パネルとカードの装飾枠の9-slice画像（通常・選択の2種）。拠点ホームの5枚のカード用の挿絵。見せ場ごとの効果音（能力獲得・購入・売却・装備・強化・冒険クリア・敗北）と、カーソル移動音。通常の敵6種と古代遺跡・深緑の森林のボス10体の待機・動作の絵、地形テーマ4種の地形の絵（C6の差し替え口を使う）。

### 検証

各見せ場について、`capture_*.gd` で演出開始・25%・50%・完了の4時点を1600×900・1280×720・1920×1080で撮影し、人の目で確認する。Headlessのテストでは、状態と保存上の値が演出の開始前に確定していること、見せ場を決定・キャンセル入力で最終状態へ飛ばせること、入場演出の途中でも選択できること、非表示・解放時に表示層とオーバーレイが基準状態へ戻ることを検証する。ヒットストップと画面揺れは、戦闘の論理座標とターン順序を変えないことを既存の戦闘テストで確認する。
