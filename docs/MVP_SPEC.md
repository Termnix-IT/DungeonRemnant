# Dungeon Remnant MVP仕様

この文書は、Dungeon Remnantの現在のゲーム仕様です。ゲームは2026年10月に、ターン制のローグライクから、リアルタイムの見下ろしアクションに大量の敵との戦闘と周回ごとの育成を組み合わせたローグライトへ作り替えました。作り替えの経緯・計測結果・各Phaseの判断は [リアルタイム化_再設計計画.md](リアルタイム化_再設計計画.md) に残しています。MVPの完成条件と判定は [MVP受け入れ確認.md](MVP受け入れ確認.md) にあります。

---

## 1. ゲームの概要

プレイヤーは主人公ミオを操作し、拠点から章へ出撃します。章は分岐する層の連なりで、層ごとに2〜3個のエリアから1つを選んで戦い、最後の層でボスに挑みます。戦闘はリアルタイムで、移動・ダッシュ・コンボ攻撃・溜め攻撃・スキルを使い、時間とともに増える敵の群れを倒します。

ラン（1回の出撃）の中では、倒した敵の宝石で経験値を集めてレベルを上げ、レベルアップとエリアの報酬で「周回限定強化」を取って攻撃の挙動を変えていきます。強化はランが終わると消えます。ランで得た「残響」は勝っても負けても拠点へ持ち帰り、拠点で「永続強化」に使うと次のラン以降ずっと効きます。

1ランは約10分（フィールド約3分、アリーナ約2分を2回、ボス約2〜3分と、分岐と報酬の選択）を目安にしています。

---

## 2. 開発方針

- 操作の手応え（入力から攻撃が出るまでの速さ、命中の感触、回避の分かりやすさ）を最優先にする。調整値はすべて `data/` の `.tres` に出し、操作確認で決める。
- ルールは `step(delta)` で進む `RefCounted` に置き、Headlessのテストで固定の `delta` と固定のシードで検証する。Nodeは物理移動と描画だけを受け持つ。
- Autoloadは使わない。共有処理は `class_name` を持つstaticなScriptで提供する。
- 当たり判定とダメージは攻撃データの時間（予備動作・攻撃判定・硬直）だけで決まり、アニメーションはそれに合わせて再生するだけにする。描画方式を替えても戦闘の結果は変わらない。
- MVPに必要のない仕組み（汎用のスクリプト言語、ノードグラフ、外部Addon）は作らない・入れない。

## 3. 技術構成

| 項目 | 内容 |
|---|---|
| エンジン | Godot 4.7.2 stable、GDScript |
| レンダラー | Forward+（Windowsはd3d12）。撮影用Scriptは `gl_compatibility` でも動く |
| 画面 | 基準解像度1600×900（16:9）、Stretchは `canvas_items` |
| 物理 | 標準のGodot Physics 2D。主人公と敵は `CharacterBody2D`、攻撃の当たり判定は物理を使わず計算する（`HitQuery`） |
| 入力 | `project.godot` の `[input]` にInputMapとして定義し、エディターのInputMap画面から変更できる |
| ワールドの単位 | 1マス48px。戦場の床と柱は48pxの格子に置くが、主人公と敵は格子に縛られず自由に動く |

## 4. 操作

| アクション | キーボードとマウス | ゲームパッド |
|---|---|---|
| 移動（`move_*`） | WASD・矢印キー | 左スティック・十字キー |
| 照準（`aim_*`） | マウスの位置 | 右スティック（倒していなければ移動方向） |
| 通常攻撃（`strike`） | 左クリック | X |
| 溜め攻撃 | 左クリックの長押し | Xの長押し |
| 回避（`dash`） | Space | A・RB |
| スキル（`skill_1`） | Q | Y |
| メニュー（`pause`） | Esc | Start |

`skill_2`（E・B）はInputMapに定義済みで、2つ目のスキルを入れるときに使います。拠点とメニューは `ui_accept`・`ui_cancel`・方向の標準アクションで操作し、ゲームパッドでは十字キーでFocusを移し、Aで決定、Bで戻ります。

入力には先行入力（攻撃の硬直中に押した次の攻撃やダッシュを0.18秒覚えておく仕組み）があります。溜め攻撃は、押した瞬間に1段目の攻撃が出て、押し続けると押した時点から数えて溜めが進み、溜め終わってから離すと溜め攻撃が出ます。押した瞬間の反応を遅らせないためです。

## 5. 主人公のアクション

主人公の調整値は `data/hero/mio.tres`（`HeroTuning`）、攻撃の組み合わせは `data/movesets/sword.tres`、各攻撃は `data/attacks/` にあります。`HeroMotor` が入力から移動・ダッシュ・攻撃の状態遷移を計算し、`Hero` が物理移動と攻撃の発生を行い、`HeroView` がリグの向きとアニメーションを合わせます。

- 移動は加速・減速付きのアナログ移動で、最高速度は250px/秒です。溜めている間は速度が0.35倍になります。
- ダッシュは0.17秒で150px進み、0.22秒の無敵があり、0.45秒で再び使えます。回数は1回で、永続強化の「二段ダッシュ」で2回、「三段ダッシュ」で3回になります。
- 通常攻撃は3段のコンボ（`sword_combo_1`〜`3`）で、各段にキャンセルできる時刻があり、次の段やダッシュへつなげられます。
- 溜め攻撃（`sword_charged`）は、広い範囲を大きな威力で斬ります。
- スキル（`skill_ring`）は主人公の周り半径140pxを打つ範囲攻撃で、使うと6秒休みます。
- 被弾すると0.8秒の無敵になります（永続強化の「立て直し」で1.0秒）。最大HPは100で、永続強化の「鍛えた体」で増えます。

主人公の見た目は、カットアウトリグ（部位に分けたイラストを骨で動かす方式）で描きます。動きは各向きのリグの記述（`art/characters/mio_rig/<向き>_rig.json`）に骨のキーフレームとして持ち、`tools/build_character_rig.gd` でSceneにします。

| 動き | 使う場面 |
| --- | --- |
| `attack_sword` | コンボの1段目 |
| `attack_back` | コンボの2段目（逆向きの薙ぎ） |
| `attack_heavy` | コンボの3段目と溜め攻撃（大きく振りかぶる） |
| `attack_slam` | スキル（剣を頭上から地面へ叩きつける） |
| `brace` | 溜めている間の構え（繰り返す） |
| `dash` | ダッシュ（低く踏み込む） |
| `hurt` | 被弾（のけぞる） |

どの攻撃がどの動きを使うかは `AttackData.motion` で決め、リグにない動きは `attack_sword` で代用します。ダッシュ中は、その瞬間の姿勢を青く透けた残像として床に残し、0.26秒で消します。溜めている間は歩く動きを止めて構えたまま進みます。

## 6. 戦闘

`AttackData` が1回の攻撃を定義します（当たり形状は扇形・円・直線の帯、範囲、予備動作・攻撃判定・硬直の時間、キャンセルできる時刻、威力倍率、ノックバック、ヒットストップ、移動速度倍率）。`HitQuery` が攻撃の形と敵の位置から命中した敵を計算で求め、1回の攻撃で同じ敵に二度当たらないようにします。`Combatant` がHP・防御・無敵時間を持ち、`DamageInfo` を受けてダメージを確定します。主人公も敵も同じ仕組みで攻撃します。

命中の手応えとして、次の演出を出します。

- ヒットストップは `Engine.time_scale` を短く下げて戻します。同じフレームに命中が重なっても延長は1回に限り、大量戦闘中に動きが止まり続けないようにします。
- 敵の白い明滅、のけぞり（`hitstun`）、ノックバック、ダメージ数字、`StrikeEffect`（斬撃・衝撃・撃破の1枚絵を拡大・回転・明滅させる演出）を出します。
- 画面の揺れは設定の「画面の揺れ」で強さを変えられます。
- 円形の攻撃（溜め攻撃・スキル）は、届く範囲まで床に光の輪が広がります（`GroundRing`）。ダッシュの踏み出しには土煙、レベルアップで強化を取った直後には主人公の周りに光の柱が立ちます。
- 撃破と命中のエフェクトは種類ごとに同時表示数の上限を設け、効果音も短い間隔の重複を1つにまとめます。

敵の攻撃は、予備動作の間に攻撃の形が床に赤く描かれ、内側から埋まっていきます（`Telegraph`）。見てから避けるための予兆です。

状態異常は感電（4秒間、歩く速さが30%落ちる）と燃焼（3秒間、0.5秒ごとに攻撃力の30%）の2つで、周回限定強化から付きます。

効果音は `GameAudio` が鳴らします。攻撃は効果の種類ごと（斬撃・衝撃・魔法）、命中・撃破・宝石の取得（短い間隔の重複は1つにまとめる）、ダッシュ、溜め完了、連鎖する雷、炎や旋風の爆発、レベルアップ、エリアの開始、ボスの登場、ボスの第2フェーズ、エリアの制圧、敗北に音があります。同時発音は12音までです。録音素材のない音はコードで合成した音で鳴らします。戦場では、生成した低い風の音（`BattleAmbience`）を環境音として繰り返し、設定の「環境音」の音量に従います。

## 7. 敵

敵の定義は `data/foes/` の `FoeData`、行動は `FoeBrain`（追跡・飛びかかり・突進・たたきつけ・ボスのフェーズ）、本体は `Foe` です。図鑑に載せる敵の順と分類は `actors/foes/foe_catalog.gd` にあります。

| 敵 | 分類 | HP | 行動 |
|---|---|---|---|
| さまよう番兵 | 群れ | 30 | 群れで追いかけ、ぶつかって傷を負わせる |
| 疾走ネズミ | 群れ | 14 | 速く追いかけ、近づくと短い予兆のあとに直線で飛びかかる。予兆の間に攻撃を当てるとひるんで中断する |
| 猛る突進獣 | 精鋭 | 320 | 近くでは円のたたきつけ、離れると長い帯の突進。ひるまない |
| 遺跡王 | ボス | 1500 | 前方220度の薙ぎ払い、長い帯の突進、半径240pxの地震を距離に合わせて選ぶ。HPが半分を切ると第2フェーズに入り、歩く速さが1.3倍、攻撃の間隔が0.6秒になり、半径330pxの大地震が加わって、疾走ネズミ6体を呼び寄せる |

- フィールドでは `EnemyDirector` が出現表（`data/spawns/`）に従い、時間とともに同時に出す敵の数を増やし、カメラの外に出現させ、一定間隔で精鋭を送ります。倒れた敵はプールへ戻して再利用します。
- アリーナでは `WaveRunner` がウェーブごとに敵を出し、敵は床の紫の印のあとに現れます。
- 画面外の敵は、考える処理を4フレームに1回に減らし、アニメーションを止めます。
- 群れの敵（番兵とネズミ）は、リグのアニメーションを開発時に連番画像へ焼き出し（`tools/bake_foe_frames.gd`、`art/enemies/frames/`）、`AnimatedSprite2D` で描きます。精鋭・ボス・主人公はカットアウトリグのまま描きます。この使い分けで、敵200体でもフレーム時間を約2.8ms（RTX 3060、1600×900）に収めています。
- 倒れた敵は経験値の宝石を落とします。主人公から110px以内の宝石は吸い寄せられます。

## 8. ランの構成

### 8.1 章と分岐マップ

章は `ChapterData`（`data/chapters/ash_corridor.tres`「第1章　灰の回廊」）で、3層とボスからなります。`RouteMap` がランの開始時に分岐マップ全体を作り、各層に2〜3個の候補を並べます。最初の層はフィールドだけで、同じ層に「同じエリアで同じ報酬」の候補は並びません。どの候補からでも次の層のどの候補へも進めます。

分岐マップ（`RouteMapView`）は、ローグライトで定番のノードマップです。章の挿絵を暗くして敷き、その上の枠の中で、層を左から右へ並べ、各エリアを丸い節点（`RouteNode`）で示します。節点の絵はクリアで得る報酬（強化は光る籠手、回復はハート、残響は金貨、ボスは髑髏）で、下に形式と難易度（★3段階）を書きます。節点どうしは線でつなぎ、通ってきた道を明るく、今選べる道を金で、それ以外を薄く引きます。今の層の節点だけが明るく選べ、ほかは暗くなります（通った節点は金の輪）。右の詳細パネルに、選んでいる節点のエリア名、形式・難易度・目安時間、報酬、クリア条件、出現する敵の傾向と「このエリアへ進む」ボタンを出します。先の層の節点もマウスを合わせれば詳細を読めますが、進めません。操作は、マウスのクリック、矢印キー（十字キー）で選んでEnter（A）、または1〜3キーです。上部の帯には章の名前と、取得した強化の紋章・HP・Lv・残響を、その下に直前のエリアで得たものを出します。

### 8.2 エリア

エリアは `data/areas/` の `AreaData` です。

| エリア | 形式 | クリア条件 | 残響 |
|---|---|---|---|
| 苔むす平原 | フィールド | 2分30秒を生き延びる | 60 |
| 灰の荒野 | フィールド | 敵を150体倒す | 80 |
| 石柱の闘技場 | アリーナ | 3つのウェーブを全滅させる | 40 |
| 聖堂の試練 | アリーナ | 3つのウェーブを全滅させる（最後のウェーブに精鋭） | 70 |
| 守護者の間 | ボス | 遺跡王を倒す | 150 |

フィールドは約90×64マスの広い戦場に柱が散らばり、アリーナは固定の地形です。守護者の間では、入って1.5秒後に床の大きな印のあとにボスが現れ、画面上部にHPゲージ（`BossGauge`）が出ます。

エリアをクリアすると残りの敵は消え（宝石は落としません）、落ちている宝石はすべて主人公へ吸い寄せられ、1.4秒後に報酬へ進みます。HP・レベル・強化は次のエリアへ持ち越します。

### 8.3 報酬

報酬は「強化（3択から1つ）」「回復（最大HPの35%）」「残響（エリアごとの量）」の3つで、エリアごとの重み（`AreaData.reward_weights`）で抽選し、分岐マップのカードに先に示します。フィールドは残響、アリーナは強化が出やすく、ボスの報酬は必ず残響です。取れる強化が残っていない場合、強化の報酬は残響に替わります。

### 8.4 ランの終わり

ボスを倒すと踏破、HPが0になると1.6秒後に敗北、戦闘中のメニューから「ランを中断する」を確認して選ぶと中断で、ランが終わります。結果画面（`RunEndView`）は、ランのまとめの定番の形です。章の挿絵を暗くして敷き、見出し（踏破・敗北・中断）と終わった場所の一文、持ち帰った残響（大きな金の数字を0から数え上げる）、「拠点へ戻る」を常に出し、到達・戦った時間・撃破・レベルの4つのタイルと取得した強化の紋章の列は「詳しく見る」で開きます。残響は踏破・敗北・中断のどれでも全額を持ち帰ります。結果は拠点へ戻る操作の前に保存し、保存できなかった場合は結果画面にその旨を出します。

戦闘中のメニュー（`DungeonMenu`）は「戦いに戻る」「設定」「ランを中断する」の3つで、開いている間は戦闘が止まります。メニューの左には「このランの強化」として、取得した強化を紋章・名前・段階の行で並べ、指した（Focusした）強化の効果だけを一覧の下に出します。メニューから左キーで一覧へ移れます。

## 9. 周回限定強化

### 9.1 経験値とレベル

経験値は敵の宝石から得ます。必要経験値は `data/progression/action_levels.tres`（Lv2まで8、以後6ずつ増える）です。宝石は1つのノードでまとめて描き、300個を超えると近くの宝石に合算します。

レベルが上がると戦闘が止まり、強化のカードを3枚（永続強化の「四枚目の札」で4枚）出します（`AbilityChoice`・`AbilityCard`）。カードには強化の紋章、名前、新しく得る強化では「新規」（指すかFocusすると系統）、ランクを上げる強化では「Lv a → b」、効果の説明を出します。マウスと数字キーは開いた直後から受け付け、Focus（とEnter・A）は、レベルを上げた攻撃の連打で誤選択しないよう0.3秒後に最初のカードへ置きます。永続強化の「引き直し」を持っていると、カードの下の操作ガイドに「R 引き直す（残りn）」（ゲームパッドはY）が出て、1ランに決まった回数まで、出ているカードを引き直せます。エリアの報酬と旅立ちの加護のカードは3枚のままで、引き直せません。

### 9.2 強化の一覧

強化は `data/boons/` の `BoonData` で、効果は次の3種類の組み合わせです。

1. `StatBoon` は、攻撃速度・移動速度・最大HPなどの数値に加算や倍率をかける。
2. `AttackBoon` は、条件（コンボの何段目か、ダッシュ直後か、溜め攻撃か）に合う攻撃の写しを、攻撃の開始時に変える。元の攻撃データは変わらない。
3. `TriggerBoon` は、`CombatEvents` のイベント（命中・撃破・回避・スキル使用・被弾）に、範囲爆発か連鎖する雷で応える。連鎖が止まらなくならないよう、1物理フレームに発動できる回数を24回までにしている。

| 強化 | 系統 | 効果 | 最大ランク |
|---|---|---|---|
| 雷刃 | 属性・状態異常 | 通常攻撃・溜め攻撃・スキルが感電を付与する | 1 |
| 連鎖雷 | 属性・状態異常 | 感電した敵が倒れると、220px以内の敵へ雷が3体（ランクごとに+1体）まで飛び移り、感電させる。雷刃が前提 | 3 |
| 旋風斬 | 回避・範囲 | ダッシュの終わりに半径95pxを斬り払う | 3 |
| 残影の構え | 回避・範囲 | ダッシュ後0.6秒以内の攻撃が、開き300度・範囲1.25倍の大振りになる | 2 |
| 衝撃波 | 連撃 | 連撃の3段目が、敵を貫く斬撃の波を340px（ランクごとに+100px）飛ばす | 3 |
| 大溜め | 範囲 | 溜め時間がランクごとに15%短くなり、溜め攻撃の範囲が1.25倍になる | 3 |
| 業火 | 属性・状態異常 | 命中で燃やし、燃えている敵が倒れると半径80pxに炎が弾けて燃え移る | 3 |
| 剣速 | 連撃 | 攻撃の振りがランクごとに12%速くなる | 5 |

ランの状態（レベル・経験値・強化・HP・残響・撃破数）は `RunState` にまとめ、ランごとに作り直すため、次のランには何も持ち越しません。

## 10. 永続育成

### 10.1 残響と永続強化

残響はランで得る通貨で、拠点の「強化」で永続強化に使います。永続強化は `data/meta/` の `MetaUpgrade` で、中央の「残響の灯」（`MetaProgress.ROOT`）から枝分かれする強化ツリーの節です。各節は、それが伸びている元の節（`parent`）が段階1以上になると買えます。元の節を最後の段階まで上げる必要はありません。主人公の数値に効く節は、ランの開始時に主人公の数値の写しへ当てます（`MetaProgress.tuning`、元のデータは変えません）。ランの決まりごとに効く節は、`MetaProgress.lasting()` の値を `RunState.lasting` に写し、ランの中で読みます。

左の「身体」の枝はステータスを、右の「成長」の枝はレベルアップを強くします。上の「スキル」と下の「必殺技」の枝は、戦闘側の仕組みがまだないため、封印の印だけを置いています。価格の単位は残響です。

### 10.2 記録

`MetaProgress` は、残響、永続強化の段階、挑んだラン数、踏破数、最深到達の層、出会った敵を持ちます。ランの結果は `MetaProgress.record_run` で受け取ります。敵は、ランでその敵が戦場に現れた時点で「出会った」と記録され、図鑑に載ります。

## 11. 拠点

拠点（`Hub`）はロビーと3つの個別画面からなり、右上に残響の所持数を常に示します。

- ロビー（`HubLobby`）は左にメニュー（出撃・強化・図鑑・設定）、中央下に選んだ項目の情報パネル、右に主人公の立ち絵を置きます。出撃の情報パネルは章の名前・説明・挿絵、道のり（「3層とボス」）、最深到達、「第1章へ出撃する」のボタンを示します。ほかの項目のパネルは、強化できる数、出会った敵の数、音量などをそれぞれ示します。
- 強化（`MetaUpgradePage`）は、スキルツリーで定番の形です。左の石板の中に、透けない黒い面（`TreeWell`）を窓として置き、そこに窓より広い盤を載せて、中央の節から枝を伸ばします。節の紋章は60px、中央の節だけ84pxで、節の間隔は横108px・縦92pxです。名前や効果は選ぶと右の列に出るため、盤の紋章は小さく保ちます。節は紋章だけで描き、段階が複数ある節は下に目盛りを付けます。名前は盤に書かず、右の列に出します。各節は元の節と線でつなぎ、線は前提を満たすと少し明るく、習得すると最も明るくします。前提を満たさない節は紋章を暗くし、未開放の枝の封印は点線でつなぎます。選んでいる節は金の輪で示します。各枝の最初の節のそばに枝の名前を書き（下の封印だけは、上から線が来るため下に書く）、節が窓から完全に外れた枝は、窓の端に矢印と枝の名前で示します。この名前は板に載せず、窓の色で縁取った文字だけにします。板に載せると、窓の端まで延びる線の先を隠し、線が途中で消えたように見えたためです。
  - 盤はドラッグ（ゲームパッドは右スティック）で動かし、マウスホイール（ゲームパッドはLT／RT）で0.7〜1.8倍に拡大・縮小できます。ホイールはポインターの下の点を、LT／RTは窓の中央を動かさずに拡大・縮小します。盤は、節の全体に窓の半分の余白を足した範囲までしか動きません。Focusした節が窓の端から90pxの内側に入っていないときは、盤が220msでその節を追います。マウスで選んだときは盤を動かしません。
  - 矢印キー（十字キー・左スティック）は、押した向きの±60°にある節のうち、線でつながった節、近い節、上の節の順に選んで移ります。C（Y）で中央の節へ戻り、拡大率も1倍に戻します。マウスは節に少し合わせるかクリックで選び、押したまま8px以上動かすとドラッグになって、何も選びません。開いたときは、そのプレイ中に最後に選んだ節（初めは中央）を選びます。
  - 右の判断の列には、選んだ節の紋章、名前、枝と「段階 x / y」と目盛り、今と次の数値（未習得なら「習得すると」の数値）、効果、前提を満たさないときの案内（「『鍛えた体』を習得すると解放」）、次の段階の価格を書いたボタンを並べます。Enter（A）を節で押しても、このボタンと同じ操作になります。上限に達したものは「習得済み」、前提を満たさないものと残響が足りないものはボタンを押せない状態にし、Tooltipで理由を示します。封印を選ぶと、枝の名前と「この枝はまだ開放されていない」だけを出し、ボタンは出しません。
  - 購入は保存まで成功してから演出し（節の脈打ちと、新しく買えるようになった節の明るさの戻り）、保存に失敗した場合は購入を取り消します。
- 図鑑（`HubCodex`）は、モンスター図鑑で定番の絵のタイルの格子です。分類タブ（すべて・群れ・精鋭・ボス、Q／Eで切り替え）、出会った数、敵ごとのタイル（絵と名前、5列）を左に、選んだ敵の絵・名前・分類・数値・説明を右に示します。タイルの絵は敵の形にかかわらず同じ大きさの正方形に収め、足元をそろえるので、名前は全部同じ高さに並びます。出会っていない敵は、タイルを黒い影と「？？？」にし、数値と説明を隠します。
- 設定（`HubSettings`）は8項目（全体の音量・効果音・環境音・画面の揺れ・画面モード・操作の案内・ヘルプ・ゲームの終了）で、「サウンド」（音量3つ）「グラフィック」（画面の揺れ・画面モード）「その他」（操作の案内・ヘルプ・ゲームの終了）の3つのタブで切り替えます。タブはQ／E（ゲームパッドはLB／RB）かクリックで替わり、替えるとそのタブの先頭の項目にFocusが移ります。上下キーのFocusはタブの中だけを巡ります。選んでいる項目の名前と説明は、右の列に出します。変更はすぐに反映され、`GameSettings` が保存します。「操作の案内」は戦闘中の画面下の操作説明の表示を切り替えます。ヘルプは、設定画面を暗くした上に重ねる枠付きのウィンドウで開き、左に話題の一覧、右にその話題の本文を出します。閉じるには、Esc（ゲームパッドはB）のほか、窓の下の「閉じる」の案内か、窓の外の暗い部分をクリックします。ロビーのメニューと同じく、マウスを話題に少し合わせるとその話題が選ばれます。設定の項目も同じで、項目名か操作部品にマウスを少し合わせるとその項目が選ばれます。設定とヘルプでは、選んだ項目に枠を付けず、行の帯と左端の金の縦線だけで示します。「環境音」は戦場の風の音の大きさです。ヘルプはランの流れ・残響と永続強化・操作・図鑑の4つの話題を持ちます（`HubSettings.HELP`）。同じ設定画面を戦闘中のメニューからも開けます。

出撃すると `SceneTransition` が章の挿絵と名前を出し、分岐マップへつなぎます。旅立ちの加護を持っている場合は、分岐マップの前に強化を3択で1つ選びます。

## 12. セーブ

保存先は `user://progress.json`（`MetaStore`、形式は `MetaCodec` のversion 5）で、残響・永続強化の段階・挑んだラン数・踏破数・最深到達の層・出会った敵を保存します。強化ツリーの中央の節がなかったころのversion 5のセーブで何かを習得していれば、読み込むときに中央の節を習得済みにして、持っている節を前提ごと活かします。端末ごとの設定（音量・画面モード・揺れ・操作の案内）は `GameSettings` が別のファイル（`user://settings.cfg`）に保存します。

保存するのは拠点での購入、出撃の直前、ランの終了時だけで、ランの途中の状態は保存しません。保存は一時ファイルへ書いて読み戻して検証し、前の内容をバックアップしてから置き換えます。読めないデータは退避して保存を止め、拠点にその旨を示します。

旧形式（version 1〜4、ターン制のゲーム）のデータを読んだ場合は、最初の保存の前に旧ファイルを `progress.json.v4` として残し、所持Goldと旧永続強化に使ったGoldの合計を、4 Goldあたり残響1の割合で換算して引き継ぎます。出会った魔物は、同じ絵の敵がいるもの（番兵・疾走ネズミ・突進獣・遺跡王）だけ引き継ぎます。アイテム・装備・到達階・途中開始の解放は、新しいゲームに対応する概念がないため引き継ぎません。

## 14. UI

### 14.1 共通Theme

UIは `res://ui/theme/dungeon_theme.tres` をプロジェクト共通Themeとして使用する。暗色の面・明るい本文・控えめな金色を基調とし、通常面は低彩度の細い輪郭、選択と主要操作は金色の輪郭を使い、面の明度・余白・控えめな影で階層を示す。金色は、どこにでも使うと特別に見えなくなるため、次の2つの意味に限る。1つは「今選んでいるもの・押すべき操作」（選択枠・Focus・主要ボタン）、もう1つは「通貨と手に入れた価値」（残響の残高、獲得済みの段階の目盛り、勝利の見出し）である。能力値やエリアの情報は明るい本文色（`BodyLabel`・`ValueLabel`・`ItemNameLabel`）で示し、上昇は緑（`StatUp`・`PositiveLabel`）、下降と損失は赤（`StatDown`・`LossValueLabel`）で示す。規則の常設案内は控えめな色（`MutedLabel`）とする。参考アートは方向性の基準であり、実行時素材として使用しない。HUDのHPなど意味を持つ専用表示は別途維持する。

- 操作は `PrimaryButton`（主要操作）、`SecondaryButton`（戻る・補助操作）、`DangerButton`（取り消せない操作）、`ItemButton`（選択）、`GoldButton`（購入・成長）を使い分ける。
- 文字は画面名 `TitleLabel`（30px）、見出し `HeadingLabel`（24px）、項目名 `ItemNameLabel`（20px）、主要値 `ValueLabel`（26px）、本文 `BodyLabel`（18px）、説明 `DescriptionLabel`（18px）、補足 `MutedLabel`（16px）、価格 `GoldLabel`（21px）を使用する。ボタンは原則18px、補助操作は16px。画面ごとのフォントサイズ・色overrideは追加しない。
- 拠点のヘッダー・ページ・フッター、各画面の列はContainerで配置する。ただしロビー（`HubLobby`）は、背景の一枚絵と一体に見せるため、1600×900の画面全体へ直接配置する。`HubUI` はパネルとMargin・VBox/HBoxの構造だけを共通化する。基準内容幅1440px・高さ810px（1600×900の画面で左右に80pxずつ背景を残す）、画面端は最低20px相当を確保して縮小する。通常のパネル内余白24px、列間20px、縦間隔12px、密な詳細は8px。
- 外観の調整はTheme内の名前付きStyleBox（`MainSurface`、`SurfaceHover`、`FocusOutline`など）を編集する。同一のStyleBoxを共有するControlへ一括反映されるため、画面側で複製しない。Theme内の色項目とStyleBoxの色はGodot上では別プロパティであり、自動連動するパレットではない。

色の役割は背景 `#020305`、主面 `#252525`、浮いた面 `#2B2B2B`、一覧の内側 `#1C1C1C`、Hover `#363636`、選択面 `#26241A`、通常境界 `#525252`、選択境界 `#B89759`、金 `#D6B77B`、本文 `#EEE9DF`、説明 `#C9C9BF`、補足 `#B2B3AA`、減少 `#DB857A`、増加 `#91C2A3` とする。拠点背景の画像は暖かい光を残し、上に重ねる中立色の暗幕を薄くして石造りの奥行きを見せる。主パネルは青みを含まない不透明な石墨色で背景と分離する。

画面上の用語は日本語に統一する。1回の出撃は「ラン」、通貨は「残響」、周回限定強化は画面上では「強化」、永続強化は「永続強化」と書く。通貨の量は数字だけ（例：残響 160）で示し、Lvは「Lv 3」、層は「第2層」と書く。ロゴは「Dungeon Remnant」と単語の間を空ける。

書体は、日本語のゲームで定番の「題名は明朝、本文と数字はゴシック」の組み合わせとする。表示書体はSIL Open Font Licenseのしっぽり明朝（Bold・Medium、`ui/fonts/`）とし、`TitleLabel`・`HeadingLabel`・結果の見出し・ロゴ・中央の知らせの帯（`HudBanner`）・通貨（`PurseValue`）・ロビーの数値（`LobbyFactValue`）に当てる。本文・ボタン・数値は、同梱したSIL Open Font LicenseのBIZ UDPゴシック（Regular・Bold、`art/third_party/biz_udp_gothic/`）とする。ThemeのDefault Fontを Regular にし、数値の役割（`ValueLabel`・`HudValue`・`StatValue`・`SettingsValue`・`PriceLabel`・`OptionCycler` など）と項目名（`ItemNameLabel`）・主要ボタン（`PrimaryButton`・`PrimaryAction`）は Bold にする。端末に入っている書体に頼らないため、どのPCでも同じ見た目になる。本文と説明は行間を6px空ける。Themeの `FontVariation` でOpenTypeの `palt` を有効にし、小書きカナの字間が開かないようにする。2行に収まる日本語の説明は `TextWrap` で中央付近の助詞・句読点の後に改行を入れ、最終行に1〜2文字だけが残らないようにする。大きなパネルの地は `art/ui/` の9-slice装飾枠を使う `StyleBoxTexture` とする。

### 14.2 動き

操作の時間変化は `ui/ui_motion.gd` の `UIMotion` で管理する。色・枠線はThemeに残し、scaleとalpha、選択カードの内側金枠の強さ、HPの残像ゲージの表示値を動かす。Controlごと・プロパティごとに前のTweenを停止し、非表示・解放時に基準値へ戻す。Containerの位置や最小サイズはアニメーションせず、位置の動きが必要な場合は表示層を動かす。表示層とは、Containerが配置するControlの内側に置いた、Containerの管理を受けない見た目用のControl（`mouse_filter` はIgnore）であり、その `position`・`scale`・`modulate` だけをTweenする。

各画面に「プレイヤーの選択が結果に変わる瞬間」を1つだけ定め、その瞬間の演出を最も手厚くする。これを見せ場と呼ぶ（強化カードを取る瞬間、永続強化を買う瞬間、ランの結果が出る瞬間）。見せ場以外の操作は控えめな反応にとどめる。演出の時間は3段階に分け、Hover・Focus・押下などの反応は80〜120ms、画面・パネル・選択詳細の入れ替わりなどの遷移は180〜260ms、見せ場は400〜900msとする。入場は `TRANS_CUBIC` の `EASE_OUT` を基本とし、見せ場の強調だけ `TRANS_BACK` の `EASE_OUT` で最大1.05倍までのオーバーシュートを許す。退場は120msの `EASE_IN` とし、退場中も次の画面が入力を受け付ける。

残響や撃破数など結果の数値は、状態と保存上の値を即時に確定させたうえで、表示だけを前の値から新しい値へ数えて見せる。購入の成功演出は保存まで成功してから始め、UIのTween完了をゲーム処理から待たない。開いた直後の誤選択は、キーリピート（`echo`）を受け付けないことで防ぐ。

拠点の画面切り替えでは、ページ全体を表示層として扱い、16px横から180msで入場させる。奥の画面へ進むときは右から、ロビーへ戻るときは左から入る。

### 14.3 個別画面のUI文法

拠点の個別画面（強化・図鑑・設定）は、次の共通ルールに従う。画面ごとに作法が違うと、同じ操作でも毎回探し直すことになり、ロビーで整えた雰囲気も画面を開くたびに途切れるためである。ロビーはこの対象に含めない。新しい個別画面を足すときも、この節に合わせる。

**画面の骨格。** すべての個別画面を上段・本体・下段の3段で組む。上段は左に画面名（`TitleLabel`）だけを置き、右に残響の表示を置く。本体は主要パネル1〜2枚とする。下段は左端に操作ガイドを置く。上段と下段はページ本体（1440×810）の内側ではなく、画面の端を基準に置く（左右40px、上22px、下16px、`Hub.EDGE_X` など）。

**メインコンテンツパネルは1枚の静かな面。** 拠点の個別画面の本体は、ポップアップの窓と同じ静かな面（`QuietWindowStyle`）の1枚のパネルとし、画面の左右端から40pxずつ空けて置く。左の選ぶ場所（`SlabSolid`）と右の判断の列（`SlabSolidEnd`）は同じパネルの2列で、間を1本の細い縦線で区切り、上端の金の細線は2列にまたがって続く。石の質感と青銅のレールは使わない。パネルの中の区切りは金の細線（`HubUI.rule()`）と余白で付ける。

**画面の型は定番に合わせる。** 画面の配置は独自に考えず、多くのゲームで使われている形式に合わせる。プレイヤーがほかのゲームで覚えた読み方と操作がそのまま通じるようにするためである。今の対応は、戦闘HUDがアクションローグライトとサバイバー系の配置、分岐マップがノードマップ、結果画面がランのまとめ、永続強化がスキルツリーと詳細の列、図鑑が絵のタイルの格子と詳細パネル、設定が見出しで分けた行と説明の列、戦闘中のメニューが一時停止画面とビルドの一覧である。他のゲームの絵・枠・アイコンはまねず、色と書体と枠の素材はこのThemeのものを使う。

**選ぶ場所と判断の列。** 選んで決める画面（強化・図鑑・設定）は「選ぶ場所（左）＋判断の列（右）」で組み、右の列は画面の右端まで延びる石板（`SlabSolidEnd`）に、上から絵や名前、数値、説明の順で並べる。強化の選ぶ場所は強化ツリーの盤とし、主要操作（購入）は右の列の下に1つだけ置く。左の石板は不透明な `SlabSolid` とし、背景の絵の上に文字を直接載せない。

**金色の用途。** 個別画面の金色は、①選択中とFocus、②主要操作、③通貨の3つに限る。③の通貨は、残響の残高と、今の判断に関わる値だけを金とする。

**等間隔の格子と埋め込みパネルを避ける。** 同じ大きさの箱を同じ隙間で縦横に並べると、表計算やフォームのように見える。まとまりの中は詰め、まとまりの間は大きく空け、大事なものだけを大きくして、間隔に強弱を付ける。箱の中に箱を重ねない。ただし強化ツリーの盤だけは、パネルの中の透けない黒い面（`TreeWell`）に置く。動かせる盤が石板の質感に重なると、節と線が背景に紛れるためである。

**主要操作は1つ。** 1画面（強化では1行）に主要操作は1つとし、`PrimaryAction`（`HubUI.primary_action()`）か `PrimaryButton` で作る。見た目は静かな札（金を薄く敷いた面と1pxの金の縁、指すと少し濃く、押せないときは縁も面も消えかける）とし、装飾の金具は使わない。ロビーの出撃ボタンだけは、ロビーの絵と一体の装飾の札（`LobbyAction`）を残す。そのほかの操作は `SecondaryButton` とする。押せないときは理由をTooltipで示す。

**戻るは全画面で左下、操作ガイドとして示す。** 下段の左端に、キーの記号と動作を並べる操作ガイド（例：`Esc 戻る`　`Enter 決定`）を置く。ボタンの枠には入れず、記号の部分を押しても同じ操作になる。キーボードとマウスの間はキーの名前を文字だけで書き、ゲームパッドの操作中だけ記号を札（`B`・`A`）にして示す。部品は `KeyGuide`（`add_hint()` でキーの記号・ゲームパッドの記号・動作を渡す）。

**文字の階層を固定する。** 1つのまとまりの中は、見出し（`HeadingLabel` 24px）→ 主要数値（`ValueLabel` 26px）→ 補足（`MutedLabel` 16px）の順に並べ、1つのパネルの中で使う文字の段階は、見出し・主要数値・本文・補足の4段階までとする。

**通貨の強弱。** 残響の表示は全画面で同じ位置（ロビーと同じ右上）に置く。通貨を使う画面（強化）では今の強さで示し、それ以外の画面では大きさと明るさを落として控えめにする（`GoldPurse.quiet`）。位置を変えたり隠したりしないのは、残高を確かめたいときに探さずに済むようにするためである。

**説明の置き場所。** 画面には、その場で選ぶ・決めるために要る情報（名前・数値・条件・価格・結果）だけを置き、ゲームの決まりごとや操作の説明を文章で常に並べない。
- 詳しい説明は、設定画面の「ヘルプ」に話題ごとにまとめる（`HubSettings.HELP`）。ここに書く内容は、ゲームの実際の規則と一致させ、規則を変えたら一緒に直す。
- その場で知らないと困る決まりごとは、見出しの横の小さな「?」（`HintMark`）にする。マウスを合わせると1行のTooltipで規則を示し、押すとヘルプのその話題を開く。
- 部品の補足は、その部品のTooltipに短く置く。操作ガイドに出ている操作は、画面の文章で繰り返さない。

**背景とキャラクターは全部を見せようとしない。** 背景の絵と主人公の立ち絵はロビーで全体を見せているため、個別画面では背景を雰囲気の役とし、パネルの外の上段と下段にだけ見せる。

**情報は「常時表示／開いた時だけ／別画面」に分ける。** その場で判断に要る情報だけを常に出し、詳しい情報は選んだとき・指したとき・「詳しく見る」で開いたときにだけ出し、決まりごとの説明はヘルプ（別画面）に置く。表示から外した情報も、この3つのどれかの導線で必ず読めるようにし、機能は消さない。キー・マウス・ゲームパッドのどれでも同じ情報に届くようにする。

| 画面 | 常時表示 | 開いた時だけ | 別画面 |
| --- | --- | --- | --- |
| 確認 | 質問、結果の一文、2つの選択肢 | ― | ― |
| 強化ツリー | 節の紋章・段階の目盛り・つながり、枝の名前、残響 | 選んだ節の数値・効果・前提・価格 | ヘルプ |
| 戦闘中のメニュー | 3つの操作、強化の紋章・名前・段階 | 指した強化の効果 | ヘルプ |
| 強化カード | 紋章、名前、効果、新規か段階か | 新規の強化の系統 | ― |
| 分岐マップ | 節点（報酬の絵）、HP・Lv・残響 | 選んだ節点の条件・敵・目安時間 | ― |
| 結果 | 勝敗、持ち帰った残響、次へのボタン | 統計のタイルと取得した強化（「詳しく見る」） | ― |
| 操作ガイド | キーの名前（文字だけ） | ゲームパッドの操作中のボタンの札 | ― |

**枠線は必要な箇所だけに絞る。** 枠を付けるのは、主要操作（`PrimaryButton`・`PrimaryAction`）、選択中とFocus中の項目、取り消せない操作の確認（`DangerButton` の細い赤枠）だけとする。通常の操作（`SecondaryButton`）は文字だけとし、指したときは淡い帯、Focus中は左端の金の縦線と淡い帯で示す。窓の中に箱を重ねず、区切りは細線（`HubUI.rule()`）と余白で付け、まとまりを示したいときだけ枠のない淡い面（`QuietSection`）を使う。

**項目カードは共通の1つの形。** 一覧の1件（図鑑のタイル、レベルアップの強化カード、結果の統計のタイル）は、同じカードの面とする。普段は枠のない淡い面（`CardSurface`・`CardButton` の通常）、指すと少し明るく、Focus中は明るい本文色の細い縁（`CardSurfaceActive`・`CardButton` のFocus）、選んだものは金の枠とする。カードに常に出すのは絵・名前・主な数値と主要操作だけとし、説明や条件は選んだときに右の判断の列か、カードの中の「開いた時だけ」の欄に出す。強化カードは、上端の色の帯で新規（青）と段階上げ（琥珀）を示す。

**ポップアップの窓は静かな面にする。** 確認・ヘルプ・戦闘中のメニュー・強化カード・分岐マップ・結果の窓は `QuietWindow`（`QuietWindowStyle`：暗い半透明の面、細い縁、上端だけ中央が明るい金の細線、下へ落ちる淡い影）で作り、装飾の金具は使わない。強化カードも共通のカードの面を使う。

**状態表現の共通化。** ボタン・カードなどの部品ごとに、通常・Hover・Focus・選択中・押下・無効の6つの状態を全画面で同じものにする。選択中は金の枠、Focusは明るい本文色の細い縁と軽い拡大で示し、ゲームパッドで「今どこにいるか」と「何を選んだか」を見分けられるようにする。Focusの縁は全部品で共通の1つ（`FocusOutline`。面を塗らず、下の状態を隠さない）とする。行を選ぶ一覧（設定の項目、ヘルプの話題、戦闘中メニューの強化）は、尖った帯や枠を使わず、行全体の淡い暖色の帯と左端の金の縦線で選択を示す。

**普段の動き。** 画面を開いたとき、部品を一度に出さず順に入れる（`play_entrance()`。拠点が画面を開くときに呼ぶ）。メインコンテンツパネルの右の判断の列（図鑑の敵の説明、設定の項目の説明、ヘルプの本文）は、示す内容が替わるたびに、右から40pxの位置から淡く入って0.2秒で定位置に収まる（`UIMotion.slide_in()`）。示す内容が同じとき（同じ項目をもう一度選んだとき、クリックがFocusと押下の2回として届いたとき）は動かさない。列は内容を自分の枠の中で切り取るので、左の列の上へははみ出さない。選択の光の帯と、文字タブの金の下線は、前に選んでいた場所から新しい場所へ0.12秒で滑って移る（`UIMotion.follow_mark()`、`TabUnderline`）。見せ場より目立たせず、入力は動きの途中でも受け付ける。

**数値の表記。** 3桁ごとに区切り（1,280）、通貨の表記は `UIFormat.amount()` で作る。変化は「現在 → 変更後」で示す。

### 14.4 ラン中の画面

- 戦闘のHUD（`ActionHud`）は、アクションローグライトとサバイバー系で定番の配置にし、中央の主人公の周りを空ける。上端に経験値の帯と、その右端にレベル。上中央にエリア名、目標の文（`HudObjective`）、目標の進み具合の帯（ボスが現れたら、同じ位置にボスのHPゲージが代わりに出る）。左上に取得した強化を紋章（40px）と段階の数字で並べる。右上に撃破数とこのランの残響。左下にHPの数値と帯（減った分は明るい残像が少し残ってから追いつく。`UIMotion.update_vital`）。右下に攻撃・回避・スキルの丸い枠（`ActionSlot`）を並べ、それぞれの紋章、キー（ゲームパッドで遊んでいる間はボタン名）、再使用を待つ間の暗い扇、ダッシュの残り回数の点、溜めている間の輪を示す。画面下に枠にない操作の案内、中央の上寄りにエリア名・制圧・敗北・ボスの激昂を知らせる帯（`BannerBand`・`HudBanner`）を置く。sandboxでは、右上の下に敵の数・FPS・出現の状態を出す。
- HPが最大値の30%以下になると、画面周辺を赤く脈打たせる。残りが少ないほど濃く、速く脈打ち、回復すれば消える。色は共通Themeの `HpCaption` から取り、入力は妨げない。
- レベルアップの強化カードは横並びの3枚（永続強化で4枚）とし、取った瞬間を見せ場にする。報酬の強化と旅立ちの加護も同じカードで選ぶ。強化と永続強化の紋章は、それぞれ専用の絵（`art/emblems/<強化のID>.png`）を使う。
- 分岐マップと結果画面は、章の挿絵を暗くした上の画面中央に置く。
- 戦闘中のメニューは戦闘を止めた上に重ねる。
- 確認（`ChoicePrompt`）は、ゲームで定番のモーダルの形とする。画面全体を暗くして後ろの操作を止め、中央の枠に見出し・質問・結果の説明と、左に戻る・右に進むの2つのボタンを置く。取り消せない操作（ゲームの終了、ランの中断）を確かめるときは、進むボタンを細い赤枠と赤い文字（`DangerButton`）にして、最初のFocusを戻るボタンに置く。Enter・Aで決定、Esc・Bで戻る。拠点の確認も同じ部品を使う。

## 16. MVPの範囲外

探索・イベントフィールド、必殺技、2つ目のアクティブスキル（強化ツリーの封印した2枝はこの2つを育てる場所として置いている）、武器種の解放、遠距離攻撃の特殊敵、アイテムと装備、2つ目以降の章は、MVPの完成条件に含めず、MVP後の候補とする。
