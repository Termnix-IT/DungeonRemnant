# Godot 2Dローグライク MVP開発仕様 Ver.0.1

## 1. プロジェクト概要

Godotを使用して、2D見下ろし型・ターン制のローグライク／ローグライトゲームを制作する。

「不思議のダンジョン」系の探索・レベルリセット・ランダム生成をベースにしつつ、

- 武器ごとに異なる攻撃範囲
- 8方向を利用した位置取り
- 障害物・地形を利用した戦闘
- Fog of War
- 敵ごとに異なる索敵特性
- レベルアップ時の3択能力
- 拠点による微小な永久成長

を特徴とする。

MVPでは「1回の冒険を開始し、ダンジョンを探索・戦闘・成長し、死亡またはクリアして拠点へ戻る」というゲームループの完成を最優先とする。

---

# 2. 開発方針

## 最重要方針

MVPでは必要最小限の機能のみ実装する。

将来の拡張を妨げない構造にはするが、将来機能を先回りして実装しない。

以下は禁止する。

- 要求されていない機能の追加
- 過剰な抽象化
- 不必要なデザインパターン導入
- MVPで使わないシステムの実装
- Hardモードの先行実装
- オンライン機能
- マルチプレイ
- 実績システム
- 課金システム
- 複雑なクラフトシステム
- 高度すぎる敵AI
- 大規模なストーリーシステム

実装前には必ずPlanを提示し、変更対象・新規ファイル・実装内容を説明すること。

ユーザーの承認なしに仕様を拡張しないこと。

# 4. ターンシステム

基本ルール：

1. プレイヤーが行動
2. プレイヤーの行動が確定
3. 1ターン経過
4. 敵が行動
5. プレイヤー操作へ戻る

ターンを消費する行動：

- 移動
- 攻撃
- アイテム使用
- その他、ゲーム世界へ直接作用する行動

ターンを消費しない操作：

- インベントリ確認
- ステータス確認
- マップ確認
- 攻撃方向選択
- 攻撃範囲確認
- 攻撃キャンセル
- Main / Sub武器切り替え
- 武器・防具・アクセサリーの装備変更

安全な探索済み区間では、移動キーを押し続けると通常入力の後に連続移動する。連続移動の各1マスは通常の移動と同じく1ターンを消費し、敵も1マスごとに行動する。敵を視界内に発見、未探索マスの直前、アイテムまたは階段の発見、分岐への到達、既知のアイテムまたは階段の直前、移動入力の解除、UI表示、攻撃モードへの移行のいずれかで停止する。停止後は新しい移動入力が必要となる。

連続移動は同じ方向への入力反復だけを行い、自動探索・経路探索・分岐選択は行わない。

# 7. 武器システム

武器ごとに攻撃範囲そのものが異なることを本ゲームの主要な特徴とする。

## 想定武器

### 剣

- 射程：1
- 指定方向と左右隣の計3方向を同時攻撃
- 隣接した複数敵への対応

### 槍

- 射程：2
- 直線攻撃
- 間合い管理に優れる

### 斧

- 短射程
- 高威力
- 前方複数マスへの攻撃候補

### 大剣

- 前方横方向への広範囲攻撃
- 複数敵への対応

### 短剣

- 射程：1
- 低威力
- 将来的に連続攻撃・背面攻撃などを追加可能

### ハンマー

- 射程：1
- 生存した敵を最大2マスノックバック
- 途中に壁・敵・マップ外・斜めの角があれば、移動可能な距離まで押す

### 斧

前方2マスの固定範囲を攻撃し、剣より高火力にする。槍のレベル上昇による射程拡張は適用しない。

### 弓

- 遠距離直線攻撃
- 射程4～6程度を想定
- 将来的に弾薬システム対応可能

### 杖

杖ごとに1枚の魔導スクロールを装着し、MPを消費して魔法を使う。未装着時は剣型の低威力近接攻撃。初期魔法は直線攻撃・範囲攻撃・回復の3種類。

スクロールは購入・敵のレアドロップで入手する。装着中は装備の一部として保護し、未装着なら通常の所持品としてロスト対象にする。操作と数値は[開発メモ](../rogue-like-play/開発メモ.md)の「杖と魔法」を参照。

# 9. 防具・アクセサリー

装備枠：

- Armor ×1
- Accessory ×2

装備中アイテムは死亡時ロスト対象外とする。

## 防具の役割

基本的には、

- 防御力
- 属性耐性
- 軽度の特殊効果

を担当する。

## アクセサリーの役割

コンテンツ追加では、購入・敵ドロップで得る消費型アクセサリー（護符）を追加する。通常の床配置には含めない。既存の装備型は互換性のため保持する。

同じ効果の再使用は不可。ターン継続バフは異なる5種類まで、フロア継続効果は枠外。使用不可時は消費せず、帰還時は全効果を終了する。ダンジョンでは、発動中の効果を階層・Goldパネルの下の「効果中」パネル（`HudEffects`）に1件1行で示し、記号・名前・残りターン（フロア継続は「この階」）を並べる。残り5ターン以下は赤で示し、効果がない時はパネルを隠す。冒険終了時は、止めの一撃を見せ終えるまで最後の一覧を残す。具体的な種類・数値と追加敵の挙動は[開発メモ](../rogue-like-play/開発メモ.md)の「追加の敵と消費型アクセサリー」を参照。

# 17. ダンジョン

ランダム生成されたフロアを探索する。

現在のコンテンツ構成：古代遺跡と深緑の森林を各50階とする。10・20・30・40Fに中ボス、50Fに最終ボスを配置する。ボス階は2つのマップで構成する。降りた先は敵とアイテムのない小さな前室で、奥の守護者の扉（赤と金の封印のある両開きの扉）に乗って確認すると、同じ階のボス部屋へ進む。前室には戻れない。ボス部屋は柱の立つ横長の広間で、ボスだけが待つ。前室もボス部屋も、入口から右へ7マスの所に扉とボスを置き、到着した時点で視界と画面に入るようにする。ボス撃破まで階段は使用できず、撃破後はボスのいた場所に次への階段（金縁の石枠と青白い光の階段）、ボス部屋の入口に戻る扉（青緑の光の石のアーチ。脱出口）が開く。この3つは通常の階段タイルではなく、床の上に専用の絵（`art/tiles/guardian_door.png`・`descent_stairs.png`・`return_door.png`）を重ねて描き、探索済みで視界外のときは暗くする。遺跡の最終ボス撃破で森林を開放し、その先は「？？？」として表示する。

## 地形の表示仕様

テストプレイ時の視認性と雰囲気を整えるため、フロア地形は暗い青灰色の石造ドット絵で表示する。

- 1 Tileは32×32pxとし、16×16px相当のドット絵をNearestで2倍表示する
- 床には少数の模様差分を用意し、座標に基づいて固定選択する
- 壁は上下左右の接続状態を16通りのタイルへ対応させ、連続した輪郭として表示する
- 階段は暖色の金色、Pillarは床と区別できる石柱として表示する
- Fog of Warの現在視界・探索済み表示は既存の明暗差を維持する
- 1～3Fは青灰の遺跡、4～6Fは苔むした洞窟、7～9Fは灼熱の深層、10F以降は黒曜の聖域として配色を切り替える
- 各テーマは同じタイル形状を共有し、地形ルールや当たり判定を変更しない

森林では苔色の床と木々の装飾を使用する。当たり判定と視界のルールは遺跡と共通。

# 18. Dungeon Layout

通常の階は、四角い部屋を通路でつないだ構成（Room）だけで生成する。以前は不規則な洞窟（Cave）と障害物のある広間（Open Area）も階ごとに切り替えていたが、部屋と通路の構成に限定した。ボス階の前室とボス部屋は生成せず、固定の配置とする（17章）。

---

# 19. 特殊フロアと将来的なマップタイプ

モンスターハウスは通常フロアで暫定5%の確率で生成する。7×7の部屋に敵8体・アイテム8枠を追加し、床の色と発見ログで危険を伝える。床はマスごとの枠線で囲まず、暖色の薄い染み、一部のマスの爪痕、部屋の外周だけに引いた燻った色の線で「荒らされた部屋」として見せる。ボス階では生成しない。ショップ・ドロップ限定品は床配置に含めない。

入室や通路を封鎖しないため、配置次第では回避・撤退できる。開始地点がモンスターハウス内になるケースも意図した不意打ちとして許容する。部屋と通路だけの構成では、ハウスが唯一の通路上に置かれると避けられなくなる。そのため、開始地点がハウスの外にある場合は、階段もハウスの外にあり、ハウスを通らずに階段へ行ける配置だけを採用する。条件を満たす位置が6回の試行で見つからなければ、その階にはハウスを置かない。

以下は将来の追加候補。

- Maze
- Island
- Bridge
- Trap Floor
- Treasure Floor
- 特殊環境フロア

# 25. MVP Enemy Detection

MVPでは複雑にしない。

最低限：

- Vision型
- Proximity型
- Fixed/Turret型

程度から開始する。

HearingやShared AlertはMVP対象外。

通常敵は遺跡で各階3体、森林で4体を基本とし、Vision・Proximity・Turret・高速型・召喚型を巡回配置する。10階ごとに別途ボス1体を追加する。深度ごとに通常敵を強化し、森林は遺跡より補正を1段階高くする。

Turretは1敵ターン予告した後、同じ位置・方向から射線が通る場合に射撃する。予告中は長い白線を表示する。射線から外れる、射程外へ出る、遮蔽物が入ると予告を解除する。射撃後およびノックバック後は再予告が必要。装備・UIなどの無料操作では予告は進まない。

# 31. Permanent Upgrade

拠点のスキルツリーは、基礎HP（3段階）から生命力・攻撃力・魔力量・防御力の4本の枝が延び、各枝は複数の段（生命力 I〜IV、攻撃力 I〜IV、魔力量 I〜III、防御力 I〜III）を順につないだものとする。基礎HPを上限まで育てると4本の枝の最初の段が開き、各段を上限まで育てると次の段が開く。各枝の段は1本の価格の並びを続けて分けたもので（例：生命力は段をまたいで100・150・200…Gold）、枝全体の上限と効果の合計は、段に分ける前の1つの強化（生命力20段階・攻撃力20段階・防御力10段階・魔力量10段階）と同じにしている。段の構成と前提条件・価格は `data/upgrades/` のResourceと `SkillCatalog.BRANCHES` で調整する。セーブの版4より前の、枝を1つの強化として保存したデータは、読み込み時に作られた当時の条件で検査したうえで、その段階数を枝の段へ順に振り分ける。当時は基礎HP Lv 1で開いた攻撃力・魔力量を育てていた場合は、枝を失わせないよう基礎HPを上限に引き上げる。

ステータス強化とは別に「ダンジョン途中解放」の枠を設ける。各ダンジョンの10・20・30・40F中ボス撃破後、コインで対応する11・21・31・41F開始を解放する。価格は暫定150・350・600・900 Gold。条件と解放はダンジョン別に保持する。

途中開始はLv1で、永久強化と持ち込み装備を適用する。深層は永久強化を前提とする一方、1Fから時間をかけて育成する攻略も可能とする。

# 33. 死亡時ペナルティ

## Level

## Ability

すべてリセット。

## Gold

所持Goldの50%を失う。

## Inventory

非装備アイテムのおよそ50%をランダムに失う。

## Equipped Items

以下の装備中5枠は必ず保持する。

- Main Weapon
- Sub Weapon
- Armor
- Accessory 1
- Accessory 2

Inventory内にある予備装備はロスト対象になる。

# 34. Item Loss

Inventory内のロスト対象の所持枠から、半数（奇数は切り上げ）をランダムに選択して消失させる。選択された枠はスタック全体を失う。

例：回復薬×10、爆弾×6、毒消し×2の3枠なら、ランダムな2枠を全個数失う。

装備中アイテムは抽選対象外。死亡・中断・滞在上限による強制帰還に共通して適用する。Goldは半額を失い、損失の端数は切り捨てる。

# 36. Safe Return

最終階以外の10Fごとの中ボス撃破後、フロア入口に脱出口を出す。脱出口に乗り確認で「帰還する」を選ぶと、Gold・Inventory・Equipmentを保持して帰還する。消費アイテムは不要。

各フロアの滞在上限は暫定5000ターンで、次階への移動と、ボス階の前室からボス部屋への移動でリセットする。ボス階にも適用し、中ボス撃破では一度だけ150ターン延長する。残り30%・20%・10%・100ターンでイベントログに警告を出す。上限で強制帰還し、通常の損失を適用する。

階段では確認後に次階へ移動する。確認は共通Themeの `ChoicePrompt` で画面下寄りに出し、主人公と周囲を隠さない。「降りる」「とどまる」を選び、Escとゲームパッドのキャンセルでも留まる。ボタン名に「（Esc）」のような括弧書きのキーは付けず、ボタンの下に拠点と同じキーの図（`KeyGuide`、「Enter 決定」「Esc 戻る」。ゲームパッドではA・B）を置く。確認・キャンセルやメニュー閲覧でターンは進まない。同一マス上で確認を繰り返さず、再進入時に表示する。上限と重なる場合の優先順は階段移動、ボス撃破、脱出、強制帰還。死亡時は移動・脱出できない。

# 40. 設計上の注意

Godotの責務を適切に分離する。

候補：

TurnManager
RunManager
DungeonManager
Player
Enemy
Inventory
Equipment
AbilitySystem
FogOfWar
SaveManager

ただしMVP段階で必要のないManagerを大量に作らない。

巨大なGameManager一つにすべてを詰め込むことも避ける。

UIは `res://ui/theme/dungeon_theme.tres` をプロジェクト共通Themeとして使用する。暗色の面・明るい本文・控えめな金色を基調とし、通常面は低彩度の細い輪郭、選択と主要操作は金色の輪郭を使い、面の明度・余白・控えめな影で階層を示す。金色は、どこにでも使うと特別に見えなくなるため、次の2つの意味に限る。1つは「今選んでいるもの・押すべき操作」（選択枠・Focus・主要ボタン・有効な装備枠）、もう1つは「お金と手に入れた価値」（Gold残高・取引額・収支、獲得済みの段階の目盛り、勝利の見出し）である。拠点の個別画面では、後述「個別画面のUI文法」によりお金の金色をさらに絞り、一覧の各行の価格は本文色とする。アイテムの効果、能力値、ステージの階数と難易度、移動の方向、キャラクターの台詞は情報として明るい本文色（`BodyLabel`・`ValueLabel`・`ItemNameLabel`）で示し、上昇は緑（`StatUp`・`PositiveLabel`）、下降と損失は赤（`StatDown`・`LossValueLabel`）で示す。冒険結果の数値のうち、今回獲得と残高だけが金（`MoneyValueLabel`、`GoldLabel` から色を受け継ぐ）となる。規則の常設案内は控えめな色（`MutedLabel`）とし、操作の結果だけを本文色で示す。参考アートは方向性の基準であり、実行時素材として使用しない。拠点・ショップ・装備・倉庫・永久強化・出撃準備はこのThemeの役割を使用し、HUDのHP・MPなど意味を持つ専用表示は別途維持する。

- 操作は `PrimaryButton`（主要操作）、`SecondaryButton`（戻る・補助操作）、`ItemButton`（選択）、`GoldButton`（購入・成長）を使い分ける。
- 文字は画面名 `TitleLabel`（30px）、見出し `HeadingLabel`（24px）、項目名 `ItemNameLabel`（20px）、主要値 `ValueLabel`（26px）、本文 `BodyLabel`（18px）、説明 `DescriptionLabel`（18px）、補足 `MutedLabel`（16px）、価格 `GoldLabel`（21px）を使用する。ボタンは原則18px、補助操作は16px。画面ごとのフォントサイズ・色overrideは追加しない。
- 拠点のヘッダー・ページ・フッター、各画面の列はContainerで配置する。ただし拠点ホームのロビー（`HubLobby`）は、背景の一枚絵と一体に見せるため、縮小されるページ内容とは別に1600×900の画面全体へ直接配置する。`HubUI` は `MainPanel` / `ItemPanel` とMargin・VBox/HBoxの構造だけを共通化する。基準内容幅1440px・高さ810px（1600×900の画面で左右に80pxずつ背景を残す）、画面端は最低20px相当を確保して縮小する。通常のパネル内余白24px、列間20px、縦間隔12px、密な詳細は8px。倉庫は、左右の石板を各510pxの固定幅とし、間の広間を空けるContainer構成を、同様に縮小する。
- 外観の調整はTheme内の名前付きStyleBox（`MainSurface`、`SurfaceHover`、`FocusOutline`など）を編集する。同一のStyleBoxを共有するControlへ一括反映されるため、画面側で複製しない。文字色・文字サイズは該当するTheme Typeを編集する。Theme内の色項目とStyleBoxの色はGodot上では別プロパティであり、自動連動するパレットではない。
- `CharacterButton` と `SpeechPanel` は拠点キャラクターの透明なクリック領域と吹き出し専用とする。新規画像を要する装飾は、後述「UI体験の改善」の素材差し替え口を通してのみ追加し、素材がない状態でも現行の表示で成立させる。

色の役割は背景 `#020305`、主面 `#252525`、浮いた面 `#2B2B2B`、一覧の内側 `#1C1C1C`、Hover `#363636`、選択面 `#26241A`、通常境界 `#525252`、選択境界 `#B89759`、Gold `#D6B77B`、本文 `#EEE9DF`、説明 `#C9C9BF`、補足 `#B2B3AA`、減少 `#DB857A`、増加 `#91C2A3` とする。拠点背景の画像は暖かい光を残し、上に重ねる中立色の暗幕を薄くして石造りの奥行きを見せる。主パネルは青みを含まない不透明な石墨色で背景と分離する。透過率と影はTheme内のStyleBoxに集約する。一覧／詳細比率はショップ約53:47、出撃約52:48、倉庫は左右の石板が各510pxで、残りが広間。拠点ホームの配置は後述のB3に従う。

ショップの商品詳細と装備比較は `ItemDetails`（RichTextLabel）を使用する。商品名・価格・補足は既存LabelのTheme役割から色と文字サイズを取得し、能力差分は変更前→変更後と符号付き数値を併記する。増加は `PositiveLabel` の控えめな緑、減少はThemeの `ItemDetails/decrease_color` を使用する。長文は枠内でスクロールし、Tabで詳細へFocusを移した後は方向キー・Home/Endで閲覧できる。アイテム名・説明はBBCodeとして解釈せず、選択変更時は先頭へ戻す。

ショップ・装備・倉庫の一覧とマスは `ItemTooltipList` で標準Tooltipを共通化する。幅はThemeの `ItemList/tooltip_width`、背景は既存TooltipPanelを使い、長文を折り返す。表示待ち・消去・画面端の位置調整はGodotに任せる。Tooltipは補助表示とし、選択内容の説明は画面内にも表示する。

画面上の用語は日本語に統一する。装備枠は `Equipment.SLOT_NAMES` の「主武器・副武器・防具・装飾 1・装飾 2」、能力値は「HP・MP・攻撃力・防御力・射程」、1回の挑戦は「冒険」と表記し、ATK・DEF・Main・Sub・Runなどの英語表記は使わない。金額は数値の後に「G」を付け（例：20 G）、見出しや項目名としてだけ「Gold」を使う。Lvは「Lv 3」、階数は「全50階」のように書く。ダメージ補正が0の武器は、カードの主効果に「+0」を出さない。ロゴは「Dungeon Remnant」と単語の間を空ける。

表示書体（しっぽり明朝）はThemeの `FontVariation` でOpenTypeの `palt` を有効にし、「ショップ」「モンスターハウス」のような小書きカナの字間が開かないようにする。2行に収まる日本語の説明は `TextWrap` で中央付近の助詞・句読点の後に改行を入れ、最終行に1〜2文字だけが残らないようにする。

ダンジョンの所持品画面の一覧は `ItemCardList` を使用し（拠点のショップと準備は絵のマス `ItemCell`、C1・C2）、48pxの種類アイコン・名前・主効果を約80pxの行に配置する。一覧がFocusを持つ間は、一覧全体を細い半透明の本文色の線（`ListFocus`、1px）で囲む。ボタンと同じ2pxの金枠（`FocusOutline`）にすると、行の選択枠と二重になり、所持品が少ないときは空の大きな金枠が目立つためである。選択中の行は従来どおり金枠で示す。ショップは価格と所持数、準備では個数を表示する。レアリティは現行ItemDataに存在しないため表示しない。アイテムはアイテムごとの絵で示す。`ItemIcons` が `ItemData.id` から `art/items/<id>.png`（武器は `weapon_<種類>`）を引き、アイテムのデータには手を加えない。絵は48pxのピクセルアイコンを2倍で保存したもので、48pxのカードではちょうど半分、`ItemVisual` では48の整数倍で描き、画素をぼかさない。画像のないアイテムは、`ItemGlyph` が武器種・防具・装飾品・護符・巻物・HP／MP回復薬をGodotの図形で描く共通記号で表示する。どちらも `ItemGlyph.paint()` を通るので、一覧・詳細・HUD・移動演出・永久強化で同じ絵になる。Themeの色は、明るい役割ではそのまま、灰色の役割では絵を暗くする形で反映する。床に落ちたアイテムも同じ絵を敵と同じ0.8倍で描き、影を付ける。絵は `art/items/source/` の生成画像の格子（行・列・並び順は `tools/process_item_icons.py` の `BOARDS`）から切り出す。`ItemShowcase` は絵・商品名・分類・主効果を並べ、商品名は行数を制限せずに折り返して全文を示すため、その下の詳細は名前も主効果も繰り返さない。ショップの詳細は装備の比較と同じ `InsetPanel` の枠に収める。ショップ購入・売却・装備の詳細で共用する。

カードの入力・選択・検索・Tooltip・スクロールは標準ItemListに任せ、描画だけを拡張する。ネイティブの項目文字列は名前検索とアクセシビリティのために保持し、Themeの `ItemCardList/font_*_color` を透明にして二重描画を防ぐ。表示色・文字サイズは既存Labelの役割を参照し、行高・アイコンサイズ・価格領域・余白は `ItemCardList` のTheme定数で調整する。長い名前はTextLineで省略し、全文は選択品の表示（`ItemShowcase` の商品名）とTooltipに残す。

永久強化の画面の配置は後述のC3に従う。前提条件はSkillNodeの定義から取得し、条件未達・Gold不足（不足額）・強化上限を区別する。各強化は能力と同じ紋章（後述A1）で示し、基礎HPは最大HP、攻撃力・防御力は同名の能力の紋章を共用し、生命力（芽の出たハート）と魔力量（青い結晶）は専用の紋章を持つ。同じ枝の段は同じ紋章を使う。途中開始の解放は選択ステージごとに、中ボス撃破→開始地点の関係、ステージ未解放・中ボス未撃破・Gold不足・解放済みを表示する。購入可否の判定と保存は既存のRunCarryover／Mainが担う。

条件未達の強化も選択して説明を読める。購入操作は詳細の列のPrimary Actionで行い、可否は既存の状態判定に従う。

拠点の個別画面の題の下には、機能の説明（「品を選び、価格と取引後の所持数を確認。」など）も置かない。各画面でできることはロビーの情報パネルで項目ごとに1行で説明しているため、個別画面で繰り返すと同じ言葉を二度読ませることになり、上段も高くなるためである。操作や規則の説明の置き場所は「個別画面のUI文法」の「説明の置き場所」に従う。数個の選択肢から1つを選ぶ操作（ショップの購入先・売却元の「倉庫／持ち込み」、出撃画面の開始階「1F／11F…」）はドロップダウンに隠さず、`SegmentedChoice` の切り替えボタンで全部を並べて見せる。開始階では各ボタンを階数だけにする。売却後の選択解除と、保存成功後だけに出す符号付きGoldフィードバックを維持する。持ち込みと倉庫の間の移動は準備画面（後述のC2）で行う。移動は既存の1スタック単位であり、全種類を一括転送する機能は持たない。

準備画面（装備と倉庫）の配置は後述のC2に従う。出撃画面（ステージ選択と出撃確認）の配置は後述のC7に従う。存在しない推奨Lv・報酬は表示しない。

操作の時間変化は `ui/ui_motion.gd` の `UIMotion` で管理する。主要ボタンのHoverとFocusは100ms、押下は70ms、選択詳細は140ms、Gold増減は220ms、装備枠は160ms、画面表示は180msを基準とする。色・枠線はThemeに残し、scaleとalpha、選択カードの内側金枠の強さ、HUDのHP・MP残像ゲージの表示値を動かす。選択枠は140msで強まり、ショップの詳細・大型アイコン・所持数、装備の比較・大型アイコン、倉庫の詳細・大型アイコン・移動方向は、選択内容と操作可否を即時更新した後に同じ140msでFade更新する。装備枠の切り替えで自動選択される候補にも選択枠の演出を適用する。通常の一覧再描画では選択演出を再生せず、古い選択のTweenと透明度をリセットする。倉庫では選択元を切り替えた際に反対側の選択演出も解除する。Controlごと・プロパティごとに前のTweenを停止し、非表示・解放時に基準値へ戻す。Containerの位置や最小サイズはアニメーションせず、位置の動きが必要な場合は後述「UI体験の改善」の表示層を動かす。

HUDのHP・MPは数値と実ゲージを即時更新し、減少時は明るい残像を120ms保持してから280msで現在値へ追従させる。増減時は数値を220msで一度だけ1.06倍に拡大して戻す。同値の再描画は演出を再開せず、連続減少は残像の現在位置から追従し直し、回復は残像を即時更新する。初回表示・最大値変更・冒険開始時は演出せず同期し、非表示時はTweenを停止して残像と拡大率をリセットする。実数値・ゲーム処理・入力は演出を待たない。残像の色と実ゲージのStyleBoxは共通Themeで管理する。

HPが最大値の30%以下になると、ダンジョンとHUDパネルの間の層（`DangerVignette`）で画面周辺を赤く脈打たせる。残りが少ないほど赤を濃く、脈を速くし、回復すれば消える。色は共通Themeの `HpCaption` から取り、入力は妨げない。

取引・装備・倉庫移動・永久強化の成功演出は、保存まで成功した `Main.preparation_completed` 通知で開始する。UIのTween完了をゲーム処理から待たず、残高・一覧・装備は即時更新する。購入は負、売却は正のGold増減を既存のフィードバック欄に表示する。永久強化は、確定したランク増加がある能力カードを220msで1.025倍に拡大して戻し、選択中の能力が上がった場合は詳細の現在値も同時に1.04倍で強調する。初回表示・選択だけでは成功演出を出さず、選択変更時は詳細の拡大をリセットする。画面を閉じる操作は即時とし、退場演出による入力待ちを設けない。

戦闘の結果は先に確定し、`BattlePresentation` が記録済みのイベントから予備動作・攻撃・被弾・死亡を再生する。攻撃のエフェクト（`StrikeEffect`）は、剣は三日月の斬撃、ハンマーは地面が割れる衝撃、魔弾は秘術の弾、炎波は火の玉、治癒は金の光、被弾は火花、敵の撃破は少し遅れて立つ煙とし、無料のドット絵素材（CC0。`art/third_party/`、入手元は `THIRD_PARTY_NOTICES.md`）の連番を、作者の想定する速さ（多くは20コマ/秒）でぼかさずに再生する。連番は `tools/build_effect_sheets.py` が元の素材から作る。魔弾のように並んだマスでは、先のマスほど少し遅れて出す。斬撃・魔弾・炎は攻撃の向きへ回し、左向きは上下を逆さにせず左右反転する。魔法を込めていない杖は剣と同じ振りなので斬撃を出す。槍の突きは合う素材がないため、線で描く表現のままとする。攻撃範囲の演出は視界内に限定する。敵は種類ごとの描画と待機・移動・被弾の姿勢を持つ。同一敵の連続移動、追従、交差する斜め移動は順序を維持し、経路が重ならない敵の移動だけを同時再生する。演出は論理座標を変更せず、既存の戦闘演出中の入力制御を維持する。中断・階層移動時は姿勢、位置補正、残存エフェクトを解除する。

攻撃方向の選択中は、射程の各マスを薄い下地と金色の角ブラケットで示し、ゆっくり明滅させる。敵がいるマスには赤みのある照準を重ね、ベタ塗りの四角は使わない。ダメージ数値は、与えたダメージを淡い金、止めの一撃を濃い金でひと回り大きく、受けたダメージを赤で大きく強い弾みで表示し、いずれも同系色の暗い縁取りと影を付ける。敵のHPバーは減った時だけ表示し、暗い枠付きの太いバーで残量に応じて金・橙・赤に変える。

冒険結果は、タイトルの下に結末を1文で示す（例：「3Fで突進獣に倒された。」「最深部の主を倒した。」）。数値は到達階・今回獲得・失ったGold・残高に加え、到達Lv・倒した敵・経過ターンを表示する。死亡時は、止めの一撃の演出後に主人公が崩れ落ちて暗くなり、画面が0.7秒かけて沈んでからパネルを出す。この間は確定・再挑戦の入力を受け付けない。結果の確定と保存は演出を待たず先に終える。

カメラは探索中の追従を平滑化し、新しい階の開始位置へは即座に合わせる。カメラは主人公より1マス弱（40px）下を中心に映し、主人公を画面中央より少し上、下側のHUDにかからない位置に置く。倍率は1.5倍とし、主人公の周りを大きく見せる。0.8倍で描くキャラクターの絵は1.2倍で表示されるため、画素の大きさは完全には揃わない。画面に映るのは主人公の左右約11マス、上に約5マス、下に約7マスで、視界（半径8マス）より狭い上下方向の敵はミニマップで確かめる。ボス階の前室とボス部屋を横長に作るのは、この範囲に扉とボスを入れるためである。階層開始とモンスターハウス発見は短い非操作型バナーで知らせ、ボスはその階で初めて視界に入った瞬間に一度だけ `BossCutIn` で知らせる。画面上部を横切る暗い帯に、ボスの待機コマ（1.5倍）を左から、階とボスの名前を右から入場させ、約1.35秒保ってから0.3秒で消す。帯は入力を受け取らず、ターンは演出を待たない。専用の絵がないボスは名前だけを中央に示す。表示中の階層バナーはカットインに置き換え、成長選択・冒険結果・階の移動では即座に消す。画面の揺れは被弾時だけのため、登場では揺らさず専用の効果音（`boss`）を鳴らす。成長選択・持ち物・冒険結果には共通ThemeとUIMotionを適用する。環境の微粒子と階段・脱出口の淡い光は視界内に限定し、未探索の情報を表示しない。

効果音は `audio/game_audio.gd` の `GameAudio` が鳴らす。武器（剣・槍・ハンマー・魔法）、被弾、撃破、取得、足音、保存成功後の拠点操作、成長、階層開始、警告、ボス登場、帰還・敗北を鳴り分ける。被弾・レベルアップ・クリア・帰還以外は、無料の効果音素材（CC0。`audio/third_party/`、入手元は `THIRD_PARTY_NOTICES.md`）を鳴らす（`GameAudio.ASSETS`）。素材は `tools/build_sound_effects.py` で、置き換え前の合成音と同じ平均音量へそろえてから使う。各所が `GameAudio.play` に渡す音量の意味を変えないためで、`play` は音量を-12dBまでに抑えるため、小さい録音を再生時に持ち上げることはできない。素材のない被弾・レベルアップ・クリア・帰還は、`GameAudio` が生成する合成音（`PROFILES`）のままとする。同時発音は最大8音で、音の生成はゲーム進行の乱数を消費しない。`GameAudio.set_override(cue, AudioStream)` はどちらの音も差し替え、nullを渡すと元へ戻る。環境音は `audio/dungeon_ambience.gd` が、遺跡と森でそれぞれの録音（CC0）を低音量で繰り返す。録音がない場合は生成した低音のループで代用し、`stream_override` で別の音を設定できる。

拠点UIはキーボードの既存操作に加え、ゲームパッドの十字キーでFocus移動、Aで決定、Bで戻る操作を受け付ける。`ui_accept`・`ui_cancel`・方向の標準アクションへ登録し、マウスと同じButton signalで演出する。既存のキーボード割り当ては保持する。

ダンジョンでは、ゲームパッドの十字キーを上下左右の移動、左スティックを8方向の移動（`StickDirections` がスティックの向きを移動アクションの押下と解放に変換し、押し続けによる連続移動もキーボードと同じ仕組みで行う）、Aを攻撃、Bをキャンセル、Xを所持品、Yを武器切替、Startを中断と結果画面からの再挑戦・帰還に割り当てる。所持品画面は開くと一覧にFocusを置き、Space・Enter・Aで選択中の消耗品を使うか、装備品を比較中の枠へ装備し、Yで武器を切り替える。能力選択は1〜3キーとマウスを開いた直後から受け付け、Focusは攻撃の連打で誤選択しないよう0.3秒後に最初のカードへ置く。中断の確認はEnter・Aで確定し、Esc・Bで取り消す。所持品の取り外しは、現状マウス操作だけとする。杖に魔法を込める操作は、所持品画面の `M`（ゲームパッドは `RB`）で開く魔法の選択画面で行う。

変更時は `tests/test_ui_theme.gd`、`tests/test_ui_layout.gd`、`tests/test_ui_motion.gd`、`tests/test_upgrade_ui.gd` に加え、該当する取引・装備・セーブのテストを実行する。描画可能な環境では `tests/capture_art_direction.gd`（7画面を1600×900・1280×720・1920×1080で確認）、`tests/capture_shop.gd`、`tests/capture_preparation.gd`、`tests/capture_ui_motion.gd`、`tests/capture_item_details.gd`、`tests/capture_upgrade_ui.gd`、`tests/capture_item_cards.gd` で通常サイズ・縮小表示・各入力・ボタン端のクリックを確認する。演出用キャプチャは60 FPS上限でアイドル時と演出中のフレーム時間も比較する。生成画像は `.godot/` に出力する。

## UI体験の改善（優先度順）

現行UIは、情報を正しく・崩れずに表示するという条件は満たしているが、プレイヤーに何かを感じさせる場面としては設計されていない。拠点の背景は描き込まれているのに、その上のパネルは平らな石墨色の矩形とゴシック体の文字だけで構成されているため、背景とUIが別々の作品のように見える。全画面が「ヘッダー＋暗いパネル＋戻る」の同じ構造なので、画面を移っても場面が変わった感覚がない。演出は0.07〜0.28秒の縮小・拡大と透明度の復帰だけで、動きに方向や溜めがなく、購入・装備・能力獲得のような報酬の瞬間も、ボタンを押した時と同じ手触りで終わる。さらに、プレイ時間の大半を占めるダンジョン側の能力選択・所持品・冒険結果は、拠点側で整えた `ItemCardList`・`ItemGlyph`・`ItemShowcase` を使っておらず、文字だけのボタンとリストで構成されている。この節は、これらを製品として遊べる水準へ引き上げるための方針と、画面ごとの改善内容を優先度順に定める。本節と上記の記述が矛盾する場合は本節を優先する。ゲームロジック・セーブ仕様・Item / Stage / Ability Dataは変更せず、現行データにない値を表示のために作らない。

### 共通方針

各画面に「プレイヤーの選択が結果に変わる瞬間」を1つだけ定め、その瞬間の演出を最も手厚くする。以下ではこれを見せ場と呼ぶ。見せ場以外の操作は控えめな反応にとどめる（個別画面の普段の動きは「個別画面のUI文法」の「普段の動き」に従う）。演出を全画面に均等に足すと、どれも見せ場にならないためである。

演出の時間は3段階に分ける。Hover・Focus・押下などの反応は80〜120ms、画面・パネル・選択詳細の入れ替わりなどの遷移は180〜260ms、能力獲得・購入・装備・冒険結果などの見せ場は400〜900msとする。入場は `TRANS_CUBIC` の `EASE_OUT` を基本とし、見せ場の強調だけ `TRANS_BACK` の `EASE_OUT` で最大1.05倍までのオーバーシュートを許す。退場は120msの `EASE_IN` とし、退場中も次の画面が入力を受け付ける。見せ場の演出は、決定・キャンセル入力で即座に最終状態へ飛ばせるようにする。いずれの演出もゲーム処理・保存・入力の可否を待たせないという既存の原則は維持する。

位置を動かす演出は、Containerの子そのものではなく表示層で行う。表示層とは、Containerが配置するControlの内側に置いた、Containerの管理を受けない見た目用のControl（`mouse_filter` はIgnore）であり、その `position`・`scale`・`modulate` だけをTweenする。Focus・入力・レイアウト計算は元のControlが持ち続ける。一覧から詳細へアイコンが飛ぶような、Controlの境界をまたぐ演出は、画面最上位の `CanvasLayer` に置いたオーバーレイへ一時的な複製を描いて行い、終了後に破棄する。

Gold・EXP・到達階など結果の数値は、状態と保存上の値を即時に確定させたうえで、表示だけを前の値から新しい値へ数えて見せる。数える時間は差の大きさに応じて最大600msとし、差が小さいときは短くする。開いた直後の誤選択は、キーリピート（`echo`）を受け付けないことで防ぎ、時間による入力の無視は設けない。入場演出の途中でも、キー入力で即座に選択できる状態を保つ。

書体は、画面名・見出し・ロゴ用の表示書体（明朝体またはセリフ体）と、本文用のゴシック体の2系統にし、数値には等幅数字を使う。書体の指定はThemeの `TitleLabel`・`HeadingLabel`・`ValueLabel`・`GoldLabel` などで行い、画面ごとのoverrideはしない。採用する書体は商用利用と同梱が許されるライセンスのものに限る。

パネルの質感は、Themeの `MainSurface`・`ItemSurface` などを、装飾枠つきの `StyleBoxTexture`（9-slice）へ差し替えられる構成にする。枠素材がない間は現行の `StyleBoxFlat` のまま表示する。これを素材差し替え口と呼び、カードの挿絵や背景の差し替えも同じ考え方で、素材がない場合は現行表示で成立させる。

ダンジョン中のHUD・能力選択・所持品・冒険結果も、拠点と同じTheme・書体・`ItemGlyph` を使う。拠点とダンジョンで作品の質感が途切れないようにするためである。効果音は、反応段階にカーソル移動音と決定音を、見せ場ごとに専用の音を割り当てる。素材が揃うまでは `GameAudio` の仮音cueを追加して代用する。

### 優先度A：ダンジョンの見せ場

**A1. レベルアップの能力選択。** 現行は縦に並んだ3つの文字ボタンで、能力名・Lv・効果が1行に詰め込まれている。これを横並びの3枚のカードにし、各カードに能力の記号、能力名、Lvの進捗（上限までの目盛り）、次のLvで得る効果を大きく表示する。記号は、ブロンズの縁と鋲を持つ暗い円盤に浮き彫りの図柄を載せた生成画像の紋章とし、96pxで描く。紋章は `EmblemIcons` が `Effect` の名前の小文字（`max_hp`・`sword_damage` など）から `art/emblems/<キー>.png` を引くため、AbilityDataには手を加えない。絵はアイテムと同じく48pxのピクセル絵を2倍で保存したもので、`art/emblems/source/` の2×3の生成画像2枚（並び順は `tools/process_emblems.py` の `BOARDS`）から切り出す。武器別の威力は橙の火花、槍の射程は先へ伸びる青い山形、貫通は穂先が通り抜ける青い輪で区別し、全武器に効く攻撃力は火花をまとう籠手で表す。紋章がない能力は、`Effect` から `ItemGlyph` の図形の記号へ対応づけて描く。見せ場は能力を選んだ瞬間とする。カードは開いた時に60ms間隔で下から順に入場し、Hoverしたカードは少し持ち上がる。選択と同時にダイアログは閉じてターンが再開し、選んだ瞬間の演出は、入力を受け取らない別の `CanvasLayer` に複製したカードで再生する。選んだカードは拡大して金色に光り、Lvの目盛りが1つ埋まり、他の2枚は沈んで消える。次の選択が続く場合は、前の演出を即座に破棄して新しいカードを入場させる。1・2・3キーとマウスでの選択は維持し、操作は説明文ではなく、カードの下のキーの図（「1・2・3 選ぶ」）で示す。残り回数は2回以上あるときだけ「あと2回選べます」と添える。今後、HUDの該当する数値（最大HPなど）を一度だけ強調する演出と、ゲームパッドでの選択を加える。

剣」、攻撃処理が使う射程（`Player.effective_weapon().reach`。強化や杖に込めた魔法を含み、回復の魔法は「射程 自身」）、副武器の淡い絵、`Tab 切替` のキーの図を並べる。Tabで武器を切り替えた結果と、今の攻撃がどこまで届くかを、その場で確かめられるようにするためである（武器ごとに攻撃範囲が違うことがこのゲームの核なのに、以前は切り替えたあとの武器も射程もHUDに出ていなかった）。階層は地図の枠の最上段に「階層 5 / 50」として置き、Goldはステータスの枠のターン数・所持数の行の右端に、桁区切りの「1,280 G」として置く。HUDは、主人公のまわり縦横±4マスの盤面には重ねない（戦闘はこの範囲で起きるため）。画面の右下には「今できる操作」の札（`HudActions`）を置き、HUDのほかの場所に出ていない操作（`Space 構える`・`I 所持品`・杖を装備しているときだけ `M 魔法`・`R 中断`。ゲームパッドでは **B1. ダンジョン内の所持品。** 所持品画面は、拠点の準備画面（C2）と同じ作法で組む。拠点で覚えた操作がダンジョンでもそのまま通じるようにするためである（以前は「主武器に装備」「副武器に装備」のボタンの横並びと、装備中の5行ごとの「外す」に操作が散らばり、比較も説明文の中の1行で目立たなかった）。盤面は暗幕で沈め、その上の中央に1360×760の区画を置く。上段は「所持品」（`TitleLabel`）と使用枠（「7 / 40 種類」）、右端に「ターンが進むのは「使う」だけ」。左は暗い石板（`SlabSolid`）で、上に装備5枠のマス（`SlotCell`、88px、下に枠名。杖の枠には `MagicSocket`）、金の細線、「持ち物」の見出しと2列の一覧（`ItemCardList`、行に絵・名前・主効果・数量）。右は判断の列（`SlabSolidEnd`）で、選んだ品の `ItemShowcase`（絵・名前・分類・主効果）、金の細線、`ItemDetails`（追加の説明と比較）、その下の操作とする。装備品は、比較先の枠（空いている対応枠、なければ最初の対応枠。武器ならMain）への装備がPrimary Action（最下部）で、ほかに入る枠への装備をその上に置く。消耗品は「使用する（1ターン）」がPrimary Actionで、使えないときは「HPは満タンです」などと理由を示して無効にする。巻物は杖への「〇〇に魔法装着」がPrimary Actionになる。装備枠のマスを選ぶと一覧の選択を外し、その枠の品を列に示して「〇〇を外す」をPrimary Actionにする（主武器は「主武器は外せない」で無効、空の枠には操作を出さない）。選んでいる一覧の品が入らない枠は暗く沈める。装備後の最大HP・攻撃・防御・射程・視界のうち変化するものだけを現在値→装備後の値で示し、装備の操作にポインタを重ねるとその枠との比較に切り替える。比較値はプレイヤーの `stats_with()` で求め、レベルアップの能力と一時効果を含めて実際の装備後の値と一致させる。下段は操作ガイド（`Esc 閉じる`・`Enter 決定`・`Tab 武器切替`（副武器がないときは無効）・杖を装備しているときだけ `M 魔法`）。Enterは選ぶことと決めることを分ける（まだ選んでいない枠では選ぶだけ、選んでいればPrimary Actionを押す）。マウスでは共通のドラッグ＆ドロップの作法に従い、一覧の行を装備枠のマスへ落とすと装備し（巻物は杖に魔法を込める）、装備中のマスを一覧へ落とすと外し（主武器は外せない）、主武器と副武器のマスを互いへ落とすと入れ替える。どれもターンを消費しない。

### 個別画面のUI文法

拠点の個別画面（出撃・準備・ショップ・強化・設定）は、次の共通ルールに従う。画面ごとに作法が違うと、同じ操作でも毎回探し直すことになり、ロビーで整えた雰囲気も画面を開くたびに途切れるためである。本節と下記「優先度C」や上記の各画面の記述が矛盾する場合は本節を優先し、各画面を改修するときに該当する記述を本節に合わせて書き換える。ロビー（B3）はこの対象に含めない。

**画面の骨格。** すべての個別画面を上段・本体・下段の3段で組む。上段は左に画面名（`TitleLabel`。ショップでは画面名の代わりに購入／売却の切り替え）だけを置き、右にGold表示を置く。ロビーにないロゴ「Dungeon Remnant」は個別画面にも置かない。本体は主要パネル1〜2枚とする。下段は左端に戻る操作を置く。上段と下段はページ本体（1440×810）の内側ではなく、画面の端を基準に置く（左右40px、上22px、下16px、`Hub.EDGE_X` など）。ページより外側に寄せて端を攻めることで、画面全体を使った構図にし、ロビーのGoldとも同じ位置にそろえる。本体の列は、必要に応じて画面の端まで延ばしてよい（ショップの石板は画面の左端まで）。その場合は、列の中身の左端を上段の画面名にそろえる。

**主要パネルは1〜2枚。** 枠付きの面（`MainPanel`）を主要パネルと数え、1画面に2枚までとする。0枚でもよく、枠の代わりに背景へ溶ける石板（`SlabSolid`・`SlabSolidEnd`）や文字の後ろだけの影（`ShadeColumn`）と、金の細線（`HubUI.rule()`）で区切ると、ロビーとの連続性が強まる。

**判断の列は全画面で同じ位置。** 個別画面の本体は「選ぶ場所（左）＋判断の列（右）」で組む。左は画面ごとに中身が変わり（出撃は地図、準備は装備枠と倉庫・持ち込みの格子、ショップは商品の一覧、強化はツリー）、右の判断の列は画面の右端まで延びる石板（`SlabSolidEnd`）に、上から名前と種類、今との比較（今 → 選んだ後）、補足、費用と残高、Primary Actionの順で並べる。左の石板は暗い石の面（`SlabSolid`、上下に金の細線）、右の判断の列は一段明るい石の板（`SlabSolidEnd`、上・下・左に金の細線、上端から淡い明かり）とし、どこで決めるかを面の明るさで示す。以前の石板はほぼ黒の半透明の平塗りで縁も質感もなく、背景を暗くしただけに見え、左と判断の列の境目も明るさの差でしか分からなかった。どちらの面にも、生成した石の質感のタイル（`art/ui/slab_stone.png`）を `SlabStyle.grain` で敷き、`grain_tint` で石板の暗さまで掛け下げる（面の平均の明るさは色の値が決め、タイルは模様の濃淡だけを持つ）。列の幅は左とのstretch比2.1：1.0でそろえる。以前は詳細の位置が画面ごとに違い（ショップは中央、ステージと強化は右、装備は右下、倉庫は下中央）、画面を移るたびに視線の行き先を覚え直す必要があったためである（`tests/test_ui_layout.gd` が、全画面のPrimary Actionの左端がそろっていることを検査する）。

**金色の用途。** 個別画面の金色は、①選択中とFocus、②Primary Action、③お金の3つに限る。③のお金は、Gold残高と、勘定台の取引額や強化に必要なGoldのように「今の判断に関わる値」だけを金とし、一覧の各行の価格や強化カードの費用は本文色で示す。能力値の上昇は緑、低下は赤のまま、金は使わない。

**等間隔の格子と埋め込みパネルを避ける。** 同じ大きさの箱を同じ隙間で縦横に並べると、表計算やフォームのように見える。まとまりの中は詰め、まとまりの間は大きく空け、大事なものだけを大きくして、間隔に強弱を付ける。箱の中に箱を重ねない。一覧の行はカードに分けず、端が溶ける細い金の線で区切った1つの連続したリスト（`OpenCardList`）とする。品の絵は台に載せず、淡い光の上に直接置く（`ItemVisual.framed = false`）。数量は「〈 1 〉」のセレクターと「最大」（`QuantityStepper.use_selector()`）、少数の選択肢は下線の文字タブ（`SegmentedChoice.option_role = &"CategoryTab"`）、分類のタブは文字の幅に合わせて並べる。

**選択の見せ方はロビーと同じにする。** 一覧で選んだ行は、金の四角い枠で囲まず、ロビーの左メニューと同じく、右端が詳細の方へ尖った暖かい光の帯と金の文字で示す（`OpenCardList`）。未選択の行には枠線を引かず、Hoverはわずかに明るくするだけとする。ボタンや装備枠のように行でない部品も、枠線は選択中（金）だけに使う。

**Primary Actionは全画面で同じ位置・同じ部品。** 1画面に1つとし、判断の列の最下部に全幅で置く。部品はロビーの決定ボタンと同じ `PrimaryAction`（高さ60px・文字20px）とし、`HubUI.primary_action()` で作る。そのほかの操作は `SecondaryButton` とし、Primary Actionの上にまとめる。`SecondaryButton` は、青銅の縁に暗い石の面の札（キーの札と同じ絵）とし、指している間と押している間は金の縁、押せないときは縁のない暗い面と薄い文字にする。押せる補助の操作と押せない操作を見分けられるようにするためである（以前は灰色の平らな四角と灰色の文字だけで、押せないボタンと同じ見た目だったため、ショップの「全部売却」などが常に押せないように見えていた）。準備では、選んだ品が入る枠への装備（「防具に装備」）がPrimary Actionで、ほかに入る枠への装備（「副武器に装備」）と反対側への移動（「持ち込みへ移す」「倉庫へ預ける」）をその上に置く。装備できない品はPrimary Actionが移動になり、装備枠を選んだときは「〇〇を外す」になる（主武器は外せないため無効）。設定のように変更がその場で反映される画面には、Primary Actionを置かない。キーボードとゲームパッドでは、一覧の行・マス・強化のノード・出撃の島でEnter（ゲームパッドはA）を押すと、その画面のPrimary ActionへFocusが移り、もう一度押すと実行する（`HubUI.accept_to_action()` と同じ作法）。選ぶ操作だけでGoldや持ち物が動かないようにしつつ、操作ガイドの「Enter 購入」などが2回の押下で実際に届くようにするためである。マウスのダブルクリックも、Primary ActionへFocusを移すだけとする。別の画面へ移る文字だけの操作（`TextAction`。「準備を開く ›」「遊び方と決まりごとを読む ›」など）は、文末に「 ›」を付け、その場の操作ではなく移動であることを示す。

**アイテムのドラッグ＆ドロップは全画面で同じ作法にする（`ItemDrag`）。** アイテムを扱う画面（準備・ショップ・ダンジョンの所持品）では、品の絵や行をマウスで掴める。掴んだ品は金色の記号としてポインタに付いて動き、掴んでいる間は落とせる場所だけが金の細い枠と淡い光で示される（マスは `ItemCell.drop_ready`、列や行は `ItemDrag.glow()`）。落としたときの動きは、取り消しのきく操作（反対側への移動、装備、取り外し、主武器と副武器の入れ替え、杖に魔法を込める）ならその場で実行し、Goldが動く操作（購入・売却）なら、その品を選んで取引のボタンへFocusを移すだけにする（押すまでGoldは動かない）。落とせない場所で離すと何も起きない。判断の列へ落とすと、どの画面でもその品を選んでPrimary Actionの前で待つ。列の中のボタンや文字の上に落としても列に落としたものとして扱う（`ItemDrag.accept_drops()`）。画面ごとに掴めたり掴めなかったり、落とした結果が実行だったり選択だったりすると、マウスで遊ぶ人が画面ごとに作法を覚え直すことになるためである。

**戻るは全画面で左下、操作ガイドとして示す。** 下段の左端に、キーの記号と動作を並べる操作ガイド（例：`Esc 戻る`　`Enter 決定`）を置く。ボタンの枠には入れず、記号と動作の文字だけを並べ、記号の部分を押しても同じ操作になる。ゲームパッドの操作中は記号を `B`・`A` に切り替える。倉庫も他の画面と同じページとし、専用の「閉じる」ボタンは置かない。部品は `KeyGuide`（`add_hint()` でキーの記号・ゲームパッドの記号・動作を渡す）とし、最後に受けた入力がゲームパッドかキーボード・マウスかで記号を切り替える。キーの記号は、青銅の縁に暗い石の面のキーの札の絵（Themeの `KeyGuideButton` の `cap`・`cap_active`）に載せ、指している間は金の縁の札に替える。1文字のキーの札は正方形以上の幅にする。

**文字の階層を固定する。** 1つのまとまりの中は、見出し（`HeadingLabel` 24px）→ 主要数値（`ValueLabel` 26px）→ 補足（`MutedLabel` 16px）の順に並べ、1つのパネルの中で使う文字の段階は、見出し・主要数値・本文・補足の4段階までとする。品の名前・価格・所持数・数量・取引額・能力の値のように遊ぶうえで判断に使う情報は今の大きさで示し、品の説明文・注意書き・「購入先」「数量」のような項目名・取引後の残高の行のように、読まなくても判断に影響しにくい説明文は `NoteLabel`（16px・補足よりさらに控えめな色）で示す。同じ意味の情報は、どの画面でも同じ役割の文字で示す。拠点の文字は、キーガイドの記号・分類の「Q」「E」・「?」・強化のLvも含めて16px以上とする。基準の1600×900で16pxは1920×1080で約19pxになり、Xbox Accessibility Guideline 101のPC向けの下限（1080pで18px）を満たすためである。`NoteLabel` は `MutedLabel` と同じ大きさになるため、色の明るさで一段下げて階層を保つ（`tests/test_ui_theme.gd` が下限と色の差を検査する）。ダンジョンのHUD（`Hud*`）は床を覆う面積との兼ね合いがあるため、この下限の対象外とする。

**Goldの強弱。** Gold表示は全画面で同じ位置（ロビーと同じ右上）に置く。売買と強化のようにお金を使う画面（ショップ・強化）では今の強さで示し、それ以外の画面では大きさと明るさを落として控えめにする。位置を変えたり隠したりしないのは、残高を確かめたいときに探さずに済むようにするためである。控えめな表示は `GoldPurse.quiet`（金額24px・不透明度0.7）で切り替える。

**段階的な開示（Progressive Disclosure）。** 一覧に出すのは、名前・主な効果・数量・価格までとする。説明や比較は、選んだときだけ詳細欄に出す。

**説明の置き場所。** 画面には、その場で選ぶ・決めるために要る情報（名前・数値・条件・価格・結果）だけを置き、ゲームの決まりごとや操作の説明を文章で常に並べない。説明が多いと、画面が説明書のように読まれ、大事な数字が埋もれるためである。説明は次の3段に分けて置く。
- 詳しい説明は、設定画面の「ヘルプ」に話題ごとにまとめる（`HubSettings.HELP`。冒険の流れ・失うもの・拠点の準備・永久強化と開始地点・操作）。ここに書く内容は、ゲームの実際の規則と一致させ、規則を変えたら一緒に直す。
- その場で知らないと困る決まりごと（売れない品、倉庫の品は失わない、持ち込みは倒れると半分失う、どの開始階でもLv 1、など）は、見出しの横の小さな「?」（`HintMark`）にする。「?」はマウスを合わせると1行（48字まで）のTooltipで規則を示し、押すとヘルプのその話題を開く。ヘルプから戻ると「?」を押した画面へ戻る。
- 部品の補足（ボタンが何をまとめて行うか、杖に魔法を込めると前の魔法はどこへ戻るか、など）は、その部品のTooltipに短く置く。
- 操作ガイドに出ている操作（左右キーで変える、など）は、画面の文章で繰り返さない。一覧が空のときの一言（「持ち込みの品はない」）は、理由や次の行動まで書かずに状態だけを言う。

**背景とキャラクターは全部を見せようとしない。** 背景の絵とキャラクターは、ロビーで全体を見せているため、個別画面では全部を見せようとしない。背景は雰囲気を伝える役とし、UIの後ろでは暗く沈めてよい。ただし薄い石板（`SlabColumn` など）の上下の端は、本体の外側へ約48pxかけて背景へ溶かす。水平な線で背景を切ると、部屋の絵が窓越しに見えるようになり、ロビーの「部屋の中」という感覚が途切れるためである（変更前は暗幕の上下端で1行のうちに明るさが約2.5倍変わっていた）。個別画面の本体を載せる石板（`SlabSolid`・`SlabSolidEnd`）は、暗幕ではなく置かれた石の板として見せるため、上下の端に金の細線（両端が溶け、中央に菱形の鋲）を引き、ぼかしは外側14pxにとどめる。線が板の縁として読まれるので、端で背景が切れても窓越しには見えない。48pxのぼかしと金の線を併用すると、線の外にもやの帯が残ったため詰めた。文字は完全に不透明な範囲に載せ、ぼかしの帯には載せない。見せるのは、UIのない場所や、UIの切れ目からのぞく程度で十分であり、背景を見せるためにUIの間に大きな空きを作らない。個別画面にはキャラクターを置かない。背景の絵には画面ごとに「その場所を示す物」（ショップなら商人の台、準備なら武器庫）があり、立ち絵を置くとそれを隠して、背景がただの壁紙になるためである（ショップで立ち絵を外すと、商人の台と薬瓶が現れて画面が店に見えた）。能力の変化のような判断に使う数字は、判断の列で操作のそばに置く。地図とツリーは背景の物（武器棚や燭台）が島やノードの後ろに透けて紛れないよう、薄い石板ではなく暗い石板（`SlabSolid`）に載せる。ロビーとの空間の連続性は、背景の絵が同じ広間の続きであることと、Gold表示と戻る操作の位置で保ち、画面の切り替えは横からのスライドで行う。画面ごとの絵を持つ画面（現在は準備の武器庫、`Hub.PAGE_BACKGROUNDS`）は、ロビーの絵と画風と光の色（暖色の灯りと遠くの冷たい青）を揃え、UIの載る側を石壁と床だけの静かな領域にし、その画面の物（武器棚・鎧）を、石板に隠れない側に置く（準備は、石板の切れ目から鎧の台座がのぞく）。画面を移るときは0.18秒でクロスフェードし、ロビーの絵に描いた灯りの明滅（`HubAmbience.LIGHTS`）は絵の位置が合わないため止める。絵を持たない画面は、これまでどおりロビーの絵を使う。共通の絵を暗幕で隠すより、画面ごとの絵のほうが「その場所へ来た」感覚を出せたためである（共通の絵では、ショップの台や装備の棚が一覧や立ち絵の下に隠れて、UIが背景の上に置かれたように見えた）。

**状態表現の共通化。** ボタン・一覧の行・装備枠などの部品ごとに、通常・Hover・Focus・選択中・押下・無効の6つの状態を1つの表で決め、全画面で同じものを使う。選択中は金の枠、Focusは明るい本文色の細い縁と軽い拡大で示し、両者を別の見た目にする。ゲームパッドで操作するとき、「今どこにいるか（Focus）」と「何を選んだか（選択中）」を見分けられるようにするためである。Hoverは面を一段明るくし、押下は一段沈め、無効は文字と面の明るさを落として操作できないことを示す。未選択とHoverの面（`surface_raised`・`surface_hover`、`tools/build_ui_frames.py` が作る）は縁を面と同じ色にして枠線を見せず、Focusの縁（`FocusOutline`・`ListFocus`）は本文色とする。一覧の行の価格は、選択中の行だけ金で、ほかは本文色とする。どの状態でも部品の余白（content margin）は変えない。Hoverや無効の表示だけ余白が広いと、上限に達した「最大」で数量のセレクターごと位置がずれたり、ボタンの幅に収まらない文字が欠けたりするためである（`tests/test_ui_theme.gd` が全ボタン型の余白をそろえていることを検査する）。スクロールバーも同じ作法で描く（`ScrollRailStyle`）。溝は暗い細い溝の中央に両端が溶ける青銅の細線、つまみは金の縁の細い青銅の棒で両端に菱形の鋲を付け、Hoverで明るく、押下で金にする。以前の灰色の角丸の棒は、ブロンズと石の画面の中で汎用アプリの部品に見えたためである。

**普段の動き。** 見せ場とは別に、個別画面の普段の操作にも、反応と遷移の範囲（250ms前後まで）の控えめな動きを付け、止まった表のように見えないようにする。見せ場より目立たせず、入力は動きの途中でも受け付ける。いずれも `UIMotion` の定数で時間を決める。
- 画面を開いたとき、部品を一度に出さず順に入れる。左の一覧の行は上から順に、左から14pxずれて現れる（1行0.2秒、次の行は0.035秒遅れ。`ItemCardList.play_intro()`、装備枠も同じ間隔）。中央の列は0.06秒遅れて現れる（`play_entrance()`。拠点が画面を開くときに呼ぶ）。分類・購入／売却・売却元を切り替えたとき、装備枠を切り替えたときも、新しい一覧の行を同じように入れる。取引後の再描画では入れ直さない。
- 選択の光の帯と、文字タブの金の下線は、前に選んでいた場所から新しい場所へ0.12秒で滑って移る（`UIMotion.follow_mark()`。帯は一覧・装備枠が、下線はタブの並び（`TabUnderline`）が自分で描く）。最初の選択や、一覧を作り直した後は、滑らせずにその場へ出す。
- 中央に飾った品の絵（`ItemVisual.idle`）は、3.2秒周期で上下に3px漂い、後ろの光がそれに合わせて弱く明滅する。ドット絵がぼけないよう、位置は整数の画素で動かす。表示中だけ動かす。
- 永久強化の「永久補正の合計」の棒（`StatBars`）は、ノードを選び替えたとき今の長さから新しい長さへ0.22秒で伸び縮みする。能力の表示（`StatBars`）で新しく出た▲▼は同時に浮かび上がる。数字は常にすぐ確定値を示す。

**空の状態。** 一覧が空のときは空白のまま残さず、一覧の中央に一言を補足の文字で出す（例：「持ち込める品はまだない」）。`ItemCardList.empty_text` に一言を渡す。

**数値の表記。** 3桁ごとに区切り（1,280）、単位は数字の後ろに置く（20 G、40 枠）。お金の表記は `UIFormat.amount()`・`UIFormat.gold()` で作る。変化は「現在 → 変更後」で示し、上昇は緑、低下は赤とする。

### 優先度C：拠点の各画面

**C1. ショップ。** ショップも他の個別画面と同じく「選ぶ（左）→ 判断する（右）」の2つの領域で組み、枠付きのパネルでは区切らない。以前は一覧と判断の列の間の広間に品の大きな絵（240px）を飾っていたが、絵がどの面にも載らず広間に浮いて置き場所が分からず、一覧で選んだ小さな絵を大きく繰り返すだけで情報が増えず、一覧から判断の列へ向かう視線を中央で止めていたため、ワイヤーフレームで2案（一覧を広げる案と、品を絵と値札だけで棚に並べる陳列棚の案）を比べ、画面の骨組みが他の画面とそろう前者にした。陳列棚の案は、名前が一覧に出ず、似た絵の品（3種の魔導スクロール）を選ぶまで見分けられないため採らなかった。配色と装飾は拠点のブロンズの作法のままとする。
- 購入と売却は、上段の画面名の位置に置いた2つのタブ（`ModeTab`、選んでいる方に金の下線）で切り替える。キーボードは `R`、ゲームパッドは `Y` でも切り替わり、操作ガイドに「売却へ／購入へ」として示す。切り替えても分類の選択は保つ。
- 左は、画面の左端から延びる暗い石板（`SlabSolid`）に載せる。左の上には分類タブ（すべて・武器・防具・装飾・消耗品・魔法、`CategoryTabs`、文字の幅に合わせて並べる）を置く。分類は `Q`／`E`（ゲームパッドは `LB`／`RB`）で順に切り替え、両端にその記号を示す。その下に、小さな絵（`ItemCell`の高さ72px、絵は原寸の48px）の右に名前と価格の2行だけを添えた平らな行（`ItemRow`、幅254px）を、3列の格子（`IconGrid`、行の幅320px）に並べる。購入では22品すべてがスクロールなしで収まる（売却では売却元の行のぶん、最後の段がスクロールになる）。名前・主効果・説明を行に書き並べる一覧にすると、帳簿のように見えて背景の上に表を貼ったように読まれるため、行に書くのは名前と価格だけにする（装備・倉庫は絵だけのマスで、名札に名前を出す。C2・C4）。絵を大きくすると、4列で原寸の絵を並べても品の名前が読めず、探しにくかった。行の右下には、売却では持っている数（「×3」）を添える。購入では数を添えず、持っている数は勘定台で示す。主効果と全文の説明は、行のTooltip（「購入 40 G」「売却 5 G」付き）と、判断の列に置く。選んだマスは金の輪郭と強い光で示し、マスにFocusが乗ったとき（矢印キー、ゲームパッドの十字）にもそのマスを選んで判断の列に出す。マスの上で `Enter`・ゲームパッドの決定、またはダブルクリックをすると、取引ボタンへFocusが移る（取引はしない）。売却のときだけ、一覧の上に売却元（倉庫／持ち込み、下線の文字タブ）を出し、「売却元」の横の「?」で売れない品（装備中の品と、魔法を込めた杖）を示す。売却元は一覧の中身を決めるため一覧のそばに、購入先は品の行き先のため勘定台に置く。
- 右の判断の列（`SlabSolidEnd`）は、上から品の絵（120px、48pxの絵を2倍で、台なしで淡い光の上）と、その右の名前・分類・主な効果（`ItemShowcase` の横並び）、金の細線、品が自分にどう効くか、勘定台（購入のときは購入先、数量を「〈 1 〉」と「最大」で、取引額を大きな1つの数字、「倉庫 3 → 4個 ・ 購入後 1,260 G」の1行）、取引ボタン（`PrimaryAction`）とする。売却では取引ボタンの上に「全部売却」を置く。品を選んでいないときは、残高は右上に任せて勘定台に所持金を出さない。説明文は列に並べず、マスのTooltipに任せる。一覧の品を判断の列へドラッグして落とすと、その品を選んで取引ボタンへFocusを移す（Goldは押すまで動かない）。
- 品が自分にどう効くかは、購入の判断に最も効く情報なので、判断の列の勘定台の真上、取引ボタンのそばに置く（`HeroStats.move_stats_to()`）。購入で装備品を選んだときだけ、「次の冒険の能力」の見出し、「防具と入れ替え（今：なし）」のように入れ替える枠と今の品の1行、変化する能力だけの「現在 » 購入後」（上昇は緑の▲、低下は赤の▼。`StatBars.changed_only`）を示し、何も変わらないときは「能力は変わらない」と1行で示す。消耗品・魔法を選んだときと売却のときは比べるものがないため、能力は出さない。能力には棒を付けない。装備品の組み合わせに決まった上限がなく、棒の長さを今の値に対してしか測れないため、長さが能力の大きさを表さないからである。比較する枠は、空いている対応枠、なければ最初の対応枠とする。
- 同じ数字を何度も見せない。主効果は判断の列の名前の下と勘定台の上の能力の変化、所持数は売却のマスの角の数と勘定台、所持金は右上のGoldだけに出す。

購入数は `QuantityStepper` のセレクター表示（「〈 1 〉」、左右キーで増減、「最大」で上限まで）とし、見出しに上限を示す。見せ場は取引の瞬間とし、商品の記号を購入なら所持数の表示へ、売却なら画面右上のGold欄へ飛ばし、着地した表示を強調する。Goldの表示は常に確定した値を示し、数え上げはしない。購入後は同じ品を選んだ状態に戻して続けて買えるようにし、売却後と通常の再描画では選択を解除する。

**C2. 準備（装備と倉庫）。** 準備画面（`HubPrepare`）は、装備と、持ち込みと倉庫の間の移動を1画面で行う。以前は装備画面と倉庫画面が分かれ、どちらにも持ち込みと倉庫の品が並び、出撃確認からは「装備・持ち込みを見直す」で装備画面へ飛べたため、持ち込みを整える入口が3か所あり、どこで何をするか迷わせていた。品は文字ではなく絵だけの正方形のマス（`ItemCell`、72px、絵は48pxの原寸）で見せる。品の名前・効果・価格を行に書き並べる一覧にすると、帳簿のように見えて背景の上に表を貼ったように読まれるためである。主武器・副武器・防具・装飾 1・装飾 2の5枠は維持する。上段は画面名「準備」とGold（控えめ）、下段は操作ガイド（`Esc 戻る`　`Enter 決定`　`← / → 倉庫・持ち込み`、杖を装備しているときだけ `M 魔法`）とする。
- 左の、画面の左端から延びる暗い石板（`SlabSolid`）の上段に、5つの装備枠を枠名を下に添えて横一列に並べる（`SlotCell`、88px、絵は72px）。空の枠にはその枠が受け付ける種類の共通記号を淡く描く。その下に、倉庫と持ち込みの2つの格子（`StockGrid`。倉庫は6列、持ち込みは4列）を左右に並べ、間に両端が溶けて中央に菱形の鋲がある縦の金の細線（`HubUI.column_rule()`）を立てて区切る（空きだけで分けると、どこまでが倉庫かが分かりにくかった）。装備枠と2つの格子を近くに並べるのは、品を枠へ運ぶ距離と、反対側へ移す距離をどちらも短くするためである。各格子は上段に名前（「倉庫」「持ち込み」）と使用枠（「22 / 120 枠」）、右端に並べ替え（標準・名前順・種類順のセレクター）、その下に種類の絞り込み（すべて・武器・防具・装飾・魔法・道具の文字タブ）を持ち、絞り込みと並べ替えはそれぞれ独立する。装備できない品（回復薬など）も、移すために並べる。一覧が空のときは数だけを出し、絞り込みで1つもなくなったときだけ「この種類の品はない」と添える。数が複数のときはマスの右下に「×3」を添える。「倉庫の品は冒険へ持っていかず、倒れても失わない。」という規則は「倉庫」の名前の横の「?」に置く。マスは、生成した青銅の枠（`art/ui/cell_frame.png`、装備枠は宝石付きの金の枠 `art/ui/slot_frame.png`）と絵の後ろの暖かい光で見せ、選んだマスは金の輪郭と強い光になる。同時に選べるのは枠かマスのどちらか1つとする。
- 右の判断の列には、選んだ品（なければ選んだ枠の品）の絵・名前（折り返して全文を示す）・種類と置き場所、その品が入る枠に装備した場合の「次の冒険の能力」（「防具と入れ替え（今：なし）」の1行と、変わる能力だけの「今 » 後」。何も変わらなければ「能力は変わらない」。`HeroStats` を `move_stats_to()` で借りる）、主な効果と説明、操作のボタンを並べる。選んだ品に入らない枠は暗く沈め、入る枠だけを明るく残す。装備できる品では、入る枠（空きがあれば最初の空き、なければ最初の枠）がPrimary Actionの「〇〇に装備」になり、ほかに入る枠があれば「副武器に装備」などを、その上に反対側への移動を置く。品を選んだまま入る別の枠を押すと、その枠がPrimary Actionの行き先になる。移動や装備のあとも同じ品を選んだままにし（移動したときは反対側の格子で）、続けて操作できるようにする。
- 装備と移動のしかたは、判断の列のボタンのほかに3つある。マスを装備枠へドラッグして落とすと、その枠に装備する（取り消しがきくため、落とした時点で実行する。「アイテムのドラッグ＆ドロップ」の作法）。判断の列へ落とすと、その品を選んでPrimary Actionの前で待つ。マスを反対側の格子へドラッグして落とすと移す。マスを右クリックすると、その品が入る枠ごとの「〇〇に装備」と反対側への移動を並べた小さなメニュー（`ContextMenu`）が出て、選ぶとすぐに実行する。装備中の枠のマスを右クリックすると「外す」（主武器は出さない）、杖なら「魔法を込める」と、込めた魔法があれば「魔法を外す」、武器の枠なら「主武器と副武器を入れ替え」が出る。メニューは、外の場所のクリックかEscで閉じる。以前の確認のポップアップ（`EquipPrompt`）はなくした。能力の比較が判断の列に常に出ているため、同じ内容を重ねて聞く必要がないからである。
- 装備中の枠のマスをどちらかの格子へドラッグして落とすと外せる（主武器は外せない）。主武器と副武器は、互いへドラッグして落とすと入れ替わる。装備や移動のあとに文章の通知は出さない。絵が飛んで着地点が弾む動きが成功を示すためである。移動先に空きが足りず一部だけ移ったとき（「空きが足りず、◯個だけ移しました。」）と、1個も移せないとき（「移動できません。移動先の空き容量を確認してください。」）だけ、判断の列に文章を出す。移るのは選んだ1スタックのすべてで、入らない分は元に残る。倉庫の格子の右端で右、持ち込みの格子の左端で左を押すと、もう一方の格子の同じ段のマスへFocusが移る。出撃画面の「準備を開く ›」から開いたときは戻ると出撃画面へ、ロビーから開いたときはロビーへ戻る。
- 杖への魔法は、杖の側からも込められるようにする（`MagicSocket`・`MagicPicker`）。以前は巻物を選ぶ・右クリックする・杖の枠へドラッグするの、巻物の側から始める操作しかなく、装備した杖の枠を見ても魔法が入っているか分からなかったため、杖を持っていても魔法を込める操作に気づけなかった。杖が入っている主武器・副武器の枠の右下に丸い穴を重ねる。空のときは青い輪と「＋」がゆっくり明滅し、込めてあるときは青銅の輪の中に魔法の絵を示す。判断の列の種類の行には「魔法：魔弾」または「魔法なし」を添える。穴を押す、`M`（ゲームパッドは `Y`）を押す（選んでいる枠が杖ならその杖、違えば最初の杖）、右クリックのメニューで「魔法を込める」を選ぶ、のいずれでも魔法の選択画面を開く。操作ガイドの「M 魔法」は、杖を装備しているときだけ出す。選択画面は、確認と同じ飾り枠の中に、持ち込みと倉庫の巻物を1枚ずつ大きなカード（巻物の絵、魔法の名前、効果、消費MP、置き場所）で並べ、今込めている魔法のカードは「込めている」として選べなくする。カードを選ぶことが決定で、確認は重ねない（カードの効果と消費MPが確認の役を兼ねるため）。込めてある魔法は「魔法を外す」で所持品へ戻せる。巻物がないときは、手に入れ方を一言添える。ダンジョンの所持品画面でも、装備の行の杖の名前のすぐ右に同じ穴を置き、穴か `M`（ゲームパッドは `RB`）で、持っている巻物から同じ選択画面を開く。込める・外すはターンを消費しない。巻物を選んでから「主武器に魔法装着」を押す従来の操作も残す。
- 見せ場は装備を変更した瞬間と移動の瞬間とする。装備では、マスの絵を変更した枠へ飛ばして着地で枠を弾ませる。主武器と副武器の入れ替えや取り外しのように運ぶ品がない変更は、変わった枠を弾ませるだけにする。移動では、品の絵を元のマスの位置から移動先の格子の該当のマスへ飛ばして弾ませ、該当のマスが見えていない場合は格子の中央へ着地させる。

**C3. 永久強化。** 永久強化は「能力の成長」と「開始地点」の2つの表示を持ち、ショップの購入／売却と同じく、上段の画面名の位置に並べた大きな文字のタブ（`ModeTab`）と `R`（ゲームパッドは `Y`）で切り替える。操作ガイドは `Esc 戻る`　`Enter 強化`（開始地点では `解放`）　`矢印 選ぶ`　`R 開始地点へ` とする。
- 能力の成長は、画面の左端から延びる暗い石板（`SlabSolid`）の上に、配線でつないだスキルツリーとして描く（`SkillTreePanel`）。ツリーはフォルダー構造のように左から右へ読む。左端に基礎HPを大きく（紋章96px）置き、その右に生命力・攻撃力・魔力量・防御力の枝を上から順に1行ずつ並べ、各枝の段（紋章48px）を右へ並べる。どの枝も同じ段が同じ列にそろう。基礎HPは4行の上下の中央に置く。配線は円の右の縁から次の円の左の縁まで引き、同じ枝の段の間はまっすぐ、基礎HPから各枝の最初の段へは、間の幹まで横に出て幹を縦に通り、枝の行へ直角に曲がって入る。矢印キーは、左右で枝に沿って移り（最初の段の左は基礎HP、基礎HPの右は生命力 I）、上下で隣の枝の同じ段（その枝にない段なら最後の段）へ移る。
- 各ノード（`SkillNodeButton`）は、暗い円の中に紋章、その周りに段階数と同じ数の目盛りの輪を置き、ツリーには名前や「Lv 2 / 5」などの文字を置かない。紋章と目盛りの輪で枝と育ち具合が分かり、名前とLvは選んだときの右の列とTooltipで示す。まだ開いていないノードは紋章を暗くし、目盛りも淡くして、円の右上に小さな鍵の印を付ける。開いていて上限に達しておらず、今の所持金で強化できるノードには、同じ位置に金の菱形の印を付け、選ぶ前にどこを育てられるかが分かるようにする（印は `StateMark` が描き、開始地点の行と共通）。選んだノードはロビーの帯と同じ暖かい光を背にする。配線は元のノードの育ち具合（Lv ÷ 上限）だけ元の側から光り、上限に達すると全体が光って淡くにじみ、小さな光の粒が流れ続けて、次のノードが開いたことを示す。
- 矢印キーでノードの間を移るとそのノードを選び、マウスはクリックで選ぶ。選ぶだけではGoldを使わない。キーボードでは選んだノードでEnterを押すとPrimary Actionへ移り、もう一度Enterで強化する。
- 右の列（画面の右端まで延びる石板）は、選んだノードの紋章・名前・Lv、今の効果と次の効果、開く条件（「開く条件：生命力 I を上限（Lv 5）まで　あと Lv 2」）と上限で開く段、「永久補正の合計」（最大HP・攻撃力・防御力・最大MPを `StatBars` で示す。次の段階で増える能力だけを今 » 強化後とし、棒は全ノードを上限まで育てたときの合計を満タンとして、その能力の成長がどこまで進んだかを表す）を示し、下端はショップと同じ勘定台（必要なGold、強化後のGold）と、Primary Actionの「強化する」（「あと20 G」「条件未達」「強化上限」）とする。
- ツリーの開き方（基礎HPの上限で4本の枝、各段の上限で次の段）と、開始地点の決まり（中ボスを倒した階の次から始められ、どの階からでもLv 1）は、それぞれ能力の成長の左上の「ツリーの開き方」と、開始地点の左上の「開始地点の開き方」の見出しの横の「?」に置く。見出しのない「?」は何の説明か分からないためである。詳細の今の効果と次の効果は「今　最大HP +0」「次　最大HP +1」のように、どちらにも名前を付ける。
- 開始地点も、能力の成長と同じく左から右へ読むツリーとし、ツリーには文字を置かない。ステージごとに1行を使い、左端にステージの浮島の絵（`StageData.diorama`、紋章96pxの円）を置いて、その右に11F・21F・31F・41Fの4つのノード（64pxの円）を並べる。ステージの行は左端に上から順に積み、前のステージ（`previous_stage`）の浮島から次のステージの浮島へ縦の配線を引いて、フォルダー構造のように前のステージを踏破すると下の行が開くことを示す。各階のノードには、その階を開く中ボス（11Fなら10Fの中ボス）の待機の絵を出す。まだ倒していない中ボスは暗い影にして、出撃画面の「？？？」と同じく姿をはっきり見せない。中ボスを倒しておらず解放できないノードは鍵の印、今の所持金で解放できるノードは金の菱形の印を付け、解放済みのノードは目盛りの輪を光らせ、そこへ入る配線を光らせる。浮島は選ばず、クリックするとその行の11Fを選ぶ。矢印キーは、左右で同じステージの階に沿って移り、上下で隣のステージの同じ階へ移る。右の列に階・条件・ステージの説明・価格と「解放する」を示し、ステージ名もここで示す。
- 見せ場は強化の瞬間とし、育てたノードの目盛りの輪の発光と拡大、配線が前の長さから新しい長さへ光っていく動き、永久補正の合計の強調を同時に見せる。上限に達してノードが開いたときは、開いたノードも光らせる。

**C5. 拠点の環境演出。** `HubAmbience` が、背景画像の光源（吊りランタン・燭台・商人の台のランタン）の位置に暖色の光を加算合成で重ねて個別にわずかに明滅させ（強さの揺れは約3割以内）、画面全体に暖色の埃の粒子をゆっくり漂わせる。光源の位置は背景画像内の相対座標で持ち、背景と同じく縦横比を保って画面を覆う配置に換算する。拠点の立ち絵は呼吸・瞬き・髪の揺れなどの待機動作を続け、ホームでは選択中の項目に対応する背景の物を光らせる（B3）。操作していない間も画面が生きて見えるようにするためである。これらはUIの読みやすさを妨げない強さに抑え、Focus表示と本文の視認性を優先する。

**C6. ダンジョンの環境演出と絵の差し替え口。** 拠点の描き込みに対してダンジョンが平板に見えないよう、画像がなくても成立する環境演出を先に置く。`DungeonLights` は、見えている床を見下ろす壁面に座標のハッシュで松明を掛け（1画面最大10本、森林では掛けない）、炎を2つの波で明滅させ、光を加算合成で床へ落とす。見えている階段には、広い光と階段のマスに絞った強い光の2層の金色を重ねてゆっくり脈打たせ、暗い石段の絵でもログの言う「金色の階段」として見つけられるようにする。光の色は地形テーマごとに変える。`AmbientDetails` の粒子は地形テーマに合わせ、蒼灰は埃、苔と森林は立ちのぼる胞子、燠火は上昇して消える火の粉、黒曜は瞬く光とする。どちらもゲーム進行の乱数を消費せず、見えているマスだけに出す。`DungeonVignette` は画面の縁を暗くし、照らされた部屋を画面の中心として見せる。地形の下には 霧の層（`world/dungeon/unexplored_mist.gd`）を敷き、まだ知らない範囲を真っ黒の画面ではなく、地形テーマ（森林は専用の緑）の色でゆっくり流れる薄い霧として見せる。霧の模様は位置だけから作るノイズで、間取りとは無関係なので未探索の部屋を示さない。既知のマスの地形が上を覆うため、霧は未知の範囲にだけ見える。層は危険表示とHUDより下とする。

敵の絵は `art/enemies/<id>.png` に置いた右向きの横一列の帯（通常96px・ボス176pxの正方形コマ。待機4コマ、溜め、攻撃、被弾、倒れの順）で差し替える。体の高さは主人公の56pxを基準に敵ごとに決め（人型の番兵は主人公と同程度、ネズミやスライムは小さく、ボスは約2倍）、コマの余白は突進などの動作に使う。待機のコマで決めた倍率を動作にも使い、それでも枠からはみ出す動作のコマだけを個別に縮める。`EnemySprites` が敵の種類（ボスは表示名）から `id` を決め、画像がない敵は従来の図形で描く。名前付きのボスに専用の画像がなければ共通の `boss` を使う。溜め・攻撃・被弾のコマは `BattlePresentation` が演出の間だけ保持する。砲台の射線予告と突進獣の突進予告の間は溜めのコマを出し続け、矢印だけでなく体の姿勢でも次の行動を示す。突進の巣は攻撃しないため、孵化の1ターン前に溜め、孵化したターンに攻撃のコマを出す。とどめを受けた敵は、のけぞりの直後に倒れのコマへ切り替え、不透明なまま約0.2秒見せてから消える。倒れのコマがある敵は、図形用の潰れる演出を行わない。キャラクターの層は行でY方向に並べ替え、下の行ほど手前に描く。同じ行では主人公を最後に描き、大きな敵が隣に立っても主人公を隠さない。コマの大きさは主人公と同じく画素の0.8倍とし、主人公と同じ密度で見せる。生成画像は `art/enemies/source/` と `art/tiles/source/` に置き（`.gdignore` によりGodotへ取り込まない）、`tools/process_enemy_sheet.py` が背景の除去・コマの分割・縮小・減色・縁取りを、`tools/build_terrain_atlas.py` が3×2の地形の絵から48pxのアトラス（床3種・柱・階段、壁は接続16通りを合成）を作る。壁の開いた辺は、平らな線を描かずに石の模様そのものを明るく、または暗くして縁を表す。壁の石は床より暗く（0.6倍）、模様の濃淡も半分に抑え、通れない場所より床と敵・アイテムに目が行くようにする。森林の木も同じ理由で、見えている木を少し暗く描く。敵の減色は、目の光や宝石のような少数の差し色が残るoctree方式とする。主人公のダンジョン用の絵は承認済みの64pxのコマ（`art/characters/mio_dungeon_chibi_64/`）を元とし、`tools/refine_mio_sprites.py` が `art/characters/mio_dungeon_refined/` に敵と同じ1pxの暗い縁取りを付けた版を作る。デザインを変えないため作り直しの生成はせず、待機は同じ絵の頭と肩を1px下げたコマとの2コマで呼吸させ、正面の瞬きもコマに焼き込む。松明にも `torch` の帯を置くと、図形の炎を置き換える。深緑の森林の壁は木として描き、`art/tiles/forest_trees.png`（生成した4種類の木を64pxに変換したもの、`tools/process_tree_sprites.py`）から座標のハッシュで1本を選び、マスの下端に根元を置いてマスより大きく描く。上の行から順に描いて手前の木が奥の木に重なるようにし、覚えているだけで見えていない木は暗くする。

**C7. 出撃（ステージ選択と出撃確認）。** 出撃は、ステージを選ぶことと、持ち物と能力を確かめて挑戦することを1画面で行う（`HubDeparture`、画面名「出撃」）。以前はステージ選択・出撃確認の2画面に分かれ、ロビーのカードとあわせて同じステージの情報を3回見せてから冒険が始まっていたためである。
- 左は、画面の左端から延びる暗い石板（`SlabSolid`）の上の地図とする。各ステージは、楕円の浮島の上にダンジョンが立体的に建つジオラマの絵（`StageData.diorama`、`art/hub/dioramas/`）で示し（`StageMapNode`）、地図の左から右へ、1つおきに高さを変えて（2つ目は1つ目より上）一直線に並べない。島どうしは点線の道でつなぎ、道は開いているステージまで暖かい色で、その先は淡く示す。島の正方形は隣と重なってもよいが、クリックできる範囲は島の形と名前だけとし、隣のステージを誤って選ばないようにする。
- 選んだステージの島は、暖かい光を背にゆっくり浮き沈みし、名前を金にする。ほかの島は一段暗く休ませ、まだ開いていないステージは暗く沈めたうえで開いた島の約0.74倍の大きさにし、名前の前に強化ツリーと同じ鍵の印（`StateMark`）を付けて「古代遺跡を踏破で解放」のように条件を添える。開いていない島が高い位置にあっても、選べる島より目立たないようにするためである。今後追加するステージ（「？？？」）は封印された扉の島として置き、「未解放」とだけ示す。
- 矢印キーで島の間を移るとそのステージを選び、Enterで挑戦のボタン（Primary Action）へ移る。右の判断の列は、上から、ステージ名、全階数と難易度（横の「?」で、10階ごとの中ボスと脱出口の規則を示す）、1行の説明と守護者、金の細線、持ち込む装備（5枠の小さなマス `SlotCell`（64px、Tooltipで名前）と、右上の文字の操作「準備を開く ›」）、持ち込みの使用枠（「1 / 40 枠」、横の「?」で倒れると持ち込みのおよそ半分を失うこと）、金の細線、「次の冒険の能力」（`HeroStats` の4行を `move_stats_to(..., true)` で借りる）、開始階（下線の文字タブ、横の「?」でどの階からでもLv 1で始まり永久強化と持ち物は引き継ぐことを示す。選べる階が1Fだけのときは選択肢が1つのタブにせず「1F」を文字で示す）、Primary Actionの「古代遺跡・1Fから挑戦する」とする。開いていないステージを選んだときは、ボタンを「〇〇は未解放」として無効にする。守護者は「守護者　1 / 5 撃破」の1行に、撃破済みの守護者を階と名前で1行ずつ、まだ倒していない最初の守護者を「次　20F ？？？」の1行で続ける。未撃破の階ごとに「？？？」を並べても、10階ごとにいることを繰り返すだけになるためである。全ステージに共通する規則や、ステージで差のない敵の傾向は出さない。まだ開いていないステージの条件は地図の島の下に出すため、右の列では繰り返さない。説明の欄は長いときにキーボードでもスクロールできる。`R`（ゲームパッドは `Y`）か「準備を開く ›」で準備画面（C2）を開き、戻るとこの画面の同じステージへ帰る。ロビーの出撃の決定ボタンからは、前回のステージを選んだ状態で挑戦のボタンにFocusを置いて開く。
- 持ち物を絵だけにしたのは、行に名前と効果を書き並べると帳簿のように見え、確認が事務的に読まれるためである（C2と同じ文法）。持ち込みの品の中身はこの画面では一覧にせず、使用枠の数だけを示す。中身を見直すときは準備画面を開く。
- ジオラマの絵は、Codexの画像生成（gpt-image-2.5）で、既存のステージ画像と利用者のスケッチを参照して、平らなマゼンタの背景の上に描かせた元絵（`art/hub/source/diorama_<stage>.png`）から、`tools/build_stage_dioramas.py` がマゼンタを抜いて作る。森の葉に移ったマゼンタの照り返しは、紫や藍を緑へ寄せて取り除く。封印された扉の島は紫が本来の色なので、縁の色かぶりだけを取る。
**C8. 設定。** 設定画面（`HubSettings`）の項目は、全体の音量・効果音・環境音・画面の揺れ・画面モード・ヘルプの6つとする。音量を3つに分けるのは、効果音と環境音を別々に調整・消音できるようにするためである（Game Accessibility Guidelinesの「Provide separate volume controls」）。音声は `default_bus_layout.tres` の `Effects`（`GameAudio` の効果音）と `Ambience`（ダンジョンの環境音）の2つのバスを通り、どちらも全体の音量（`Master`）の下で鳴る。画面の揺れは、被弾時の画面揺れに弱い人が弱めたり止めたりできるようにするために置く。項目が少ないので、画面の高さいっぱいの列にはせず、項目の分だけの高さの帯として画面の縦の中ほどに置く。帯は画面の左端から延び、右端だけがロビーの左メニューと同じく広間に溶ける石板（`SlabBand`）とし、右側は広間をそのまま見せる。Focusのある項目の短い説明（全体の音量は「すべての音の大きさ。0%で消音。」など）は、帯の尖った先の右側の広間に、その行と同じ高さで淡い影の上へ置く（行を移ると帯と一緒に滑る）。行の下に置くと、音量を動かす視線が行と説明の間を往復するためである。「ヘルプ」の行の「遊び方と決まりごとを読む」で、ヘルプ（「説明の置き場所」を参照）を開く。ヘルプは左に話題の行（同じ光の帯で選ぶ）、右にその話題の段落を置き、画面名は「ヘルプ」に変わる。段落の1行は全角40字以内に収め（Xbox Accessibility Guideline 101の日本語の目安）、右に広間を見せる。Focusのある行は画面の左端から始まるロビーと同じ光の帯で示し、上下キーで行を移ると帯が滑って移る。変更はその場で反映されるため、Primary Actionは置かない。操作ガイドは `Esc 戻る`　`↑ / ↓ 項目`　`← / → 変更` とする。

### 必要な素材

以下の素材は外部で用意する。どれも差し替え口を通して使い、未着手の状態でも各項目の実装は進められる。表示書体と本文書体のフォントファイル（ライセンス確認済みのもの）。パネルとカードの装飾枠の9-slice画像（通常・選択の2種）。拠点ホームの5枚のカード用の挿絵。見せ場ごとの効果音（能力獲得・購入・売却・装備・強化・冒険クリア・敗北）と、カーソル移動音。通常の敵6種と古代遺跡・深緑の森林のボス10体の待機・動作の絵、地形テーマ4種の地形の絵（C6の差し替え口を使う）。

### 検証

各見せ場について、`capture_*.gd` で演出開始・25%・50%・完了の4時点を1600×900・1280×720・1920×1080で撮影し、人の目で確認する。Headlessのテストでは、状態と保存上の値が演出の開始前に確定していること、見せ場を決定・キャンセル入力で最終状態へ飛ばせること、入場演出の途中でも選択できること、非表示・解放時に表示層とオーバーレイが基準状態へ戻ることを検証する。ヒットストップと画面揺れは、戦闘の論理座標とターン順序を変えないことを既存の戦闘テストで確認する。
