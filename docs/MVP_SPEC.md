# Godot 2Dローグライク MVP開発仕様 Ver.0.1

## 1. プロジェクト概要

Godotを使用して、2D見下ろし型・ターン制のローグライク／ローグライトゲームを制作する。

「不思議のダンジョン」系の探索・レベルリセット・ランダム生成をベースにしつつ、

- 武器ごとに異なる攻撃範囲
- 8方向を利用した位置取り
- 障害物・地形を利用した戦闘
- Fog of War
- 敵ごとに異なる索敵特性
- レベルアップ時の3択能力
- 拠点による微小な永久成長

を特徴とする。

MVPでは「1回の冒険を開始し、ダンジョンを探索・戦闘・成長し、死亡またはクリアして拠点へ戻る」というゲームループの完成を最優先とする。

---

# 2. 開発方針

## 最重要方針

MVPでは必要最小限の機能のみ実装する。

将来の拡張を妨げない構造にはするが、将来機能を先回りして実装しない。

以下は禁止する。

- 要求されていない機能の追加
- 過剰な抽象化
- 不必要なデザインパターン導入
- MVPで使わないシステムの実装
- Hardモードの先行実装
- オンライン機能
- マルチプレイ
- 実績システム
- 課金システム
- 複雑なクラフトシステム
- 高度すぎる敵AI
- 大規模なストーリーシステム

実装前には必ずPlanを提示し、変更対象・新規ファイル・実装内容を説明すること。

ユーザーの承認なしに仕様を拡張しないこと。

# 4. ターンシステム

基本ルール：

1. プレイヤーが行動
2. プレイヤーの行動が確定
3. 1ターン経過
4. 敵が行動
5. プレイヤー操作へ戻る

ターンを消費する行動：

- 移動
- 攻撃
- アイテム使用
- その他、ゲーム世界へ直接作用する行動

ターンを消費しない操作：

- インベントリ確認
- ステータス確認
- マップ確認
- 攻撃方向選択
- 攻撃範囲確認
- 攻撃キャンセル
- Main / Sub武器切り替え
- 武器・防具・アクセサリーの装備変更

安全な探索済み区間では、移動キーを押し続けると通常入力の後に連続移動する。連続移動の各1マスは通常の移動と同じく1ターンを消費し、敵も1マスごとに行動する。敵を視界内に発見、未探索マスの直前、アイテムまたは階段の発見、分岐への到達、既知のアイテムまたは階段の直前、移動入力の解除、UI表示、攻撃モードへの移行のいずれかで停止する。停止後は新しい移動入力が必要となる。

連続移動は同じ方向への入力反復だけを行い、自動探索・経路探索・分岐選択は行わない。

# 6. 戦闘システム

## 攻撃操作

「攻撃ボタン + 8方向指定」方式とする。

フロー：

1. 攻撃ボタン
2. 攻撃モードへ移行
3. 8方向から攻撃方向を指定
4. 武器の攻撃範囲をハイライト表示
5. 攻撃確定
6. ターン消費

方向選択中はターンを消費しない。

キャンセル可能。

# 7. 武器システム

武器ごとに攻撃範囲そのものが異なることを本ゲームの主要な特徴とする。

## 想定武器

### 剣

- 射程：1
- 指定方向と左右隣の計3方向を同時攻撃
- 隣接した複数敵への対応

### 槍

- 射程：2
- 直線攻撃
- 間合い管理に優れる

### 斧

- 短射程
- 高威力
- 前方複数マスへの攻撃候補

### 大剣

- 前方横方向への広範囲攻撃
- 複数敵への対応

### 短剣

- 射程：1
- 低威力
- 将来的に連続攻撃・背面攻撃などを追加可能

### ハンマー

- 射程：1
- 生存した敵を最大2マスノックバック
- 途中に壁・敵・マップ外・斜めの角があれば、移動可能な距離まで押す

### 斧

前方2マスの固定範囲を攻撃し、剣より高火力にする。槍のレベル上昇による射程拡張は適用しない。

### 弓

- 遠距離直線攻撃
- 射程4～6程度を想定
- 将来的に弾薬システム対応可能

### 杖

杖ごとに1枚の魔導スクロールを装着し、MPを消費して魔法を使う。未装着時は剣型の低威力近接攻撃。初期魔法は直線攻撃・範囲攻撃・回復の3種類。

スクロールは購入・敵のレアドロップで入手する。装着中は装備の一部として保護し、未装着なら通常の所持品としてロスト対象にする。操作と数値は[開発メモ](../rogue-like-play/開発メモ.md)の「杖と魔法」を参照。

# 9. 防具・アクセサリー

装備枠：

- Armor ×1
- Accessory ×2

装備中アイテムは死亡時ロスト対象外とする。

## 防具の役割

基本的には、

- 防御力
- 属性耐性
- 軽度の特殊効果

を担当する。

## アクセサリーの役割

コンテンツ追加では、購入・敵ドロップで得る消費型アクセサリー（護符）を追加する。通常の床配置には含めない。既存の装備型は互換性のため保持する。

同じ効果の再使用は不可。ターン継続バフは異なる5種類まで、フロア継続効果は枠外。使用不可時は消費せず、帰還時は全効果を終了する。具体的な種類・数値と追加敵の挙動は[開発メモ](../rogue-like-play/開発メモ.md)の「追加の敵と消費型アクセサリー」を参照。

# 17. ダンジョン

ランダム生成されたフロアを探索する。

現在のコンテンツ構成：古代遺跡と深緑の森林を各50階とする。10・20・30・40Fに中ボス、50Fに最終ボスを配置する。ボス撃破まで階段は使用できない。遺跡の最終ボス撃破で森林を開放し、その先は「？？？」として表示する。

## 地形の表示仕様

テストプレイ時の視認性と雰囲気を整えるため、フロア地形は暗い青灰色の石造ドット絵で表示する。

- 1 Tileは32×32pxとし、16×16px相当のドット絵をNearestで2倍表示する
- 床には少数の模様差分を用意し、座標に基づいて固定選択する
- 壁は上下左右の接続状態を16通りのタイルへ対応させ、連続した輪郭として表示する
- 階段は暖色の金色、Pillarは床と区別できる石柱として表示する
- Fog of Warの現在視界・探索済み表示は既存の明暗差を維持する
- 1～3Fは青灰の遺跡、4～6Fは苔むした洞窟、7～9Fは灼熱の深層、10F以降は黒曜の聖域として配色を切り替える
- 各テーマは同じタイル形状を共有し、地形ルールや当たり判定を変更しない

森林では苔色の床と木々の装飾を使用する。当たり判定と視界のルールは遺跡と共通。

# 19. 特殊フロアと将来的なマップタイプ

モンスターハウスは通常フロアで暫定5%の確率で生成する。7×7の部屋に敵8体・アイテム8枠を追加し、床の色と発見ログで危険を伝える。ボス階では生成しない。ショップ・ドロップ限定品は床配置に含めない。

入室や通路を封鎖しないため、配置次第では回避・撤退できる。開始地点がモンスターハウス内になるケースも意図した不意打ちとして許容する。

# 25. MVP Enemy Detection

MVPでは複雑にしない。

最低限：

- Vision型
- Proximity型
- Fixed/Turret型

程度から開始する。

HearingやShared AlertはMVP対象外。

通常敵は遺跡で各階3体、森林で4体を基本とし、Vision・Proximity・Turret・高速型・召喚型を巡回配置する。10階ごとに別途ボス1体を追加する。深度ごとに通常敵を強化し、森林は遺跡より補正を1段階高くする。

Turretは1敵ターン予告した後、同じ位置・方向から射線が通る場合に射撃する。予告中は長い白線を表示する。射線から外れる、射程外へ出る、遮蔽物が入ると予告を解除する。射撃後およびノックバック後は再予告が必要。装備・UIなどの無料操作では予告は進まない。

# 31. Permanent Upgrade

拠点のスキルツリーで、基礎HPから生命力・攻撃力・防御力・魔力量の永久強化へ分岐する。段階と前提条件・価格はResourceで調整する。

ステータス強化とは別に「ダンジョン途中解放」の枠を設ける。各ダンジョンの10・20・30・40F中ボス撃破後、コインで対応する11・21・31・41F開始を解放する。価格は暫定150・350・600・900 Gold。条件と解放はダンジョン別に保持する。

途中開始はLv1で、永久強化と持ち込み装備を適用する。深層は永久強化を前提とする一方、1Fから時間をかけて育成する攻略も可能とする。

# 34. Item Loss

Inventory内のロスト対象の所持枠から、半数（奇数は切り上げ）をランダムに選択して消失させる。選択された枠はスタック全体を失う。

例：回復薬×10、爆弾×6、毒消し×2の3枠なら、ランダムな2枠を全個数失う。

装備中アイテムは抽選対象外。死亡・中断・滞在上限による強制帰還に共通して適用する。Goldは半額を失い、損失の端数は切り捨てる。

---

# 35. Loss Reduction

将来的に、

- Gold損失軽減
- Item損失軽減
- 特定アイテム保護

などをアクセサリーやアイテムで実装可能にする。

ただし損失率を完全な0%にする設計は避ける。

# 36. Safe Return

最終階以外の10Fごとの中ボス撃破後、フロア入口に脱出口を出す。脱出口に乗り確認で「はい」を選ぶと、Gold・Inventory・Equipmentを保持して帰還する。消費アイテムは不要。

各フロアの滞在上限は暫定5000ターンで、次階への移動でリセットする。ボス階にも適用し、中ボス撃破では一度だけ150ターン延長する。残り30%・20%・10%・100ターンでイベントログに警告を出す。上限で強制帰還し、通常の損失を適用する。

階段では確認後に次階へ移動する。確認・キャンセルやメニュー閲覧でターンは進まない。同一マス上で確認を繰り返さず、再進入時に表示する。上限と重なる場合の優先順は階段移動、ボス撃破、脱出、強制帰還。死亡時は移動・脱出できない。

巨大なGameManager一つにすべてを詰め込むことも避ける。

UIは `res://ui/theme/dungeon_theme.tres` をプロジェクト共通Themeとして使用する。暗色の面・明るい本文・控えめな金色を基調とし、通常面は低彩度の細い輪郭、選択と主要操作は金色の輪郭を使い、面の明度・余白・控えめな影で階層を示す。参考アートは方向性の基準であり、実行時素材として使用しない。拠点・ショップ・装備・倉庫・永久強化・出撃準備はこのThemeの役割を使用し、HUDのHP・MPなど意味を持つ専用表示は別途維持する。

- 操作は `PrimaryButton`（主要操作）、`SecondaryButton`（戻る・補助操作）、`ItemButton`（選択）、`GoldButton`（購入・成長）を使い分ける。
- 文字は画面名 `TitleLabel`（30px）、見出し `HeadingLabel`（24px）、項目名 `ItemNameLabel`（20px）、主要値 `ValueLabel`（26px）、本文 `BodyLabel`（18px）、説明 `DescriptionLabel`（18px）、補足 `MutedLabel`（16px）、価格 `GoldLabel`（21px）を使用する。ボタンは原則18px、補助操作は16px。画面ごとのフォントサイズ・色overrideは追加しない。
- 拠点のヘッダー・ページ・フッター、各画面の列はContainerで配置する。`HubUI` は `MainPanel` / `ItemPanel` とMargin・VBox/HBoxの構造だけを共通化する。基準内容幅1280px・高さ810px、画面端は最低20px相当を確保して縮小する。通常のパネル内余白24px、列間20px、縦間隔12px、密な詳細は8px。倉庫は独立した1280×650pxのContainer構成を同様に縮小する。
- 外観の調整はTheme内の名前付きStyleBox（`MainSurface`、`SurfaceHover`、`FocusOutline`など）を編集する。同一のStyleBoxを共有するControlへ一括反映されるため、画面側で複製しない。文字色・文字サイズは該当するTheme Typeを編集する。Theme内の色項目とStyleBoxの色はGodot上では別プロパティであり、自動連動するパレットではない。
- `CharacterButton` と `SpeechPanel` は拠点キャラクターの透明なクリック領域と吹き出し専用とする。新規画像を要する装飾は、後述「UI体験の改善」の素材差し替え口を通してのみ追加し、素材がない状態でも現行の表示で成立させる。

色の役割は背景 `#020305`、主面 `#252525`、浮いた面 `#2B2B2B`、一覧の内側 `#1C1C1C`、Hover `#363636`、選択面 `#26241A`、通常境界 `#525252`、選択境界 `#B89759`、Gold `#D6B77B`、本文 `#EEE9DF`、説明 `#C9C9BF`、補足 `#B2B3AA`、減少 `#DB857A`、増加 `#91C2A3` とする。拠点背景の画像は暖かい光を残し、上に重ねる中立色の暗幕を薄くして石造りの奥行きを見せる。主パネルは青みを含まない不透明な石墨色で背景と分離する。透過率と影はTheme内のStyleBoxに集約する。一覧／詳細比率はショップ約53:47、出撃約52:48、倉庫は所持品／中央／倉庫が約37:26:37。拠点の左右Navigationは各約390pxで中央のキャラクター空間を残す。

ショップの商品詳細と装備比較、倉庫の選択説明は `ItemDetails`（RichTextLabel）を使用する。商品名・価格・補足は既存LabelのTheme役割から色と文字サイズを取得し、能力差分は変更前→変更後と符号付き数値を併記する。増加は `PositiveLabel` の控えめな緑、減少はThemeの `ItemDetails/decrease_color` を使用する。長文は枠内でスクロールし、Tabで詳細へFocusを移した後は方向キー・Home/Endで閲覧できる。アイテム名・説明はBBCodeとして解釈せず、選択変更時は先頭へ戻す。

ショップ・装備・倉庫の一覧は `ItemTooltipList` で標準Tooltipを共通化する。幅はThemeの `ItemList/tooltip_width`、背景は既存TooltipPanelを使い、長文を折り返す。表示待ち・消去・画面端の位置調整はGodotに任せる。Tooltipは補助表示とし、選択内容の説明は画面内にも表示する。

ショップ・倉庫・装備・出撃確認の所持品は `ItemCardList` を使用し、48pxの種類アイコン・名前・主効果を約80pxの行に配置する。ショップは右端に価格と所持数、倉庫と装備では個数と所在を表示する。レアリティは現行ItemDataに存在しないため表示しない。`ItemGlyph` は武器種、防具、装飾品、護符、巻物、HP／MP回復薬をGodotの図形で描画する。個別アイテムの専用イラストではなく、種類の識別を補助するための共通記号とする。`ItemVisual` は同じ記号を拡大表示し、`ItemShowcase` が商品名・分類・主効果と組み合わせる。ショップ購入・売却・装備の詳細で共用する。

カードの入力・選択・検索・Tooltip・スクロールは標準ItemListに任せ、描画だけを拡張する。ネイティブの項目文字列は名前検索とアクセシビリティのために保持し、Themeの `ItemCardList/font_*_color` を透明にして二重描画を防ぐ。表示色・文字サイズは既存Labelの役割を参照し、行高・アイコンサイズ・価格領域・余白は `ItemCardList` のTheme定数で調整する。長い名前はTextLineで省略し、全文は詳細欄とTooltipに残す。

永久強化は、強化名・現在Lv・その強化による補正の現在値→次回値・前提の必要Lvと現在Lvを、購入ボタンと分けて表示する。前提条件はSkillNodeの定義から取得し、条件未達・Gold不足（不足額）・強化上限を区別する。上部には永久補正の合計を表示する。途中開始の解放は選択ステージごとに、中ボス撃破→開始地点の関係、ステージ未解放・中ボス未撃破・Gold不足・解放済みを表示する。購入可否の判定と保存は既存のRunCarryover／Mainが担う。

永久強化は能力選択カードと選択詳細に分け、現在Lv・上限・進捗と次回効果を表示する。能力強化と途中開始の解放はカテゴリタブで切り替える。条件未達の能力も選択して説明を読める。購入操作は詳細領域のPrimary Actionで行い、可否は既存の状態判定に従う。

ショップは購入価格／売却収入、所持数の現在→取引後、残高の現在→取引後を分けて表示する。売却後の選択解除と、保存成功後だけに出す符号付きGoldフィードバックを維持する。倉庫は所持品・選択品と移動操作・倉庫の3領域とし、中央に移動方向を示す。移動は既存の1スタック単位であり、全種類を一括転送する機能は持たない。

装備は候補／比較／キャラクターと装備枠を隣接させ、既存のMain・Sub・Armor・Accessory 1・Accessory 2の5枠を維持する。`CharacterPreview` は既存の待機アニメーションを使用する。出撃は `StageCardList` でステージの既存画像・階数・難易度・説明を示し、右側に選択先の詳細と準備操作を置く。存在しない推奨Lv・報酬は表示しない。最終出撃確認は引き続き別段階とする。

操作の時間変化は `ui/ui_motion.gd` の `UIMotion` で管理する。主要ボタンのHoverとFocusは100ms、押下は70ms、選択詳細は140ms、Gold増減は220ms、装備枠は160ms、画面表示は180msを基準とする。色・枠線はThemeに残し、scaleとalpha、選択カードの内側金枠の強さ、HUDのHP・MP残像ゲージの表示値を動かす。選択枠は140msで強まり、ショップの詳細・大型アイコン・所持数、装備の比較・大型アイコン、倉庫の詳細・大型アイコン・移動方向は、選択内容と操作可否を即時更新した後に同じ140msでFade更新する。装備枠の切り替えで自動選択される候補にも選択枠の演出を適用する。通常の一覧再描画では選択演出を再生せず、古い選択のTweenと透明度をリセットする。倉庫では選択元を切り替えた際に反対側の選択演出も解除する。Controlごと・プロパティごとに前のTweenを停止し、非表示・解放時に基準値へ戻す。Containerの位置や最小サイズはアニメーションせず、位置の動きが必要な場合は後述「UI体験の改善」の表示層を動かす。

HUDのHP・MPは数値と実ゲージを即時更新し、減少時は明るい残像を120ms保持してから280msで現在値へ追従させる。増減時は数値を220msで一度だけ1.06倍に拡大して戻す。同値の再描画は演出を再開せず、連続減少は残像の現在位置から追従し直し、回復は残像を即時更新する。初回表示・最大値変更・冒険開始時は演出せず同期し、非表示時はTweenを停止して残像と拡大率をリセットする。実数値・ゲーム処理・入力は演出を待たない。残像の色と実ゲージのStyleBoxは共通Themeで管理する。

取引・装備・倉庫移動・永久強化の成功演出は、保存まで成功した `Main.preparation_completed` 通知で開始する。UIのTween完了をゲーム処理から待たず、残高・一覧・装備は即時更新する。購入は負、売却は正のGold増減を既存のフィードバック欄に表示する。永久強化は、確定したランク増加がある能力カードを220msで1.025倍に拡大して戻し、選択中の能力が上がった場合は詳細の現在値も同時に1.04倍で強調する。初回表示・選択だけでは成功演出を出さず、選択変更時は詳細の拡大をリセットする。画面を閉じる操作は即時とし、退場演出による入力待ちを設けない。

戦闘の結果は先に確定し、`BattlePresentation` が記録済みのイベントから予備動作・攻撃・被弾・死亡を再生する。剣は斬撃、槍は突き、ハンマーは衝撃波、魔法は発光輪で表現し、攻撃範囲の演出は視界内に限定する。敵は種類ごとの描画と待機・移動・被弾の姿勢を持つ。同一敵の連続移動、追従、交差する斜め移動は順序を維持し、経路が重ならない敵の移動だけを同時再生する。演出は論理座標を変更せず、既存の戦闘演出中の入力制御を維持する。中断・階層移動時は姿勢、位置補正、残存エフェクトを解除する。

カメラは探索中の追従を平滑化し、新しい階の開始位置へは即座に合わせる。階層開始とモンスターハウス発見は短い非操作型バナーで知らせ、成長選択・持ち物・冒険結果には共通ThemeとUIMotionを適用する。環境の微粒子と階段・脱出口の淡い光は視界内に限定し、未探索の情報を表示しない。

音源素材が揃うまで、`audio/game_audio.gd` の `GameAudio` が生成する仮のPCM効果音を使用する。武器、被弾、撃破、取得、足音、保存成功後の拠点操作、成長、階層開始、警告、帰還・敗北を鳴り分ける。同時発音は最大8音で、音の生成はゲーム進行の乱数を消費しない。実素材への差し替えには `GameAudio.set_override(cue, AudioStream)` を使い、nullを渡すと仮音へ戻る。環境音は `audio/dungeon_ambience.gd` の低音量ループで代用し、`stream_override` へ実素材を設定できる。これらは完成音源ではなく、音量とタイミングを確認するための仮実装とする。

拠点UIはキーボードの既存操作に加え、ゲームパッドの十字キーでFocus移動、Aで決定、Bで戻る操作を受け付ける。`ui_accept`・`ui_cancel`・方向の標準アクションへ登録し、マウスと同じButton signalで演出する。既存のキーボード割り当ては保持する。

変更時は `tests/test_ui_theme.gd`、`tests/test_ui_layout.gd`、`tests/test_ui_motion.gd`、`tests/test_upgrade_ui.gd` に加え、該当する取引・装備・セーブのテストを実行する。描画可能な環境では `tests/capture_art_direction.gd`（7画面を1440×900・1152×720・1920×1080で確認）、`tests/capture_shop.gd`、`tests/capture_preparation.gd`、`tests/capture_ui_motion.gd`、`tests/capture_item_details.gd`、`tests/capture_upgrade_ui.gd`、`tests/capture_item_cards.gd` で通常サイズ・縮小表示・各入力・ボタン端のクリックを確認する。演出用キャプチャは60 FPS上限でアイドル時と演出中のフレーム時間も比較する。生成画像は `.godot/` に出力する。

## UI体験の改善（優先度順）

現行UIは、情報を正しく・崩れずに表示するという条件は満たしているが、プレイヤーに何かを感じさせる場面としては設計されていない。拠点の背景は描き込まれているのに、その上のパネルは平らな石墨色の矩形とゴシック体の文字だけで構成されているため、背景とUIが別々の作品のように見える。全画面が「ヘッダー＋暗いパネル＋戻る」の同じ構造なので、画面を移っても場面が変わった感覚がない。演出は0.07〜0.28秒の縮小・拡大と透明度の復帰だけで、動きに方向や溜めがなく、購入・装備・能力獲得のような報酬の瞬間も、ボタンを押した時と同じ手触りで終わる。さらに、プレイ時間の大半を占めるダンジョン側の能力選択・所持品・冒険結果は、拠点側で整えた `ItemCardList`・`ItemGlyph`・`ItemShowcase` を使っておらず、文字だけのボタンとリストで構成されている。この節は、これらを製品として遊べる水準へ引き上げるための方針と、画面ごとの改善内容を優先度順に定める。本節と上記の記述が矛盾する場合は本節を優先する。ゲームロジック・セーブ仕様・Item / Stage / Ability Dataは変更せず、現行データにない値を表示のために作らない。

### 共通方針

各画面に「プレイヤーの選択が結果に変わる瞬間」を1つだけ定め、その瞬間の演出を最も手厚くする。以下ではこれを見せ場と呼ぶ。見せ場以外の操作は、現行の控えめな反応のままでよい。演出を全画面に均等に足すと、どれも見せ場にならないためである。

演出の時間は3段階に分ける。Hover・Focus・押下などの反応は80〜120ms、画面・パネル・選択詳細の入れ替わりなどの遷移は180〜260ms、能力獲得・購入・装備・冒険結果などの見せ場は400〜900msとする。入場は `TRANS_CUBIC` の `EASE_OUT` を基本とし、見せ場の強調だけ `TRANS_BACK` の `EASE_OUT` で最大1.05倍までのオーバーシュートを許す。退場は120msの `EASE_IN` とし、退場中も次の画面が入力を受け付ける。見せ場の演出は、決定・キャンセル入力で即座に最終状態へ飛ばせるようにする。いずれの演出もゲーム処理・保存・入力の可否を待たせないという既存の原則は維持する。

位置を動かす演出は、Containerの子そのものではなく表示層で行う。表示層とは、Containerが配置するControlの内側に置いた、Containerの管理を受けない見た目用のControl（`mouse_filter` はIgnore）であり、その `position`・`scale`・`modulate` だけをTweenする。Focus・入力・レイアウト計算は元のControlが持ち続ける。一覧から詳細へアイコンが飛ぶような、Controlの境界をまたぐ演出は、画面最上位の `CanvasLayer` に置いたオーバーレイへ一時的な複製を描いて行い、終了後に破棄する。

Gold・EXP・到達階など結果の数値は、状態と保存上の値を即時に確定させたうえで、表示だけを前の値から新しい値へ数えて見せる。数える時間は差の大きさに応じて最大600msとし、差が小さいときは短くする。開いた直後の誤選択は、キーリピート（`echo`）を受け付けないことで防ぎ、時間による入力の無視は設けない。入場演出の途中でも、キー入力で即座に選択できる状態を保つ。

書体は、画面名・見出し・ロゴ用の表示書体（明朝体またはセリフ体）と、本文用のゴシック体の2系統にし、数値には等幅数字を使う。書体の指定はThemeの `TitleLabel`・`HeadingLabel`・`ValueLabel`・`GoldLabel` などで行い、画面ごとのoverrideはしない。採用する書体は商用利用と同梱が許されるライセンスのものに限る。

パネルの質感は、Themeの `MainSurface`・`ItemSurface` などを、装飾枠つきの `StyleBoxTexture`（9-slice）へ差し替えられる構成にする。枠素材がない間は現行の `StyleBoxFlat` のまま表示する。これを素材差し替え口と呼び、カードの挿絵や背景の差し替えも同じ考え方で、素材がない場合は現行表示で成立させる。

ダンジョン中のHUD・能力選択・所持品・冒険結果も、拠点と同じTheme・書体・`ItemGlyph` を使う。拠点とダンジョンで作品の質感が途切れないようにするためである。効果音は、反応段階にカーソル移動音と決定音を、見せ場ごとに専用の音を割り当てる。素材が揃うまでは `GameAudio` の仮音cueを追加して代用する。

### 優先度A：ダンジョンの見せ場

**A1. レベルアップの能力選択。** 現行は縦に並んだ3つの文字ボタンで、能力名・Lv・効果が1行に詰め込まれている。これを横並びの3枚のカードにし、各カードに能力の記号、能力名、Lvの進捗（上限までの目盛り）、次のLvで得る効果を大きく表示する。記号はAbilityDataに分類がないため、既存の `Effect`（最大HP・攻撃・防御・武器別の威力・射程・貫通・視界・撃破回復）から `ItemGlyph` の記号へ対応づけて描く。見せ場は能力を選んだ瞬間とする。カードは開いた時に60ms間隔で下から順に入場し、Hoverしたカードは少し持ち上がる。選択と同時にダイアログは閉じてターンが再開し、選んだ瞬間の演出は、入力を受け取らない別の `CanvasLayer` に複製したカードで再生する。選んだカードは拡大して金色に光り、Lvの目盛りが1つ埋まり、他の2枚は沈んで消える。次の選択が続く場合は、前の演出を即座に破棄して新しいカードを入場させる。1・2・3キーとマウスでの選択と、残り回数の表示は維持する。今後、HUDの該当する数値（最大HPなど）を一度だけ強調する演出と、ゲームパッドでの選択を加える。

**A2. ダンジョンHUDと戦闘の手応え。** HUDのパネル・書体・色を拠点のThemeへ揃える。装備欄は「Main 槍」のような文字だけの表示をやめ、`ItemGlyph` の記号と名前で5枠を示す。ミニマップは既知の範囲をパネルいっぱいに拡大し、プレイヤーと既知の階段を記号で示す。未探索の情報は表示しない。メッセージログは古い行から薄くして、最新の2行だけをはっきり見せる。階層開始のバナーは、画面中央の箱から、上下に余白を持つ帯状の見出しへ変え、階数を表示書体で大きく見せる。戦闘では、プレイヤーの被弾と敵の撃破の瞬間に40〜60msのヒットストップを入れ、プレイヤーの被弾時だけ3〜6pxの画面揺れを加える。ヒットストップは `BattlePresentation` が再生中のTweenを一時停止して実現し、`Engine.time_scale` は変更しない。揺れは固定のパターンで行い、ゲーム進行の乱数を消費しない。揺れの強さは1か所の定数で管理し、将来の設定画面で弱められるようにする。HUDのパネルは共通Themeの `HudPanel` とHUD用の文字役割（`HudCaption`・`HudValue`・`HudSmall` など）を使い、Scene側のTheme overrideを持たない。パネル内部の配置は、テストと演出が参照するノードの構成を保つため当面は固定配置とし、Containerへの移行は表示書体の導入（B4）と合わせて行う。ダメージ数値は大きさと縁取りで他のポップアップより目立たせ、EXP・Goldの取得表示とは位置と色で区別する。

**A3. 冒険結果。** 現行は到達階・獲得Gold・失ったものを文字で並べただけで、クリアと敗北の見た目がほとんど変わらない。見せ場は結果が確定する瞬間とする。タイトルを表示書体で大きく出したあと、到達階・獲得Gold・残高を1行ずつ順に表示し、Goldは数えて見せる。失ったアイテムは `ItemCardList` と同じ記号付きの形式で並べ、失われたことが一目でわかる表示にする。持ち帰れた装備5枠も記号で並べる。クリアは暖色の金、敗北は彩度を落とした赤を基調とし、効果音も分ける。値は表示前にすべて確定させ、行の順次表示と数値の数え上げは約1秒以内に終える。演出中も拠点へ戻る・再挑戦の操作は即座に受け付け、画面を閉じた時点で数値と表示を最終状態に戻す。失ったアイテムと持ち帰る装備は、基準解像度と縮小表示のどちらでもスクロールせずに見える高さを確保する。保存状態の表示は維持する。

### 優先度B：流れと第一印象

**B1. ダンジョン内の所持品。** 現行は文字だけの所持品リストと「Main：剣」形式の装備一覧である。拠点の装備画面と同じく、所持品を `ItemCardList`、選択品を `ItemShowcase` と `ItemDetails`、装備5枠を記号付きの枠で表示する。選択品の主効果は `ItemShowcase` に1回だけ表示し、説明欄には射程やノックバックなど追加の情報だけを載せる。装備品を選んだ場合は、装備後の最大HP・攻撃・防御・射程・視界のうち変化するものだけを、現在値→装備後の値で示す。比較先は空いている対応枠、なければ最初の対応枠（武器ならMain）とし、装備操作にポインタを重ねるとその枠との比較に切り替える。比較値はプレイヤーの `stats_with()` で求め、レベルアップの能力と一時効果を含めて実際の装備後の値と一致させる。空の装備枠には取り外し操作を出さず、Main枠は外せないことを無効化した操作で示す。装備・取り外し・使用・武器切替の操作と、ターン消費の説明は維持する。

**B2. 画面遷移と出撃の流れ。** 拠点の画面切り替えでは、新しいパネルを表示層で16〜24px横から180〜220msで入場させ、一覧の項目を30ms間隔、最大6件まで順に表示する。出撃確認からダンジョンへ移る時は、画面を暗転させてステージの既存画像と名前を見出しとして出し、そのまま1Fのバナーへつなげる。冒険終了から拠点へ戻る時も暗転を挟む。暗転中も読み込みや状態の確定は待たずに進める。

**B3. 拠点ホーム。** 左右のナビゲーションカードは、出撃を他より大きく扱い、表示書体の見出し、装飾枠、カードごとの挿絵を差し替え口で受け付ける。挿絵がない間は現行の記号とする。右下の「Main 剣／持ち込み／倉庫」の情報欄は、文章の羅列をやめ、記号と数値で次の冒険の準備状況を示す。ロゴ「DungeonRemnant」は表示書体で描き、本文と同じ格に見えないようにする。

**B4. 書体と枠素材の導入。** 共通方針で定めた表示書体と `StyleBoxTexture` の差し替え口をThemeに用意する。B3と優先度Cの画面は、この差し替え口を前提に作業する。

### 優先度C：拠点の各画面

**C1. ショップ。** 右パネルで商品名・分類・効果が上下に2回表示されている重複をなくし、空いた領域を購入前後の比較に使う。購入数はGodot標準のSpinBoxをやめ、−／＋ボタンと数値の組にする。見せ場は購入の瞬間とし、Goldを数えて減らし、商品の記号を所持数の表示へ飛ばしてから、所持数を強調する。売却も同じ形でGoldを増やす。

**C2. 装備。** 比較欄では変化のある能力値を先頭に大きく表示し、変化のない行は薄くまとめる。装備枠は文字だけのボタンをやめ、装備中の品の記号を表示する。見せ場は装備を変更した瞬間とし、枠に記号が収まる動きと、`CharacterPreview` の短い発光を加え、次の冒険の能力値を数えて更新する。

**C3. 永久強化。** 各能力のLvを上限までの目盛りで示し、前提条件の関係を線で結んで、ツリーとしての構造が見えるようにする。見せ場は強化の瞬間とし、目盛りが1つ埋まる動き、光の広がり、上部の永久補正の合計の数値更新を順に見せる。

**C4. 倉庫。** 見せ場は移動の瞬間とし、選択品の記号を移動元の一覧から移動先の一覧へオーバーレイで飛ばしてから、移動先の該当行を強調する。

**C5. 拠点の環境演出。** 背景の燭台の光の揺らぎと、空中の埃の粒子を加え、拠点キャラクターは既存の待機アニメーションで呼吸させる。操作していない間も画面が生きて見えるようにするためである。これらはUIの読みやすさを妨げない強さに抑え、Focus表示と本文の視認性を優先する。

### 必要な素材

以下の素材は外部で用意する。どれも差し替え口を通して使い、未着手の状態でも各項目の実装は進められる。表示書体と本文書体のフォントファイル（ライセンス確認済みのもの）。パネルとカードの装飾枠の9-slice画像（通常・選択の2種）。拠点ホームの5枚のカード用の挿絵。見せ場ごとの効果音（能力獲得・購入・売却・装備・強化・冒険クリア・敗北）と、カーソル移動音。

### 検証

各見せ場について、`capture_*.gd` で演出開始・25%・50%・完了の4時点を1440×900・1152×720・1920×1080で撮影し、人の目で確認する。Headlessのテストでは、状態と保存上の値が演出の開始前に確定していること、見せ場を決定・キャンセル入力で最終状態へ飛ばせること、入場演出の途中でも選択できること、非表示・解放時に表示層とオーバーレイが基準状態へ戻ることを検証する。ヒットストップと画面揺れは、戦闘の論理座標とターン順序を変えないことを既存の戦闘テストで確認する。
