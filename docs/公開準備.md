# 公開準備

この文書は、Dungeon RemnantをSteamで公開するまでの進め方と、品質向上の課題を管理するためのものです。MVPと内容の区切り（M1〜M3）は2026年10月までに終わり、今は公開に向けて品質を上げる段階にあります。ゲームの仕様は [ゲーム仕様.md](ゲーム仕様.md)、Windows向けの書き出しは [Windows配布手順.md](Windows配布手順.md) にあり、この文書には公開までの区切り、品質の基準、課題の記録、Steamで必要な作業、決めたことと、まだ決めていないことを置きます。

## 1. 公開までの区切り

| 区切り | 中身 | 終わったと言える条件 |
| --- | --- | --- |
| M4 仕上げ | 残響と永続強化ツリーの総額の調整、4章分での難易度の段階の調整、初めて遊ぶ人のプレイでの計測、余裕があれば呪い+2（[ゲーム仕様.md](ゲーム仕様.md) の16章「制作の順番」） | 初めて遊ぶ人の計測で、初回エンディングまで約30ラン、やり込みの天井まで約60ランに収まる |
| R1 製品の体裁 | 3章の課題のうちP0・P1の解消と、ゲーム名・アイコン・保存先など、ストアで売る製品として必要な体裁。日本語と英語の切り替え（5章） | 3章にP0・P1の課題が残っておらず、IMP-005〜IMP-007（アイコン・名前・保存先）が完了している。設定画面で日本語と英語を切り替えられ、英語でも初回起動からエンディングまで遊べる。6章の未決事項のうち、R2までに決める項目が決まっている |
| R2 ストアページの公開（近日登場） | Steamworksへの登録、ストアページの文章と素材、ストアページの審査 | 近日登場のページがSteamで見られる |
| R3 発売 | 発売用ビルドのアップロード、ビルドの審査、発売の操作 | Steamで購入して遊べる |

R2は、M4やR1と並べて早めに進めてもよい。近日登場のページは発売の2週間以上前に出しておく必要があり、ページを出してからの期間がウィッシュリストを集める期間にもなるためです。

## 2. 公開できる品質の基準

公開するビルドは、次をすべて満たすものとします。仕組みやコンテンツの採否は、引き続き [ゲーム仕様.md](ゲーム仕様.md) 2章のデザインの柱で決めます。

- 3章の課題に、P0（進行不能・データ消失・クラッシュ）とP1（主要操作・戦闘・ランの流れを大きく損なう）が残っていない。
- M4の条件のとおり、初めて遊ぶ人が初回エンディングまで約30ラン、やり込みの天井まで約60ランで届く。
- 公開するビルドと同じコミットで、`python tools/run_tests.py` のすべてのスイートと、撮影用Script（`tests/capture_*.gd`）による見た目の確認が通っている。
- ゲームパッドだけ、またはキーボードとマウスだけで、初回起動からエンディングまで遊べる。
- 1280×720・1600×900・1920×1080のどれでも、日本語と英語のどちらでも、文字切れ・重なり・Focusの見失いがない。
- 敵200体の場面で、フレーム時間が8ms以内に収まる（RTX 3060・1600×900。MVPの完成条件と同じ目標で、`tests/capture_crowd_perf.gd` で測る）。
- 同梱する第三者素材が、すべてCLAUDE.mdの「第三者素材の採用」の基準を満たし、`THIRD_PARTY_NOTICES.md` に載っている。

## 3. 課題の記録

### 記録ルール

1. まず観察した事実を「気になった点」に記載する。
2. 再現条件、期待した状態、実際の状態を分ける。
3. 原因や解決策を決めつけず、プレイヤーへの影響を記録する。
4. 同じ問題を再現または複数回確認してから、改良課題へ移す。
5. 改良課題ごとに優先度と完了条件を決め、Plan承認後に実装する。

優先度は次の基準を使います。

| 優先度 | 基準 |
| --- | --- |
| P0 | 進行不能、データ消失、クラッシュなど、プレイ継続を妨げる |
| P1 | 主要操作・戦闘・ランの流れを大きく損なう |
| P2 | 分かりにくさ、バランス、反復的な不便など、体験を継続的に損なう |
| P3 | 軽微な表示、演出、将来的な拡張候補 |

## 5. 決めたこと

### 対応言語は日本語と英語（2026-11-08）

Steam版は、日本語と英語の両方に対応して発売します。日本語だけでは、ストアページもゲームも日本語を読める人にしか届かないためです。英語は今の2つのフォント（しっぽり明朝・BIZ UDPゴシック）でそのまま表示できるので、フォントを足さずに済みます。簡体字中国語は、日本語のフォントにない字が多く、中国語用のフォントの追加と訳の確認まで要るため、今回は対象にしません。

決めた時点では、画面に出る日本語は重複を除いて約690件・約7,900字あり、約350件が `data/` の `.tres`（強化・敵・章などの名前と説明）、残りが `ui/` と `game/` のScriptに直接書かれていました。Godotの翻訳の仕組み（`tr()` と翻訳ファイル）はまだ使っていません。そのため、次の順に進めます。

1. 文字をScriptと `.tres` から翻訳ファイルへ移し出し、設定画面に言語の切り替えを足す。ゲームの名前（`config/name`）も翻訳ファイルで訳し、日本語ではウィンドウの題名を「残響の迷宮」にする。数値を差し込む文（約140件）は、言語ごとに語順を変えられる形にする。仕組みの選び方は、実装の前に調べて決める。
2. Claudeが用語集（残響・周回限定強化・永続強化・章や敵の名前などの訳語と、訳さない語）を作り、ユーザーが確かめる。
3. 用語集に沿ってClaudeが全文を英訳し、ユーザーが読んで直す。
4. 英文は日本語より長くなりやすいため、撮影用Script（`tests/capture_hub.gd` など）を英語でも撮り、2章の基準で文字切れを確かめる。
5. 発売の前に、英語の分かる人に英語版を遊んでもらい、訳の分かりにくさを3章の「気になった点」に記録する。

### Steamの機能は、クラウド保存だけを使う（2026-11-08）

発売時のSteam版は、Steamworks SDKを組み込まず、Steamの機能のうちコードを書かずに使えるものだけを使います。

- **Steamクラウド**: Auto-Cloudで、セーブ（`progress.json` とその控えの `progress.json.bak`）だけを同期します。Auto-CloudはSteamworksで保存先のフォルダーとファイルの形を登録するだけで、Steamが起動時と終了時に同期するため、ゲーム側の変更は要りません。`settings.cfg`（画面モード・音量など）は、PCごとに合う値が違うため同期しません。登録するルートは `WinAppDataRoaming`、その下のフォルダーは `DungeonRemnant` です（このあとの「名前と保存先」）。
- **実績・統計・リーダーボード・リッチプレゼンス**: 発売時は入れず、発売後のアップデートの候補にします。これらはSteamworks SDKをGodotから呼ぶAddon（GodotSteamなど）が要り、[ゲーム仕様.md](ゲーム仕様.md) 2章の「外部Addonは入れない」方針の見直し、Godot 4.7で動く版の確認、Steamを通さないZIP版でも動く分岐が必要になります。公開までの作業を品質と英訳に集中させるため、後に回しました。入れるときは、実績の一覧（章の踏破、難易度の段階など）を [ゲーム仕様.md](ゲーム仕様.md) 2章のデザインの柱に照らして設計します。
- **オーバーレイとSteam Input**: Steamから起動すれば、SDKがなくてもSteamのクライアント側で動きます。ゲームパッドは今のGodotの入力で対応しているため、発売の前にSteamから起動して、オーバーレイが開くことと、ゲームパッドで最後まで遊べることを確かめます。

### Steam Deckへの対応は発売時には約束しない（2026-11-08）

発売時は、Steam Deckへの対応を約束せず、Deck向けの作業と確認もしません。ユーザーがDeckの実機を持っておらず、Deckでの性能とProton（WindowsのゲームをLinuxで動かす互換レイヤー）上での描画を確かめる手段がないためです。Valveはすべてのゲームを審査してストアに結果（認証済み・プレイ可能・非対応など）を表示しますが、結果が「非対応」でも販売はできます。ストアページの説明文やタグでも、Deckへの対応はうたいません。

決めた時点で調べた、Valveの審査の基準と今のゲームの差は次のとおりです。発売後に対応を目指すときは、ここから始めます。

- 画面は1280×800か1280×720で動くことが求められます。今のStretchは縦横比を保つため、1280×800では1280×720に縮小され、上下に40pxずつ帯が出ます。この形でも基準に合う見込みです。
- 1280×800で、最も小さい文字の高さが9px以上であることが下限で、12px以上が推奨です。今のThemeで最も小さい文字サイズ13pxは、縮小すると約10.4pxになります（文字サイズと字の高さは同じではないため、実際の高さは撮影して測る）。
- 画面に出すボタン名は、DeckかXboxのボタン名にし、キーボードやマウスの表示は、それを使っている間だけ出します。操作ガイド（`KeyGuide`）は入力に合わせて切り替わりますが、設定画面のヘルプの文章は「Esc」や「左クリック」を常に書いています。
- 性能（敵200体の場面）と、d3d12の描画がProton上で正しく動くかは、実機でしか確かめられません。

審査の結果が出たら、3章の「気になった点」に記録し、対応するかどうかをそのときに決めます。

### 売り方は正式発売・体験版なし・4.99米ドル前後（2026-11-08）

- **正式発売**: 早期アクセスではなく、正式発売で売ります。Steamは早期アクセスを、遊びの形がまだ大きく変わっている作品のための仕組みとし、遊びの形が決まって仕上げだけが残っている作品には向かないとしています。このゲームは全4章とエンディングまででき、新しい仕組みはもう足さないと決めているため、正式発売が合います。発売後の不具合の修正や、実績などの追加はアップデートで行います。
- **体験版は出さない**: 体験版の制作と管理をせず、Steam Next Festにも参加しません。Next Festは体験版がないと参加できないため、ウィッシュリストを集める場は、近日登場のストアページ（1章のR2）だけになります。
- **価格は4.99米ドル前後**: 基準の価格を4.99米ドル前後とし、各地域の価格は、Steamworksで米ドルの価格から出る地域価格の案を基に決めます。今は目安で、R3でストアに価格を設定する前に見直します。

### 名前は「Dungeon Remnant」と「残響の迷宮」、保存先は `%APPDATA%\DungeonRemnant`（2026-11-08）

- **名前**: 正式な名前は、英語で「Dungeon Remnant」、日本語で「残響の迷宮」とします。英語名はREADMEとエンディングのスタッフロールですでに使っており、決めた時点でSteamを調べた範囲では、同じ名前の作品はありませんでした。日本語の題名は、英語名を読みのまま写さず、ゲームの中で持ち帰る通貨や最終章の名前に使っている「残響」と結びつけて訳しました。ストアページでは、日本語の表示にこの題名を使います（Steamworksで名前を言語ごとに設定できるかは、R2で確かめる）。ウィンドウの題名・実行ファイル名・製品名の書き換えはIMP-006で行い、日本語のウィンドウの題名は、翻訳の仕組みを作るときにゲームの名前を翻訳ファイルで「残響の迷宮」と訳して出します。「Remnant」は他社の別のシリーズの名前にも含まれる語のため、商標として問題がないかは、ストアページを出す前に必要に応じて専門家に確かめます。
- **保存先**: セーブと設定は、Godotのフォルダーを通さずに `%APPDATA%\DungeonRemnant` に置きます。遊ぶ人がゲームの名前で探せ、空白のない名前なのでコマンドでも扱いやすいためです。Steamクラウドに登録するフォルダーもこの名前になります。
- **引き継ぎ**: 名前を変えると今の保存先を読まなくなるため、起動時に一度だけ、旧い保存先のセーブと設定を新しい保存先へコピーします。新しい保存先にセーブがあるときはコピーせず、旧いファイルは消しません。Steam版はまだ出ていないため、引き継ぎで守るのは開発中のセーブと、ZIPで配った版のセーブです。作業はIMP-007で行います。

- **ゲームの終了をロビーに置くか（OBS-037）**: ロビーのメニューに項目を足すことになる。
- **エンディングを見返す導線（OBS-038）**: 設定の項目を足すことになる。
- **エリアを選ぶたびの確認の窓（OBS-059）と、結果画面からの再出撃（OBS-067）**: 好みの範囲で、今の作りにも理由がある。
- **ラン開始直後の敵の硬さ（OBS-018）、ランの長さ（OBS-024）、第1層の3択（OBS-025）**: 道のりを延ばす件（OBS-009）と一緒に、初めて遊ぶ人の計測（M4）の結果を見てから決める。
